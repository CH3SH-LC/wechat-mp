## 这是什么故障

`::: photo 说明` 在引擎协议里是**单行指令**，正文从下一行开始。旧解析器却从照片位一路向后扫，
直到遇见第一个 trim 后等于 `:::` 的行为止——而那个 `:::` 很可能是**后面某个 `::: art` 素材块的结束符**。
于是照片位把紧随其后的段落、`::: art` 头部（含别名列表）与**整段 SVG** 全部吞进自己的"说明"字段，
再由 `escapeHtml` 转义成**可见文字**输出。

真实成品 `article.html` 的实测计数（本目录 `failing-doc.json` 的 `html` 字段保存了这 3 段原文）：

| 指标 | 实测 |
| --- | --- |
| `<img>` | 6（全是照片位占位与侧栏图，**没有一张是 art 素材**） |
| 有效 art | 0 |
| 可见的转义 `&lt;svg` | **3 处** |
| 可见的内部 `::: art` 文本 | **3 处** |
| `【照片位】` | 3 处 |

3 处泄漏与 3 个照片位一一对应——每个照片位吞掉紧跟它的那个素材块。

同一份 `meta.json` 里 `checkHtml` 的结论是 `ok:false`（`emoji`：`发现 emoji/图标字符：① ② ③`），
但保存流程仍以 `ok:true / 成稿已保存` 收尾，也没有触发自动修订。**这条"红了下游却放行"的链路不在本样例的断言范围内**，
本样例只钉住解析器这一侧的根因。（另可参考仓库外证据
`~/.codex/visualizations/2026/09/29/01a0eb06-c18e-72d1-b7b0-892d6dee2387/latest-quality-evidence.json`：
`probe.unclosedThenArt = { arts: 0, leak: true, unclosedWarning: false }`。）
