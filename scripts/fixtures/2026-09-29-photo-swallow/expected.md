# 可证伪的期望（修复后应当是什么样）

对着 `failing-source.md` 的两个用例（`CASE: minimal` / `CASE: real`）逐条写死。
每条都能被一次 `node scripts/photo-swallow-check.mjs` 判定真假——没有"看情况""大体上"这类不可证伪的措辞。
脚本里的断言与此表一一对应；改断言必须同时改这里，改不动这里就说明在删证据。

口径：

- **可见文本** = 成品 HTML 剥掉标签、反转义 `&lt; &gt; &quot; &#39; &amp;`、折掉空白之后的文本，
  **并先跳过行内代码 span**（`inline()` 产出的等宽 span）——合法代码示例里出现 `::: art` 或 `<svg` 属于内容，
  不能被全局字符串规则误杀。与 `src/lib/compose.ts` 的 `visibleTextOf()` 同口径。
- **照片位的说明** = `【照片位】…</section>` 这一小段里的文本，不含它后面的正文。
  判定"吞没"必须查这里，不能拿整篇可见文本去查（那是假阳性，本脚本初稿就栽在这上面）。

## 期望清单

| # | 期望 | 怎么证伪 | 对应断言 |
| --- | --- | --- | --- |
| E1 | `CASE: minimal`：单行照片位之后的段落**仍在正文** | 该段文字不出现在可见文本里即失败 | ① 最小片段：段落仍在正文里 |
| E2 | `CASE: minimal`：该段落**不在照片位的说明里** | 照片位说明包含该段文字即失败（吞没） | ① 最小片段：照片位的**说明**里没有紧随其后的段落 |
| E3 | `CASE: minimal`：源文范围不跨块——素材块被解析成素材 | `arts.length !== 1` 即失败 | ① 最小片段：源文范围不跨块 |
| E4 | `CASE: minimal`：可见文本无内部协议泄漏（`<svg` / `::: art` / `[[asset:` 各 0） | 任一项计数 > 0 即失败 | ① 最小片段：可见文本无内部协议泄漏 |
| E5 | `CASE: real`：可见文本里转义 `<svg` **出现 0 次**（真实成品为 3 次） | 计数 > 0 即失败 | ② …无转义 `<svg` |
| E6 | `CASE: real`：可见文本里内部 `::: art` **出现 0 次**（真实成品为 3 次） | 计数 > 0 即失败 | ② …无 `::: art` |
| E7 | `CASE: real`：可见文本里 `[[asset:` / `[[img:` / `[[deco:` **出现 0 次** | 计数 > 0 即失败 | ② …无未解析协议（本例已固化素材，源文里没有未解析协议行，此项是**空转的守门员**；真正会命中它的是素材固化失败留下的原文） |
| E8 | `CASE: real`：3 个照片位全部保留（不多不少） | `【照片位】` 计数 ≠ 3 即失败 | ② …3 个照片位全部保留 |
| E9 | `CASE: real`：3 处照片位的后续段落都在正文里，且都不在照片位说明里 | 任一段缺失、或被吸进说明即失败 | ② …后续段落都在正文里且不在照片位说明里 |
| E10 | `CASE: real`：**素材落位或明确阻断**——源文 7 个 `::: art` 块，每个要么产出素材（`arts`），要么留下带原因的可见占位（`（此处原为美术素材「…」，未达标已略过）`）；不得静默消失 | `arts.length + 明确阻断数 ≠ 7` 即失败 | ② …素材位不静默消失 |
| E11 | `ComposeResult` 暴露结构化的 `issues` 与 `rejectedArts`（调用方要能按代码而非中文文案分支、并按行定位） | 任一不是数组即失败 | ② …ComposeResult 暴露 issues / rejectedArts |
| E12 | 容器块（`::: card`、`::: steps` …）的块体**不跨越下一个块起点**——不能只修照片位 | 卡内的 art 块被并进容器、或 `arts.length !== 1` 即失败 | ③ …art 块未被并进 card |
| E13 | **显式闭合的历史多行照片块仍被兼容**：`::: photo 说明` + 纯文本说明行 + `:::` 仍渲染为**一个**照片位，补充说明进入照片位说明；不得为了修故障把合法旧块判死 | 照片位计数 ≠ 1、或说明里没有补充说明即失败 | ④ … |
| E14 | 歧义输入（单行照片位 + 空行 + 段落 + 后面某块的 `:::`）按**单行**处理：照片位只吃行内头部，后续段落与后续块照常解析，不被吸进照片位 | 照片位说明里出现后续段落/后续块内容即失败 | ⑤ … |

## 不属于本样例的期望（别把它们算进来）

- **`checkHtml` 不通过却仍 `ok:true / 成稿已保存` 且不自动修订**：这是保存链路的门禁问题
  （证据：`latest-quality-evidence.json` 的 `autoReviseTriggers: []`），本样例只钉解析器一侧的根因，
  不在此断言。修它需要在保存链路上加断言，不是本 fixture 的职责。
- **① ② ③ 这类圈码字符触发零 emoji 铁律**：真实成品被它判了 `ok:false`；文案层问题，不在此断言。
- **超过 20000 字符的微信保存限制**：与吞并没因果关系（吞并反而让字符数虚增），不在此断言。
- **真实模型下重新生成整篇**：需要付费调用授权，本样例全程离线。
