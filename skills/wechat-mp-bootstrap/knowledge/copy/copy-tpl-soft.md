# 产品软文模板（copy-tpl-soft）

> **定位**：
> 把一款产品 / 服务放进读者真实的生活场景里。
> 先让读者认同「我确实有这个需要」，
> 再顺理成章引出「这个产品恰好能解决」。
> 用价值建立信任，用信任带动行动。
>
> **调用时机**：
> 写「推广产品但不硬广」的文章时用，也就是种草文、带货文、测评导购文。
> 典型场景——推荐一个学习效率工具、种草一台空气炸锅、
> 介绍一门课程、安利一款护肤精华、推荐一个记账 App。
> 核心是「软」：先给读者价值（内容 / 知识 / 共鸣），再自然地带出产品，
> 别一上来就王婆卖瓜。判断依据见「内容类型」维度判断流程。

## 一、结构与写法

软文最大的天敌，是「读者一眼看穿你要卖货就划走」。
所以不能开头就上产品，要先用读者认同的内容留住他。
结构：场景 / 痛点切入 → 产品引出 → 卖点分点（功能 + 利益）→ 证言 / 数据 → 行动。

### 阶段一：场景 / 痛点切入（约占 20%）

**写作目标**：
先写你懂读者的处境，让读者觉得「这篇是给我看的，不是广告」。

**写法要点**：
- 写一个读者真实会遇到的场景或痛点，要有代入感。
  例：「每天下班想学点东西，
  打开某 App 刷了两小时却什么都没干成，还觉得挺累。」
- 场景要具体到细节，可信度全靠细节：
  「手机上装了十几个学习软件，全都在『下载后打开过一次』的名单里。」
- 此阶段不出现任何产品信息，纯讲读者处境。
  忍住不提前推销，是软文成败的关键。
- 可以做一点铺垫式观察：
  「后来我慢慢发现，问题不在自律，在工具。」

**判断切入好不好**：
读者读到这里，会不会觉得「这就是我、说得对」。
如果读者没这个处境，或觉得「这是在教育我」，
说明切入点没选对，重写。

**时长/篇幅建议**：
首段即可进入场景，但整个切入段约 15-25%，150-300 字。
足够长到建立信任，又别长到读者失去耐心。

### 阶段二：产品引出（约占 10%）

**写作目标**：
把产品和前面讲的需求自然挂钩，让产品「出场」得不突兀。

**写法要点**：
- 用「转折 / 发现」方式引出：
  「直到朋友推荐了这个工具，我才发现原来可以这么省事。」
  把产品当成「我踩坑后的答案」，而不是「厂家塞给我的广告」。
- 一句话说清产品是「什么」（是什么、给谁用）。
- 不急着夸，先给读者一个「为什么我会选它」的理由铺垫。

**引出时最忌讳**：
直接甩产品名和一堆参数。
要先让读者认同「我需要这个」，产品才接得住。

**时长/篇幅建议**：
50-100 字。
引出要短，自然过渡，别停在卖点轰炸上。

### 阶段三：卖点分点（功能 + 利益，约占 40%）

**写作目标**：
把产品最打动人的几个点讲清楚，
每个点都要让读者明白「这个功能对我有什么用」。

**写法要点**：
- 3-5 个卖点，每个卖点 = 功能（它是什么 / 能做什么）→ 利益
  （对读者有什么用 / 解决他什么）。
  只有功能没有利益，读者不知道跟自己的关系。
- 例：「1 自动分类记账——不用每月手动对账，
  月底自动生成支出图表，你知道钱花哪了（功能 → 利益）。」
- 卖点要挑「读者最痛」的：
  回到开头那个痛点，你的卖点应该逐一回应它。
- 多用「我」的使用体验来举例，比干巴巴列参数可信。
- 可在关键处插一个「我用了半个月的感受」的真实叙事，拉近信服度。

**避免「罗列参数」陷阱**：
写参数是为了支撑利益，不是为了展示参数。
每写一个功能，都要问一句「这对读者有什么用」。

**时长/篇幅建议**：
约 40%，500-900 字，这是全文的信任建立核心。每点 100-180 字。

### 阶段四：证言 / 数据（约占 15%）

**写作目标**：
用第三方的声音给「我」的推荐背书，弥补自说自话的分量不足。

**写法要点**：
- 用真实的用户证言（别人用了之后的反馈）
  或可查证的数据（参与人数、效果数据、官方统计）。
  证言最好指名或带具体细节，比「大家都说好」可信。
- 数据要真实可核验，不虚构（见合规）。
  例：「官方数据显示，上线 3 个月已有 20 万用户在使用。」
  若无法核验，不写或标注来源。
- 证言可以和「用户证言 / 口碑卡」模块配合做视觉展示。

**证言的可信度排序**：
指名 + 具体细节 > 具体细节 > 笼统转述 > 编造。
宁可少写一条真实的，也别写一条假的。

**时长/篇幅建议**：
100-200 字，一条到两条有力的证言或数据即可，多则腻。

### 阶段五：行动（约占 10%）

**写作目标**：
给读者一个明确的下一步，把好感转换成动作。

**写法要点**：
- 动作要低门槛：
  「想试试的，文末『阅读原文』有 7 天免费试用」；
  「长按识别二维码领取专属优惠」。
- 明确写清价格 / 优惠 / 门槛，别藏着掖着让读者失望。
- 常配合「小程序卡片」「资料领取 / 福利入口」。

**行动与软文调性**：
软文的行动号召要自然，
别突然变成命令式「立即购买」。
给读者「想试就来」的轻松感，转化反而更好。

**时长/篇幅建议**：
80-120 字，明确收口。

## 二、完整骨架（可套用，标出的地方是替换处）

```
【标题】
〔标题走「价值/解决方案」路，别一眼像硬广。
  例「下班后想学点东西，凭什么总坚持不下去？」；
  或「我用半个月的记账 App，真的救了我」；
  避免带品牌名的硬邦邦顶格〕

【切入 · 场景/痛点】
〔写一个读者真实处境/痛点，带细节，2-3 行〕
〔此段不出现产品，纯讲读者的事〕

【引出 · 产品】
〔用「转折/发现」引出产品：它是什么、给谁用〕
〔给一个「为什么我选它」的铺垫〕

【卖点 · 功能+利益分点】
### 〔卖点一：功能是什么〕
〔利益：对你有什么用，回应开头痛点〕
〔可用「我」的使用感受举例〕

### 〔卖点二：功能 + 利益〕
〔同样格式〕

### 〔卖点三/四/五〕
〔挑最痛的，逐一回应开头痛点〕

【证言/数据】
〔一条真实用户证言或可核验数据，指名带细节〕
〔可配「用户证言/口碑卡」模块〕

【结尾 · 行动】
〔低门槛动作：点击/扫码/领试用〕
〔写清价格/优惠/门槛〕
```

### 骨架用法说明

- 骨架是「填空题」，〔方括号〕处换成你推荐的产品内容。
- 卖点按「回应开头痛点」来选，不是把产品说明书搬来。
- 软硬比例没有固定值，见「个性化空间」，以「别让读者觉得被骗」为底线。

## 三、示例（职场 / 理财入门场景，标注结构）

> 主题：推荐一个记账 App（账号调性温和）

**【场景 / 痛点切入】**
每次月底看支付宝账单，我都有种「这钱不是我花的」的错觉——
工资到手一个月，翻账单全是 15 块的外卖、30 块的奶茶、随手点的视频会员。
以前我记过两三次账，每次都是记了三天就忘了，
然后看着那些半途而废的账本发呆。
不是我没决心，是那个账本真的太麻烦了。

**【产品引出】**
后来朋友推荐了一个叫「XX记账」的 App，
我本来没抱希望，结果用了一个月，居然坚持下来了。
它不是什么黑科技，就是解决了我上面说的「麻烦」这件事。

**【卖点 · 功能 + 利益】**
**自动同步账单**——微信、支付宝、银行卡的消费记录自动同步，
不用我手动一笔笔记。月底我只要花十分钟扫一眼，
就知道这个月钱花哪了（回应「记了三天就忘」的痛点）。
**自动分类**——它会把「买菜」「打车」「外卖」自动归类，
月底生成一张很直观的支出图。我第一次看清了
自己一个月在「奶茶」上花了 240 块，从此下意识少点了两杯。
**预算提醒**——设个「每月 3000」的预算，
快超时会轻轻提醒一句，不怼人、不焦虑，
就是一句「本月支出已到 85%」。比我自己反复查要省心得多。

**【证言 / 数据】**
我查了一下，这款 App 上线两年，官方数据是已有 3000 万用户在用。
我身边两个同事被我安利后也下了，其中一个说：
「以前我月月光，现在月底还有剩，就靠那个预算提醒。」
这种朴素的反馈，比什么「理财神器」都可信。

**【结尾 · 行动】**
记账不是自律，是别让麻烦拦住你。
想试试的，点文末「阅读原文」就能下载，免费功能完全够日常用；
如果你想升级自动同步等进阶功能，Pro 版有个一次买断的优惠价。
第一次记账，就当是跟自己把钱算清楚的开头。

## 四、语气与禁忌

**语气要求**：
真诚、平等、像分享经验的老朋友，不像推销员。
多用「我试过」「我一开始也不信」「后来发现」的第一人称体验口吻，
少用「你还在等什么」「立即购买」的生硬催促。
软文的信任来自「让读者感觉你在帮他省事 / 省钱 / 省心」，
而不是「你赚我钱」。

**具体落地**：
- 用「我」的体验讲卖点，而非「本品具备」的说明书腔。
- 先帮读者解决问题，再自然带出产品。
- 承认产品的边界（「它不算便宜，但值」），反而更可信。

**禁忌**：
1. 虚假宣传、夸大效果。
   把普通产品吹成「包治百病」「用了必瘦」「学会必然成功」——
   踩广告法红线也透支信任（交叉「内容合规」的违禁词与行业红线）。
2. 软硬失衡。
   开头就硬上产品，或卖点部分全在自我表扬（「工艺精湛」「品质卓越」），
   没给读者任何价值。先价值后推销是铁律。
3. 只列功能不讲利益。
   罗列参数 / 功能不给读者「这对我有什么用」，读者无感。
4. 虚构证言与编造数据。
   为了显得可信伪造用户反馈或统计数字，
   一旦被察觉，账号信誉全毁（也涉及合规）。
5. 隐瞒利益关系。
   带货不说明是「推荐 / 测评 / 合作」，读者感觉被套路。
   按平台规则和企业情况，必要时标注「广告」「含推广」——这也是合规要求。

## 五、与排版配合

软文的排版目标是「先吸住（场景）、再立信（卖点）、后转化（行动）」，节奏要分层。
- **开篇**：
  用「开头页眉」，场景段保持清爽有重点；
  内容有料可加「目录 / 索引区」。
- **卖点**：
  用「卡片」归纳每个卖点，
  「功能 + 利益」可用两栏「对比 / 分栏卡」呈现；并列卖点可用「列表」。
- **信任**：
  用「用户证言 / 口碑卡」展示真实反馈；
  有案例可加「案例展示卡」；参数用「价格表 / 套餐对比」和「数据表格」。
- **答疑**：
  读者常见顾虑用「FAQ / 问答卡」提前排掉。
- **插入产品图**：
  用「图片」展示产品实际使用画面，比纯文字可信。
- **转化**：
  结尾用「结尾行动号召」＋「小程序卡片」＋「资料领取 / 福利入口」。

> 具体模块语法与样式见「模块」维度各条目，这里只给组合建议。

## 六、个性化空间

模板是起点不是终点，以下环节需**结合账号调性与读者改写**。
- **软硬的刻度**：
  同样推产品，生活方式号可以偏「体验随笔」（读者冲你人来的），
  工具测评号可以偏「客观参数测评」（读者冲信息来的）。
  判断依据：你账号的读者更信任「亲测体验」还是「客观数据」。
- **卖点的取舍**：
  产品可能有很多卖点，但只选「能回应你读者实际痛点」的 3-5 个。
  不同账号读者痛点不同——教育号读者关心「能不能坚持、效果」，
  职场号关心「省时间、涨薪」，别把全产品说明书搬来。
- **证言的占比**：
  新账号、冷门品，证言数据要更足补信任；
  老号、熟品，读者已经信你，证言可以点到即止。
  判断依据：读者对这个品类的熟悉度与对你的信任度。
- **价值前置的比例**：
  内容价值（干货 / 知识 / 共鸣）占多少、广告占多少，取决于账号定位——
  干货号可以前 60% 都是干货最后引出产品；
  纯种草号可直接场景 → 产品。
  没有固定比例，只有「别让读者感觉被骗」的底线。
- **利益关系的透明**：
  是否标注「广告 / 合作」，既影响法规合规，也影响读者信任密度。
  如实透明的号，读者反而更买账。
