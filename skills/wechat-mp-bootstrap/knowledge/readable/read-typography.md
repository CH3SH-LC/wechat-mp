# 字号行距舒适区（排版尺度基准）

> 定位：正文、标题、引用、注释的字号与行距该定多大，依据与例外是什么；顺带讲中文字距、标点与两端对齐的排版注意。这是"读得舒服"的尺度底座。
> 调用时机：每篇排版设定字号行距时；和"手机单栏阅读检查项"条目一起做最终核对。

## 一、核心规则：字号与行高的舒适区

**正文基准（微信事实，见 legacy/09 平台事实）：**
- **正文字号 15–16px**，行高 **1.75**。
- 段间间距 **16px**（见 00-GUIDE 间距硬规范第三节）。
- 段首**不缩进**（微信正文标配顶格）。

**为什么是 15–16px：**
- 微信手机端内容区窄（实际可用宽约 300 多像素，显示"视口宽 - 120px"左右边距）。
- 字号 <14px，在手机屏上长文就偏小伤眼；15–16px 是手机屏上"连续读一小时不累"的常见舒适区间。
- 字号过大（正文 20px+）会让一屏信息量骤减、拉动浏览，短线可，长文累，所以以 15–16px 为基准。
- **给一组手感参照**：14px 是"勉强能读"，15px 是"舒服起点"，16px 是"阅读偏大"，17px+ 是"大字号/大字报"。主流公众号正文咬在 15–16px 之间，不要轻易下探 14。

**为什么行高是 1.75：**
- 行高 1.75 意味着每行文字上下留着足够空隙，行与行不粘连。
- 中文没有词间空格，全靠行距区隔行与行；行距不足，整段看起来像"刷子刷过的一片墨"，极累。
- 1.6 偏挤、2.0 偏松，1.75 是宽行距的舒适平衡点；长文尤其该卡在 1.7–1.75，不冒险用紧凑行高。
- 这一数值与 00-GUIDE 第三节"正文与块内文字统一行高 1.75"一致。
- **换算成空间感**：字号 15px × 行高 1.75 = 每行约 26px 的行高，行与行之间有约 11px 的垂直空隙，这个空隙就是"不粘连"的来源。行高 1.5 时每行约 22px，空隙只有约 7px，明显挤。

**例外情况：**
- 大屏（PC 端）阅读为主的账号可保持同字号，但行高不宜低于 1.7。
- 若你的文章以"浅谈/随笔"为主、段落极短，可把行高略升到 1.8 增加松弛感。
- 干货/资讯密集文保持 1.75，不散、信息密度不塌。
- 特殊情况如"超大标题、代码块、分割线小标签"这类非正文，行高可单独设（代码块 1.6），见下方。

**字体（补充，不是硬规范）：** 微信正文基本沿用微信内置默认中文宋体/系统体，多数工具可自定义中文字体。若可自定义，正文建议用"常规笔画、笔画粗细均匀"的字体，别用极细字体或装饰手写体铺正文（只适合标题/短句）。正文与标题可用同一家族字体、靠字号/字重区分，保证成套感。

## 二、标题字号层级

建议一套清晰的三级标题，避免层级混乱、读者分不清主次：

| 层级 | 建议字号范围 | 使用建议 |
|---|---|---|
| h1（文章总题 / 最大分节） | 20–22px | 一篇只用一两次，做最强的分节锚 |
| h2（主要分节） | 17–19px | 每章一个小标题，是主结构 |
| h3（小节 / 要点） | 15–16px（与正文同，但加粗） | 再往下的细分，靠加粗区分 |

**标题特征：**
- 标题可加粗，颜色可与正文明度区分（见"对比度与色弱"），但不建议为标题堆纯装饰色。
- **不要出现"只换颜色不换字号/字重"的伪层级**——读者分不清是标题还是强调。
- 层级间距：标题上方 **28px**、下方 **12px**（h3 上 24px 下 10px），见 00-GUIDE 间距规范，别让标题贴段落。
- **字号差要拉得开**：相邻两级标题的字号至少差 2px（如 h2 18px 对 h3 15px），否则只靠颜色在手机上一眼难辨主次。若设计需要 h3 与正文同号，那 h3 必须加粗且颜色加深，形成明确字重差。
- **不建议 h3 直接套用正文同号却不加粗**：那样 h3 和普通段落彻底分不出来，等于没层级。

**判断依据（可调）：** 长文干货可把 h1 放到 22px 增强节奏；极简短篇甚至可只有 h2 + h3 两级，不必强凑三级。核心是"读者一眼能看出谁是大标题、谁是小标题、谁是正文"。若一篇里出现 h4，务必让它的字号/字重明显弱于 h3，且 h4 出现频率低，避免层级碎掉。

## 三、引用 / 注释小字的底线

- **引用块正文**：可与正文字号相同（15–16px）或略降，但**建议不低于 14px**，保持可读；行高 1.7–1.75。
- **图注 / 注释 / 来源小字**：**底线 12px**——低于 12px 手机端基本不可读，且对比度要求更高（见"对比度与色弱"）。行高 1.5。
- **代码 / 参数 / 标签：** 非正文可更小，但 **10px 是强底线**；除非是纯装饰，否则别低于 10px。
- **给一组直观对应**：12px 的图注大概相当于"一行能装 28–30 个汉字"的密度，手机上可读但要细看；13–14px 明显从容；11px 就开始偏小，10px 基本只能当角标/装饰。
- **小字的具体色：** 见"对比度与色弱"条目——注释不能用 `#999` 放任，尺寸越小对比越要压深（12px 注释至少 `#666`）。

## 四、字距与中文排版注意

**字距（letter-spacing）：**
- 正文建议 `letter-spacing: 0.5px`（见 00-GUIDE），不放大到 1px+，否则中文正文行距松垮、像散开的点阵。
- 标题可 1–6px 视风格（标题字偏大才适用），正文不要用。
- 字距 >2px 偏"设计感"但伤正文流畅度，只用于标题/英文字母，不用中文正文字。
- **换算**：0.5px 字距是"基本看不见、但弥补中文笔画挤"的微调；1px 开始能看出留白；2px+ 是明显的"疏朗标题感"。正文千万 0.5px 封顶。

**中文排版要点：**
1. **标点**：中文正文用全角标点；避免在中文字符后跟半角英文逗号/句号。引号建议用中文直角引号「」或中文弯引号，与正文等宽对齐，别用英文直双引号。
2. **两端对齐**：正文建议 `text-align: justify`（两端对齐），微信正文在窄屏下自动换行，两端对齐能避免右侧参差的"锯齿感"；若工具对 justify 支持不稳，退而用默认左对齐也不破版，但理想是 justify。
3. **数字与英文**：句中出现英文/数字时，前后按中文习惯加空格（"iOS 系统"、"3 个要点"），避免中西文紧贴造成单词断裂。
4. **段首不缩进**：微信正文顶格排版，靠段间距区隔，不手工等 `&nbsp;` 缩进——缩进在窄屏下还会挤兑行首对齐。

**中文字对齐的额外注意：**
- 别用"居中读整段"（正文长段居中是灾难），正文段落一律左对齐或两端对齐。
- 数字列 / 时间列若需对齐，可在同一宽度下用等宽处理，别靠空格硬凑。
- 标题和短句可以居中（如章节标题居中、活动口号居中），但**正文不得居中**；判断标准很朴素：三个字以内的短句居中没问题，超过一行半的居中必破版。

**换行与断字注意：**
- 中文靠标点自然换行，长 URL 或超长英文单词若整行放不下，请在 URL 前允许换行或加断点，避免"把一行顶破"造成横向溢出（横向滚动是铁律，见"手机单栏阅读检查项"）。

## 五、示例

**合规正文：**
- 正文：字号 15px、行高 1.75、字距 0.5px、段距 16px、段首顶格、两端对齐。
- h2 标题：18px、加粗、上方 28px/下方 12px。
- 图注：12px、行高 1.5、灰（但 ≥4.5:1，实为 `#666` 这一级）。

**合规层次结构示意：**
```
h2「第一章 · 为什么慢」（18px 加粗）
  正文 2-3 行（15px）
  h3「关键点」（15px 加粗）
    正文 ≤4 行
  引用块（14-16px）
```

**不合格反例：**
- 正文字号 13px + 行高 1.5 → 长文密集、行间粘连、伤眼。
- 标题用"大字号黑色 + 小字号灰色"但没拉字号/字重差距 → 读者以为灰色那行是正文注释。
- 图注 10px → 手机上眯眼读。
- 段落不缩进 + 居中整段 → 右侧破、读着乱。
- h2 用 16px、h3 用 15px，字号差只有 1px 且都不加粗 → 两个层级在手机上分不出来。

**一段"练习排版"的检查顺序（可操作）：**
1. 先把正文设 15px / 行高 1.75 / 字距 0.5px / 段距 16px / 两端对齐；
2. 标题按 h1 21px、h2 18px、h3 15px 加粗铺上去，间距按 28/12（h3 24/10）；
3. 图注补 12px / 行高 1.5；
4. 真机预览：看行与行是否清爽、标题层级是否一眼分清、有没有居中正文、有没有横向溢出；
5. 过不了哪项回去调那一项，一个个来。

## 六、常见错误（反例 + 正解）

1. **正文字号直接搬常见的 14px**
   - 反例：微信窄屏下偏小，长文伤眼。
   - 正解：正文 15–16px 起步。
2. **行高用 1.5 甚至 1.4 显得"紧密专业"**
   - 反例：中文密集行粘连，读着累。
   - 正解：行高 ≥1.7，基准 1.75。
3. **标题层级靠"颜色深浅"而不靠字号/字重**
   - 反例：层级混乱，读者分不清。
   - 正解：字号 + 加粗拉开层级，颜色仅为辅。
4. **图注小字放到 10–11px 控版面**
   - 反例：不可读。
   - 正解：底线 12px；小了就删字或调排版。
5. **字距强行拉高（正文 2px+）制造"高级感"**
   - 反例：中文正文字距松垮难读。
   - 正解：正文 0.5px，字距只可微调，不用于正文堆积。
6. **段落不缩进却手动加空行/缩进占位**
   - 反例：挤兑对齐。正解：顶格排版靠段间距。
7. **正文整段居中"显得文艺"**
   - 反例：超过一两行就右侧参差甚至破版、读着乱。
   - 正解：正文一律左/两端对齐，居中只留给超短标题/口号。
8. **相邻标题层字号差只有 1px**
   - 反例：靠加粗硬分，手机上一眼难辨。
   - 正解：相邻层级字号差 ≥2px，或 h3 靠"加粗+加深"与正文拉开。

## 七、自查要点（可勾选）

- [ ] 正文 15–16px、行高 1.75
- [ ] 段距 16px、段首顶格
- [ ] 标题层级用字号 + 字重区分，间距符合规范（28/12，h3 24/10）
- [ ] 引用正文 ≥14px
- [ ] 图注/注释 ≥12px、行高 1.5
- [ ] 正文字距 0.5px（标题除外）
- [ ] 中文用全角标点、中西文间距正确
- [ ] 正文两端对齐（或至少不破版、右侧不严重参差）
- [ ] 正文段落不居中
- [ ] 相邻标题层级字号差 ≥2px（或 h3 有明确字重区分）
- [ ] 无任何超长单词/URL 造成横向溢出

## 八、个性化空间（按账号自定，给判断依据）

- **正文字号微调**：读者偏年轻/手机重度者 15px 即可，核心是行距撑住；长文辅助、阅读年龄偏大的可升到 16px 并把行高升到 1.8。判断依据：读者年龄段与阅读时长。
- **标题风格的松紧**：极简/文艺号可让标题字距稍大、字重更轻；资讯/干货号标题字号更大、加粗更狠。判断依据：账号视觉调性（见 style/）。
- **段距的松紧**：短句体公众号喜欢更大段距（20px 甚至 24px）制造呼吸感；学术/干货号 16px 正好，段落多了不零碎。判断依据：段落平均长度与本篇内容密度。
- **是否两端对齐**：若排版工具对 justify 支持不稳定，可在真机预览确认后选择左对齐，只要不出现难以接受的右侧参差。判断依据：真机美观度实测。
- **标题层级的级数**：极长教程可做到 h1-h4 四级；极短视频脚本体一级即可。判断依据：内容长度与信息密度。
- **是否自定义字体**：有品牌字体储备的账号可给标题配专属字体建立识别；正文建议沿用系统默认体保证兼容稳定。判断依据：品牌字体可用性与对正文可读性的影响。
