# 数据复盘维度索引（index-review）

> 定位：解决「发完怎么看数据、下次怎么改」。数据复盘让每次发布都有沉淀，是提升质量的闭环。
> 用法：发完次日读 rev-metrics 看指标；定期做 rev-single（单篇）与 rev-monthly（月度）；想验证改进效果读 rev-abtest；总结改进点读 rev-next。
> 交叉：优化方向会反馈到选题（topic/）、标题（copy/copy-title）、封面（cover/）。

## 条目清单

| 条目文件 | 一句话定位 | 调用时机 |
|---|---|---|
| rev-metrics.md | 核心指标解读：阅读/在看/转发/收藏/取关/完读率各说明什么 | 看数据前必读 |
| rev-single.md | 单篇复盘：一篇推文的复盘框架与提问清单 | 每篇发布后 |
| rev-monthly.md | 月度复盘：周期汇总、趋势识别、栏目评估 | 每月一次 |
| rev-abtest.md | A/B 测试：标题/封面/推送时间对比实验方法 | 想验证改进时 |
| rev-next.md | 数据反推优化：从数据表现到下一篇文章的具体动作 | 每次复盘收尾 |

## 使用顺序

发布后：rev-metrics 读懂数据 → rev-single 单篇复盘 → rev-next 产出改进点；周期末：rev-monthly；需要验证：rev-abtest。
