# 话题标签与合集（grow-tags）

> 定位：用「话题标签」和「合集」把散落的单篇串起来，让好内容能被反复找到、被二次分发。合集是账号的"内容图书馆"，标签是内容进图书馆的"分类抽屉"。
> 调用时机：设置话题标签、为系列内容建合集时；新读者想"集中看某类内容"却没处可去时；想让老文章持续获得曝光时。

## 一、核心方法

### 步骤 1：话题标签的布局——文首还是文末、数量与命名

**放文首还是文末：**

- 文末是多数用法——正文结束后、引导关注前，放一行或一行多的标签，不打扰开场。
- 文首适用于"这一篇有明确归属主题"的时候（如合集/系列首篇），可放在标题后、开头前，帮读者先确认"哦这是哪个系列"。判断依据：文首加标签会不会打断开头钩子——会就放文末。
- 微信话题标签可以点进去看该话题下的全部文章，是跨篇串联和曝光入口，以官方后台"话题标签"功能及最新规则为准。

**数量：** 一篇 3–5 个为宜，别贪多。太少覆盖不全，太多像凑数、且可能稀释单个标签权重。

**命名规则：** 标签要"读者能搜到、一眼懂"，避免太抽象：

| 命名方式 | 示例 | 说明 |
|---|---|---|
| 主题式 | #快手菜 #职场话术 #周会报告 | 宽主题，读者好搜 |
| 系列式 | #妈妈的周记 #新人的一封信 | 绑栏目/系列名，形成辨识 |
| 与栏目一致 | #周会工具箱 | 标签=栏目名，最利于归集 |

> 核心：**标签名尽量稳定复用，不要每篇新造一个。** 反复用同一批标签，才能形成"这一类内容都在这儿"的聚集与曝光效应。

### 步骤 2：合集——两类型：系列文章合集 + 主题合集

合集是把多篇同类内容打包，可放进账号主页/文章内引导入口的核心工具。

- **系列文章合集**：按"连载"归——如"采访 10 位妈妈"「如何做好一次向上汇报」上中下。适合有完整序列的内容，读者可从第 1 篇顺到最后一篇。
- **主题合集**：按"主题方向"归——如"快手菜大全""入职第一个月手册"。适合同主题但零星发布的文章，反正常曝光的兜底收纳。

| 维度 | 系列合集 | 主题合集 |
|---|---|---|
| 收录方式 | 按连续产出、顺序整理 | 同一主题下的所有散篇 |
| 阅读价值 | 读者从头追到尾 | 读者按需挑着看 |
| 适合 | 教程连载、采访系列 | 内容库、常被反复查询的主题 |

> 合集的价值：**把"连载的完整性"和"主题的检索性"都做出来。** 读者想看某一类内容时，不用翻几十篇，进合集一次看完，也提升单篇的反复访问。

### 步骤 3：标签与搜索曝光

- 标签主题命名贴合读者真实搜索用词，更容易在搜索/推荐里被命中——命名前想"读者会用什么词找这种内容"。
- 标签做得越"标准规范、一致复用"，越容易形成内容带，有利于同一主题内容被连带刷到。
- 具体搜索与推荐曝光机制以微信官方当前规则与产品功能为准，标签是"辅助归类"，不是"刷量的工具"——靠内容质量 + 规范标签长期经营，不承诺玄学涨粉。

### 步骤 4：合集页的引导——文中插入合集链接

合集建好后，要在文章里主动引导读者进合集：

- 文中插入合集入口：当正文提到"更多同类内容"时，顺手放一句"这个主题的其他篇，都收在合集「____」里，点进去一次看完"。
- 文末引导：结尾统一加"想系统看，进合集「____」"，配合固定元素（见《栏目体系》）。
- 合集的命名和描述别空着，写清"这个合集里有什么、适合谁"，比默认文案更能让人点进。

> 关键：**合集不是建了就完，要持续把新篇归进去、在文里引流。** 否则合集只是个空壳文件夹，失去二次分发价值。

### 步骤 5：与栏目体系的配合

合集和栏目要配合，不是重复：

- 栏目是"更新的节奏与形式"（见《栏目体系》），合集是"内容的归集与检索"。
- 一个固定栏目跑一段时间后，自然沉淀成一个或几个合集——栏目负责"持续产"，合集负责"把产物收拢"。
- 建议栏目名 = 主合集名（或一对一），读者从标签/合集能直接对应到固定的栏目内容，记忆点更连贯。

### 步骤 6：标签与合集的维护节奏——别"建了就忘"

标签和合集是"越维护越值钱"的资产，要按固定节奏打理：

| 频率 | 维护动作 |
|---|---|
| 每次发布 | 发布时顺手归入合集、标好规范标签（见工具 3 双检） |
| 每周 | 新篇及时收进对应合集，别攒着一起补 |
| 每月 | 核对合集是否收录全、标签用词是否仍统一 |
| 每季度 | 因内容新增而建新合集/新标签，删除或合并已无效的 |

> 一个提醒：**合集顺序要常看，尤其是系列合集，别让新篇排错位置。** 读者按顺序追连载时，顺序乱会直接劝退。系列合集建议"最新在前"或"时间顺序"统一，别一时一样。

## 二、可操作工具

**工具 1：标签规范表（账号内统一用词）**

```
主题标签（宽、好搜）：1 #____ 2 #____ 3 #____
系列/栏目标签：1 #____ 2 #____
命名禁则：不用模糊词（#好内容）、每篇新造词
数量规则：每篇 3–5 个，稳定复用
```

**工具 2：合集规划表**

```
合集名：______   类型：系列合集 / 主题合集
一句话说明（放合集描述）：______
收录内容：____（已收录/待收录）
关联标签/栏目：#____（与哪个栏目对应）
引流位置：文中何时插入口 / 文末引导
```

**工具 3：文章发布双检（发布前过一遍）**

- [ ] 标签是否 3–5 个、都符合规范表、无新造模糊词
- [ ] 是否有对应的合集、本篇是否该归入某合集
- [ ] 文中/文末是否放了合集入口（如适用）

## 三、示例（虚构账号）

**示例 1：「妈妈厨房周记」（虚构）**

- 标签：每篇 3–5 个，「#快手菜 #30分钟上桌 #妈妈的周记」稳定复用；按主题新增「#娃的便当」时用统一该标签至少 3 篇，再沉淀成合集。
- 合集：「快手菜大全」主题合集收录所有快手上桌菜，描述写"30 分钟上桌、连图带步骤，翻不完也没关系，先收藏";「娃爱吃的便当」系列合集按连载顺序排。
- 引流：文中做某道菜时说"其他 20 个快手菜都收在「快手菜大全」合集里"，文末固定"想省时间就进合集看全"。

**示例 2：「Echo 的职场说明书」（虚构）**

- 标签：「#周会工具箱 #汇报话术 #职场沟通」稳定复用；系列标签「#新人的一封信」归集信件栏。
- 合集：「向上汇报全案」主题合集收所有汇报相关篇，「周会工具箱·往期」系列合集按篇目顺序整理栏目历史。
- 引流：每篇周会工具箱内引用关联篇时放合集入口，文末固定引导"一期没看够，进「周会工具箱往期」合集一次刷完"。

## 四、常见错误

- **错误 1：标签每篇新造、用词不统一。**
  反例：这周 #快手菜、下周 #10分钟美食、再下周 #快手做饭——读者搜不到、也聚不成一类。
  正解：定一套稳定标签，反复复用，形成"这一类都在这里"。
- **错误 2：标签贪多，一篇挂十几个。**
  反例：一篇挂 12 个标签，看着热闹，实际稀释、还像凑数。
  正解：3–5 个、都贴合主题且规范复用，宁少勿滥。
- **错误 3：合集建了从不收录、也不在文里引流。**
  反例：建了个「职场合集」，一篇都没放进去，读者根本不知道有它。
  正解：新篇及时归入、文中放入口、文末引导，让合集真有行踪。
- **错误 4：合集名/描述空着，读者不知里面是什么。**
  反例：合集就叫"合集 002"，描述空白，没人会点。
  正解：合集名直白（「向上汇报全案」），描述写一句"这里有什么、适合谁"。
- **错误 5：把标签当"玄学刷量"，以为打标签就涨粉。**
  反例：靠堆标签期待被推荐暴涨，忽略内容与规范经营。
  正解：标签是"规范归类 + 辅助曝光"，跟内容质量和长期经营配合才有价值，以官方当前规则为准。
- **错误 6：合集顺序混乱，系列合集让读者追不下去。**
  反例：连载合集的新篇排错位置、忽前忽后，读者按顺序追到一半跳序号。
  正解：系列合集统一排序规则（最新在前或时间顺），每次收录后检查顺序。
- **错误 7：建了一堆"空壳合集"却没有一篇内容。**
  反例：一口气建了十几个合集，绝大多数是空的，主页看着乱、也没用。
  正解：合集跟着内容走——有 3 篇以上同类内容再建合集，先精后多。

## 五、个性化空间

- **标签放文首还是文末**：判断依据是内容形态——系列/合集首篇可放文首助确认归属;普通单篇放文末不打扰开头钩子；别为了打标签破坏开场节奏。
- **标签数量 3 vs 5**：判断依据是主题宽度——窄主题用 3 个精，跨主题内容用 5 个覆盖；宁精勿滥。
- **合集建得多还是少**：判断依据是内容存量——起步期内容少先建 1–2 个核心合集，内容多了再细分，避免空壳合集一堆。
- **栏目=合集的一对一**：判断依据是栏目内容的连贯性——连载/方法论型栏目适合一对一建合集；散点型的栏目建"主题大合集"收纳即可。看读者更想"追完"还是"按需查"。
