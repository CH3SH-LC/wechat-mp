# 模块 · 列表

> 定位：把 3 条以上**平级、并列**的信息用"项目符号"排成清单，让读者一次性扫读、不遗漏、不费眼。列表几乎零装饰成本，却瞬间建立"并列结构"——比一段一段写更省读者力气，是回读率最高的排版之一。
> 调用时机：并列要点、清单、特点、注意事项、可选项**多于 3 条**时。**黄金规则：>3 条用列表，≤3 条用分栏**（见「模块 · 卡片」的分栏变体）。列表只装"平级信息"，有层级、有因果的要用段落、步骤条或时间线。每个列表出现前必须是引出句或小标题，否则读者不知道这串符号在讲哪件事。

## 一、可用写法与语法

列表的标记有**圆点 / 箭头 / 编号**三种语义，完全不同，别混着用。注意：本规范禁止 emoji 与图标字符，标记一律用 CSS 几何形状 span（实心圆点、旋转 45° 的方块）或 `art://` 植物图案实现，见下方速查：

| 标记 | 实现方式 | 用途 | 表达的情绪 |
|---|---|---|---|
| 圆点（实心圆点 span） | `<span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span>` | 并列、无顺序的通用列表 | 中性、列举 |
| 箭头/引导（旋转方块） | `<span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span>` | 强调"递进 / 指向去做什么" | 行动感、引导 |
| 编号 `1.` | `<ol>` 自带数字 | 有先后顺序 / 计数 | 顺序、步骤预备或计数 |

**三种标记怎么选（速查）**：这些信息之间有没有"先后/因果/顺序"？——完全并列就用圆点；想带读者一步步往下走、有"先…再…"就用旋转方块（菱形）；本身就是第几分、第几步、有几个就编号。三种混着写等于告诉读者"这个清单结构是乱的"。选标记不光看"有没有序号"，更要看你想让读者怎么读：圆点是"停在这里一起看"，箭头是"跟我往下一步"，编号是"按数来、别漏"。

**列项写作要点（比符号更关键）**：
- **结构一致**：每条要么都是"名词短语"（优点、参数），要么都是"动词短语"（可用、支持），要么都是"判断短句"。类型统一，扫读才顺畅；一半名词一半长句，读者眼球得反复重新对焦。
- **每条 ≤1 行**：能在一行内扫完最好。超过一行就压缩措辞，或拆成两张列表，别让单条膨胀成一段、拖慢整组节奏。
- **先想清是否真并列**：这是最容易踩的。有主次关系、有因果推理、有包含关系的内容，硬排成列表就是"列表滥用"。宁可拆成段落加卡片，也别把逻辑装进并列里。

**列项一个隐藏加分项**：每条首字尽量同词性对齐（都以动词"支持/可/提供"开头、或以名词结尾），读者扫过第一列就能抓住规律；首字乱改，扫读节奏就断。

## 二、双模式表现（文字类/宣传类）

**文字类（文字排版优先）**：用实心圆点 span、深灰文字、行距宽松。符号色细、克制——可以每条开头用一枚主色小圆点，但整体以"清晰列举"为主，不抢正文。适合干货文、资讯文、方法论——重点是"把并排列清楚"，颜色只是最轻的区分，真正靠的是符号与字距建立的"块感"。

**宣传类（视觉优先）**：用旋转方块菱形或主色圆点，可加大行距、重点项加粗，甚至每条加浅色衬底。视觉更"生动、有引导感"，适合卖点列举、权益清单、行动步骤——想让它"逐条跳起来"让读者逐条点头。宣传类的核心是"这条就得亮出来"，衬底加粗把信息从正文里"顶"出来。

**两个模式在同一篇里只选其一**：文字类全文深灰圆点，宣传类全文主色菱形或衬底。不要一半圆点一半衬底——混用等于让读者以为"圆点和衬底是两种不同层级"，破坏一致性（见模块组合铁律）。要变的花样交给全篇色盘，列表自己的模式先定死。

## 三、样式变体（6 种常用，具体参数）

**所有列表统一遵守**：整组 `margin:0 0 16px`（块距 16px）、块内行高 1.75、正文字号 14px；微信正文不自设左右 padding。以下每种都给足"符号、字号、圆角、padding、行高"的具体取值。

**变体 A｜圆点列表（最通用）**——适用：并列特点、参数清单：
```html
<p style="margin:0 0 16px;line-height:1.75;font-size:14px;color:#333;">
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 一键导出微信图文<br/>
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 多账号切换管理<br/>
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 排版模板一键套用
</p>
```
- 参数：每条用一枚主色实心圆点 span（6px 圆、`border-radius:50%`）、正文 14px，逐条用 `<br/>` 换行；整体一个 `<p>`，`margin:0 0 16px`、行高 1.75。文字类可把圆点换成灰 `#999`，克制到极。

**变体 B｜菱形引导列表（行动/优先推荐感）**——适用：操作"先/再/最后"、引导阅读顺序：
```html
<p style="margin:0 0 16px;line-height:1.75;font-size:14px;color:#333;">
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 先做需求清单<br/>
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 再定风格选型<br/>
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 最后套用模块排版
</p>
```
- 参数：用旋转 45° 的 6px 方块拼出菱形（`transform:rotate(45deg)`）、主色填充，表达"指向/递进"。适合有"先…再…最后"的引导序列，但不是需要严格计数的步骤——要计数就换编号列表（变体 C）。

**变体 C｜编号列表（有顺序/计数）**——适用：第几分、有先后要求的轻量排序：
```html
<ol style="margin:0 0 16px;padding-left:20px;line-height:1.75;">
  <li style="font-size:14px;color:#333;">登录并创建项目</li>
  <li style="font-size:14px;color:#333;">上传素材</li>
  <li style="font-size:14px;color:#333;">生成并导出</li>
</ol>
```
- 参数：`<ol>` 自带数字编号，`padding-left:20px` 给编号留位（硬规范）；行高 1.75；字号 14px。适合真正有先后顺序、但不想上重步骤条（数字圆）时的轻量排序。

**变体 D｜带色点衬底的强调列表（宣传类）**——适用：卖点/权益清单：
```html
<section style="margin:0 0 16px;">
  <p style="margin:0 0 8px;line-height:1.75;font-size:14px;color:#333;background:#fff7f2;border:1px solid #ffe0d0;border-radius:6px;padding:8px 12px;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 全年无限次更新</p>
  <p style="margin:0;line-height:1.75;font-size:14px;color:#333;background:#fff7f2;border:1px solid #ffe0d0;border-radius:6px;padding:8px 12px;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 优先技术支持</p>
</section>
```
- 参数：每条整行浅色底（`#fff7f2`、圆角 6px、padding `8px 12px`）配细边框 `1px solid #ffe0d0`、条目名前列主色实心圆点、条目间 8px。底色的 `#fff7f2` 是主色橙的极浅，宣传诉求强就换成主色正衬底、弱就换成纯色浅底。适合"卖点/权益清单"逐条醒目地列举给读者打卡。

**变体 E｜符号分组带小标题（信息分层）**——适用：清单较长、需要分组归并：
```html
<section style="margin:0 0 16px;">
  <p style="margin:0 0 8px;font-size:14px;color:#333;font-weight:600;">核心功能</p>
  <p style="margin:0 0 8px;line-height:1.75;font-size:14px;color:#555;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 排版模板一键套用　<span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 多账号切换管理</p>
  <p style="margin:0 0 8px;font-size:14px;color:#333;font-weight:600;">增值服务</p>
  <p style="margin:0;line-height:1.75;font-size:14px;color:#555;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 全年免费更新　<span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#ff6b35;"></span> 优先技术支持</p>
</section>
```
- 参数：小标题 14px 加粗、正文 14px 灰 `#555` 用 `　` 全角空格在同一行排多条，适合"核心—扩展"分层，避免 7 条以上一坨、也避免普通列表一屏装不完。

**变体 F｜品牌单色系列表（克制风）**——适用：品牌账号不想花哨、只想一套色贯穿：
```html
<p style="margin:0 0 16px;line-height:1.75;font-size:14px;color:#333;">
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#2777ff;"></span> 品牌蓝单色系列表<br/>
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#2777ff;"></span> 标记只用一枚品牌色<br/>
  <span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#2777ff;"></span> 其余交给深灰正文
</p>
```
- 参数：标记用一枚品牌主色（如 `#2777ff`）的实心圆点、正文深灰，全篇列表就一套色。判断依据：品牌色够不够撑起"举例—重点"的区分，够就用，最专业也最省心；只能挤出一个色就退回"灰圆点 + 主色仅重点标粗"的混法。

## 四、使用时机与位置

- **并列特点/优缺点**：产品功能的"亮点列表"、方法论的"三要素"，用圆点或菱形列表，逐条是并列关系。
- **注意事项清单**：注意事项 >3 条时，列表比段落清晰得多——注意事项是"并列的一条条规矩"，天然适合列表。
- **卖点/权益**：宣传类用带色点衬底的进式列表（变体 D），逐条亮给读者看，配小标题"为什么选我们/你能带走什么"。
- **位置（铁律）**：列表前必须有**引出句或小标题**——"它的三个亮点是：""使用前请注意：""下单前确认如下几点"。**列表绝不凭空出现**，孤零零一列标记等于让读者猜"这串在讲哪件事"。
- **位置节奏**：列表用在"信息密集、想让人停下来逐条核对的段落"后。长文里列表是"暂停＋确认"的标点，文章开头和结尾各放一组即可，别通篇都是列表压掉叙述感。
- **与前置段落关系**：列表紧跟的引出句结尾用冒号，让读法自然；列表后若还有解释，用一段普通正文收口，别让列表孤零零悬在文末。
- **一篇文章里的分布**：开头钩子后可用一组卖点列表立住框架，正文中部干货处可再用一组，收尾"你能带走什么"再用一组收心——三处各自独立，别让开头就把所有清单用光、中段无事可列。

## 五、风格适配（4 个例子）

- **极简/商务**：圆点列表，圆点用灰 `#999` 甚至省略、文字 14px 深灰、行距宽松、全黑白。克制到极点，列表只是"排列"，不制造任何情绪，全靠排版节奏。
- **电商/促销**：带色点衬底列表（变体 D）+ 主推橙实心圆点，卖点逐条"跳"，配小标题"为什么选我们"。也可加一枚草叶图案 `![草叶](art://sprig-grass)` 标记"限时权益"，把促销感拉满。
- **教育/干货**：菱形列表 + 每条加粗首词组（如"首二字 **结构**：保持一致"），引导"先看什么、再看什么"；标记用主色、正文深灰，节奏带读。
- **科技/数码**：圆点用品牌冷蓝，参数类条目可对齐（等宽思路），突出"参数清单"，行高可稍收紧但仍是 1.75，保持整齐的参数感。

**风格统一原则**：列表风格要与整篇其他模块一致——如果卡片用圆角浅底，列表的衬底（变体 D）也用同色浅底同圆角；如果标题用主色，列表标记也跟随主色。风格是"全篇穿的一套衣服"，列表不能自己换颜色。

## 六、间距与尺寸（遵守硬规范）

- **列表与前后块**：整组 `margin:0 0 16px`（块距基线 16px），列表后若紧跟另一组列表/段落仍是 16px，不贴合也不加厚。
- **行内列表**：变体 A/B/C 靠 `line-height:1.75` 自然隔开，条目间**不额外加 margin**，逐条用 `<br/>` 或 `<ol>` 自带换行。
- **整行衬底列表**：变体 D 条目间 8px；每条内 padding `8px 12px`（内容与衬底边框 ≥8px，硬规范内）。
- **列表标记缩进**：编号列表 `<ol>` `padding-left:20px`（给定编号留位，硬规范）；圆点/菱形列表无需额外缩进，标记就压行首。
- **字号**：列表正文 14px（与正文一致或略小）、行高 1.75；小标题（变体 E）同为 14px 加粗，与正文同字号不另造台阶。
- **标题与列表关系**：小标题引出列表时，小标题与列表之间自然留行距即可（约 8-12px），整组仍是块距 16px，不把小标题当成独立大标题来加 24px。
- **与正文行的统一**：列表块与前后段落行高同为 1.75，读者从段落滑入列表不会感到节奏突变；只有衬底列表（变体 D）因成块、内部行高保持 1.75 而整体更"实"。

## 七、配色配合（与全篇色盘协同）

列表不是独立元素，它的标记色/衬底色必须从全篇色盘里"取"。**一篇正文只用 1 个主强调色贯穿**（卡片、气泡、列表标记、高亮共用同一主色），最克制也最专业。

- **单主色用法**：全篇列表标记统一一枚主色（如橙 `#ff6b35`），衬底用它的极浅（`#fff7f2`）。清单只管罗列，靠"一枚色反复出现"建立辨识，颜色是重复的锚点。
- **双主色用法**：主色 + 一个警示色。强调要点用主色，规避/慎用点用警示色（如红），对比强、适合宣传类，但红色只能是少数几条，别让规避点盖过主卖点。
- **与正文关系**：列表标记色要与正文文字 `#333`、正文灰 `#555` 区分度足够；衬底浅色配深色文字，对比度 ≥4.5:1（见「可读性」维度）。浅底深字最稳，别拿深底配深字。
- **避免**：五种标记五颜六色（红黄蓝绿开会）——读者分不清谁重要，也显"彩虹排版"。列表颜色 ≤2 个主色最佳，其余交给灰与深灰的层次。
- **标记色与高亮统一**：列表标记色尽量与全文高亮、气泡边框用同一主色，读者才会把"这种颜色=重点"的契约记住。
- **颜色数量即情绪**：单色列表克制理性（适合方法论、干货），双色列表更有张力（适合促销、权益）。颜色越多越像"标注满满的研究生笔记"，越少越像"编辑过的定稿"——常用 1-2 个主色。

## 八、微信兼容注意

写列表时的"可用子集"与"要绕开的坑"（微信富文本编辑器）：

- **可用**：`<p>` + `<span>`、`<ol>/<li>` 自带数字、`<br/>` 换行、内联 `color/font-weight/background/border-radius/padding/line-height:1.75/font-size/margin`、`display:inline-block;width;height;transform:rotate(45deg);border-radius:50%`（拼 CSS 圆点/方块/菱形）。
- **尽量别用**：`list-style:none` + 伪元素手动造标记（`::before` 大多被剥除）、`display:flex` 做复杂对齐（可能在旧客户端回退错位）、`letter-spacing` 过大（个别机型渲染异常）。
- **标记写法避坑**：不要用 `<ul>/<li>` 默认黑点（样式难控、不同机型黑点大小不一、剥除风险高），也**不要**用 emoji / Unicode 图标字符；首选"HTML 里的 CSS 形状 span（实心圆点 / 旋转 45° 方块）+ 上色"或 `<ol>` 自带数字，需要更优雅点缀时用 `![说明](art://sprig-grass)` 草叶等植物图案。
- **换行避坑**：用 `<br/>` 逐条换行（编辑器稳定保留），别把多条挤进同一个 `<p>` 只靠空格分行——部分端会合并、换行丢失。
- **编号避坑**：需要数字编号时用 `<ol>` 自带排序最稳；别用"1. 2. 3."文字手敲，改行插入空格时前端不一定帮你续号，且行首数字字体随正文走、不受控。
- **衬底兜底**：宣传类想用衬底时，给 `background` 写纯色浅底；本规范推荐统一纯色 + 细边框（`border:1px solid`），不写渐变。任何装饰都要"锦上添花可丢、内容仍可读"。
- **通用兜底原则**：最稳的列表永远是最简的"CSS 形状 span + 字号 + 行高"组合；任何圆角失效后，列表仍应是一条条清晰可读的并列项。

## 九、密度限制（重要）

- **>3 条才用列表，≤3 条用分栏**：列表省装饰，但 3 条以下没必要成行罗列，分栏卡更省屏。这是列表的黄金规则，先数条数再决定用不用列表。
- **一组 ≤7 条**：超过 7 条读者就看不过来，拆成"核心—扩展"两组、或分组带小标题（变体 E）。
- **一屏幕列表组不宜太多**：一篇通常 **2-3 组列表**足够，别处处都是列表压得没有叙述感；列表是"暂停点"，太多就成了"堆砌清单"。
- **列表不叠列表**：一项里再缩进子列表（除非真有必要）会破坏并列语义，层级混乱。有层级的用段落、步骤条见「模块 · 步骤」或「模块 · 时间线」。
- **列表不与其他强装饰同屏叠太多**：这一屏已有花纹色带 + 大字号标题 + 衬底列表，就别再叠气泡了（见模块组合铁律：气泡 ≤2、徽章 ≤3）。

## 十、常见错误（反例 + 正解）

- **反例**："优点：功能多。价格也不贵。然后客服还挺好的。界面好看点。"（句式参差、结构不一致）**正解**：统一为名词短语或判断短句——"功能全面、价格亲民、客服响应快、界面清爽"。
- **反例**：信息只有 2 条却用列表 **正解**：2 条用分栏卡或其他处理；列表是"3 条以上"的机制，2 条成行罗列纯属浪费屏。
- **反例**：把有因果、有层级的内容硬做成列表（"第 1 步；而第 1 步是因为……"）**正解**：有逻辑关系的用段落、步骤条见「模块 · 步骤」或时间线，列表只装"并列"。
- **反例**：列表没有引出句，正文直接蹦出一个符号清单 **正解**：列表前加"它的三个亮点是""使用前请注意"或居中小标题，让读者先知道这清单在讲什么再逐条看。
- **反例**：一段 12 条的巨长列表，一屏装不下、滑都滑不完 **正解**：砍到 5-7 条，或按"核心—扩展"拆成两组带小标题的列表（变体 E）。
- **反例**：标记乱用——这一组用圆点、下一条变菱形，计数项又用圆点 **正解**：同一列表用同一标记，全篇"并列=圆点、引导=菱形、计数=编号"的标记契约保持一致。

## 十二、个性化空间（可调参数与判断依据）

- **标记选择**：圆点（中性并列）/菱形（递进行动）/编号（顺序计数）。判断依据：信息有无顺序与引导需求——纯列举用圆点、引导"先…再…"用菱形、计数用编号；全篇按此契约统一。
- **标记颜色**：正文灰 `#999` 或品牌主色。判断依据：想让标记"指引重点"就用主色（宣传），想安静克制就用灰（文字）。
- **是否加衬底**：整行浅色底适合"权益/卖点"类要逐条打卡认可的内容。判断依据：这几条是不是读者最看重、需要逐条点头的信息——是才加衬底，普通列举不加。
- **条目在行内还是衬底**：行内靠行高隔开最省屏；衬底成块最醒目但最占屏。判断依据：信息量 vs 强调强度，普通清单用行内、重点权益用衬底。
- **条目长度**：1 行内 or 允许 1-2 行。判断依据：复杂名词可放 1-2 行，琐碎短句压到 1 行；超过一行就压缩措辞。
- **是否分组带小标题**：一条清单 ≥6 条 / 信息要分两档时才带小标题（变体 E）。判断依据：清单有没有自然的"核心—扩展"分层，有才分，没有就保持一条干净清单。
- **列表在行内还是整段**：同一行用全角空格 `　` 排多条（最省屏）还是换行逐条（更好读）。判断依据：是一扫而过的短清单还是逐条核对的要点，前者同行、后者换行。
- **列表出现次数**：一篇 2-3 组足矣。判断依据：列表越多阅读节奏越碎，干货密集处才上列表，叙述段落保持段落。
