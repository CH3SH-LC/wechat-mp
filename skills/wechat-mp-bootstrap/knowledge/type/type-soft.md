# 产品软文（type-soft）

> 定位：把产品放进真实生活场景，让读者觉得"这东西确实解决了我一个问题"，心甘情愿而不是被硬塞地往下看。
> 调用时机：要推广一个具体产品（非纯打折活动）、想让读者认可并考虑购买、不想写成像广告的广告时。

---

## 一、类型定义与特征

产品软文是**"交付价值"**的内容：不直接喊"快买"，而是通过讲场景、讲卖点、讲别人怎么用，让读者自己得出"这东西适合我"的结论。它的本质是**先让读者认可产品给自己带来什么好处，购买只是水到渠成。**

### 核心特征

1. **藏锋芒**：明面上是分享一个东西/一种生活，暗地里在推产品——但绝不是骗，读者看完能明显感到"这是安利"，只是不反感。
2. **场景驱动**：先讲一个读者熟悉、正被困扰的场景，再把产品"顺手"放进去解决——产品是剧情里的工具，不是主角。
3. **卖点与好处绑定**：卖的从来不是"功能参数"，而是"参数带给你的好处"。**功能是"它能做什么"，好處是"你用它得到什么"。**
4. **有证言加持**：别人的真实使用反馈（用户、同事、测试）能补足"你不是自夸"的可信度。
5. **软硬平衡**：有清晰的"转"（从分享切入产品），转得自然，不突兀。
6. **合规**：只能讲真实存在的功效，不能虚假宣传、过度夸大、捏造证言。

### 适用范围

- 一个具体的产品：家居好物、护肤、数码、食品、母婴、课程、工具；
- "安利式"内容：我用了半年怎样、闺蜜实测、编辑部亲测。

> 判断关键：核心是不是"推一个具体产品、靠场景和卖点打动"。如果是，就是产品软文。它与 **活动促销**（type-promo）的区别：软文主打"产品好用"，促销主打"现在买划算"（见 **类型全谱总览** type-catalog 第三节）。

## 二、标准结构骨架

> 四段式：**场景 → 卖点 → 证言 → 行动**。前两段是软硬转换的关键。

### 阶段一：场景（先讲痛点/向往，后引产品）

- **目标**：让读者代入一个他真实有感的处境，为产品出场做铺垫。
- **要点**：
  - 场景要"读者多数人都有"——痛点或向往都行；
  - 这段不出现产品名，只讲"我当时的困扰/理想状态"；
  - 场景铺得自然，越像普通分享越不违和。
- **篇幅建议**：全篇 20-25%，是决定"像不像广告"的成败段。

### 阶段二：卖点（把产品带进来，讲对你好在哪）

- **目标**：从场景转折到"于是我用到了××"，把产品卖点翻译成读者听得懂的好处。
- **要点**：
  - **一个自然的"转"**：从"我感到困扰"转到"朋友给我推荐了××"；别生硬地说"下面介绍产品"；
  - 卖点绑定好处：不堆参数，讲每个功能让你生活好在哪里；
  - 挑 **2-3 个核心卖点**说透，别十几个卖点平均用力；每个配一个场景/细节；
  - 用大白话，避免堆术语自嗨。
- **篇幅建议**：全篇 40-50%，是正文主体。

### 阶段三：证言（用他人可信度补足）

- **目标**：引入其他人的真实反馈，证明"不是你自己夸"。
- **要点**：
  - 证言来源要可信：身边同事、长期用户、测试数据、专业背书；
  - 证言要具体：谁、什么情况、用了之后得到什么，别只写"都说好"；
  - 证言最好覆盖不同需求，让不同读者都能找到"像我的人"。
- **篇幅建议**：全篇 15-20%。

### 阶段四：行动（自然的购买/进一步引导）

- **目标**：给读者一个"想了解/要买"的出口，但别硬逼。
- **要点**：
  - 说明从哪能获得（链接/店铺/活动入口），简单直接；
  - 如有限时优惠可以轻点一下，但软文的重心是"值"不是"急"；
  - 可加一句"如果你也有××困扰，可以试试"降低被推销感。
- **篇幅建议**：全篇 5-10%。

## 三、写作要点（每条配示例）

### 1. 卖点绑定好处：功能是原料，好处是菜

参数自己不会打动人，把参数变成"你的日子好了"才算卖点。

- 反例： "这款台灯有 5000mAh 电池、8 档色温、90 度可调。"（全是参数）
- 正例： "充一次电能用一周，晚上不用满屋找插头；色温能调到暖黄，睡前看书眼睛不酸。"（讲清用它得到什么）

### 2. 场景要真实、可代入

读者要先"哦我也有这困扰"，才会接着看。

- 反例： "如果你想要更高品质的生活，可以试试这款……"（虚）
- 正例： "带娃妈都知道，晚上给孩子喂完奶困得睁不开眼，还得摸黑下床开灯，一开灯娃就醒……直到我拿到这个能挂在床头、用手轻轻一拍就亮的灯。"（具体到能代入）

### 3. "转"要自然，别生硬

从分享转产品，是软文最容易露馅的地方。

- 反例： 前半篇讲完生活，突然一句"好了，重点来了，现在给大家隆重介绍本产品"。
- 正例： "后来我实在受不了，闺蜜就给我寄了一个××。我用了两周，才发现原来这件事可以这么简单。"

### 4. 只讲真实功能和功效，不虚假宣传

夸大功能/捏造证言/承诺做不到的效果，是软文的法律与信任红线。

- 反例： "喝这个 7 天瘦 20 斤""用这款抗老面霜，皱纹当场消失""全网 10 万人都在夸"（编造或夸大，违规）。
- 正例： 只讲产品实际可验证的卖点；证言用真实使用者，效果叙述留有余地（"坚持用了 4 周，我自己觉得皮肤状态稳了很多"）。

### 5. 证言要把"信不信"考虑进去

不同人对同一产品需求不同，证言要覆盖多种"像我的人"。

- 反例： 只有一句"我用了很好"。
- 正例： "上班族小 A：每天通勤两小时，戴着它午休能睡着；宝妈小 B：它不夹头发，梳娃打结的乱发不扯疼；我：就冲它充一次顶一周。"（不同人各取所需）

## 四、风格与模块建议

### 推荐风格

| 产品类型 | 首选风格 | 理由 |
|---|---|---|
| 科技/数码/办公工具 | **科技风** | 深蓝紫+青、数据感，专业可信，配参数与对比自然 |
| 家居/生活方式/母婴 | **日系风** | 治愈慢生活，契合"让日子更舒服"的诉求 |
| 国货/礼赠/文化向 | **国潮风** | 红金墨、庄重，凸显品质与文化感 |
| 有设计感/审美向产品 | **极简风** | 高级克制，凸显产品本身质感 |
| 快消/娱乐/大众向 | **插画风** | 活泼热闹，降低"广告感" |

> 风格细节与色板看 **风格维度索引**（index-style）对应条目；拿不准先读 **风格选择方法**（style-guide-choose）。

### 推荐模块组合

- **开头**：场景代入配图（痛点图/向往图，见 **开头写法** copy-open）；
- **正文**：图文卡片/大图（产品实拍、使用前后对比）+ 自定义模块（把"卖点们"排成卡片，见 **自定义模块** module）+ **价格表模块**（若要讲价格/规格，module-price）+ **证言模块**（引用真实用户反馈，module-testimonial；注意标注是用户反馈）；
- **结尾**：购买/详情引导 + 免责声明（若涉功效，加 **免责声明模块** module-disclaimer，规避夸大与合规风险）+ 引导关注模块（**引导关注** module-followbar）。

## 五、常见错误（反例 + 正解）

### 错误 1：变成纯广告，失去"软"
- 反例： 上来就介绍产品、列参数、喊"快买"，读者一眼关掉。
- 正例： 先讲场景与痛点，让读者认可"我也有这个困扰"，再自然地把产品放进来解决。

### 错误 2：卖点堆砌，没有主次
- 反例： 十个卖点平均用力，读者一个都记不住。
- 正例： 挑 2-3 个核心卖点说透，每个都绑一个好处、配一个场景。

### 错误 3：虚假宣传、夸张承诺
- 反例： 承诺做不到的效果（"7 天瘦身""逆龄变年轻"）、捏造证言、盗用他人数据。
- 正例： 只讲真实可验证的卖点；证言用真实体验；功效留有余地并适当加免责声明（见 **内容合规** index-compliance）。

### 错误 4："转"生硬露馅
- 反例： 讲到产品像突然插入广告，读者感到被冒犯。
- 正例： 用"朋友推荐/同事在用/后来发现"这类自然话术转折，保持分享感。

### 错误 5：证言空洞或无背书
- 反例： "无数人都说好用""全网好评"这种无法核实且显假的表述。
- 正例： 给具体可信的证言：谁、什么情况、达成什么效果；或用实测数据/专业背书补可信度。

## 六、示例骨架（可套用大纲）

```
标题：带娃妈实测 4 周，这个"一碰就亮"的床头灯治好了我的夜醒焦虑

[场景]
晚上孩子一醒就得喂奶。开灯怕惊醒孩子，摸黑下床又怕绊倒。
那阵子我常想：有没有一盏灯，亮的时候别太刺眼，又不用我满屋找开关？

[转折+卖点]
闺蜜给我寄了个××。它挂在床头，用手轻轻一拍就亮——不吵孩子，
光还是暖黄的、不刺眼。
卖点 1：一拍就亮，夜里不用摸黑，省下满屋找开关的燥。
卖点 2：暖黄低亮不刺眼，孩子醒了也不怕灯光吓到接着睡。
卖点 3：充一次电顶一周，不用频繁插电。

[证言]
我让同栋楼的宝妈也试了一周。
宝妈小 C："以前夜里喂奶每次开灯孩子就哭，现在暖灯亮起他都不睁眼。"
实测：连续 2 周只充过一次电，续航符合说明。

[行动]
如果你也有深夜起夜、怕吵醒家人或孩子的困扰，可以试试它。
本期下单还有满减，链接在下方。也可以先收藏，等需要时再回看。
```

## 七、个性化空间（按账号自定的部分）

软文的"软硬程度"是最大自变量，全由账号与目的决定：

- **软/硬程度**：可"极软"（前 70% 像普通生活分享，只在结尾露出产品）到"中等偏即"（明确说明是测评/安利，快速进卖点）。判断依据=账号与读者的信任深度、平台氛围。信任深的可更诚实直接，信任浅的用极软更保险。
- **篇幅**：可简洁卡片式（600 字、一个场景几个卖点）到深度测评（2000 字、含实测与多证言）。判断依据=产品复杂度与决策成本，越贵越复杂越要写详。
- **口吻**：可专业测评（科技风、数据说话）、可生活化安利（日系、像朋友推荐）、可幽默吐槽式（插画、先抱怨再转）。判断依据=产品调性与账号人设。
- **证言真实与控制**：证言必须真实，但可以自定"用真实熟人还是用公开评测"；涉及功效类建议同步对照 **内容合规**（index-compliance）确认不越线。
- **是否点"已种草/广告"**：部分平台/账号要求如实标注广告身份；如实反而能建立信任。判断依据=平台规则与账号透明策略。

> 一句话原则：**先让读者认可"这东西对我有用"，购买只是顺理成章。** 卖点永远绑定好处、场景永远真实可代入、证言永远可信不作伪、功效永远不夸大。在"软硬平衡"上，你的账号信任度说了算——但任何情况下都不虚假宣传。
