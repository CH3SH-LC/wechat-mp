# 摘要写法（cover-summary）

> 定位：解锁「摘要=第二标题」的写法——摘要的作用机制、≤120 字限制、承接标题制造点开冲动的三种写法、默认取正文前 54 字的坑、以及摘要与标题的分工。发布时需要填摘要时必读。
> 调用时机：在公众号后台填「摘要」一栏、或想在正文前做一次「二次钩子」时。也建议在拟标题的同时就想好摘要，两者配合着写。

## 一、核心规范

### 1. 摘要的定位：它是「第二标题」，不是正文开头

很多运营者把摘要当成「正文第一段的复制」，这是最大的误区。真正的定位是：**摘要是给那些「标题已经抓住了你、但还差最后一推」的人准备的第二句话。**

- 读者在信息流里先看到「标题 + 封面 + 摘要」三件套，他点不点，由这三者共同决定。
- 标题负责「抓注意力」——让人停下来；摘要负责「补决策信息」——让人下决心点进来。
- 所以摘要不是「复述正文」，而是「标题的续写 / 补强」，它承接标题抛出的钩子，再补一刀，制造出「不点开就很亏」的感觉。
- 一句话记住它的地位：**标题是钩子，摘要是把钩子拉得更紧的那根线。**

**为什么摘要值得单独写而不是敷衍：**

- 摘要位是微信默认显示在封面 / 标题附近的免费展示位，它不占正文长度、不用额外成本，几乎等于「白送的第二条钩子」。
- 但它的存在感很容易被忽略——很多账号摘要就是空着、或自动取正文。这会白白损失掉最后一次「在读者点开前加分」的机会。
- 一个判断：**在列表里，读者能同时看到标题、封面、摘要。如果你把摘要写得好，等于让读者在下决心的那一刻，多了一个「点开」的理由。** 这个理由，每篇都值得亲手给。

### 2. 摘要的字数上限：≤120 字

微信明确规定摘要上限 **120 字**，超过会被截断或不通过。

- 安全写法：把它压在 **30–80 字**，给微信留出被截断的余量，也符合「越短越有力」。
- 不要为了「多放信息」把 120 字塞满——塞满等于没有重点，读者根本读不完。
- 更不要写「太长的一整段」；理想状态是 **1–2 句话**，最多 3 句，句句都有信息增量。
- 字数不是越多越好：**在能说清的前提下，越短越好。** 120 字是上限，30–60 字是舒适区。

### 3. 不填时默认取正文前 54 字的坑

这里有个非常容易被忽略、而且会自动失效的机制：

- 如果你**不填摘要**，微信会自动取**正文的前 54 个字**当摘要展示。
- 这个机制有两个大坑：
  1. **正文第一行通常是标题重复、问候语、或铺垫**，取出来当摘要，读者看到的是一句毫无吸引力的开头，等于白白浪费了「第二标题」这个免费的金贵位置。
  2. 正文第一句有时还会包含链接、代码、引用，被自动取出来的摘要可能是不完整、甚至不通顺的句子。
- 解决方法很简单也唯一：**每次发布都手动填摘要。** 永远不要把开头第一段当摘要，哪怕你想「这是第一段」，也要亲手改写成一句有钩子的 30–80 字短句。
- 这是「平台会帮我自动做」的典型陷阱——它确实做了，但做得让你吃亏，而你必须主动救回来。

### 4. 摘要与标题的分工

把两者放一起看，用途完全不同，配合才能发挥最大作用：

| 项 | 标题 | 摘要 |
|---|---|---|
| 任务 | 抓注意力，让人停下来 | 补决策信息，让人下决心点开 |
| 篇幅 | 短，通常 1 句 | 稍长，1–3 句 |
| 信息 | 把最扎心的点抛出来 | 补充「点进来能获得什么」 |
| 避免 | 与摘要信息重复 | 只是复述标题 |

一个配合的常见套路：**标题抛出「悬念 / 利益」，摘要把悬念的「答案或程度」提前给一点，或把利益的「具体内容」点名。** 比如标题说「我戒掉了无效社交」让人好奇，摘要就补「我把每天 3 小时无效社交，换成了雷打不动的阅读时间」——补充决策信息，让人想点进去看具体怎么做。

## 二、摘要的三种写法：承接标题制造点开冲动

摘要承接标题、制造点开冲动，有三大招：**补信息、加利益、设悬念**。它们可以单独用，也可以组合着用。

### 招法一：补信息（把标题没说全的补一句）

标题说了「一半」，摘要补「另一半」——先把标题吊起的胃口接住，再喂一口。

- 适用：标题偏悬念、偏概括的场合。
- 写法：把「标题里没说、但读者想知道」的事实/细节补出来。
- 示例：标题「为什么你读了很多书却记不住？」→ 摘要「不是你的记忆有问题，是阅读方法错了：试过「复述式阅读」，没有 1 本能白读。」

**怎么判断该补什么**：想象标题是读者发问「然后呢？」，摘要就要回答那个「然后」。

### 招法二：加利益（把点进来能得到什么点透）

标题给了「你会想看为什么」，摘要补「你点进来能得到什么」，直接报出收益。

- 适用：干货类、教程类、清单类内容。
- 写法：把正文里最实在的「结果 / 好处 / 数字」提前亮出来。
- 示例：标题「7 个让你效率翻倍的阅读习惯」→ 摘要「不卖鸡汤，就 7 个能直接用的习惯：手抄金句法、一行浓缩法，读完马上能上手。」

**怎么判断该不该加利益**：干货 / 教程 / 学习类内容几乎必用这一招——读者点不点，很大程度上取决于「我能得到什么」。

给两个补充示例，方便直接套用：

- 标题「给打工人的 3 个下班充电法」→ 摘要「不熬到半夜，用 30 分钟把身体和状态补回来——适合通勤两小时、晚上真没精力的你。」
- 标题「为什么你总在深夜焦虑」→ 摘要「不灌鸡汤，给你 4 个任选一个就能立刻做的压力缓冲动作，今晚就能用上。」

### 招法三：设悬念（把结论藏起来吊胃口）

标题抛了钩子，摘要用「只给引子不给答案」再吊一下。

- 适用：故事类、观点类、有反转型内容。
- 写法：说出「是什么在等着你」的引子，但不把结果说完。
- 示例：标题「30 岁后，我戒掉了无效社交」→ 摘要「前 20 年我把「人脉」当命，30 岁那年一场大病让我重新定义朋友圈——结果出乎所有人意料。」

**怎么判断该不该设悬念**：故事 / 见闻 / 有反转的品类最适合；干货类慎用悬念，因为读者等的就是「答案」，不是「猜答案」。

设悬念时注意一个分寸：**悬念要有「钩」，也要让人感觉得到「里面真有值得看的东西」**，否则只会干吊胃口。判断方法——读完摘要你说得出「这篇里让我好奇的点」是什么；说得出才有效，只让人好奇却不觉得有料，读者会直接滑走。

### 三招怎么组合

- 抽象公式：**补信息 + 加利益** 最常见；**设悬念** 多在故事 / 观点类。
- 「补信息 + 加利益」适合大部分内容类型：先用一句把标题没说的补全，再用一句报出收益。
- 「设悬念」单独用即可，别叠太多把读者绕晕；悬念一旦太多，读者会失去耐心。

### 摘要写法的小技巧清单

下面几条技巧能顺手把摘要写得更好，不用所有都用，按需挑：

1. **用具体词，不用抽象词**：「省 20 分钟」优于「节省时间」；「手抄金句法」优于「一个方法」。
2. **给一个「立刻能做」的动作或收益**：让读者觉得「点进去马上有收获」，会显著加分。
3. **适当点名读者身份**：「适合通勤两小时的人」「给资金不多又爱买的人」——让读者觉得「这条就是为我写的」。
4. **避免绝对化夸张**：少用「百分百」「包你学会」这类词，会反噬可信度；宁愿给「一个就够了」这样更可信的承诺。
5. **一句话里只给一个重点**：如果写了两句，确保第二句是「升级」而不是「重复」，第三句以上通常就是多余的。

这三招加这五条技巧，摘要有 90% 的可参考写法都在这了。其余 10% 是结合你自己的栏目、语气带来的灵活性。

## 三、可执行步骤（写摘要流程）

1. **先有标题**：摘要永远基于标题来写，标题都没定，摘要无从谈起（标题写法见 copy 维度）。
2. **确定这篇的类型**：干货 / 教程 / 清单 → 用「加利益」；故事 / 观点 / 有反转 → 用「设悬念」；悬念型标题 → 用「补信息」。
3. **挑一招（或组合）**：选定主招法后，围绕它写 1–2 句，控制在 30–80 字。
4. **检查是否重复标题**：如果摘要说的和标题是同一句话、同一意思，删掉重写，让它做「标题没做的事」。
5. **口语读一遍**：自己念出声，如果像广告、太僵硬，就改成更像「和读者说话」。
6. **控制长度**：真到 120 字也不怕，但尽量压在 60 字内；超过就当「太长没重点」处理，重新浓缩。
7. **发布前确认摘要已手填**：绝不停留在「让微信自动取正文前 54 字」的状态。

## 四、示例

**示例一：补信息（悬念型标题）**

来源：写作型推文
标题：为什么你读了很多书却记不住？
摘要：不是记忆的问题，是方法错了——试过「复述式阅读」，把读过的书讲给别人听，没有一本白读。

作用拆解：标题问「为什么」，摘要直接回答「不是记忆问题、是方法错」，再用「复述式阅读」这个具体名词抛出干货预期，把读者从「好奇」推进到「想学方法」。
（可替换处：换成你标题对应的「另一半答案」；具体方法名换成你正文里真实的方法。）

**示例二：加利益（干货型标题）**

来源：知识干货推文
标题：7 个让你效率翻倍的阅读习惯
摘要：不灌鸡汤，就 7 个能直接上手的习惯——手抄金句法、一行浓缩法，至少 3 个你现在就能用。

作用拆解：「不灌鸡汤」立住「实在」的预期，再亮出两个具体方法名让人觉得「能学到真东西」，最后「至少 3 个现在就能用」给出低门槛行动承诺，推动点开。
（可替换处：换成你正文里真实的方法名；收益数字按真实内容写，不要虚夸。）

**示例三：设悬念（故事型标题）**

来源：个人见闻推文
标题：30 岁后，我戒掉了无效社交
摘要：前 20 年我把「人脉」当命，30 岁一场大病让我重新审视朋友圈——结果出乎所有人意料。

作用拆解：「一场大病」给出故事转折的引子，「结果出乎意料」把答案藏起来，让人点进去看「到底发生了什么」。三个示例都遵循「摘要是标题的第二钩子，不同招法服务不同内容类型」。
（可替换处：把病换成你的真实转折事件；把「重新审视朋友圈」换成你的真实改变。）

## 五、常见错误

| 错误反例 | 问题出在哪 | 正确做法 |
|---|---|---|
| 直接把正文第一段复制进摘要 | 第一段常是铺垫，无钩子、浪费第二标题位 | 单独写一句带钩子的 30–80 字短句 |
| 不填摘要，让微信自动取前 54 字 | 取出来的是开头铺垫，等于白白浪费摘要位 | 每次发布都手动填摘要 |
| 摘要和标题说同一句话 | 两处重复，等于没有增量 | 摘要做标题「没做的事」，补信息 / 加利益 / 设悬念 |
| 把 120 字全塞满 | 信息过载，读者读不完、没重点 | 压在 30–80 字，1–2 句话说完 |
| 摘要写得太像广告、太夸张 | 失信、像推销，反而劝退 | 用口语、具体、实在的语言，立住可信度 |
| 只复述标题不往决策推进 | 标题「我戒掉了无效社交」，摘要「是的，我戒了」 | 补上「怎么戒 / 戒了得到什么」，推读者下决心 |

## 六、自查要点

- [ ] 摘要 ≤120 字（建议 30–80 字），且**已手动填写**，未停留在自动取 54 字
- [ ] 摘要不是正文第一段的复制
- [ ] 摘要与标题信息互补（补信息 / 加利益 / 设悬念），没有重复同一句话
- [ ] 摘要说出了「点进来能得到什么」或吊起了想看的胃口
- [ ] 语言口语、具体、实在，不用夸张辞藻
- [ ] 摘要与封面（尤其压字关键词）不冲突、层级不打架（配合 cover-text 检查）

## 七、个性化空间

- **招法选择取决于内容类型而非喜好**：干货 / 教程惯用「加利益」，故事 / 观点惯用「设悬念」，悬念型标题惯用「补信息」。判断依据：你这篇是「给别人答案」还是「给故事过程」。
- **摘要篇幅可依账号调性微调**：专业/知识号可稍长（用到 60–80 字交代信息），轻快/情绪号可短（20–40 字一句点到为止）。判断依据：你的读者更耐心听解释，还是更吃短平快的钩子。
- **是否带具体数字看真实度**：能给具体数字（7 个、省 20 分钟）就给；但数字必须真实对应正文，虚夸会反噬信任。判断依据：正文里是否有真实可引以为据的数字。
- **是否点破「能学到什么」取决于栏目习惯**：有的栏目习惯了靠悬念留着不放，有的习惯直接报利益——都可以，只要和你账号一贯的调性一致。判断依据：读者对你这个栏目已有「给干货」还是「讲见闻」的预期。
- **和封面的关系可自定义**：当封面已把关键词压得很大时，摘要可以更偏「补信息 / 设悬念」而非再重复同一个词；当封面偏氛围没压字时，摘要可以更偏「加利益」把钩子补全。判断依据：封面已经抛了多强的钩子，摘要在旁边补什么最有效。
