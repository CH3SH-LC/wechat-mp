# 深色模式（深色模式适配）

> 定位：微信开启深色模式（暗黑模式）后，正文的背景、文字、边框会发生反色或变暗处理；本篇讲清哪些样式会被改、哪些会翻车、怎么保证在任何环境下都读得清。
> 调用时机：每篇排版完成后、发布前，切换到微信深色模式预览检查一遍；配色工具/风格条目里定色时也要考虑深色表现。

## 一、核心规则：深色模式下"发生了什么"

微信深色模式不是简单的黑底白字。它有一套后台算法把正文里的颜色做"反色/调明度"处理，**不是逐像素反转**，而是有选择地调整。理解这套规则才能避免翻车。

**1. 默认行为：两边不同底色出路**

- 微信深色模式会把**未显式设背景色的内容**放在深灰底（约 `#191919`~`#1c1c1c`，依 iOS/安卓版本略有差异），把**未显式设文字色的内容**变成浅灰白（约 `#ececec`~`#f2f2f2`）。
- 也就是说，一篇不写任何自定义底/自定义字的纯文本正文，在深色模式下自动变成"深灰底 + 浅灰字"——这是系统的安全默认，不必担心。
- 真正需要操心的是**你手动设置了底色或文字色**的那些块，它们在深色模式下会进入"反色/调色"流程。
- 阴影/透明度：`rgba(0,0,0,x)` 这类带透明度的深色，在深色模式下可能被"反向淡化"或保留，不同版本不稳定，别当作可靠手段。

**2. 会被"反色处理"的元素（逐项说清）**

用一张对照表把常见元素在深色模式下的表现讲透：

| 元素 | 深色模式下表现 | 观察要点 |
|---|---|---|
| 白底卡片（background 写死 #fff） | 大概率被反成深底；但手机上不一定反得干净 | 浅卡变深卡时，卡内文字要能跟着变浅 |
| 浅灰底（#f5f5f5 / #fafafa） | 常被压暗成更深的灰，甚至接近主背景 | 比纯白更快变"脏"，可能失去卡顿感 |
| 中灰底（#e0e0e0 ~ #f0f0f0） | 会被压到和主背景接近甚至更难区分 | 若用来做"分区"，深色模式下可能消失 |
| 深文字（#333 / #222 / #111） | 会被提亮成浅灰，以适配深底 | 正文用深字在深色下基本自动可读 |
| 浅灰小字（#999） | 被提亮，但幅度不如正文 | 提亮后仍偏暗，接近可读下限 |
| 描边/分隔线（#e0e0e0 / #ececec 浅灰边） | 被压暗成深灰线，视觉变淡 | 分隔感可能变弱甚至消失 |
| 图片本身 | 背景色被反色，但**图片像素内容不变** | 容器底的明度变化不影响图内细节 |
| 图上的文字叠加（压在图片上的字） | 不随图片反色，靠原图对比度 | 原图浅底+白字在深色下仍看不清 |

**3. 最重要的认知：微信是"整体调色板反转"，不是"逐块保证可读"**

- 微信会把整篇颜色往"深底 + 浅字"的方向拉，但**它不保证每个块都达到可读对比**，只做"整体明暗翻转"。
- 所以你不能依赖"我这张卡是浅底深字，所以一定能读"。真正稳的是**文字与背景的明暗对比在反色前后都成立**。
- 换句话说：凡是"靠纯明度反差（白底黑字）"才成立的配色，反色后就变成"深底浅字"，通常还好；而"深底深字 / 浅底浅字"这类**同一端叠一起**的，反色后依然糊。
- 行业共识的稳妥方向：**底色尽量用中间灰阶（不走纯白/纯黑极值），文字明度与底色拉开两档以上**。这样无论微信怎么反，明暗关系都站得住。

## 二、会出问题的样式（规避清单）

逐类讲清为什么会出事、具体长什么样：

**反例 · 问题 1：深色底 + 深色字的"深卡深字"**
- 表现：背景 `#1a1a2e`（藏青）、`#2a2a2a`（深灰）、墨绿等深底上，文字用 `#333`/`#222` 甚至更深。
- 为什么：深色模式下这坨底本身就已经是深色，字又是深色，两者明度同一端，糊成一片。
- 微信不会把这种"写死的深字"提亮到够亮，尤其当字的明度与背景明度几乎相等时，反色算法无从下手。

**反例 · 问题 2：浅色底 + 浅色字**
- 表现：背景 `#fff` 或浅卡上写 `#bfbfbf`、`#ccc` 这类浅灰字，本意是"弱化次要信息"。
- 为什么：浅底在深色模式下变深底，浅字可能仍是浅字（或提亮幅度不足），结果浅色字落在深灰底上对比极差。
- 这条尤其坑：它在浅色模式里看着"有层次"，但深色模式下整块糊。

**反例 · 问题 3：依赖"浅底 + 深字"的强反差卡片，完全交给微信反转**
- 表现：白底一句黑字的大标题卡、浅蓝底深字的信息卡，期望微信"自动反转成好看的样子"。
- 为什么：微信的"反转"是**算法折中**，不是设计级重排。你的品牌浅卡反色后可能变成"脏灰色 + 提亮不全的字"，观感大打折扣，品牌色也丢了。
- 提醒：不设底色/文字色的纯系统内容反色最干净；一旦你自定义了颜色，反色结果就不受你控制。

**反例 · 问题 4：图内文字靠"白字压在浅色图上"**
- 表现：在产品图、场景图的浅色区域上叠加白字；深色模式下图片像素不变。
- 为什么：图片里的文字不随微信反色，原图浅底 + 白字照样看不清。这不是"深色模式救图"能解决的，是原图本身的对比度问题，只是深色模式下观感更突兀。

**反例 · 问题 5：用浅灰 #999 做正文主色**
- 表现：整段正文都是 `#999` 浅灰，自诩"高级"。
- 为什么：深色模式下 #999 提亮有限，行距不足时一整段都读不清；对比度本身就不够（见"对比度与色弱"条目）。

**反例 · 问题 6：用带透明度的白色 rgba(255,255,255,0.6) 当正文**
- 表现：深色底上写 60% 透明白字。
- 为什么：半透明在反色/叠加时不稳定，透明度不同机型表现不同，很可能比预期更淡，做正文尤其危险。只能做次要注释，不能当主内容。

## 三、保证深色模式可读的做法

一条条给出可执行的指定：

**1. 文字与背景的明暗对比足够，且不依赖"纯浅底+深字"一种表达。**
- 正文主字用深色（`#333`/`#222`，进阶 `#111`），落在任意底色上反色后都能自动变成浅字。
- 对比度的硬底线看"对比度与色弱"条目（正文 ≥4.5:1）。
- 关键词：**正文文字永远选"深字"这一端**，把"浅字/白字"留给专门的深色块或标题，而不是当正文默认。

**2. 卡片 / 气泡底色，倾向用"中性灰序列"而非纯白/纯黑极值。**
- 例：气泡底 `#f8f8f8`、描边 `#e8e8e8`，反色后落在可读区间，比 `#ffffff` 更稳。
- 太灰（`#eeeeee` 下端）在深色下会和主背景贴住，反而失去"卡顿"感；取 `#f5f5f5`~`#fafafa` 这个浅灰带，反色后既有分区又不至于糊。
- 品牌浅底卡同理：别用最亮一档的纯白做整卡底，带一点灰阶更稳。

**3. 深色背景上的文字，前台用浅色并加足对比。**
- 深卡（深蓝 `#1a1a2e`、墨绿、黑）上文字用 `#ffffff` 或 `rgba(255,255,255,0.9)`。
- 正文级文字不要用低于 0.85 透明度的白配在深底上当主内容——`rgba(255,255,255,0.6)` 那种只配做次要注释（而且也要谨慎）。
- 判断深浅是否"够深"：深底够暗，白字对比自然 ≥4.5:1；深底偏亮的（如 `#4a4a6a`），白字要再确认。

**4. 不写死纯白 `#fff` 大块背景 + 固定深字，让微信有反色余地。**
- 需要"信息完整可读"的块，底色走中间灰，别用纯白极值，这样无论反不反都可读。
- 需要"强制保持浅色"（比如为了配固定浅色图片）的整块，考虑干脆不隐藏背景、交给系统默认，反而最稳。

**5. 边框/分隔线用中间灰（如 `#e0e0e0`），深色模式下保留分隔感。**
- 不要用几乎透明的极浅线（`#f5f5f5` 级）——深色下直接消失。
- 分区依赖"线的对比"而非"色相"的，把线色选在 `#d0d0d0`~`#e8e8e8`，颜色模式下清晰、深色下变深仍可辨。

**6. 图片上方用于压文字的色条，用"深色纯底 + 白字"。**
- 这类"标题条"（见"图片与标题条"模块）用深色纯底（如深蓝灰 `#1a1a2e`，单色不渐变）+ 白字，深色模式下底和字都稳定，文字始终读得清。
- 反之若用"浅色条 + 深字"压图，深色下反色不可控。

**7. 图内文字直接做进图里时，确保原图本身对比度足够。**
- 原图浅底上别压白字、深底上别压深字——反正色不等于救图。
- 用设计工具做"带文字的图"时，按"对比度"条目先在原图里对齐好。

## 四、可执行步骤 / 对照表

**深色模式检查三步：**
1. **列块**：写正文时把所有"自定义底 + 自定义字"的块列出来（卡片、气泡、标题条、引用、色块）。
2. **切预览**：在编辑器预览里切到**深色模式**（进入方式见下"检查方法"），逐个块看：字清不清楚、卡有没有脏、分隔线还在不在、品牌色丢没丢。
3. **逐项改**：对每一处翻车的块按第三节"做法"调整——底色走中间灰、深底换浅字、浅底换深字、删掉不必要的自定义底。

**快速自查表：**

| 检查项 | 合格标准 | 不过怎么改 |
|---|---|---|
| 深卡深字 | 深底配浅字 | 深底文字统一提亮成白/浅 |
| 浅卡浅字 | 浅底配深字 | 浅底文字统一压成深色 |
| 纯白大块底 | 尽量带灰阶 | 改 `#f8f8f8`~`#fafafa` |
| 浅灰主字 #999 | 正文不用 | 升到 `#333`/`#555` 及以上 |
| 描边 | 分隔感保留 | 用 `#e0e0e0` 级，不用极浅线 |
| 图内文字 | 原图对比就够 | 原图修对比或改色条方案 |
| 半透明白当正文 | 不做正文 | 升到实体白或在深底上足量对比 |
| 分隔/分区靠底色 | 深色下仍有区隔 | 底色选灰阶或改靠边框区分 |

## 五、示例

**可读（推荐）深卡标题条：**
顶栏背景 `#1a1a2e`（深蓝），标题字 `#ffffff`，副文字 `rgba(255,255,255,0.85)`。深色模式下：底仍是深、字仍是白，无论深浅环境都稳。

**可读（推荐）浅卡：**
卡片底 `#f8f8f8`（浅灰，非纯白），正文 `#333`，边框 `#e8e8e8`。深色模式下微信反成深底 + 浅字，因底色带中间灰，字段反得干净，分区仍在。

**可读做法（纯文字正文）：**
不写任何自定义底/字，正文五行正文直接交给系统默认 → 深色模式自动"深灰底 + 浅灰字"，最稳最省心。

**翻车反例：**
卡片底 `#ffffff`，正文 `#333`，强调高亮字 `#bfbfbf`（浅灰）。深色模式下：底色被反成深灰、`#333` 被提亮成浅字（可读）、但浅灰高亮字提亮后仍偏暗——本段里最该强调的字反而最看不清，高亮失去意义。

**翻车反例 2：**
深蓝底 `#1a1a2e` 上写 `#333` 句子（深卡深字），深色模式下底色已是深、字也是深，整句糊进背景里。

## 六、常见错误（反例 + 正解）

1. **「我设了白底黑字，深色模式应该自己处理」**
   - 反例：白底 `#fff` + 黑字在深色模式被反成"灰底 + 灰字"，对比打折、卡感丢失。
   - 正解：底色用中间灰 `#f8f8f8`，给算法反色余地；或干脆不设底。
2. **「反正图片不受影响，图里随便写字」**
   - 反例：浅色产品图上压 `#ffffff` 白字，深色模式下图不变、字依旧看不清。
   - 正解：图内文字保证原图对比度足够——浅图压深字、深图压浅字。
3. **「正文主色我用 #999，显得高级」**
   - 反例：深色模式提亮有限，整段读不清。
   - 正解：正文用 `#333` 及以上对比，`#999` 只做图注/次要注释。
4. **「深卡很酷，字用深色也没关系」**
   - 反例：深蓝底 `#1a1a2e` 上 `#333` 字，深色模式下糊死。
   - 正解：深底一律配浅字，明度拉开两档以上。
5. **「只在编辑器里看了一遍，没切深色」**
   - 反例：编辑器默认浅色预览看着没问题，真机深色模式读者全糊。
   - 正解：发布前必切深色预览逐块检查。

## 七、自查要点（可勾选）

- [ ] 所有自定义底色的块，深色预览下字都清晰可读
- [ ] 没有"深底+深字"或"浅底+浅字"的组合
- [ ] 没有大面积写死纯白 `#ffffff` 的块依赖微信反转
- [ ] 正文主字不是 `#999` 级浅灰（深色下会糊）
- [ ] 描边/分隔线在深色模式下仍有分隔感
- [ ] 图内文字在原图上对比度就够，不指望反色救
- [ ] 半透明白/rgba 透明字未用于正文主内容
- [ ] 在 iOS 与安卓微信各切一次深色预览
- [ ] 品牌浅卡反色后仍可读、不至于脏灰

## 八、个性化空间（按账号自定，给判断依据）

- **底色策略可调**：你的账号若走"清新浅色"风格，卡底气统一在 `#f8f8f8`~`#f2f2f2` 区间选一个；若走"暗黑科技"风格，可以整篇主动用深色系，但必须统一确保前台文字 = 浅色。判断依据：读者是否大量用深色模式（可看后台用户设备/系统设置占比）以及品牌主底色本身明度。
- **品牌色的深色表现**：如果你的品牌色偏深（墨绿、藏蓝、深紫），深色模式下要换成更亮一档的品牌色用在深底上，保证对比；品牌色偏亮（明黄、亮蓝）则问题不大，但要避免亮色直接做大面积底。判断依据：品牌色在 `#191919` 级深底上能否满足 ≥4.5:1。
- **是否主动支持深色**：若你的内容以浅色阅读为主且大量使用固定浅卡，可以"接受深色模式下这些卡反色后略灰"——只要可读就合格，不必追求形象完全一致。判断依据：可读性优先于形象一致性，形象一致性靠"中间调底色"尽量兼顾。
- **卡片/气泡的"卡感"取舍**：深色模式下有些号喜欢"卡片还是明显分区"（保留边框），有些接受"卡片融入背景更自然"。判断依据：你的排版是否依赖卡片作为信息边界（若依赖，就别省边框/底色灰阶）。
