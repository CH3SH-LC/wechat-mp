# 手机单栏阅读检查项（发布前终检清单）

> 定位：每篇推文发布前，用手机单栏视角逐项核一遍可读性——字号、行高、段距、对比度、深色模式、图片清晰度、无横向滚动、链接可点、重点标记数量。给每一项"查什么 + 不过怎么改"、检查顺序与怎么自查。
> 调用时机：每篇推送发布前、保存草稿前的最终检查。它是可读性维度（read-*）的统一出口。

## 一、检查项清单（每项：查什么 · 不过怎么改）

以下按"打开一篇真机草稿"的顺序逐项核。逐项给判定标准与改法。

### 1 字号
- **查什么**：正文是否 15–16px；标题、图注层级是否分明（见"字号行距舒适区"）。
- **判断标准**：正文一眼能读不费力；标题 vs 正文 vs 图注字号有明确落差。
- **不过怎么改**：正文字号调回 15–16px；图注 <12px 的升到 12px；标题层级靠"字号+字重"拉开的就不要再靠颜色凑。
- **注意**：真机预览时把屏幕放到阅读距离看，别贴着屏，贴合真实阅读。

### 2 行高
- **查什么**：行与行是否粘连，行高是否 1.75（正文）；（见"字号行距舒适区"）。
- **判断标准**：任取两三行正文，行与行之间有清爽的空隙，不是紧贴。
- **不过怎么改**：行高不足 1.7 的提回 1.75；大段引文至少 1.6；图注至少 1.5。

### 3 段距
- **查什么**：段落/卡片/图片之间是否统一 16px 底部间距、无紧贴无过大（00-GUIDE 间距规范）。
- **判断标准**：段落之间有稳定一致的间隔，前后篇一致；没有"两段粘一起"或"突然一大段空白"。
- **不过怎么改**：间距用统一的块级底部留白设到 16px；不要用加空行堆（不可控）。

### 4 对比度
- **查什么**：正文/链接/注释/小字对比是否 ≥4.5:1（见"对比度与色弱"）。
- **判断标准**：眯眼看能清晰分辨文字轮廓；远一点看正文仍清楚。
- **不过怎么改**：主字升到 `#333` 级、注释别用 `#999`；白字上深底、深字上浅底；用计算器核主要配色。

### 5 深色模式
- **查什么**：切到微信深色预览，所有自定义底色块的字是否清晰（见"深色模式"）。
- **判断标准**：深色模式下每块字都能无碍读，卡片不脏、分隔线还在。
- **不过怎么改**：深卡配浅字、浅卡走中间灰、白字只上深底；图内文字原图就够对比。
- **注意**：深色模式是本文重点项，务必真机切，不能只在编辑器浅色里看。

### 6 图片清晰度
- **查什么**：图片是否模糊、文字发糊、长图细字是否黏（见"图片处理规范"：≥1080px 上传、长图切段）。
- **判断标准**：图拉到满屏仍清晰，图中文字/数据一眼可读，无压缩糊。
- **不过怎么改**：原始图加宽到 ≥1080px 再传；超长信息图切成 ≤1500px 高的多段。

### 7 无横向滚动
- **查什么**：有没有任何元素在手机窄屏造成横向滚动条——固定像素宽的图、超长英文单词、无 gap 的 float 图、表格。
- **判断标准**：**绝不能有横向滚动**（这是铁律，破版即返工）。左右拖动屏幕时画面不应有水平滑动/内容被切掉。
- **不过怎么改**：图片一律限定"不超出内容区宽度"+高度自适应；长英文/URL 允许换行或加断词点；表格截图转图；float 图宽 ≤45%。
- **注意**：这条最容易漏，却最致命。在 iOS 和安卓各划一遍确认。

### 8 链接可点
- **查什么**：文中有没有链接，点击区域是否够大（≥44px 触控），能不能正常跳转、链接文字与正文是否可区分（下划线/颜色）。
- **判断标准**：手指能轻松点中；点开能正常跳转；链接和正文长得不一样（有下划线/带色），不然读者不知道可点。
- **不过怎么改**：链接文字加下划线或对比色；触控目标加大；确保 URL 是长效可访问的，不是临时占位。
- **注意**：链接是"交互项"，真机实测点一遍，别只看视觉。

### 9 重点标记数量
- **查什么**：加粗 / 高亮 / 变色强调的词是否过多（一屏内高亮超过 3 处即偏多），强调是否分散到没有重点。
- **判断标准**：每屏扫一遍，读者能一眼说出"哪些是核心重点"；如果满屏都是重点，等于没有重点。
- **不过怎么改**：每屏重点标记压到 1–3 处，把"核心记忆点"留给真正的强调，其余放回普通字。

### 10 首屏可读（追加项）
- **查什么**：首屏（不滑屏直接看到的部分）是否一上来就有清晰标题 + 可读正文，没有被大图/大片留白/过多装饰占掉。
- **判断标准**：读者打开第一眼就知道"这篇讲什么、从哪读起"。
- **不过怎么改**：首屏放"标题 + 副题/摘要 + 一两段正文"或"标题 + 一张承题图"，别让首屏全是大白底或纯图。
- **注意**：首屏决定"留不留"，和封面（cover/ 维度）配合，但首屏的正文可读性属于本维度。

## 二、检查顺序（推荐流程）

按"从整体密度 → 到单块细节 → 到终态环境"的顺序，避免漏项：

1. **整体扫读**（手机真机）：先通读一遍，抓"大问题"——大段、无锚点、节奏问题（见"长文阅读节奏"）。
2. **字号 / 行高 / 段距**：核对正文基准与间距统一（123）。
3. **配色与对比**：核对正文字、链接、注释、小字对比（4）。
4. **深色模式**：切微信深色预览逐块看（5）。
5. **图片清晰度 + 横向滚动**：缩放看每张图，并横拖动看有没有溢出（67）。
6. **交互**：点一遍所有链接，确认可点可跳（8）。
7. **重点标记**：数一遍强调是否超量，把过载的重点砍掉（9）。
8. **首屏复核**：返回顶部看首屏一屏之内是否抓得住（10）。
9. **终态复核**：在 iOS 与安卓微信各跑一遍 457（平台差异最大的几项）。

**为什么这么排序：** 先把"密度/节奏"这个最影响整体观感的搞定，再抠单块细节，最后在两个终端环境里"按真实阅读"复核——大问题先消、小问题后理、环境差异最后兜底。

**检查过程怎么留痕（可操作）：** 边核边在清单上打勾（见第五节自查要点），过不去的项当天记一句"哪项没过、怎么改的"，发布后复盘能复用这套标准。别凭感觉"大概都行"，逐项勾掉才不漏。

**什么时候做这遍终检（省时的两个时机）：**
- **草稿定稿后、保存草稿前**：先文字通读（整体密度/节奏）再排版逐项核，比发出去出了大问题再返工省得多。
- **发布前最后一小时**：只复核"环境差异最大"的几项（深色 5、横向滚动 7、链接 8），不必再全量走一遍——全量在草稿阶段做，临发只兜底。

## 三、示例

**一条完整的终检过程（快速版）：**
打开草稿真机预览 → 通读看到一个 8 行大段 → 拆成 2 段（13 + 节奏）→ 正文 14px 升到 15px、行高 1.5 升到 1.75（12）→ 图注 `#999` 升到 `#555`（4）→ 切深色，发现浅蓝卡白字看不清，白字改深蓝（45）→ 一款产品图 800px 太糊，换 1200px 原图再传（6）→ 确认无横向滚动、链接都能点（78）→ 高亮从一屏 5 处砍到 2 处（9）→ 首屏顶部加两行副题让读者不迷路（10）→ iOS/安卓各切一次深色复核（终态）。

**一条"漏了大问题"的检查：**
只在电脑编辑器里看了字号、没真机 → 深色模式、横向滚动、链接可点全没核 → 发布后手机深色糊 + 有一处横向滚动 → 读者体验崩。教训：终检必须真机 + 全清单。

**"只改不动"的反例：**
改了字号 14→15px，却没回看行距是否跟着变；改了链接颜色，却没重测一下还能不能点中。改任何一项都要把受影响的相邻项重看一遍（尤其 457），别"修了 A 忘了 B"。

**不同内容类型的检查侧重（快速参考，可写进自己的 SOP）：**
- **干货/教程篇**：重点放大在"图片清晰度（含文字数据）+ 锚点节奏 + 重点标记"，这类文长时间读图、划重点，1679 尤其别省。
- **活动/转化篇**：首屏（10）+ 链接可点（8）最重要，读者打开就要"看得到活动、点得到入口"；深色（5）也别大意，活动落地页常被深夜打开。
- **情感/随笔篇**：字号行距与节奏（123 + 节奏）是王道，读感松弛即可，图片/链接要求可放宽。
- **资讯/快讯篇**：首屏抓人（10）优先，其次是图片清晰（6）与无横向滚动（7）——资讯配图多，破版面最伤人。
- **一句话记牢**：对象不同，"火力分配"不同，但"无横向滚动 + 深色可读 + 链接可点"是任何类型都不能省的底线。

## 四、常见错误（整体检查时的坑，反例 + 正解）

1. **只在电脑编辑器里看，不真机预览**
   - 反例：电脑看没问题，手机实机行高/横向滚动/深色全翻车。
   - 正解：终检必须以手机单栏真机为准（用微信预览到真机）。
2. **把检查项当可选，尤其漏"无横向滚动"和"深色模式"**
   - 反例：这两个最易漏，一旦破版/糊字读者直接放弃。
   - 正解：清单逐项勾，不跳。
3. **跳过交互项（链接 / 重点标记数量）**
   - 反例：只查了视觉，链接点了没反应、满屏高亮看不出重点。
   - 正解：链接实测、强调计数。
4. **只看一档型号**
   - 反例：只在 iPhone 预览过关，安卓宽高比/深色表现不同。
   - 正解：至少 iOS + 安卓各一次。
5. **发现问题只改不动**
   - 反例：改了字号但没复查行距，改了亮度但没重看深色。
   - 正解：改任何一项后，把受影响的环境项（尤其 457）重跑一遍。
6. **忘记首屏**
   - 反例：只核对长文，首屏大图占满、没有可读正文，读者第一眼就走了。
   - 正解：首屏单独核，确认标题+正文抓得住（10）。
7. **凭感觉不逐项勾**
   - 反例：走一遍当看过，漏项不自知。
   - 正解：用第五节自查清单逐项打勾，没勾的不算过。

## 五、自查要点（可勾选）

- [ ] 正文 15–16px、行高 1.75、段距 16px、段首顶格
- [ ] 标题层级（字号+字重）分明
- [ ] 图注/注释 ≥12px
- [ ] 正文/链接/注释对比 ≥4.5:1
- [ ] 深色模式预览下所有块可读
- [ ] 图片 ≥1080px 足够清晰，无长图细字发糊
- [ ] 无横向滚动（最关键铁律）——iOS 和安卓都验证
- [ ] 所有链接可点、触控区够大、可与正文区分
- [ ] 每屏重点标记 ≤3 处，强调不过载
- [ ] 首屏有清晰标题 + 可读正文，不被大图/留白占掉
- [ ] iOS + 安卓各跑一遍终态复核

## 六、个性化空间（按账号自定，给判断依据）

- **检查的严格档位**：极重要的高转化推文（卖课/活动）可加一档"逐段扫读 + 两人交叉核对"；日常随笔可快速过一遍清单。判断依据：本篇的重要性与出错代价。
- **重点标记的允许量**：干货教程可适当放宽到一屏 3–4 处（读者就爱划重点）；文学性推文要克制到 1–2 处。判断依据：内容类型与读者划重点习惯。
- **图片清晰度的底线**：纯氛围图可接受略软；含文字/数据的信息图必须从严达硬标准。判断依据：图片是否承载关键信息。
- **是否做多终端检查**：若读者几乎全 iOS 或几乎全安卓，可只测主端；否则双端都要。判断依据：读者设备画像（后台数据）。
- **检查工具的选用**：极重文章的对比度/深色问题可用工具辅助算（见"对比度与色弱"）；日常凭真机目测即可。判断依据：合规与质量的严格程度。
- **首屏的承题方式**：图文资讯号首屏习惯"大图+标题"抓眼球；文字深度号习惯首屏直接给"副题+摘要正文"。判断依据：账号的内容调性与读者打开习惯。
