# 对比度与色弱（文字可读底线与颜色友好）

> 定位：正文文字能不能让人"不费力"地读出来，取决于文字与背景的明暗对比（对比度）；同时要考虑色弱读者——不能靠"红绿区分信息"。本篇给底线数值、色弱友好彩搭配、白字的用法与检查方法。
> 调用时机：设计配色、写正文、配图表/列表时；发布前与"深色模式""字号行距"条目一起核。

## 一、核心规则：对比度底线（参考 WCAG）

**什么是对比度：** 对比度衡量的不是"颜色多鲜艳"，而是**前景（字）和背景（底）的亮度差**。它是 1:1 到 21:1 之间的数值：1:1 表示字和底完全同色看不见，21:1 表示纯黑底上纯白字（理论最高反差）。颜色再花哨，只要明度相近，对比度都低，字都看不清。

**换算成大白话：** 对比度 = "字比底亮多少或暗多少"的倍数。4.5:1 的意思，就是相对较亮那一方的亮度约是较暗一方的 4.5 倍。别去记公式，记住三档就够了：
- **21:1**——黑底白字，反差拉满；
- **7:1**——黑字（`#333`）压浅底，非常稳，可作大段正文的"增强档"；
- **4.5:1**——正常正文的及格线（底线）；
- **3:1**——大号标题/图形的最低要求，正文不够用。

**底色/文字一对一的判断方法（可操作）：** 想判断任一"字+底"的组合过不过，就用 6.1 节的对比度计算器输入两者的十六进制色值，看返回的比值。下面给几个常见组合的先记住，能省一半时间：

| 字色 | 底色 | 近似比值 | 结论 |
|---|---|---|---|
| `#333`（近黑深灰） | 白 `#fff` | ≈ 13:1 | 可用，稳过正文 |
| `#555`（中深灰） | 白 `#fff` | ≈ 7:1 | 可用，可做正文/图注 |
| `#666`（中灰） | 白 `#fff` | ≈ 6:1 | 可用，图注够用 |
| `#888`（偏浅灰） | 白 `#fff` | ≈ 3.7:1 | 勉强，只够大标题 |
| `#999`（浅灰） | 白 `#fff` | ≈ 3.0:1 | 不可，正文不行 |
| `#767676` | 白 `#fff` | ≈ 4.5:1 | 可用，恰好压线 |
| `#fff`（白） | 深蓝 `#0b3a68` | ≈ 8:1 | 可用，深底白字 |
| `#fff`（白） | 浅蓝 `#cfddf3` | ≈ 1.8:1 | 不可，几乎隐形 |

> 快捷结论：在一张浅底上想稳过正文，字色往 `#555`、`#666` 这个深度取就基本不会错；想留出"可自定义的淡"，最深也只能试探 `#767676`，再浅就跌破 4.5:1 了。

**底线数值（微信正文适用，参考 WCAG 无障碍标准）：**

| 用途 | 建议对比度 | 说明 |
|---|---|---|
| 正文主文字 | **≥ 4.5:1** | WCAG AA 标准，也是微信正文应卡住的线 |
| 大号标题 / 加粗大字（≥18px 且加粗，或 ≥24px 普通） | ≥ 3:1 | 大字号对对比要求可适当放宽 |
| 图注 / 注释小字（12–13px） | **≥ 4.5:1，能到 7:1 更好** | 字号越小越要稳，别用浅灰当注释主色 |
| 链接文字 | ≥ 4.5:1（相对底） | 且要有文字本身之外的区分（如颜色 + 下划线） |
| 图标 / 分割符（非文字） | ≥ 3:1 | 装饰性图形可略低，含信息的图形需更高 |

**为什么是 4.5:1：** WCAG 把"正常字号文本"的可读阈值定在 4.5:1，这是视力正常、在中等亮度屏幕上"不加辨认就能读"的经验标准。低于它，需要读者眯眼、调亮度、凑近，长文阅读尤其受影响。4.5:1 不是玄学比例，它是经过盲人/低视力无障碍研究反复校验过的"人眼不必花精力辨认就能流畅阅读"的分界线。

**用大白话记：**
- "正文 = 深字"是最省心的保证：`#333`/`#222` 落在白/浅底上几乎必然 ≥ 12:1。
- 别把"浅灰字"当正文：`#999` 在浅底上通常只有约 2.5:1~3:1，不够。
- 只要那行字是"读者必须读出内容"的字（不是纯装饰），都按 ≥4.5:1 处置。
- **深浅要成对看**：没有"绝对安全的颜色"，只有"这个颜色落在这个底上安全"。同一个 `#666`，压在白底上 6:1 够用，压在 `#e0e0e0` 浅灰底上就可能掉到 4:1 以下——所以每一次配色都要"字+底"一起判断，别只调字色。

## 二、色弱友好配色（不要靠颜色区分信息）

**先给数据：** 约 1/12 男性、1/200 女性是红绿色弱。也就是男性读者里约每 12 人就有一位，色弱不是小众到可以忽略——如果你的信息完全靠"红 vs 绿"传导，你会发现相当一部分读者读不出来，而且他们自己往往也不吭声。

**再给一层用途场景：** 推文里最常见的"靠颜色传信息"的地方是：正误对错标记、图表分组、状态色（通过/失败/待处理）、强调句变色。这几处恰恰是色弱读者最容易"读丢信息"的地方——不是看不清图，而是"分不清哪个是哪个"。所以色弱友好的核心不是调高清晰度，而是**给颜色之外的另一重区分**。

**色弱友好的三条原则：**

1. **绝不只用颜色做唯一区分。**
   - "标注对错、胜负、分成两组"这类信息，除了颜色还加**文字 / 符号 / 形状 / 位置**差异。
   - 例：红「失败」/ 绿「成功」改成"红字标『失败』 / 绿字标『成功』"；两个图例不只靠红/蓝底色，还要带标签和编号。
   - 例：表单校验提示，除了把输入框描红，还加一行"此项必填"的文字提示。
2. **避开"纯红 vs 纯绿"或"红绿相邻"的图例。**
   - 需要并列两色时，把绿色往蓝偏（青绿），把红色偏橙或偏深，让两者明度拉开。
   - 色弱安全组合：**蓝+橙、蓝+黄、蓝+紫、橙+深蓝**。这些组合在红绿色弱眼里明度差异仍大，可分辨。
   - 若帖子风格实在要"红绿"（比如春节、党庆文案），可用"深红 + 深绿"并把两侧都配上文字/符号，就不依赖色相本身。
3. **确保可区分性不只靠色相，也靠明度。**
   - 浅蓝和浅红在色弱眼里可能都发灰；让一个浅、一个深，或一个亮、一个暗，比两色同明度更保险。
   - 判断小技巧：把两张要并列的色块转成"黑白预览"再看，如果黑白下仍能分出深浅边界，那色弱读者大概率也能分。

**配套做法：**
- **数据图表**（饼图/柱状图）在意分组时，除了柱体颜色，把数值标签直接标在图上，或加纹理/描边区别。色弱读者看颜色分不清，但看数字就能读。柱状图建议"柱色 + 柱顶数值 + 图例文字"三件套齐上。
- **强调句**：用"加粗 + 颜色加深"双重强调，而不是只靠换个颜色。只换颜色的强调，色弱读者可能完全看不出在强调。
- **表格状态**：正误/状态列加 "对 / 错 / - / 待处理" 文字而不只是底色变化，必要时再加"通过 / 失败 / 排队中"文字。
- **可及性提示**：凡一段信息表达颜色是必需含义（如"红色表示风险"），在图注里用文字再说明一次，双重保障。

## 三、白色文字的使用限制

白字（`#ffffff`）是"深底专属"——它只该出现在足够深的底上，并且要匹配字号与加粗：

| 场景 | 白字用法 | 是否合格 |
|---|---|---|
| 深色底（深蓝 / 墨绿 / 黑）上的正文 | `#ffffff` 字，字号 ≥15px | 可用，常规安全 |
| 深色底上的标题 | `#ffffff` + 加粗 | 可用 |
| 浅色/中调底（浅蓝 `#cfddf3`）上 | `#ffffff` 字 | 不可，几乎看不见，白字必须深底 |
| 深色底上小到 12px 的白字 | 需确认对比 ≥4.5:1 | 勉强，深底够暗才行 |
| 半透明白 `rgba(255,255,255,0.6)` 做正文 | 只配做次要注释 | 勉强，不能当主内容，透明度不稳定 |

**规则一句话：白字是"深底专属"，且字号越小、底越要深；半透明白只做陪衬不做正文。**
- 透明度（rgba）的坑：`rgba(255,255,255,0.6)` 表示白字看到的是"白 × 60% + 底 × 40%"的混合色，实际亮度比纯白低一截，在深浅模式下表现也不同，实际对比往往比名义值低，做正文尤其危险。
- **"多深的底才算够"给一组参考**：白字在 `#1b1b1b`（近黑）上约 16:1，在 `#333` 上约 12:1，在 `#555` 上约 7:1，在 `#777` 上约 4:1——**底掉到"中调灰"级别，白字就守不住 4.5:1 了**。所以"深底"至少要到 `#444` 或更深（色值里"黑度"≥55% 再考虑上白字）。
- 判断"底够不够深"：用计算器算白字 vs 深底的对比，≥4.5:1 才放心。

## 四、对比度检查方法（目测 + 工具）

**目测速判（不依赖工具也能抓大头）：**
- 眯眼看：能不能清晰分辨文字轮廓；分不清则对比不够。
- 把屏幕放远一点看小字（模拟弱视 / 手机距离远）。
- 把亮度调中等再看（别开到最亮，最亮会骗你）；也别在暗室里看，环境太暗会让亮对比显得虚高。
- 真机预览用"阅读距离 + 正常手机亮度"再看一遍，最贴近读者真实感受。

**工具法（精确，推荐发布前用）：**
- 用在线对比度计算器（搜索"contrast checker 对比度 计算器"），输入前景色和背景色的十六进制，直接出对比度比值是否达标。输入 `#333` 和 `#fff` 这类常见组合最快。
- 若是图片/截图里的文字，先在想测的文字上**取样它的颜色和背景色**（可用截图取色工具或图片软件的吸管），再输入计算器。
- 部分浏览器/设计软件的颜色选择器自带对比度提示，可参考，但最终以计算器精确值为准——软件提示常按"组件大字号"放宽，别只看它标的"及格"。
- **批量核对技巧**：定稿前把"用到的字色清单 + 底色调"整理成几行，一次算完，胜过一次一次翻。

**操作顺序（结合配色流）：**
1. **定配色时就先算一版**：正文/背景、链接/背景、注释/背景、标题/背景，确认全过关再排版；
2. **排版后统一核一遍**：尤其图表、色块、深色卡自己写颜色的地方；
3. **深色模式 / 手机终检时一并复查**（见"深色模式""手机单栏阅读检查项"）。

## 五、示例

**合格正文配色：**
- 正文 `#333`（深灰）落在白底/浅底 `#ffffff`/`#f8f8f8` 上 → 对比 ≥ 12:1，稳过。
- 链接 `#0b6bcb`（深蓝）落在浅底 → 约 5:1，且带下划线，区分明确。
- 图注 `#666`（中灰）落在浅底 → 约 5:1，小字也可读。
- 深蓝卡 `#0b3a68` 上白字 → 约 8:1，标题可放心用白字加粗。
- 一组柱状图"柱色用蓝+橙"且柱顶标数值 → 明度拉开，红绿色弱也能读数字。

**不合格反例：**
- 正文主字 `#999` 落在白底 → 约 3:1，不够 4.5:1，长文伤眼。
- 图例用"红柱=失败、绿柱=成功"且柱上无标签 → 红绿色弱读者分不清。
- 白字 `#fff` 压在浅蓝卡 `#cfddf3` 上 → 约 1.8:1，几乎消失。
- 正文用 `rgba(255,255,255,0.6)` 白字压在深蓝上 → 名义对比不足，深浅两模式都发灰。
- 两个并列色块"浅蓝 vs 浅红"都同亮度放在图表里 → 色弱读者视作同一灰调，无法分组。

## 六、常见错误（反例 + 正解）

1. **「浅灰 #999 显得高级，正文就用它」**
   - 反例：对比不足，长文伤眼，深色模式下尤甚。
   - 正解：正文用 `#333`/`#555` 及以上，`#999` 只做图注次要文字（且图注也要 ≥4.5:1，能深则深；实际图注至少 `#666`）。
2. **「红/绿很直观，图例就这样」**
   - 反例：红绿色弱读者读不出分组。
   - 正解：除颜色外加文字/符号/明度差，或以"蓝 + 橙"取代"红 + 绿"。
3. **「白字配什么底都好看」**
   - 反例：白字压浅卡变隐形。
   - 正解：白字只上深底（至少 `#444` 深），且字号/加粗匹配，必要时计算器验证。
4. **「对比度是好看问题，不是硬指标」**
   - 反例：凭感觉配色，深色模式 + 近视叠加直接翻车。
   - 正解：当成硬底线，用计算器核一遍主要配色。
5. **「大标题浅色没关系」**
   - 反例：超大浅灰标题在浅底上仍费劲。
   - 正解：即使大字号也建议 ≥3:1，别为"柔"牺牲标题识别度。
6. **「色弱只是少数，无所谓」**
   - 反例：男性读者多时色弱比例可到 1/12，信息分不出是不公平。
   - 正解：凡是靠颜色传信息的多加文字/符号；成本极低收益明确。
7. **「只调字色，不管底色」**
   - 反例：同一个灰字在白底和浅灰底上表现差很远，换底不重算。
   - 正解：深浅成对判断，换任何一方底色都重算一次对比。
8. **「深色卡上的字都用白字」**
   - 反例：中调底（如 `#6b6b6b`）上白字不足 4.5:1。
   - 正解：卡太浅就换深字（`#333`）或加深卡底色，按对比定字色而非"深卡必白字"。

## 七、自查要点（可勾选）

- [ ] 正文主字与背景对比 ≥ 4.5:1
- [ ] 图注/注释小字对比 ≥ 4.5:1
- [ ] 链接文字对比 ≥ 4.5:1 且有非颜色区分（如颜色 + 下划线）
- [ ] 没有任何靠红/绿单独颜色区分的信息
- [ ] 白字只出现在深底上
- [ ] 半透明白 / rgba 透明字未用于正文主内容
- [ ] 数据图表除了颜色还带标签/符号/编号
- [ ] 强调不只靠换色，还有加粗等手段
- [ ] 用对比度计算器核过主要配色（正文/链接/注释/标题）
- [ ] 每个深色/色块卡片的字色都单独与底算过对比，未只调字色
- [ ] 并列两色时明度已拉开，不靠同亮度色相硬分

## 八、个性化空间（按账号自定，给判断依据）

- **底色的明度基准**：你的账户底是纯白、浅灰还是带色调的卡其，会整体抬高或压低"默认深字"的对比度。判断依据：底色越浅，默认深字越稳；底越带灰，越要确认深字不够深。深浅卡混用时，给浅卡配深字、深卡配浅字，逐卡自定。
- **品牌色能否当正文色**：若品牌色偏深（墨绿 `#1e5a3a` 这类）且对底对比 ≥4.5:1，可少量做关键词强调；偏亮（明黄 `#ffd300`）则只做背景/图形，不做文字。判断依据：用计算器算品牌色落在底上是否达标。品牌色做文字时，只用于"点缀关键词"，不用来铺大段正文。
- **色弱读者占比**：教育/实用类账号男性读者偏多，红绿色弱风险更高，更应遵守"不用纯红绿分信息"；时尚/生活类相对宽松。判断依据：账号读者画像。不确定画像时按"男性占一半"保守处理。
- **注释文字色的程度**：若你偏好极淡注释，可接受"注释在图注单独成行、字号 12"，但务必压到 ≥4.5:1（实际需 `#666` 或更深层次），不要用 `#999` 当注释固定色。判断依据：注释只做辅助信息时可保留稍低层级感，但 4.5:1 底线不变。
- **强调强度的取舍**：干货号可让强调色+加粗双强；文艺号可能只想用颜色做细微区分。判断依据：仍以"色弱能分出强调"为前提，纯色深无法满足时补加粗。文艺号若坚持只用颜色，把强调色选成"明度明显区别于正文"的颜色（如深蓝强调落在黑字段里，明度已拉开）。
