# 00 · 知识库主索引

本库服务于把用户需求与材料做成一篇可预览、可修改的公众号文章。系统提示已提供共同编辑标准；按本次需要取用知识点，不要求先遍历目录，也不要求用户逐项规划。

## 知识职责

| 目录 | 内容 | 使用边界 |
| --- | --- | --- |
| 文本/写作 | 目的、结构、校园、产品、解释、叙事与审稿方法 | 帮助作编辑判断，不提供本稿事实或固定全文模板 |
| 文本/合规 | 版权、数据、行业及内容合规 | 对照实际题材检查，必要时核实适用规则 |
| 产品 | 已标明来源身份的应用产品事实 | 仅可证明相应产品能力，不扩展成未说明的承诺 |
| 排版引擎 | 当前 v2 语法、配色与版式声明、图片和素材引用 | 当前应用呈现协议的权威来源 |
| 视觉/风格 | 配色、字形气质、线饰与图案词汇 | 服务视觉选择，不规定文章写法、结构或配图数量 |
| 视觉/模块 | 信息组件与视觉组织 | 供需要这种信息关系时选用，实际输出服从引擎协议 |
| 插图/图片、插图/视频 | 来源、授权、处理与使用说明 | 用户原图与素材身份由实际附件或工具结果确认 |
| 其它/封面、其它/可读性 | 封面视觉、手机阅读与无障碍 | 检查呈现效果，不用阅读节奏配额反推正文结构 |

## 写作知识入口

- `writing-purpose`：确定读者、文章要解决的问题及取材范围。
- `writing-structure`：安排信息顺序与段落关系。
- `writing-campus`：校园活动、通知和校园消息。
- `writing-product`：产品、服务或工具介绍。
- `writing-explain`：解释、方法、教程和比较。
- `writing-story`：人物、事件与叙事。
- `writing-review`：检查成稿是否完成自己的目的。

点文件详见 `文本/写作/00-索引.md`。这些名称用于知识检索；是否创作、是否澄清和如何组织全文由模型结合用户需求判断。

## 呈现与素材

创作回合会提供 `排版引擎/engine-write-protocol.md` 全文。正文输出 v2，不手写 HTML 或 SVG。早期视觉资料中的 HTML 片段只能帮助理解外观，不能照搬为当前正文。

配色与版式独立选择，极简和明丽都可使用。正文容器可用协议浅底与纸色，横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构；正文零 emoji、零图标字符、零渐变、零阴影。允许协议支持的小记号与插画内部填色。尺寸、间距、颜色和对齐由引擎执行，不另立一套冲突参数。

手机阅读通过可读字号、行距和信息层级适配。不得把完整书面句拆成碎句、把段落拆成逐行短语来迁就屏宽或图框；视觉上的温暖、圆润、热闹不构成拟口语、假亲切或安慰式文案的要求。

用户原图使用实际得到的 `local-image://` 引用；库素材使用清单提供的 `[[asset:…]]` 引用；需要新素材时按协议声明占位。读取失败、素材缺失或未知事实应如实处理，不能根据文件名猜画面，不能用示例补造本次信息。

## 来源与修改边界

用户材料、明确确认以及已标明身份的产品事实，与写作知识和视觉示例分开使用。后两者不证明机构安排、人物经历、统计、采访或产品效果。

局部修改遵守用户范围，保留范围外正文、图片与引用；完整底稿的润色或排版保留其信息与篇幅尺度。未指定的编辑事项由模型判断，不以资料库中的固定目录、样句或示例数量替代判断。

本库不包含历史退休语料；归档位于运行时知识目录之外。维护时同步点文件、检索映射和本索引，避免把历史方案重新接回创作上下文。
