# 风格库维护门槛（何时升级、扩充怎么评审、命名登记）

> 定位：跨风格通用方法论。风格不是越多越好——库膨胀会让「选风格」变难、让账号辨识度稀释。本条讲「子系何时升格为顶层风格」「新风格要不要纳进来」「风格命名与登记规范」。
> 适用对象：负责维护风格库/设计规范的运营者或团队。调用方：在考虑「加一个风格 / 升级一个变体」时，先按本条目评审。

## 一、变体 vs 顶层风格的区别（先明确）

| 维度 | 变体（子系） | 顶层风格 |
|---|---|---|
| 使用频率 | 偶发、特定场景 | 高频、可作账号基线 |
| 与母风格关系 | 强烈依赖母风格 | 独立可站住、不依赖任何母风格 |
| 落位 | 只在母风格 "基础上微调局部" | 全套色板/标题/模块完整 |
| 典型例 | 治愈手绘（手账子系）、清水森系（日子系）… | 校园、科技、国潮…16 个顶层风格 |

## 二、子系何时值得升级为顶层风格（升格门槛）

一个变体要升格为顶层风格，需**同时通过**下面 3 个大项：使用强度、独立程度、运营价值。逐项打勾：

### 门槛 A：使用强度
- [ ] 近 3-6 个月，该变体被用到 ≥8 篇以上（或占全号内容 ≥15%）。
- [ ] 它不再只是「某个场景的点缀」，而成了「读者认得的一种常态外形」。
- [ ] 多个栏目/多条内容线都用它，不是单一栏目抱死一个。

### 门槛 B：独立程度
- [ ] 它已经基本脱离母风格能自洽——去掉母风格特征（如手绘去掉虚线贴纸框）仍成立。
- [ ] 它有自己的核心气质与色板，且与母风格区分明显（不撞车到分不清）。
- [ ] 用它写的文章，读者能认出它「不是母风格」。

### 门槛 C：运营价值
- [ ] 升格后能明确挂上某类内容/某个栏目 / 某段读者（有「名分」）。
- [ ] 升格不会造成选风格时的「二选一纠结」（不会让运营者更纠结）。
- [ ] 团队/运营者有精力维护它的完整条目与色板。

> **通过门槛**：A+B+C 全过 → 升格为顶层风格。只过 A、没过 B（仍强烈依赖母风格）→ 保持变体。只过 A、没过 C → 先用着，暂不升格。

### 升格评审打分表（给团队更细的判定）

| 评审项 | 权重 | 打分（0-3） | 判定 |
|---|---|---|---|
| A 使用强度：近 3-6 月出现频次 | 高 | 0 少用 / 3 高频常态 | 达标需 ≥2 |
| B 独立程度：去母特征仍自洽 | 极高 | 0 不可 / 3 完全自洽 | 一票否决不达标即不升 |
| C 运营价值：有明确挂靠 | 中 | 0 无 / 3 有栏目读者 | 达标需 ≥2 |
| 区分度：与该风格库最相近者差异 | 极高 | 0 撞车 / 3 明显区分 | 一票否决不达标即不升 |

> 用法：任一「极高」项得 0 分，则该变体暂不升格；总分达标且无否决项才考虑升格。这条比「打勾」更敏感，团队可按需选用。

### 升格后要做的事
1. 把变体条目「扩写」成完整顶层风格条目（气质/适用/完整色板/标题/模块表现/花纹/文案调性/禁忌/混搭/封面/深色模式/个性化留白）；可从本库的 `style-variant-`* 与 `style-guide-*` 条目取材。
2. 补进「风格选择」矩阵；在 `index-style` 的顶层清单里登记。
3. 更新原母风格的「变体」记录，注明该子系已独立。
4. 历史引用检查：把凡是引了「该变体」的其他风格/方法论条目，改为引用「新顶层风格」，避免索引失联。

## 三、新风格要不要纳入风格库（扩充评审 5 问）

不急着「看到好风格就加」，扩充前过 5 问：
1. **用得够吗**？是否反复遇到现有风格装不下的内容？（阈值参考：≥8 篇 / 3-6 个月）
2. **真不一样吗**？与现有 16 顶层 + 6 变体有无 60% 以上区分？（撞车太多就不加）
3. **有读者吗**？是否明确服务于某类读者/栏目，而不是「我觉得酷」？
4. **提效吗**？加了它，选风格是更快还是更纠结？（库越大越易纠结）
5. **能维护吗**？是否有精力长期维护它的条目与色板？（条目是承诺）

> 5 问里任一「否」都该缓一缓；尤其第 2、4 问是否定的，基本就不该扩。**风格库宁缺毋滥**——16 顶层 6 变体的密度已是成本边界，每多一个都要靠「独立度」硬撑。

### 扩充评审的「两票否决」项（最高优先）
- **「撞车票」**：新风格与现有任一风格的气质 / 色板 / 特征元素重叠 ≥60% → 否决。库的空位有限，重复是浪费。
- **「纠结票」**：加了它会让运营者在选风格时「更难选」，而非「更易选」→ 否决。新风格价值在于「简化决策」，不是「增加分支」。

### 「扩」还是「不扩」的决策建议
| 判断 | 结论 |
|---|---|
| 5 问全过 + 无否决 | 值得纳入，按「登记三件事」落地 |
| 1-2 问不过、无否决 | 先以「变体」或「实验栏目」试跑，观察后再定 |
| 任一否决票触发 | 明确不纳入（或放弃升级） |

## 四、风格命名与登记规范

### 命名规范（新增/升级风格统一遵守）
- **一眼懂**：名称用运营者/编辑能秒懂的中文或大众熟词（如「校园」「国潮」「波普」「敦煌青绿」），避免生造抽象词（如「羽化风」「张力系」会把调用方绕晕）。
- **带母系（若为子系）**：若还是变体，命名体现归属（「治愈手绘（手账子系）」「清水森系（日系子系）」），方便运营判断何时用。
- **避免重复**：不与现有风格、变体、模块、内容类型名字撞名；撞名会造成检索混乱。
- **一风格一名**：一个风格只保留一个正式名，别名（如有）记在条目备注，不另开条目。

### 命名示例对照（好名 vs 差名）
| 好名（一眼懂） | 差名（绕晕） |
|---|---|
| 波普艺术 | 「网点冲击流」 |
| 治愈手绘 | 「软线感应力工」 |
| 敦煌青绿 | 「苔色美学」 |
| 运动活力 | 「竞技竞速态」 |
| 清新森系 | 「绿波呼吸系」 |
> 通则：**用运营者熟悉的词，别发明新行话**。名字是给「选的人」看的，不是给「设计专利」看的。

### 登记三件事（新增任何风格都必须落）
1. **建条目文件**：按 `index-style` 规定的统一结构写全（气质/适用/色板/标题/模块/花纹/文案/禁忌/混搭/封面/深色/个性化留白）。
2. **更新索引**：在 `index-style` 的顶层清单（或变体清单）登记一行：文件名、一句话定位、调用时机。
3. **补矩阵**：把新风格写进「风格选择」条目里的 16 风格矩阵（加一行「内容类型→该风格」），保证选风格时能被找到。

### 变更记录
- 每次新增/升级/废弃一种风格，在风格库的变更说明里记一笔：日期、改动类型（新增/升格/废弃）、原因、涉及的条目与索引文件。避免风格库「静默长草」无人维护。

## 五、周期维护清单（隔段时间过一遍）

| 周期 | 做哪几件事 |
|---|---|
| 每季度 | 查变体使用频次，看有无该升格/该废弃的；抽查命名是否仍「一眼懂」 |
| 每半年 | 审一遍「扩充评审 5 问」；核对索引 / 矩阵是否与条目一致 |
| 每年 | 大清理：删长期无使用的风格 / 变体，重审库规模上限 |

## 六、常见错误与修正

| 错误 | 现象 | 修正 |
|---|---|---|
| 见样就加 | 库膨胀、选风格纠结 | 过「扩充评审 5 问」，任一否就缓 |
| 变体急着升顶 | 仍靠母风格才成立 | 先过「升格门槛 A+B+C」再升 |
| 命名抽象 | 「张力系」没人懂 | 改成能秒懂的大众名 |
| 加了不登记 | 索引/矩阵没它，调用方找不到 | 新增必做「登记三件事」 |
| 无人维护 | 条目过期、色板乱 | 设变更记录 + 定期审一次库 |
| 静默废弃 | 风格下架了没同步索引 | 废弃也走「变更记录」，更新索引/矩阵 |

## 七、FAQ（常见疑问）

**Q：现有 16 顶层 6 变体是不是已经够了？**
A：密度已接近成本边界。新增的风格必须靠「独立度 + 决策提效」硬扛，否则宁可复用 / 混搭（见「风格混搭」），不轻易扩库。

**Q：把变体升顶会不会反而废掉母风格？**
A：会稀释一点的「子系」库存，但若升格门槛 A+B+C 全过，说明它已「独立走红」，升格对运营是加码而非互相打架。母风格仍管它的份。

**Q：命名要不要带英文？**
A：以中文为主、大众熟词为准，别为「洋气」加没必要英文名的风格名（如「Art Deco」改成「装饰艺术」更易懂）。

**Q：一个变体既符合升格、又符合扩充某新风格，怎么判？**
A：两路径共用同一套「独立度 + 决策提效」原则。优先走「升格」——它从既有变体升顶，比从零造一个新风格成本低、也更贴合库的演化。

**Q：新风格团队讨论不定，拖久了怎么办？**
A：设一个「评审截止」——本月内有人能给出可用它的 8 篇实证，就走正常评审；否则先作「实验栏目」跑，不给它占正式库位。别让「要不要加」悬而未决拖垮库的稳定。

## 八、废弃一个风格的干净收尾（不要静默删）

真要废弃一个风格 / 变体，别只删条目了事，走完 4 步：
1. **再确认**：按周期维护确认它长期无使用（不是单季冷门）。
2. **迁引用**：把仍引用它的「风格选择」矩阵、其他条目、栏目模板里的指向改到「替代风格」。
3. **记录废弃**：在风格库变更记录里写「废弃日期 + 原因 + 替代方案」。
4. **留档**：不硬删历史文件，移到 `legacy`/归档区，供回查，避免信息断裂。

> 废弃和新增一样影响选风格决策，所以和登记一样要走流程、留记录，绝不「悄悄删」。

## 九、个性化留白（按账号自定）

- **库的规模上限**：本条目给了阈值参考，但「18 顶层 + 变体」已是密度边界；账号体量与运营人力决定上限，团队自行把握。
- **升级优先级**：哪些变体优先升格，看账号内容侧重（如亲子内容多的号优先把「治愈手绘」升格），是运营判断。
- **维护周期**：多久审一次库（季度/半年），是团队流程决策。
