# 跨平台视觉适配（style-guide-platform）

> 定位：在用户确实需要多个平台版本时，检查同一份内容的封面、图表、字号和组件能否在目标载体正确呈现。

选材、标题、段落组织与结尾由 `文本/写作` 知识负责：按任务需要读取 `writing-purpose`、`writing-structure`、`writing-campus`、`writing-product`、`writing-explain`、`writing-story` 或 `writing-review`。视觉风格只决定呈现方式，不绑定文章结构、篇幅或语气。

## 先确认载体

记录本次目标平台、实际发布界面、可用的正文排版能力、图片比例和导出格式。尺寸与字段限制以本次界面或已核实的规则为准，不按平台名称预设篇幅、读者耐心或修辞方式。

## 可以复用的视觉内容

- 账号主色、辅助色、字重层级和线条语言可以作为共同识别基础。
- 极简保留清楚的层级与留白；明丽风格保留有主次的撞色、线饰和图像表现。风格强度依据用户要求与实际可读性选择。
- 国潮与敦煌可保留红金墨或青绿描金，日系与森系可保留米纸与自然色，商务与科技可保留深蓝、青与清晰线条。
- 图片、图表和来源说明可以复用，但需检查裁切后是否丢失对象、坐标、单位或署名。

## 需要随载体调整的部分

| 载体条件 | 视觉处理 |
|---|---|
| 支持正文层级与组件 | 使用本次引擎支持的标题、列表、引用等功能 |
| 仅支持有限文本格式 | 保留信息层级，撤掉不支持的外观效果 |
| 需要图卡或轮播 | 依据实际信息分组安排画面，并提供可读文字与出处 |
| 需要视频画面 | 检查字幕、图表和重点标记在实际播放尺寸下可读 |
| 封面会以不同形状裁切 | 分别检查横版、方形或竖版安全区，不拉伸主体 |

图卡数量、叙述顺序、开头与行动信息由内容需要决定。转换载体时保留必要条件、证据和完整含义，不为视觉紧凑截掉限定信息。

## 交付检查

核对正文、封面、摘要与落地页事实一致；检查截断、裁切、来源和链接。只声明实际完成的导出或预览，不把一个平台的成功预览当成其他平台已验证。

实际输出以 `engine-write-protocol` 的 v2 语法为准。色板与版式分别选择；正文容器按 `fill` 选择无底或浅底，横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构，允许协议支持的小记号与插画内部填色。保持零 emoji、零图标字符、零渐变、零阴影。素材沿用有效引用，生成需求使用协议支持的 `[[img]]` / `[[deco]]`；旧 HTML/CSS 片段仅用于理解视觉，不作为桌面输出语法。
