# 按信息关系组合模块（module-guide-combos）

> 定位：把已经成立的正文关系呈现清楚，不用组件组合生成整篇文章。

选材、标题、段落组织与结尾由 `文本/写作` 知识负责：按任务需要读取 `writing-purpose`、`writing-structure`、`writing-campus`、`writing-product`、`writing-explain`、`writing-story` 或 `writing-review`。视觉风格只决定呈现方式，不绑定文章结构、篇幅或语气。

## 从信息用途选择

| 信息需要 | 可选组件 | 组合时检查 |
|---|---|---|
| 展示操作依赖 | steps、checklist | 顺序是否来自实际操作，条件与结果是否保留 |
| 比较对象 | table、spec、card | 同一维度能否对齐，单位与条件是否明确 |
| 展示事件或经历 | timeline、image、quote | 时间、画面与引语是否来自材料 |
| 呈现例证 | case、image、table | 证据是否与相关论述相邻 |
| 帮助参与或购买 | contact、price、miniapp、cta-end | 信息与入口是否真实可用，是否符合本篇目的 |
| 提供背景或来源 | disclaimer、reading、footer | 说明与对应事实是否关联、是否容易找到 |

表中是选择关系，不是顺序清单。没有相应材料或读者需要时，就不插入组件。标题、关注条、目录、行动号召、页脚均按实际用途决定，不构成每篇必配组合。

## 视觉衔接

同类信息采用一致的标题层级、边线和对齐方式。保留块距 16px、正文行高 1.75、卡内文字距边框至少 12px 等已有排版基准；具体输出交给当前引擎。标题与内容、图与图注应能直接对应。

配色和版式分别选择。明丽稿可加强标题尺度、线饰和图像，极简稿可主要使用留白与文字层级；两者都不改变原文的事实与论证顺序。

## 复核

查看组件是否帮助理解、比较、定位或行动，是否把一个连续意思割裂。遇到内容重复先回到写作知识调整材料，遇到拥挤先检查间距、宽度和组件选择，不为填满模板增加段落。

实际输出以 `engine-write-protocol` 的 v2 语法为准。色板与版式分别选择；正文容器按 `fill` 选择无底或浅底，横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构，允许协议支持的小记号与插画内部填色。保持零 emoji、零图标字符、零渐变、零阴影。素材沿用有效引用，生成需求使用协议支持的 `[[img]]` / `[[deco]]`；旧 HTML/CSS 片段仅用于理解视觉，不作为桌面输出语法。
