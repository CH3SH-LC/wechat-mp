# 目录 / 索引区（module-toc）

> 定位：长文开头的一张「地图」，用导航大纲告诉读者这篇讲什么、有几大块、能跳着读到想要的点，降低长文的放弃率。
> 调用时机：**长文专用**（约 1500 字以上）、干货教程、系统性报告、合集 / 盘点类内容。短文（≤800 字）不用目录，目录本身会成为负担。

## 一、可用写法与语法

目录区需要「逐条列出章节名 + 序号」，排版语法里没有专用目录标签，可用**列表 + 分割线装饰**组装，或用内联样式做更精致的卡片。

**排版语法（简单列表式，交给排版工具）**：

```markdown
::: card 本期内容
- 01 · 为什么读书慢
- 02 · 三遍阅读法
- 03 · 如何做笔记
:::
```

**排版语法（条目编号式，带序号文字）**：

```markdown
::: iconlist
- 01 · 为什么读书慢
- 02 · 三遍阅读法
- 03 · 如何做笔记
:::
```

**排版语法（最简无框，直接列表）**：

```markdown
- 01 · 为什么读书慢
- 02 · 三遍阅读法
- 03 · 如何做笔记
```

**内联样式——编号卡片式（推荐，稳定）**：

```html
<section style="background:#fff;border:1px solid #eee;border-radius:12px;padding:16px 18px;margin:0 0 16px;">
  <p style="font-size:14px;font-weight:bold;color:#2f6fed;margin:0 0 10px;letter-spacing:1px;">目录</p>
  <p style="font-size:14px;color:#444;line-height:1.9;margin:0;"><span style="color:#2f6fed;font-weight:bold;">01</span>　为什么读书慢</p>
  <p style="font-size:14px;color:#444;line-height:1.9;margin:0;"><span style="color:#2f6fed;font-weight:bold;">02</span>　三遍阅读法</p>
  <p style="font-size:14px;color:#444;line-height:1.9;margin:0;"><span style="color:#2f6fed;font-weight:bold;">03</span>　如何做笔记</p>
</section>
```

**条目命名规则（重要）**：

- **与正文小标题逐字一致**：目录条目名必须和后面每个章节的 `##` 标题文字完全相同，才能形成「预告 → 兑现」的呼应。改正文标题就要同步改目录。
- **简短具体**：每条 ≤12 字，写「事 / 方法」而不是「这一部分我们将要讨论的内容」。
- **动词或关键词开头**：干货条目用「如何做 X」，观点条目用「为什么 X」。

## 二、双模式表现

| 维度 | 文字类 | 宣传类 |
|---|---|---|
| 容器 | 细边框白卡 / 无框轻卡 | 白卡 + 顶部纯色顶条 + 彩色序号 |
| 序号颜色 | 强调色蓝 `#2f6fed` | 主题纯色（橙/青/紫）或彩色圆底 |
| 封面称谓 | 「目录」「本期内容」 | 「内容导航」或带栏目英文标注 |
| 语气 | 平实列出章节名 | 可加一句价值承诺（「一篇看懂 X」） |
| 是否可跳 | 微信正文无法锚点跳转，目录本质是「阅后预览」 | 同左——别误导读者以为能点击 |

> 说明：微信正文**不能真跳转**，目录是「先放预览、正文再出现对应小标题」的呼应式导航，不承诺点击跳转。想提供可跳转入口，用小程序 / 阅读原文或评论区置顶。

## 三、样式变体（≥3 种）

**变体 A｜简单列表（最短）**——无框，垂直编号条目。
参数：每行 14px、`#444`、`line-height:1.9`；序号 `color:#2f6fed;font-weight:bold` 前置；块 `margin:0 0 16px`；分隔可用一条 `<p style="height:24px">` 或细线。成本最低、极简单风格首选。

**变体 B｜编号卡片（推荐）**——白底细边框，顶部表头 + 序号。
参数：`background:#fff;border:1px solid #eee;border-radius:12px;padding:16px 18px`；表头 14px 主色加粗、下 `margin:10px`；每条 14px、`#444`、`line-height:1.9`；`margin:0 0 16px`。通用性最好。

**变体 C｜带页码式（连载/特辑感）**——左数字、右侧可加「篇幅/页码」标注。
参数：每条 `display:flex;justify-content:space-between`；左 `01` 主色加粗 + 章节名，右 12px 灰字标注（如「第 2 节 / 3 分钟」）；条目间用 `border-bottom:1px dashed #eee` 分隔；padding `12px 16px`。适合连载标注「上 / 下」进度。

**变体 D｜彩色纯色序号（宣传 / 报告）**——序号用纯色圆底白字。
参数：`<span style="display:inline-block;width:24px;height:24px;line-height:24px;text-align:center;border-radius:50%;background:#e56b2f;color:#fff;font-size:12px;font-weight:bold;">1</span>` 前缀；右接章节名 14px；块白卡 + 顶部 `border-top:3px solid` 主色。宣传 / 报告强化「进度感」。

**变体 E｜图案点缀卡（轻松 / 亲子 / 生活）**——逐条前置花草植物图案。
参数：用 `::: iconlist` 或每条前置 `![小草](art://sprig-grass)`；配合变体 B 卡片底；图案用 art:// 植物资产渲染，跨端显示一致。适合轻松主题。

## 四、使用时机与位置

- **位置**：紧跟页眉 / 关注条之后、正文第一章第一节**之前**的第一屏，让读者先看到全貌再进入正文。
- **场景**：干货教程（步骤多）、长报告（板块多）、合集 / 盘点（条目多）、连载长文（本期分节）。
- **与正文小标题的呼应**：目录条目名**必须与后面每个章节的标题文字一致**（逐字对应），形成「预告 → 兑现」的确认感；若正文改了小标题，目录同步改，绝不各写各的。
- **目录条目数建议** **3–7 条**；超过 7 条说明该拆成多篇或合并章节。
- **配合「章节标题」模块**：正文每个 `##` 用「章节标题」条目的样式呈现，并与目录条目逐字对应；有「章节分隔宣传页」时页码可与目录的页码体系呼应。

## 五、风格适配

- **国潮红金墨**：卡片底 `#faf3e7`、表头金 `#b8860b`、序号金 / 红；章节名墨色 `#3a2f26`；可加细小金色分隔线。
- **科技蓝紫**：变体 D 纯色序号（`#3f5bc2`），白卡细边框 `#e6eefb`，表头可加英文小标（CONTENTS）。
- **校园青春**：变体 B + 花草图案点缀（`![小花](art://blossom-branch)`），序号高饱和青 `#00b8a9`，卡片圆角 12px 更柔。
- **极简黑白**：变体 A 无框纯文字；序号用灰 `#999` 或 `#1a1a1a` 加粗，不出现任何色块与边框。
- **商务 / 机构报告**：变体 D 纯色序号 + 白卡，表头加英文小标，条目排列整齐，显得专业。

## 六、间距与尺寸（遵守硬规范）

- 目录卡与上下块距：**16px**（`margin:0 0 16px`）。
- 卡内 padding：`16px 18px`；表头与首条之间 `10px`。
- 条目行高 **1.9**（略高于正文 1.75 以利扫读）、字号 14px。
- 条目之间可用 `border-bottom:1px dashed #eee`，控制条目间距约 8–10px，不用大空段。
- 目录之后接正文，回落 16px 块距。
- 若目录在关注条之后，两者各自 `margin:0 0 16px`，中间不加额外空段。

## 七、密度限制

- **一篇最多 1 个目录区**，放在开头；不在中段再插第二个目录。
- 条目 3–7 条；
- 目录本身形态统一（选一种变体），不与「往期回顾」混排在同一卡片里。
- 若已用章节分隔宣传页（见「章节分隔宣传页」条目），数据较长的篇章索引可与每个分隔页的页码呼应，但别逐页都做大目录。
- 「目录」本身作为一个块，在一屏内除关注条外不再叠第二个大块（否则首屏全是导航没有正文）。

## 八、常见错误

- **反例**：目录名「三遍阅读法」，正文小标题却是「三步走向阅读自由」——预告与兑现对不上。**正解**：目录条目与正文小标题**逐字一致**。
- **反例**：条目写到 10 条以上，目录比正文还吓人。**正解**：3–7 条，超了合并章节或拆篇。
- **反例**：目录承诺「点我可跳转」，微信正文却锚定不了，读者点了没反应很失望。**正解**：明示是预览导航；要真跳转走小程序 / 阅读原文。
- **反例**：目录放正文中间（第一章开头），读者早滑到那了，前面没看到地图。**正解**：放第一屏（页眉 / 关注条之后）。
- **反例**：目录每行用超大空段隔开，把第一屏撑满却没内容。**正解**：条目紧凑 `line-height:1.9`，第一屏留出正文开头。
- **反例**：目录条目名拿正文完整段落当标题，每条巨长折行。**正解**：≤12 字，正文再展开。

## 九、示例（骨架，标注可替换处）

```markdown

::: card 本期内容
- 01 · 为什么读书慢
- 02 · 三遍阅读法
- 03 · 如何做整理
- 04 · 一个常见误区
:::

正文第一章（可替换，标题用「01 · 为什么读书慢」对应）……
```

## 十、个性化空间

- **表头称谓**：可换「目录」「本期内容」「本期导航」「CONTENTS」「读完你将掌握」；判断依据：选最能提升预期的那句（干货号用「读完你将掌握 X」更有价值感）。
- **条目命名颗粒度**：写「02 · 三遍阅读法」还是「02 · 三遍阅读法（含例子）」；判断依据：条目名与正文小标题严格一致的原则不变，但可统一加「（含例子/附模板）」等后缀，判断依据是读者需不需要这种提示。
- **序号颜色 / 形态**：换主色或纯色圆底；判断依据账号 VI，与页眉、关注条同色体系。
- **是否带页码 / 篇幅标注**（如「第 1 节」「3 分钟」）：判断依据是否连载 / 读者是否在意阅读投入，特辑和连载号建议带。
- **放还是不放**：核心判断依据是**字数与结构复杂度**——≥1500 字且有 ≥3 个清晰章节才值得放；短文放了反而拖拖拉拉。
- **条目间是否加分隔线**：判断依据信息密度——条目较密（5+ 条）加分隔线更清爽，条目少可省。
