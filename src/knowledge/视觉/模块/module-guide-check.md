# 模块清晰度检查（module-guide-check）

> 定位：定稿后检查组件是否帮助理解，是否造成遮挡、重复或阅读中断。

选材、标题、段落组织与结尾由 `文本/写作` 知识负责：按任务需要读取 `writing-purpose`、`writing-structure`、`writing-campus`、`writing-product`、`writing-explain`、`writing-story` 或 `writing-review`。视觉风格只决定呈现方式，不绑定文章结构、篇幅或语气。

## 内容与模块

- 每个组件有可说明的用途，内部内容来自本次材料；装饰不替代事实。
- 标题层级、图注、来源与对应内容一致，没有孤立或错配。
- 连续论述没有被无关卡片割裂；同一信息不因气泡、小结和结尾反复出现。
- 目录、行动入口和延伸阅读按实际需要出现，不为凑成组合添加。

## 视觉与可读性

检查字号、颜色、边线与对齐能否区分主次；明丽稿可丰富，极简稿可安静。装饰密度依据实际可读性，不按文章字数分配组件数量。同类信息采用一致表现，避免无意义换样式。

| 项目 | 既有排版参考 |
|---|---|
| 块间距 | 16px |
| 正文与块内行高 | 1.75；代码块 1.6 |
| 卡内文字留白 | 至少 12px |
| 标题上下间距 | 28px / 12px；小标题 24px / 10px |
| 图片上下间距 | 12px |
| 分隔线上下间距 | 24px |

重点不能仅靠颜色识别，可配合字重、字号、标签等信息通道。具体外观以引擎为准，不以缩小文字或删掉必要条件解决溢出。

## 功能与交付

检查链接、图片引用、跳转目标和来源；仅外观像按钮不代表有功能。查看实际导出时是否裁字、越界、出现空白或图片变形。设备预览与发布状态只记录已实际完成的部分。

发现问题后按原因修复：布局问题调整组件与间距，内容问题回到写作知识。修改后复核受影响的相邻内容。

实际输出以 `engine-write-protocol` 的 v2 语法为准。色板与版式分别选择；正文容器按 `fill` 选择无底或浅底，横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构，允许协议支持的小记号与插画内部填色。保持零 emoji、零图标字符、零渐变、零阴影。素材沿用有效引用，生成需求使用协议支持的 `[[img]]` / `[[deco]]`；旧 HTML/CSS 片段仅用于理解视觉，不作为桌面输出语法。
