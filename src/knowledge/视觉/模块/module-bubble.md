# 重点气泡与主题图文框（module-bubble）

> 当前桌面引擎指南。气泡由本地引擎渲染；正文只写 v2，不手写 HTML、CSS、SVG 或历史 art:// 底图。完整语法与素材规则见 `排版引擎/engine-write-protocol.md`，冲突时以该协议和当前实现为准。

## 内容先保持完整

气泡用于组织相关说明、发言、规则或重点，也可以容纳完整的长段落和对应照片。用户提供大部分原文、只给简单视觉方向时，保留原文信息、自然段、事实、引语及篇幅尺度；让容器适应内容，不把原文提炼成几句摘要来凑气泡。

章节数量、气泡数量、照片和插画数量没有全文配额。一次发言可以很长，一段叙事也可以不加框；按原文关系决定是否分组，不按字数或屏数强行切块。必要条件、原因、结果及人物发言保持相连，标题不重复正文第一句，也不补造材料未给的说话者。

## 可执行写法

```v2
[[theme:校园]]
[[boxes:票笺]]

> [!NOTE] 原文已有的发言标题
> 在这里放该发言的完整第一段，保留其必要解释。
>
> 这里继续保留第二段，不为迁就框高缩成一句结论。
```

示例仅说明语法，不提供本稿事实。首行可写气泡标题，也可只写 `> [!NOTE]` 省略标题；章名已说明内容时不再补重复题签。后续每一行以 `>` 开头，空段写独立的 `>`。每个原有自然段完整放在一处，不抽出首句作导语。框内原图使用同样的 Markdown 图片语法并加 `>` 前缀，地址必须照抄实际附件清单或读取工具返回的 `local-image://` URI，不能编造 ID。图片与相关段落保持相邻，不替换为装饰或生成插画。

| 语义 | 用途 |
| --- | --- |
| `NOTE` | 中性说明、背景或需要分组的内容 |
| `TIP` | 可执行的方法和技巧 |
| `WARN` | 需要注意的条件或容易出错的地方 |
| `DANGER` | 材料中确实存在的禁止事项或严重风险 |
| `KEY` | 本文已有的重要结论或信息 |

语义由内容决定，不为获得某种颜色把普通发言写成警示。主题预置用 `label=none` 隐去机械的“提示／注意／重点”小标签，由原有标题和正文表达含义。材料本身的风险提示文字仍完整保留；确需单独显示语义标签时可明确设置 `label=eyebrow` 或 `chip`。

`[!NOTE]` 等是引擎识别气泡的结构声明，并非需要删掉的可见语义标签；无标题的气泡也必须保留这行。只留下普通 `>` 会改成引用样式，不能兑现纸面气泡。文案复核仍使用同一份引擎协议，保留有效的主题和组件声明。

## 先定全文主题，再定局部容器

`[[theme:…]]` / `[[palette:…]]` 管配色，`[[boxes:…]]` 管结构、框线、底色浓度、字体气质和装饰。配色不自动绑定版式；无 `boxes` 声明时仍使用默认无底编辑感。

用户要“更花、更精致”时，先选能贯穿题头、章节、框体和分隔的主题语言。花枝、票孔、缎带应在各个位置改变尺度、保留同一笔触与颜色关系，不能只给原来的矩形提示卡换颜色或加一枚小图标。装饰围绕框边和题头建立结构，正文保持安静、宽敞的阅读区。

| 选择 | 当前效果与用途 |
| --- | --- |
| `[[boxes:花笺]]` / `[[boxes:botanical]]` | 花枝纸面主题；框体边缘与题头、章标、分隔使用同族植物线饰，适合节庆、自然、文化活动 |
| `[[boxes:票笺]]` / `[[boxes:ticket]]` | 票券主题；票孔与票面分界贯穿信息框和结构节点，适合校园市集、活动资讯、游园与展览 |
| `[[boxes:缎带]]` / `[[boxes:ribbon]]` | 缎带题头与线饰主题；适合校园报道、纪念、实践与仪式性文章 |
| `[[boxes:题签]]` | 跨细边框的题签，浅色底、8px圆角、宽松内距；适合发言、项目介绍、完整说明 |
| `[[boxes:纸笺]]` | 双层纸框、浅暖纸色、衬线题头、宽松内距；适合章节正文、规则段和图文单元 |
| `shape=botanical` / `ticket` / `ribbon` | 仅选择气泡的花笺、票笺或缎带骨架；与同名 `ornament` 搭配才能形成对应的全文主题 |
| `shape=tab` / `panel` | 跨边界题签 / 双层纸框；标题可换行，内容高度随完整段落和图片展开 |
| `shape=rail` / `cap` / `bracket` | 左竖线、顶部题头或开放角括号；适合较轻的信息分组 |
| `shape=medal` / `index` | 左侧徽章或自动序号、右侧正文；窄屏长文需确认剩余阅读宽度 |
| `shape=hanger` / `side` / `quote` | 侧悬标签、竖排标签或引文；不能凭视觉效果虚构引语 |
| `fill=none` | 不铺内容底色；用户明确极简、无底色时采用 |
| `fill=tint` / `wash` / `paper` | 语义色极浅底 / 稍深浅底 / 极浅暖纸色；不是深色反白面板 |

花笺、票笺、缎带预置同时设置对应的 `shape` 和 `ornament`，标题、横幅、章节与分隔因此自然呼应；它们默认 `size=17;label=none;mark=none;deco=none`，正文按17px舒展排入。内置主题花饰仍会出现，`deco=none` 只关闭额外胶带、引号等叠加饰件。预置可覆写，如 `[[boxes:花笺;fill=none]]` 保留主题形态、关闭内容底色。

同类信息使用一致的框线、内距和标题关系，章节介绍与成员发言可以有清楚的分工。中途的 `[[boxes:…]]` 从该行开始生效，每条从默认值重建；需保留的轴再次写明，不依赖上一条累积。局部需要更轻的容器时，可写 `[[boxes:票笺;shape=rail;frame=line]]`，保留票笺主题的章节与分隔，减轻当前气泡框体。

## 精致感来自整体关系与细节

- 让题头负责建立主题，章节负责引导，框体负责承载，分隔负责连接。不同角色可以有不同轮廓，不把标题、题签、标签和正文每一层都套成完整大圆角框。
- 细框、浅底和纸色都可用；双框应带来明确的纸面层次。已有清楚的主题框体时，不再机械套一层边框、补一行语义标签、添一枚无关角标。
- 装饰要足以辨认主题：花枝有方向与簇组，票孔沿票边组织，缎带与题头对齐。孤立的短线、小圆点或小图标散落在大空白中，不等于完成主题设计。
- 题头与章标周围可较丰富，长正文区降低纹样强度。框内正文不小于相邻普通正文，不用窄徽章栏压缩长文；长标题正常换行，照片与正文共享稳定内边界。
- 内置花笺、票笺、缎带、题签、纸框、线饰及 `mark=…` 可复用，无需额外素材接口或生成调用。不要为每节、每张气泡重复画同一种装饰。
- 确需独立角饰时才按引擎协议先定义 `[[asset:bubble|素材ID|用途]]` 或 `[[deco:名称|说明]]`，再以 `> [!NOTE|同一ID或名称] 标题` 引用。显式内置 `mark`（含 `none`）优先；不臆造素材 ID，不手写内部 `::: art deco`。
- 保留零 emoji、零图标字符、零渐变、零阴影。不生成深色反白正文面板，不把完整正文栅格化进插画来冒充可编辑气泡。

## 检查与修改

在375px窄屏预览中同时检查题头、正文中段和结尾：主题是否持续呼应，长标题是否自然换行，长段落是否连贯，图片是否可见且未被压成角饰，边框与题签是否连接清楚，装饰是否挡字。章节与紧随其后的悬置题签之间须有实际留白；分隔装饰及其上下空白不应形成无内容的大空档。检查底色与正文对比度，并保留真实微信预览/发布链路的独立验证状态；本地渲染通过不等于后台粘贴已经验收。

视觉调整只改用户授权范围。只换气泡样式时保留正文、原图和素材引用；局部改稿不重排范围外内容。内容完整性、语法可解析、375px可读与真实图片引用分别核验，不能拿视觉通过替代原文保留。
