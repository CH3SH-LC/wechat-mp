# 方法论·真机预览总检查单与无障碍基线（module-guide-mobile）

> 定位：发布前最后一次"真机验收"——在 iOS、安卓、PC 上分别预览一遍视觉与交互，并用一份无障碍基线确认所有读者（含色盲、低视力、老年用户）都读得舒服。这是所有排版工作的最后一道闸门。
> 调用时机：内容、排版、模块全部定稿后，正式发布前。它跨越所有模块，是对整篇文章的终检。

## 一、真机预览：为什么要三端都看

微信正文在不同端渲染略有差异：iOS 与安卓的字体、行高、卡片渲染、深色模式表现不同，PC 端更宽。**只在一个端看"挺好"并不可靠**，发布前至少三个端各过一遍。

### iOS（iPhone/iPad）验收清单
- [ ] 正文字号是否达标、行高 1.75 是否正常，卡片不挤压文字？
- [ ] 卡片/气泡圆角、细边框正常，没有渲染残缺？
- [ ] 图片清晰、不拉伸变形、无下方 3px 空隙？
- [ ] 强调色能看清，重点没被浅底/浅字吞掉？
- [ ] 深色模式下仍可读（重点不靠深底浅字硬撑）？

**iOS 补充核对（更细）：**
- [ ] 深色模式下背景、卡片、文字配色整体协调，无发白/发灰刺眼区块？
- [ ] 小字号备注在深色下仍能看清（深色背景上的浅灰小字尤其注意）？
- [ ] 白底图片在深色背景里没有被"黑边"包围、像缺一块？（加浅色内边或留白）
- [ ] 文字内边距充足：文字离卡片/图片边缘 ≥12px，不贴边？
- [ ] 大、小标题层级清晰，字号/字重变化一眼可辨？

### 安卓验收清单
- [ ] 字体渲染是否正常（部分安卓中文字体行高略不同，行距不塌不叠）？
- [ ] 老旧安卓客户端是否正常显示（纯色卡/细边框是否回退正常，卡片有无错位）？
- [ ] 低端机/弱网下图片是否显示正常占位/渐进加载，文字可读？
- [ ] 桌面/平板宽度（横屏）下卡片是否拉伸变形、行太长难读？

**安卓补充核对（更细）：**
- [ ] 系统放大字体后，文字清晰不变糊、行高仍留得住？
- [ ] 不同安卓厂商（小米/华为/OPPO/vivo）字体渲染略不同，是否有样机/截图核对？
- [ ] 超长关键词/数字（手机号、日期、超链接）在窄屏上不断行错位、不被挤出卡片？

### PC（微信网页/桌面端）验收清单
- [ ] 超宽屏下正文是否被拉得过长（建议加最大宽度或分列），行末难读？
- [ ] 卡片在宽屏下是否被拉伸、内文被抻开？
- [ ] 链接/小程序跳转在 PC 端是否可点正常？
- [ ] 目录/锚点跳转在 PC 端是否有效？

**PC 补充核对（更细）：**
- [ ] 极端窄窗（窗口拖很窄）下卡片分列不错乱、文字不被裁切？
- [ ] 悬停链接有明确反馈（变色/下划线/手型），读者一眼知道"可点"？
- [ ] 长文多屏滚动时，目录/锚点能准确跳到对应章节？

## 二、三端通用验收（每端都要过）

- [ ] 所有模块间距符合硬规范（16px 块距、1.75 行高、卡内 padding ≥12px）。
- [ ] 所有图片清晰、用微信上传 URL、附了图注（有说明性文字）。
- [ ] 每个可点击物（小程序、链接、关键词入口）真实可达，无死链。
- [ ] 关键信息（价格、时间、地址、日期）与当前实际一致、前后文不冲突。
- [ ] 深色模式下整体可读（见下文无障碍）。

**通用补充核对：**
- [ ] 长图、长列表、多图间距触到 16px 规范，读起来有节奏、不压成一片？
- [ ] 所有可点击物真实能打开，尾部路径/参数无残缺？
- [ ] 首屏前有清晰的小标题/目录，读者进来自知"接下来讲什么"？

## 三、降级兜底总原则：白底 + 实线 + 圆角可读

老旧客户端、弱网、低端设备、低饱和屏上，作者精心做的纯色块/装饰可能失效或回退。**兜底原则**：即使所有装饰失效，只要文章还保持"白底卡片 + 一条实线边框 + 常见圆角 + 足够字号对比"，就依然清晰可读。

- 关键信息与**正文永远用足够对比**的深字浅底（正文深灰 `#4a4150` on 白/浅底），不把重要信息压在只靠低对比纯色表达。本规范**不推荐渐变**，统一纯色 + 细边框，老客户端回退为纯色/细框仍可读。
- 纯色块/装饰**只做锦上添花**：给关键纯色块同时配一个细边框（`border:1px solid`），老客户端回退成白卡细框仍可读。
- 重要强调用**双通道**（颜色 + 字号/字重/底色），不单靠一重（转义见下文无障碍）。

**判断兜底是否成立的快速自测：**
- [ ] 把文章里所有纯色块、装饰在脑中"抹掉"，剩下的白底 + 实线边框 + 圆角仍能否讲清整篇？
- [ ] 关键信息、价格、时间、地址，是否不依赖任何纯色底也能一眼读到？
- [ ] 用一台老旧安卓/老人机（或"预览缩略图 + 离远看"）再预览，是否仍完整可读？

## 四、无障碍硬底线（每个读者都要能读）

无障碍不是可选项，是对所有读者（色盲、低视力、老年、弱网用户）的平权。硬底线四条：

1. **正文字号**：正文 ≥ **14px**（建议 15-16px），小字备注 ≥ 12px。太小的字老年/弱视用户读不了。
2. **行高**：正文与块内文字 **≥ 1.75**，给足行间呼吸，避免行叠。代码块 1.6。
3. **对比度**：正文与背景对比 ≥ **4.5:1**（WCAG AA）。深灰 `#4a4150` on 白底 OK；灰色 `#999` on 白底对比不足（≈2.8:1），只用于不关键的小字备注，不用作正文/关键信息。
4. **不单靠颜色传信息**：所有"重点/警示/对错"不能只靠颜色标记，必须叠加**字号/字重/圆点形状/底色/文字**至少一个非颜色通道（色盲用户读得了颜色区分）。如"对错"用「对：/错：」文字前缀 + 绿色/红色双通道，"警示"用 WARN 气泡 + 圆点标记 + 颜色。

**对比度速查（重要）**：
| 前景 | 背景 | 对比度 | 可用性 |
|---|---|---|---|
| 深灰 `#4a4150` | 白 `#fff` | ≈11:1 | 可用 · 正文/标题 |
| 白 `#fff` | 橙 `#ff6b35` | ≈3.5:1 | 大字/粗体可，正文慎用 |
| 深灰 `#4a4150` | 浅橙 `#fff3ea` | ≈9:1 | 可用 · 卡内正文 |
| 灰 `#999` | 白 `#fff` | ≈2.8:1 | 不足 · 仅作备注 |
| 白 `#fff` | 紫 `#7a3cec` | ≈4:1 | 大字按钮可 |

**对比度速查（补充常用色值）**：
| 前景 | 背景 | 对比度 | 可用性 |
|---|---|---|---|
| 纯黑 `#000` | 白 `#fff` | ≈21:1 | 可用 · 最强，任何场景 |
| 深灰 `#333` | 白 `#fff` | ≈12.6:1 | 可用 · 正文/标题均可 |
| 中灰 `#666` | 白 `#fff` | ≈5.7:1 | 可用 · 正文可 |
| 浅灰 `#888` | 白 `#fff` | ≈3.3:1 | 仅大号/粗体，正文慎用 |
| 浅灰 `#aaa` | 白 `#fff` | ≈2.3:1 | 不足 · 不作为正文 |
| 深蓝 `#0d47a1` | 白 `#fff` | ≈7.8:1 | 可用 · 链接/强调 |
| 翠绿 `#1e7e34` | 白 `#fff` | ≈4.9:1 | 可用 · "对/通过"正文可 |
| 暗红 `#c62828` | 白 `#fff` | ≈5.9:1 | 可用 · "错/警示"正文可 |
| 白 `#fff` | 深蓝 `#0d47a1` | ≈7.8:1 | 可用 · 深底按钮用字 |
| 白 `#fff` | 暗红 `#c62828` | ≈5.9:1 | 可用 · 深底"失败"按钮 |

> 判断口径：正文与小标题 ≥4.5:1 为合格；大号/粗体文字可放宽到 ≥3:1；低于 3:1 的配色除非是"极次要装饰"，一律不用作承载信息。

**不用背数字，用眼睛判断的实战手法：**
- 手机亮度调到 50%、离眼 40cm，正文"看得很轻松"≈对比合格。
- 眯眼/调暗屏幕，重点文字还"冒出"背景≈够，混进背景≈不足。
- 彩色强调不确定时：转成灰阶（去色）看深浅差，有色差≈色盲也能区分。

## 五、字号 / 行高 / 间距 逐项硬规范速查表

以下数值是"本次排版必须满足"的硬下限，逐项对照，缺一即返工：

| 项目 | 硬规范 | 说明 |
|---|---|---|
| 正文字号 | ≥14px（建议 15–16px） | 低于 14px 大部分中老年/弱视读者读不动 |
| 小字号备注 | ≥12px | 仅用于图注、来源、版权等不关键信息 |
| 正文行高 | ≥1.75 | 行间留足呼吸，避免行叠压字 |
| 代码/公式块行高 | 1.6 | 等宽内容本身较密，行高 1.6 已够 |
| 标题层次 | 一篇文章 ≤2–3 级 | 层级过多读者会迷路 |
| 块与块之间距 | 16px | 段与段、卡片与卡片之间的标准呼吸距离 |
| 卡内文字边距 | ≥12px | 文字离卡片/图片边缘不能贴边 |
| 标题与正文间距 | 给足 8–16px 呼吸 | 标题下不紧贴正文 |
| 图片与正文间距 | 类似 16px 的呼吸 | 图片别贴死上下文字 |

**逐项自检勾选：**
- [ ] 正文字号取 14px 以上，关键段落用 15–16px？
- [ ] 每块文字都在 1.75 行高上下，没有 1.5 以下的"压缩款"？
- [ ] 段落、卡片、图块之间都保留 16px 呼吸，没有贴死挤成一团？

## 六、老年 / 弱视 / 色盲专项核对

- [ ] 正文字号 ≥14px，行高 ≥1.75？
- [ ] 所有重点用双通道（颜色+另一通道），仅靠角标/虚线色区的不用单色区分？
- [ ] 红绿色盲下"对/错、好/坏"仍可区分（用「对：/错：」文字前缀或明暗而非纯红绿）？
- [ ] 动效/闪烁、超链接明显可见（不是只看颜色下划线的隐形链接）？

**专项补充核对：**
- [ ] 老年朋友开"长辈模式/大字模式"后，字号放大排版不崩、卡片不失衡？
- [ ] 关键操作说明（转发、进小程序、参与）用文字 + 图例双表达，不纯靠符号？
- [ ] 全文无闪烁、频闪、快速滚动动效（避免引发视敏读者不适）？

## 七、不同读者群的适配清单

不同读者对排版的敏感点不同。按号的目标人群侧重核对：

### A. 老年 / 中老年读者
- [ ] 正文字号取上限（16px 起步），行高再宽松些（1.75–1.9）？
- [ ] 强调用大字号/加粗，不依赖细线角标这类"看不太清"的表达？
- [ ] 文字对比往最稳走：正文深灰/纯墨色 on 白/浅底，避免浅灰、细体？
- [ ] 操作步骤分点、标号清晰，一步一行，读完即会做？

### B. 年轻读者
- [ ] 信息密度可高一些，但标题/分段仍清爽，别让读者先"迷路"？
- [ ] 装饰（纯色块、圆角卡片、CSS 圆点标记）锦上添花，但不遮蔽核心信息？
- [ ] 这些年轻读者更爱深色模式，重点部分的配色在深色下仍成立？

### C. 视障 / 低视力读者
- [ ] 全文用系统"朗读/语音"能否顺畅读完？有没被拆分/吞掉的句子？
- [ ] 纯图片承载的信息（如"看这张表"）同时用文字/表格复述？
- [ ] 对比度全部 ≥4.5:1，关键信息加倍保守（≥7:1 更稳）？
- [ ] 没有"只有图片里才有"的价格、时间、地址，正文一定有文字版？

### D. 弱网 / 低端设备读者
- [ ] 图片量不过多、过重？核心信息不用等图也能读到？
- [ ] 正文先于图片显示（图文混排合理），弱网下先有文字骨架？
- [ ] 卡片、装饰降级成白底+实线+圆角后仍完整可读（见第三节兜底）？
- [ ] 大图有清晰的缩略/渐进显示，不会一直空白？

### 多读者群共存：一篇文章怎么同时满足两类人
一篇文往往兼有年轻与中老年读者，不必"牺牲一方讨好另一方"，按轻重排序即可：
1. **底线先护"最读不动"的人**：字号、对比、双通道硬底线按最弱势读者设，年轻读者不反感，老年读者读得动。
2. **装饰密度取中间值**：稍加纯色块/圆角即可，别堆到眼花，"宁少勿堆"。
3. **信息密度按"最赶时间"的人排**：标题、分段、小抄让扫读者 10 秒抓重点，细读者还有下文——先结论后过程。
4. **零牺牲通道**：文字版关键信息、图注、来源小字，任何读者都用得上，多多益善。

## 八、发布前终检流程（5 步，建议固化）

1. **定稿先行**：内容、模块、组合全部定稿，别在终检时才发现要大改。
2. **桌面纯文字通读**：先在编辑器以纯文本通读一遍，改错别字、确认逻辑、清空占位符（`{}`、`你的图片ID`、示例人名）。
3. **桌面预览排版**：用排版工具预览，核对间距、行高、卡片样式、装饰密度（对照《避免堆砌》清单）。
4. **真机三端预览**：iOS / 安卓 / PC 各过一遍上面的验收清单，重点看卡片渲染、深色模式、宽屏行宽。
5. **发布前终审**：回到发布页，对照"合规"（免责/溯源）、"模块匹配"（内容类型矩阵）、"间距硬规范"、"无障碍基线"四关，确认全过再点发布。

### 逐步执行拆解（每步做什么 / 看什么 / 怎么算过）

**第 1 步 · 定稿先行**
- 做什么：把文字、配图、模块组合、配色一次性锁死，本步**不做任何新增**。
- 看什么：还有没配好的图、没定的价格时间、没定的措辞。
- 怎么算过：信息全部定为最终稿，后 4 步只查不改大内容；要大改就回炉再回第 1 步。

**第 2 步 · 桌面纯文字通读**
- 做什么：编辑器切纯文本，从头读一遍，不看排版效果。
- 看什么：错别字、病句、前后逻辑矛盾、占位符残留（大括号、示例人名、占位图提示）、术语是否一致。
- 怎么算过：零错别字、零占位符、逻辑通顺，被转载/他人接手也不误会。

**第 3 步 · 桌面预览排版**
- 做什么：用排版工具预览整篇视觉效果。
- 看什么：间距（16px 块距 / 卡内 ≥12px）、行高 1.75、标题层级、卡片样式、装饰密度（对照"避免堆砌"）。
- 怎么算过：每块间距达标、层级清晰、装饰"锦上添花而不喧宾夺主"，无一处"挤、压、乱、堆"。

**第 4 步 · 真机三端预览**
- 做什么：真实用 iPhone、安卓、PC 三端过一遍验收清单。
- 看什么：卡片渲染、深色模式、宽屏行宽、字体差异、图片拉伸、内边距、死链。
- 怎么算过：三端各走完端内清单全勾，任一端有问题即未过，修完重测该端。

**第 5 步 · 发布前终审**
- 做什么：回到发布页，逐关核对，全部通过才点"发布"。
- 看什么：合规（免责、溯源）→ 模块匹配（内容类型矩阵）→ 间距硬规范（16px/1.75/≥12px）→ 无障碍基线（字号、对比、双通道、深色、兜底）。
- 怎么算过：四关全部打勾、无遗留待办才允许发布；缺任何一关都不发。

**流程小抄（逐关勾选）：**
- [ ] 第 1 步：内容真定稿，无再改的冲动？
- [ ] 第 2 步：纯文本读完，零错别字、零占位符、逻辑顺？
- [ ] 第 3 步：排版预览核对完，间距/行高/层级达标？
- [ ] 第 4 步：iOS / 安卓 / PC 各过一遍，端内清单全勾？
- [ ] 第 5 步：合规、模块匹配、间距硬规范、无障碍基线四关全过？

**终检发现问题的处理原则：**
- 问题分两类：**错字/占位符**（改完重走第 2 步）与**排版/配色/渲染**（改完重走对应端预览）。修完哪里就从那一步重过，别只改不改检。
- 一篇文章反复大改超过 3 次，多半是"定稿没做好"——退回第 1 步想清楚再排。
- 大改后务必重走"三端通用"清单（间距、图片、链接、关键信息），改一处可能连带影响别处。

## 九、常见错误

1. **只在一个端预览**：iPhone 上看挺好，安卓/PC 就崩——三端必看。
2. **无视深色模式**：深底浅字在深色模式下亮瞎/难读——深色模式单独核对。
3. **字号行高不达标**：13px 正文、1.5 行高，老年/弱视读者读不了——正文字号 ≥14px、行高 ≥1.75。
4. **单靠颜色传信息**：红绿标对错、纯色区分重点，色盲全抓瞎——用双通道。
5. **不设降级兜底**：全篇文章只靠纯色块/装饰，老设备一挂就整个糊——白底+实线+圆角仍可读。
6. **占位符没清干净**：发出去才发现"你的图片ID""待补充"还在正文——发布前纯文字通读必须过。
7. **低对比小字当正文用**：图注灰字没问题，但价格/时间也用 `#999` 灰写看不清——关键信息一律上合格对比。
8. **把信息只放进图片**：纯图承载价格、地址，弱网图没加载出来读者就没法读——核心信息必备文字版。
9. **只在浅色下验收**：浅色调好就发，深色模式直接崩——深色模式必须单独过三端。
10. **链接不做最后验证**：发出去才发现某小程序/外链失效——发布前所有入口逐个点一遍。

## 十、个性化空间（可调参数与判断依据）

- **正文字号**：多数账号 15-16px 舒适；若读者偏年轻、内容信息量大可 14px；老年向/科普向建议 16px。判断依据＝目标读者群体的年龄与阅读习惯。
- **小字备注使用**：`#999` 这类低对比小字**只用于不关键**的备注（图注、来源小字、版权），关键信息绝不用低对比灰。判断依据＝信息是否关键。
- **深色模式适配程度**：依赖三分色+浅底设计的宣传册，深色模式可能不完美——至少保证文字、关键信息在深色下仍清晰（改变不了渲染就保证对比）。判断依据＝读者深色模式使用占比。
- **降级方案的彻底度**：面向大众/全龄的号要"白底+实线"最稳兜底；面向年轻科技读者的可多依赖纯色与细边框（他们设备新）。判断依据＝读者设备与接受度。
- **读者主体是谁**：先想清这篇主要给谁读——长辈、上班族还是年轻学生——再据此套用第七节对应适配清单。判断依据＝文章内容与读者画像的重合度。

### 落地执行小贴士（发布当天怎么稳稳过一遍）
- **固定一套"终检顺序"**：桌面通读（错字）→ 桌面排版（间距）→ 三端预览（渲染）→ 发布页终审（合规四关）。顺序错乱容易漏项。
- **深色模式至少抽一个端真机看**：很多问题是"浅色好看、深色崩"，别只在浅色下验收。
- **关键信息逐条对源**：价格、时间、地址、日期，逐个回去对一遍最新来源，别凭记忆填。
- **链接逐个点**：小程序、外链、关键词入口，用一个真实微信号从读者视角逐个点开，别只看"能亮"。
