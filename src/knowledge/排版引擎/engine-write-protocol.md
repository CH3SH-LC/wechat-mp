# 公众号推文排版引擎协议（engine-write-protocol）

> 定位：**桌面排版引擎（本地 compose）唯一权威协议**。创作公众号推文时必读本文，按它产出正文。它不是"知识"，是**输出契约**：正文会经本地引擎渲染成 375px 微信合法 HTML、跑质量检查、由图像子智能体补插画素材。违反本文会得到警告或错误渲染。
> 调用时机：创作正文前，先 `load_knowledge(engine-write-protocol)`。
> 本文与 knowledge 其它文件的关系：knowledge 语料（visual/module、文本/style 等）讲"内容与观感怎么好"，本文讲"本地引擎怎么渲染"——两者冲突时**以本文为准**（引擎只认本文语法；语料里 art:// 资产桌面不提供）。

---

## 一、产出形态

1. 创作正文用一个 ```v2 围栏代码块给出（围栏标注 `v2`）。围栏前可以用普通文字说一两句自然的话（写好了 / 按什么写的 / 采纳了什么默认）——这没问题；引擎只取 ```v2 围栏内的正文渲染预览，围栏外文字作为对话展示。
2. 不要输出 ```html（旧直通通道仅兼容历史/演示）；正文一律走 ```v2。
3. 本地引擎负责排版：间距、平面化配色、双色系、圆角、内联样式全部由引擎确定性生成——**你不写任何 CSS/HTML 标签**，正文只写下面的轻量排版语法 + 普通 Markdown。

## 二、排版语法（v2，正文可用的全部语法）

- 标题：`# 大标题` / `## 小标题`（宣传类小标题自动编号）。
- 横幅：`[[banner:主标题|副标题]]`（整行，宣传类纯色横幅/文字类下划线标题）。
- 装饰标题：`[[title:文字]]` 居中标题；`[[title:文字|box]]` 描边框；`[[title:文字|vine]]` 花边标题。
- 花边分隔：`[[lace]]`；分割线：`---` 细线 / `***` 圆点 / `___` 粗条 / `~~~` 丝带。
- 提示气泡：`> [!NOTE|TIP|WARN|DANGER|KEY] 标题`，后续行以 `>` 开头为正文；宣传类 KEY/TIP/DANGER 为纯色气泡。
- 引用：`> 文字`。
- 卡片：`::: card 标题` + 内容行 + `:::`。
- 编号步骤：`::: steps` + `- 条目`… + `:::`。
- 分栏：`::: cols` + `- 项`…（2-3 项并排）+ `:::`。
- 花纹色带：`::: band 斜纹|波点|棋盘|条纹|圆环` + `- 文字`… + `:::`。
- 时间线：`::: timeline` + `- 节点`… + `:::`。
- 边框容器：`::: frame` + `- 内容`… + `:::`。
- 列表：`- 项` / `1. 项`；表格：`| a | b |`（引擎会提示表格建议转图）。
- 行内：`**加粗**`、`*斜体*`、`代码`（反引号包裹）、`==高亮==`、`[[badge:文本]]` 徽章、`[文字](https://链接)`。
- **图片**：不要用 art:// 或本地路径图片（会被移除并警告）。确需真实照片且用户会提供 → 用照片位（§三.3）；没有真实照片、靠系统配图 → 用插画占位（§三.3）；**禁止**用"此处建议配图：…"这类文字说明代替图位（不会渲染成图）。

## 三、美术素材（图像子智能体生成——你只写图位占位，不手写 SVG）

> 正文由本地引擎渲染后，每个图位占位会交给"图像子智能体"现场生成插画（SVG→PNG）并排版。你只负责占位 + 给足说明。

1. **数量与覆盖**：每篇 5-8 处美术素材（400-600 字短篇不少于 4 处）；组件装饰位全覆盖——开篇/横幅旁 1 处 wide 主题插画、每个 `##` 小节标题下 1 处 inline、每个 `> [!KEY]/[!TIP]/[!DANGER]` 气泡配 1 枚 deco 角饰、换场/章节间 1 处 wide 花饰、`::: card/cols/band` 等容器前后按需 inline；同一屏（约 120-150 字内容）装饰不超过 1 处。素材过多过少引擎都会提示，按提示增删。
2. **你只写占位**（每处占位单独占一行）：
   - 正文插画：`[[img:wide|说明]]`（横幅/场景图）或 `[[img:inline|说明]]`（小节/容器旁小插画）；
   - 气泡角饰：先在气泡之前某行定义 `[[deco:名称|说明]]`（名称用英文小写，如 blossom），随后气泡引用同一名称 `> [!KEY|名称] 标题`；
   - **说明要具体可执行**（原样交给图像子智能体）：画什么对象与动作、用途与意象，带风格词。例：`[[img:wide|开学典礼横幅插画：晨光中升旗台与旗帜，暖色调，呼应校园风]]`。
3. **配图来源分支（澄清时确认或按话意判断）——真实照片与生成插画职责不同，可并存**：
   - **用户会给真实照片**（"插照片 / 留照片位 / 现场照片"）：真实画面用**照片位** `::: photo 说明`（占一整行，说明写清放什么照片）；**同时**仍用 `[[img]]`/`[[deco]]` 覆盖横幅旁/小节标题/气泡角饰/分隔等**组件装饰位**——照片是"信息画面"，插画是"版面装饰"，两者都要，全文不能只剩照片空框。
   - **用户无照片 / 由系统配图**：全部用 `[[img]]`/`[[deco]]` 生成插画，不用 `::: photo`。
   - 照片位较多的文章，插画不必凑满 5-8 处：覆盖装饰位（横幅旁 wide、关键气泡 deco 角饰、小节标题/换场 inline）约 2-5 处即可；纯无照片文章仍按 §三.1 的 5-8 处。照片位与插画**同一屏（约 120-150 字）不并存**，错开放。
   - **反面约束**：只有用户会提供真实照片才用 `::: photo`；明确"没照片、由你生成图"时严禁 `::: photo`。

## 四、结构、语气与审美（写正文时遵守）

1. **组件化**：正文不得是"长段落+插图"堆文，用组件组织——至少 2 种不同容器（`::: steps/cols/card/band/timeline/frame`）、至少 1 个提示气泡、至少 1 处列表或引用；连续纯文字段落不超过 2 段；宣传类参考结构 `[[banner]]` → 钩子段 → 2-3 个小节（标题+组件+素材）→ 1 个关键气泡 → 平实号召。
2. **语气克制、像人写**：具体细节/数字/场景代替空泛形容词；禁用夸张营销词（极致/颠覆/不容错过/绝绝子/yyds/天花板/火爆全城/疯狂/立刻马上等）；感叹号全篇 ≤1；不用"让我们一起""快来"式空洞口号；结尾行动号召平实。
3. **字数与充实**：默认 1500-2500 字（用户明确短篇除外）；段落短小、重点加粗；内容充实——每小节展开细节/场景/数据/过程，禁泛泛几句敷衍；短文(<600 字)引擎提示偏短。
4. **审美**：正文零 emoji、零图标字符、零渐变、零阴影；低饱和纯色 + 细边框 + 留白；全篇主色 ≤3；正文 15-16px 深灰。间距（块 16px/行高 1.75/标题上下 28/12 等）与配色落地全部由引擎完成，你无需书写。

## 五、风格声明

1. 内容采用某风格时，**在正文第一行声明** `[[theme:名称]]`。
2. **风格不限于预置清单**：可引用预置名（校园/科技/国潮/日系/极简/商务/手账/森系…）套用既定色板；也可用任何贴合内容与读者的风格名。**用非预置风格时**在 `[[theme:…]]` 后另起一行给可渲染自定义色板：`[[palette:bg=底色;accent=主色;heading=标题色;soft=浅底;border=边框;hl=高亮;orange=宣传主色;amber=点缀色;ink=正文深色]]`（十六进制，bg 与 accent 必给）。声明未收录风格名却没 `[[palette]]` → 引擎回退默认双色系并警告。
3. 风格只是"皮肤"（色板/气质/装饰词），**不是内容模板**：正文结构、分节、文案由内容类型与主题决定；注入的风格文件里标题/模块/文案示例仅说明规范，禁止照搬骨架/句式/措辞；同风格不同主题产出不得雷同。
