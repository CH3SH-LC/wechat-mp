# 公众号推文排版引擎协议（engine-write-protocol）

> 定位：**桌面排版引擎（本地 compose）唯一权威协议**。创作公众号推文时必读本文，按它产出正文。它不是"知识"，是**输出契约**：正文会经本地引擎渲染成 375px 微信合法 HTML、跑质量检查；有独立配图需要时才解析或生成素材。违反本文会得到警告或错误渲染。
> 调用时机：创作正文前，先 `load_knowledge(engine-write-protocol)`。
> 本文与 knowledge 其它文件的关系：knowledge 语料（visual/module、文本/style 等）讲"内容与观感怎么好"，本文讲"本地引擎怎么渲染"——两者冲突时**以本文为准**（引擎只认本文语法；语料里 art:// 资产桌面不提供）。

---

## 一、产出形态

1. 创作正文用一个 ```v2 围栏代码块给出（围栏标注 `v2`）。围栏前可以用普通文字自然说明；引擎只取围栏内正文渲染，围栏外文字作为对话展示。用户要求附带公众号标题、分享摘要时，在围栏外单独提供，不重复塞进正文；工具回合仍遵守各工具的字段与互斥约束。
2. 不要输出 ```html（旧直通通道仅兼容历史/演示）；正文一律走 ```v2。
3. 本地引擎负责排版：间距、平面化配色、双色系、圆角、内联样式全部由引擎确定性生成——**你不写任何 CSS/HTML 标签**，正文只写下面的轻量排版语法 + 普通 Markdown。

## 二、排版语法（v2，正文可用的全部语法）

- 标题：`# 大标题` / `## 章节标题` / `### 节内小标题`。宣传类章节由引擎处理编号；用户标题原有编号照常保留，不手工叠加第二套编号。
- 设计轴（文字框长相）：`[[boxes:轴=值;…]]`，如 `[[boxes:radius=0;frame=line;label=eyebrow;mark=枫叶]]`；也可用别名起步再覆盖（`[[boxes:亲和;radius=8]]`）。单独一行，决定**气泡 / 引用 / 卡片 / 分栏 / 色带 / 步骤 / 时间线 / 列表**的整套设计语言（角标只出现在气泡上）。**从它那一行起生效**——中途再写一条就从那里换成新语言（所以同一篇里可以"正文用默认骨架、要点用序号骨架、已有引文用引文骨架"）。轴与推断方法见 §五.4。
- 横幅：`[[banner:主标题|副标题]]`（整行）。用标题层级、线条与独立几何装饰表达；`scale=display` 可让主标题成为彩色大字主视觉。常规横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构；花笺、票笺、缎带题头由对应 `ornament` 绘制主题轮廓，其中可铺底的题头遵循 `fill`。气泡与内容容器的浅底由 `fill` 独立选择。
- 装饰标题：`[[title:文字]]` 居中标题；`[[title:文字|box]]` 描边框；`[[title:文字|vine]]` 花边标题。
- 花边分隔：`[[lace]]`；分割线：`---` 细线 / `***` 圆点 / `___` 粗条 / `~~~` 丝带。
- 提示气泡：`> [!NOTE|TIP|WARN|DANGER|KEY] 标题`，后续行以 `>` 开头为正文。可承载完整长段落与原图；`shape` 选择结构，`fill=none/tint/wash/paper` 选择无底、极浅底、浅底或纸色。深色反白正文面板不属于当前协议。
- 引用：`> 文字`。
- 卡片：`::: card 标题` + 内容行 + `:::`。
- 编号步骤：`::: steps` + `- 条目`… + `:::`。
- 分栏：`::: cols` + `- 项`…（2-3 项并排）+ `:::`。
- 花纹色带：`::: band 斜纹|波点|棋盘|条纹|圆环` + `- 文字`… + `:::`。
- 时间线：`::: timeline` + `- 节点`… + `:::`。
- 边框容器：`::: frame` + `- 内容`… + `:::`。
- 列表：`- 项` / `1. 项`；表格：`| a | b |`（引擎会提示表格建议转图）。
- 行内：`**加粗**`、`*斜体*`、`代码`（反引号包裹）、`==高亮==`、`[[badge:文本]]` 徽章、`[文字](https://链接)`。
- **图片**：已提供或读取的本地图片用标准 Markdown `![画面说明](local-image://li-<SHA256>)`，URI 必须照抄附件清单或 `read_local_image` 的实际返回（见 §三.0）。不要把磁盘路径、`file://` 或 `art://` 直接当图片地址。用户明确稍后提供照片时才用照片位；确需系统生成插画时用插画占位（§三.3）。**禁止**用“此处建议配图：…”这类文字说明代替真实图位。

## 三、配图（引用本地原图，或检索/生成插画；不手写 SVG）

> 用户提供的本地图片按原图引用，不进入生成插画流程。确需插画的图位由系统解析：先检索个人素材库，语义合适即复用；库中没有才委托素材智能体绘制并入库。你负责内容与安放位置，写准确引用或占位说明，不手写 SVG。

0. **本地图片：先看内容，再安放原图**：
   - 附件清单或 `read_local_image` 工具提供确切引用，写法为 `![画面说明](local-image://li-<SHA256>)`，每张单独一行。`li-` 后是工具给出的 64 位哈希标识；这里只解释格式，**不能把 `<SHA256>` 写进正文，不能编造、缩写或自行计算 ID**。照抄实际 URI，说明文字可以根据画面与文意调整。
   - **元数据不等于视觉内容**。文件名、路径、尺寸、图片 ID 只用于定位；要判断画面、选图或写图注，必须依据已收到的图像视觉输入。还没看到时调用读取工具；工具会给出图像输入，不凭文件名猜图，也不声称仅列出文件就已读图。读取失败时说明具体问题，不编造画面、不静默换图。
   - 用户明确要求插入的原图按原图使用；未指定位置时，按画面与相关段落的叙事关系安放，不必再让用户规划每一处位置。多图各有对应内容，图注不把同一段话抄一遍，也不从图片推断材料未给的身份、活动规则、日期或数据。
   - **已有原图不能降级成 `::: photo` 照片占位、`[[img]]` 生成插画或近似图库素材**；用户要求“这张图”时尤其如此。只改文案时保留已有 `local-image://` 引用，不重画、不换 ID。照片缺失才讨论补充，不能把已成功读取的图片当作用户尚未提供。

1. **数量与覆盖（按内容需要，用户指定的数量与位置优先）**：
   - 不按字数预设图片数量，也不默认开篇、每节或每个气泡必须配图。先判断读者需要看清什么：画面能提供正文之外的信息、对照或视觉说明时，再选择 wide / inline；角饰与花饰须有明确的视觉组织作用。
   - 每处素材都要有独立用途，正文与图片错落安排，同一屏避免堆图和多个强调框；不为凑数量扩写重复内容，不机械生成文件夹、箭头或工作台等通用示意来重复功能名。
   - **任何篇幅都可以不新增插画，也可以不用容器组件**。内置题签、纸框、线饰及角标可独立形成完整设计，章节与气泡不要求生成新 SVG。保留用户指定的原图、图片数量与位置；已有底稿优先服务原稿。用量提示只供复核，不覆盖用户明确安排。
2. **生成插画与角饰的写法（两种；本地原图用 §三.0，每处占位/引用单独占一行）**：
   - **引用个人素材库素材**：若上下文中给了「个人素材库」清单（每行形如 `art-inline（正文内嵌插画）｜id=as-…｜name=…｜… → 引用写法 [[asset:art-inline|as-…|用途说明]]`），需要某类素材时先在库清单里找语义最贴合的，**照抄行尾的「引用写法」**并把它第三段改成你这处要它做什么。要点：分类写**英文键**（如 `art-inline`，也可以写对应的中文名 `正文内嵌插画`，两者都认）；素材标识优先用 `id=` 后面的那个 ID（名称也可，但库里有同名素材时会判为歧义而不采用）。气泡角饰要**先在某行** `[[asset:bubble|素材ID|…]]` 引用定义、随后气泡引用同名/同 ID `> [!KEY|素材ID] 标题`。**风格只是参考**：库清单里的素材只要语义、形状与安放位贴合就能用，不强求匹配本文声明风格。
   - **写图位占位**（库里没有合适素材、或上下文没给库清单时）：正文插画 `[[img:wide|说明]]`/`[[img:inline|说明]]`；气泡角饰先在某行定义 `[[deco:名称|说明]]`（名称用英文小写，如 blossom），随后气泡引用同一名称 `> [!语义|名称] 标题`；系统会先检索库、无命中再委托素材智能体现场制作。
   - **要求重新画 / 换一张 / 不要用旧素材时**：在占位第三段写 `new`，即 `[[img:wide|说明|new]]`、`[[deco:名称|说明|new]]`。这会让系统**跳过素材库检索直接重新绘制**，避免复用之前的旧图。用户说"重新设计一张""别用上次那张""换成别的样子"时必须加 `new`；没有这种要求就别加（合理的复用能省时省钱）。
   - 两条路都不要写 SVG 原文；**说明要具体可执行**（原样交给检索/素材智能体）：画什么对象与动作、用途与意象，带风格词。例：`[[img:wide|开学典礼横幅插画：晨光中升旗台与旗帜，暖色调，呼应校园风]]`。
   - **不要写 `::: art` / `::: art deco` 这类容器**：那是**引擎内部格式**——引擎检索/绘制到素材、解析完之后自己生成的中间产物，不属于模型可写格式。模型用 `[[asset]]` / `[[img]]` / `[[deco]]` 表达插画与角饰，用 `![说明](local-image://实际ID)` 引用本地原图；只有尚未提供的照片才写单行照片位 `::: photo 说明`。`::: art` / `::: art deco` 任何情况下都由引擎生成，模型一律不写。
   - 引用素材库素材时，**分类要写对**（`[[asset:分类|素材ID|用途]]` 的分类应当与该素材在库清单里的分类一致）；写错分类时，若该素材的安放位仍与这处兼容（例如气泡角饰写成 `deco` 而素材是 `bubble`）引擎会按素材实际分类渲染并给出警告；若用途不兼容（例如把宽幅插图放进角饰位）引擎会**拒绝采用并提示**。
3. **配图来源（按已有材料和用途安排，不为偏好反复澄清）——真实照片与生成插画职责不同，可并存**：
   - **用户已提供图片或具体本地路径**：用读取工具与 §三.0 的本地原图引用；“插照片”“这张图”“现场照片”不自动等于留空位。
   - **用户明确稍后会给照片，当前尚未提供**：可以用**照片位**，写法**只有一行**：`::: photo 照片说明`——`::: photo` 和说明写在**同一行**，说明写清放什么照片。
     - **照片位是单行指令，没有块体、不需要结束符**：`::: photo 照片说明` 这一行写完就结束了，**下一行起就是正文**（照常写段落、组件、`[[asset]]`/`[[img]]`/`[[deco]]`）。**不要写 `:::` 闭合，也不要另起行写多条说明。**
     - **反面写法（会被按正文解析，说明行直接变成文章正文）**：把照片位写成多行块——第一行 `::: photo`（或 `::: photo 说明`）、随后若干行说明、最后一行 `:::`。超出的说明行会原样排进文章正文；紧跟其后的普通段落与素材块也容易被一起误当正文，成品会出现内部源码泄漏、素材全部落空（2026-09-29 真实故障即由此产生）。正确与错误对照：
       - 正确：`::: photo 活动现场全景` 一行，下一行直接 `当天到场的同学…`。
       - 错误：`::: photo` ＋ `活动现场全景` ＋ `:::` 三行——"活动现场全景"和 `:::` 会作为正文印出来。
     - 如需插画或角饰，仍用 `[[asset]]`/`[[img]]`/`[[deco]]`；照片提供真实画面，插画用于解释或装饰，不必为了配额让两者同时出现。
   - **用户无照片 / 由系统配图**：按内容需要用 `[[asset]]`/`[[img]]`/`[[deco]]` 配插画，也可以不配图，不用 `::: photo`。
   - 照片位较多时减少装饰插画；纯插画文章也按 §三.1 的内容用途选图。照片位与插画错开放，避免同一屏重复解释同一内容。
   - **反面约束**：只有用户明确稍后提供、当前仍缺失的照片才用 `::: photo`；已提供原图或明确“没照片、由你生成图”时均不能用照片占位替代。

## 四、呈现、修改范围与检查

文章的目的、取材与表达遵守系统编辑标准，具体方法按需读取 `文本/写作`。本协议规定可渲染的呈现和引用方式，不替文章安排固定结构、句长、篇幅、章节或配图配额。手机预览需要适配时调整版式，不能把完整书面句拆成碎句、把相互依赖的条件与结论切进不同组件来迁就框宽。

1. **修改范围**：用户明确的字数、章节、组件与图片安排优先；完整底稿的润色或排版保留原稿信息、自然段、结构与篇幅尺度；用户只给简单视觉指导也不能将长原文摘要化来凑气泡；局部修改保留范围外正文和素材引用。不能借排版或质量检查重写用户要求保留的内容。
2. **按信息关系选呈现**：连续叙述可以使用普通段落，有依赖顺序的操作可用 `steps`，并列内容可用列表或 `card`。只在确有需要时使用组件，不设种类或数量最低配额，不用按字数切块来决定正文结构。
3. **审美与视觉强度**：按本篇需求选择极简、明丽、热闹或庄重，不把所有成稿统一收成低饱和细线版式。明丽表达可用彩色大标题、对比层级与贯穿题头、章标、框体、分隔的主题装饰；主辅色应有分工，亮黄等浅色留给装饰，正文保持可读深色，花笺、票笺、缎带预置的气泡正文为17px。正文零 emoji、零图标字符、零渐变、零阴影。气泡和内容容器可用协议支持的浅底、纸色与细框；常规横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构；花笺、票笺、缎带题头按主题轮廓绘制，可铺底部分遵循 `fill`。用户明确极简或无底色时用 `fill=none`。通过 §五 声明配色与版式，不手写 CSS，也不把正文栅格化进插画文字卡。
4. **标题呈现**：使用 `#` / `##` 表达标题层级；新建标题**不要手工追加序号/编号**，由引擎处理。用户给定标题中的中文或数字编号属于原文，保持原样，渲染时避免再叠加自动编号。`[[title:文字|box]]` / `[[title:文字|vine]]` 可用于需要装饰标题的地方；用户指定的标题保持原样。是否分节以及分节位置由内容决定。
5. **重点气泡（`> [!KEY|TIP|WARN|DANGER|NOTE]…`）**：按实际语义选型，关键结论用 `[!KEY]`，实用技巧用 `[!TIP]`，易踩的坑用 `[!WARN]`，必须禁止的事项用 `[!DANGER]`，中性补充用 `[!NOTE]`。**首行可写标题，也可只写 `> [!NOTE]` 省略标题；内容从第二行起**。骨架由 `[[boxes:shape=…]]` 指定，线条、语义色、字重与标签由引擎生成，底色由 `fill` 选择。正文允许多个自然段和对应图片，各行保留 `>` 前缀；空段写独立的 `>`，不把长文改成短摘要。内置题签与纸框不需要新素材。需要角饰时先以 `[[asset:bubble|素材ID|用途]]` 或 `[[deco:名称|说明]]` 定义，再用 `> [!语义|同样的素材ID或名称]` 引用。普通引用 `>` 不代替重点气泡，不写 `::: art deco` 容器。

用户要求更花、更精致时，先形成一套贯穿全文的主题语言：题头建立主题、章标引导、框体承载、分隔连接。同族花枝、票孔或缎带在不同位置改变尺度，避免只给通用提示卡换色、叠双框、重复语义标签或散放零碎小图标。内置主题装饰可重复使用，无需额外素材接口或生成调用；不以新增插画、章节和气泡数量充当设计完成证据。完整正文只排版，不删改、拆碎或压小字体来迁就造型；极简与少装饰等明确偏好仍优先。

交付前核对 v2 围栏是否完整、组件是否闭合、配色与版式声明是否可解析、原图和素材引用是否准确、局部修改是否保留授权范围外内容。文章的内容审阅与呈现检查各自完成，不以排版通过代替内容判断。

## 五、风格声明

1. 内容采用某风格时，**在正文第一行声明** `[[theme:名称]]`。
   **它只决定配色**（色板 + 图案词汇），**不决定版式**——版式由 `[[boxes:…]]` 单独声明（见 §五.4）。
   两者是**两个独立维度**，可以任意组合：日系配色 + 编辑感版式、科技配色 + 手账版式都成立，引擎不会互相牵连。
2. **风格不限于预置清单**：可引用预置名（校园 / 科技 / 国潮 / 日系 / 极简 / 商务 / 手账 / 森系 / 杂志 / 报纸 / 奶油 / 薄荷 / 赤陶 / 靛蓝 / 孟菲斯 / 波普 / 运动）套用既定色板；孟菲斯也认 `memphis`，波普也认 `pop` / 波普艺术，运动也认 `sport` / 运动活力。也可用任何贴合内容与读者的风格名。**用非预置风格或用户指定了具体色号时**，在 `[[theme:…]]` 后另起一行给可渲染自定义色板：`[[palette:bg=底色;text=正文色;accent=主色;accentDark=主色深档;heading=标题色;border=边框;orange=宣传主色;amber=点缀色;ink=宣传标题色;sub=次要色;tip=提示色;warn=注意色;danger=警示色]]`（十六进制，bg 与 accent 必给；仍兼容 soft/soft2/hl/teal）。声明未收录风格名却没 `[[palette]]` → 引擎回退默认双色系并警告。色号须写进声明，不能只放进插画说明；用户指定的版式骨架另写 `[[boxes:…]]`。
3. 风格只是"皮肤"（色板/气质/装饰词），**不是内容模板**：文章内容与结构遵守系统编辑标准及用户需求；风格资料只用于配色、视觉层级、装饰和图案选择，不提供正文模板或本稿事实。
4. **设计轴（文字框长相：气泡 / 引用 / 卡片 / 分栏 / 色带 / 步骤 / 时间线 / 列表共用一套）**

   > **配色与版式是分开的（2026-10-11 起）**：`[[theme:名称]]` 只管**颜色与图案词汇**，
   > `[[boxes:…]]` 只管**版式**（结构、线条、字号、字体气质、装饰）。
   > 此前"选一个配色风格"会**顺带把版式也定了**（校园→亲和、日系→杂志…），现在不会了——
   > 不写 `[[boxes:…]]` 就是中性默认（编辑感）。**要什么版式就自己写出来**，别指望配色替你选。

   **这不是"从几套里挑一套"，而是"从这篇文章的风格推断出一组轴的取值"。** 单独一行写：

   `[[boxes:轴=值;轴=值;…]]`（值写中文也认；每条独立，顺序无所谓）

   | 轴 | 取值 | 它决定什么 |
   | --- | --- | --- |
   | `radius` | `0` / `4` / `8` / `14` | 圆角性格：**直角=严肃编辑感**，4=克制的现代，8/14=亲和圆润 |
   | `frame` | `line` 左竖线为主 ｜ `edge` 细框+左粗线 ｜ `plane` 浅底面板（`fill=none` 时保留线条） ｜ `dash` 虚线框 ｜ `rules` 上下夹线 ｜ `stack` 双线嵌套 ｜ `none` | **框架语言——轻重强弱靠它表达** |
   | `bar` | `2` / `3` / `4` / `5` | 竖线/左粗线的粗细 |
   | `fill` | `none` / `tint` 极浅 / `wash` 稍深 / `paper` 纸色 | 内容底色：none 关闭；tint 为语义色极浅底，wash 为稍深浅底，paper 为极浅暖纸色。默认 none；用户明确无底时保持 none |
   | `label` | `eyebrow` 紧排小标签 ｜ `chip` 胶囊 ｜ `mono` 等宽 `//` ｜ `none` | 语义标签（提示/技巧/注意/警示/重点）的形态 |
   | `title` | `sans` / `serif` / `mono` | 标题字体气质 |
   | `size` | `15` / `17` / `19` | 组件标题字号，亦影响文章标题的尺度档位 |
   | `scale` | `standard`（默认） / `display` | 标题尺度：display 用海报大字呈现横幅、`#`、`##`，正文不放大；主标题用可读主色，小节用深色与无底大序号 |
   | `align` | `auto`（默认） / `left` / `center` | 文章标题与横幅对齐；不改变正文对齐 |
   | `ornament` | `none`（默认） / `confetti` / `dots` / `speed` / `botanical` / `ticket` / `ribbon` | 无、几何、网点、速度线、花枝、票孔、缎带。作用于题头、章标与分隔；后三者形成贯穿全文的主题装饰（中文花枝/票孔/绶带也认）。装饰有独立留白区，不压正文或图片 |
   | `deco` | `none` ｜ `brackets` 对角角括号 ｜ `tape` 旋转胶带 ｜ `quote` 出血大引号（多选用英文逗号） | 额外容器饰件；none 关闭这些叠加饰件，不关闭 shape/ornament 的内置主题装饰。按需要选择，不要求所有容器加满 |
   | `pad` | `tight` / `normal` / `loose` | 内距松紧 |
   | `mark` | `圆` 空心圆 ｜ `实圆` ｜ `菱形` ｜ `实菱形` ｜ `方框` ｜ `枫叶` ｜ `叶芽` ｜ `星` ｜ `水滴` ｜ `书页` ｜ `齿轮` ｜ `印章` ｜ `心` ｜ `闪电` ｜ `钟` ｜ `none` | 气泡**角标图案**（引擎按名字画，**你不写 SVG**）；不写＝按语义自动（提示=空心圆／技巧=实心圆／注意=空心菱形／警示=方框／重点=实心菱形），**再往上还叠一层主题词汇**（`[[theme:森系]]` 会把"提示/技巧"换成叶芽/水滴等该风格图案，但**警报与结论的形状不换**）；`none`＝不画 |
   | `markat` | **四角** `tl` 左上 ｜ `tr` 右上 ｜ `bl` 左下 ｜ `br` 右下；**四边中点** `t` 顶端 ｜ `b` 底端 ｜ `l` 左侧 ｜ `r` 右侧（中文"左上/右上/左下/右下/顶端/底端/左侧/右侧"也认） | 角标落在哪条边/哪个角（默认左上） |
   | `shape` | `rail` 左竖线式（默认）｜ `medal` 徽章两栏式 ｜ `index` 序号式 ｜ `cap` 标题条式 ｜ `hanger` 悬挂标签式 ｜ `side` 竖排标签式 ｜ `quote` 引文式 ｜ `bracket` 角括号式 ｜ `tab` 跨边界题签 ｜ `panel` 双层纸框 ｜ `botanical` 花笺 ｜ `ticket` 票笺 ｜ `ribbon` 缎带（中文花笺/票笺/缎带与对应“式”也认；原有中文名 竖线式/徽章式/序号式/标题条式/悬挂式/竖排式/引文式/角括号式、题签/题签式、纸笺/纸笺式/章节卡 也认） | 气泡的**结构骨架**——不是换图案，而是**元素怎么排**：单栏还是两栏、标签在上还是在左栏、有没有大徽章 / 大序号 / 大引号。默认 `rail` |

   **角标与"断口"（R22）**：气泡可用角标覆盖局部框线形成断口——在任一角/边中点放一枚**不透明的角标徽章**，
   徽章骑在框线上、把那一段框线盖住，于是框线**天然缺一小段、由角标收口**（"一条边为什么要围满"的反面）。
   `mark` 决定徽章里画什么图案：**选贴内容的**（秋季活动→`枫叶`、书评→`书页`、数据→`齿轮`、
   时间安排→`钟`、活动报名→`星`），不要每篇都随手写一枚。
   **角标只出现在气泡上**——卡片/引用这类非强调容器不挂角标（强调记号要稀缺才有效）。推荐用 `mark=星` 等轴声明图案；`> [!KEY|星]` 这类已知本地图案后缀也可直接绘制，不用生成素材。显式 `mark` 轴（包括 `none`）优先，未知角饰仍需先定义或引用真实素材。
   （词汇表按 **15px 实显下限**验收：认不出的图形不入表。）

   **怎么从风格推断**（先想"这个账号的排版语言是什么"，再落成轴）：

   | 风格气质 | 一组可用的轴 |
   | --- | --- |
   | 严肃 / 权威 / 深度报道 / 政务 / 商务 | `radius=0;frame=line;label=eyebrow;scale=standard;ornament=none` |
   | 素净 / 极简 / 安静阅读 | `radius=0;frame=none;fill=none;label=none;mark=none;deco=none;scale=standard;align=left;ornament=none` |
   | 亲和 / 校园 / 生活 / 亲子 / 森系 | `radius=8;frame=dash;label=chip;scale=standard;align=left;ornament=none` |
   | 节庆 / 自然 / 文化活动的花笺舞台 | `花笺`，即 botanical 主题组合；配色另选 |
   | 校园资讯 / 市集 / 游园 / 展览的票笺 | `票笺`，即 ticket 主题组合；配色另选 |
   | 实践报道 / 纪念 / 仪式性内容的缎带 | `缎带`，即 ribbon 主题组合；配色另选 |
   | 校园招新 / 明丽几何 | `radius=8;frame=none;shape=medal;scale=display;align=left;ornament=confetti` |
   | 波普 / 戏剧感 / 艺术活动 | `radius=0;frame=edge;shape=bracket;size=19;scale=display;align=center;ornament=dots` |
   | 运动 / 速度 / 竞技感 | `radius=0;frame=line;shape=index;bar=4;scale=display;align=left;ornament=speed` |
   | 文化 / 专题 / 书卷 / 日系 / 国潮 | `radius=0;frame=stack;title=serif;size=17;deco=quote` |
   | 手作 / 日常 / 情感 / 活动 / 手账 | `radius=14;frame=dash;label=chip;deco=tape` |

   **这些不是绑定主题的模板**。根据本篇需要分别选择配色、标题强度、线条与骨架；亮色可以配简洁结构，温柔色也可以配醒目标题。用户只说“明亮花哨一点”也足以由你完成选择，不要求用户规划每处细节。`scale=standard;align=auto;ornament=none` 是新轴的默认值；中途重写 `[[boxes:…]]` 时每条从默认值重新取轴，需保留的轴应再次写明。

   **常用组合的别名**（赶时间可以直接用，也能在别名上覆盖）：
   `[[boxes:编辑感]]` ＝ `radius=0;frame=line;fill=none;deco=quote`；
   `[[boxes:亲和]]` ＝ `radius=14;frame=plane;fill=wash;label=chip`；
   `[[boxes:杂志]]` ＝ `radius=0;frame=stack;fill=none;title=serif;size=17;deco=quote`；
   `[[boxes:手账]]` ＝ `radius=14;frame=dash;fill=tint;label=chip;deco=tape`；
   `[[boxes:科技]]` ＝ `radius=0;frame=edge;fill=tint;label=mono`；
   `[[boxes:题签]]` ＝ `shape=tab;frame=edge;fill=tint;radius=8;size=17;deco=none;pad=loose`；
   `[[boxes:纸笺]]` ＝ `shape=panel;frame=stack;fill=paper;radius=8;title=serif;size=17;deco=none;pad=loose`。
   新增完整主题组合（英文别名 botanical / ticket / ribbon）：
   `[[boxes:花笺]]` ＝ `shape=botanical;ornament=botanical;frame=none;fill=paper;radius=0;title=serif;size=17;label=none;mark=none;deco=none;pad=normal;align=center`；
   `[[boxes:票笺]]` ＝ `shape=ticket;ornament=ticket;frame=none;fill=tint;radius=0;title=sans;size=17;label=none;mark=none;deco=none;pad=normal;align=left`；
   `[[boxes:缎带]]` ＝ `shape=ribbon;ornament=ribbon;frame=none;fill=tint;radius=0;title=serif;size=17;label=none;mark=none;deco=none;pad=normal;align=left`。
   三个预置不额外生成“提示／注意／重点”标签或无关角标，标题和正文仍表达实际语义；正文17px，完整长段自然展开。它们让 `#` / `[[banner]]` / `##` / `---` 使用同族主题，组件文字保持可编辑。只写 `shape` 不会自动替标题选 `ornament`。
   例：`[[boxes:花笺;fill=none]]` 保留花枝主题并关闭内容底色；`[[boxes:票笺;shape=rail;frame=line]]` 只减轻当前气泡，保留标题与分隔的票笺主题。`[[boxes:亲和;radius=8]]` 则用亲和的骨架但把圆角收小。

   **内容底色与完整设计**：`fill=none` 明确关闭内容底色；`tint`、`wash`、`paper` 为可用的浅底和纸色，不是深色反白正文面板。`frame=plane` 在有底时形成面板，无底时保留线条以免层级消失。默认编辑感仍无底；用户指定无底或少装饰时尊重其选择。常规横幅与小标题在 `frame=plane` 且显式选择浅底时使用浅底，默认保留标题与线饰结构；花笺、票笺、缎带题头的可铺底部分遵循 `fill`，不用 frame 强行覆盖它们的主题轮廓。

   细框、浅底、跨边界题签、纸面和内置主题装饰可组合成完整设计；整圈框或圆角本身不代表低质量，双框与标签应有明确用途。题头、章标与框体各有角色，不把每层都套成同款卡片。按同类内容保持一致比例、内距与标题关系，不强制生成新插画，不规定全文组件数量。小记号和插画内部可填色，但不能把可编辑正文移入图片替代文字流。

   **`shape`（结构骨架）**：**不是换图案，是换结构**——同一段文字换成不同 `shape`，元素的**排布**
   就变了（这正是"不能只是同一个结构换个图标"的要求）：

   | `shape` | 结构 |
   | --- | --- |
   | `rail`（默认） | 左竖线 + 标签 / 标题 / 正文三行；角标骑线 |
   | `medal` | **两栏**：左侧 44px 描边徽章（内嵌图案）+ 右侧文字；无竖线、不挂角标 |
   | `index` | **两栏**：左侧两位**序号** `01/02…`（**本节内**自动编号：只数用了 `index` 的气泡，遇到 `##` 重新从 01 起）+ 右侧文字 |
   | `cap` | 顶部一行「短横条 + 标签」当**题头**，下接标题与正文；无外框 |
   | `hanger` | 标签**悬挂在左侧栏**（与标题同一行水平位置，不在正文流里）；左细线 |
   | `side` | 左侧一列**竖排**语义字 + 右侧文字；左细线 |
   | `quote` | 大引号 + **衬线**正文；无框（已有引文或适合独立呈现的内容可用） |
   | `bracket` | 只有左上 / 右下两个 **L 形角括号**，文字内缩 |
   | `tab` | 细框与跨边界题签；标题在正常流中可换行，完整段落和图片随内容展开 |
   | `panel` | 双层纸框与章节题头；适合章节正文、长规则和完整图文单元 |
   | `botanical` | 花枝与叶簇沿单层纸面头尾布置，正文保留完整单栏；与 ornament=botanical 呼应 |
   | `ticket` | 票面框体、票孔及分界组织题头和正文，图文保持同一内边界；与 ornament=ticket 呼应 |
   | `ribbon` | 缎带题头与开放边线承载完整段落，主题线饰在头尾收束；与 ornament=ribbon 呼应 |

   建议：一篇里**主力仍用一种**骨架（结构语言要统一），只在"这一块确实该换个讲法"时换——
   已有要点清单可用 `index`、真实引文可用 `quote`、需要强调的提示可用 `medal`；不为填充骨架增加或拆短正文。容器适应正文长度与图片，不以删文、碎句或缩小字号换取紧凑。

   **引擎负责的事**（你不用记、也别去处理）：`frame=line` 要左竖线时圆角会被**自动夹到 0**
   （圆角会把竖条两头一起圆掉）；`markat=br` 而右下角又有角饰时会**自动侧移让位**
   （角饰与角标实测重叠）；角标色会自动压到与白底 ≥4.5:1（语义色偏浅时）。轴名或取值不认识会给警告且不生效。
   **主力只用一套轴**——`frame` / `radius` 这些"设计语言"全篇保持一致，不要一段一换（那是没风格的写法）。
   真正值得中途换的是 **`shape`（骨架）**：一篇里可以"正文用默认 `rail`、要点清单用 `index`、已有引文用 `quote`"——
   在新段落前另起一行 `[[boxes:frame=line;shape=index]]` 即可（它从那行起生效）。不写时使用默认编辑骨架，`[[theme:]]` 只控制配色。
