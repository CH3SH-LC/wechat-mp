# 组件与内容的呈现关系

组件是呈现已有信息关系的方式。写作方法见 `文本/写作`，可执行语法见 `排版引擎/engine-write-protocol.md`。不要求在写正文前先挑组件，也不以组件数量判断文章完成度。

## 可使用的呈现方式

| 信息关系 | 可选呈现 | 判断依据 |
| --- | --- | --- |
| 连续说明或叙述 | 普通段落与小标题 | 读者需要沿叙述顺序理解 |
| 并列条目 | 列表、分栏或卡片 | 条目是否确实并列，手机宽度能否容纳 |
| 有先后依赖的操作 | 步骤 | 顺序是否影响执行 |
| 有时间关系的事件 | 时间线 | 时间顺序是否帮助理解 |
| 需要对应比较的数据 | 表格 | 行列关系是否清楚，窄屏是否可读 |
| 需要单独强调的信息 | 气泡或引用 | 是否值得视觉停顿，语义选型是否准确 |
| 画面有信息或表达用途 | 原图、库素材或新插画 | 图片能否帮助这篇文章，是否符合用户授权 |
| 段落或章节的视觉区分 | 留白、线饰、标题层级 | 能否看清层次且不割裂阅读 |

这些选择没有最低数量或按字数触发的配额。不需要容器或新增插画的文章可以只用文字；用户指定的组件、图片、数量和位置优先。

用户提供长原文和简单视觉指导时，保留原文信息、自然段与篇幅尺度，不能摘要成短句来凑气泡。连续说明的条件、原因与结论应保持相互联系。组件宽度不足时先调整布局或改用普通段落，不把一个完整意思切成多个气泡、短句或单行清单来适应组件。

## 配色、版式与内容分别决定

- `[[theme:…]]` 与 `[[palette:…]]` 表达配色；`[[boxes:…]]` 表达框线、骨架、标题尺度、对齐和装饰。两组选择互不替代。
- 极简、明丽、热闹或庄重都可结合清楚的层次。视觉强度由内容与用户偏好决定，不把大学生题材限定为一种外观。
- 组件骨架改变信息的排布，图案与颜色改变视觉表情。选型参考视觉知识，实际写法只用当前引擎支持的语法。
- 正文容器按 `fill` 选择无底或浅底，横幅与小标题在 `frame=plane` 且显式选择浅底时可使用浅底，默认保留线条结构；小记号、线饰和插画可按协议用色。不把可编辑正文搬进插画文字卡。

## 素材与组件

内置题签、双层纸框、线饰和角标可独立形成完整设计，章节与气泡不要求新生成 SVG，也不要求固定数量插画。

原图、库素材和新生成素材是不同来源。用户原图按其稳定引用使用；库素材照抄清单中的分类与 ID；需要新插画或角饰时声明 `[[img:…]]` / `[[deco:…]]`。素材由系统解析或委托制作，主创不手写 SVG 或内部素材容器。

组件支持哪种素材位置、如何声明与引用，以及无法解析时的处理，以引擎协议为准。不把历史资料中的资产名称当作本机实际拥有的素材。

## 修改与检查

局部改稿保留授权范围外的正文、版式和素材。内容表达变化不自动授权换图，换图也不自动授权重写正文。

检查时看手机预览中的层级、对齐、对比度、溢出和素材是否可见，同时核对 v2 解析与引用结果。视觉可读、语法通过和文章内容成立分别验证，不互相替代。
