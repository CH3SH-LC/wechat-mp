# 公众号推文组件化设计逻辑（design-logic-components）

> 定位：**全库顶层的"设计世界观"**。公众号推文不是"文字 + 图片"两样东西，而是由**组件**拼装而成——**组件 = 美术素材 + 文字的结合体**。理解组件化，才能理解排版系统（module 维度）为什么这样设计、素材库（ARTS）为什么按用途分桶、文案（copy 维度）为什么要预留排版位。
> 调用时机：**任何排版工作前先读本文件**（与 00-GUIDE 配合）；写模块条目、选素材、判断"这里该放什么"时都以组件思维作答。
> 依据：2026-08-29 调研（编辑器生态组件化实践：秀米"布局+背景+文字+边框+间距"五层拼装）+ 真实推文拆解。

---

## 一、核心概念：组件是什么

**组件 = 美术素材（容器/装饰）+ 文字（内容）的结合体**。组件是推文的最小可复用单元，一篇推文 = 一组组件的序列。

| 组件 | 美术素材部分 | 文字部分 |
|---|---|---|
| 小标题组件 | 夹线 / 徽章 / 分隔线 / 色带衬底 | 标题文字 |
| 气泡组件 | 边框 + 底色 + 角饰（`|grass` 等） | 一段话 |
| 带框图片组件 | 圆角边框 / 纸感描边 / 拱门花框 | 图注文字 |
| 卡片组件 | 底色 + 边框 + 顶条 | 标题栏 + 列表条目 |
| 列表组件 | 圆点 / 符号 + 底色 | 并列条目 |
| 步骤组件 | 数字圆步骤条 | 每步动词短语 |
| 结尾组件 | 关注条 / 二维码 / 横幅 | 引导文字 |

**三要素**：① 容器（形状/边框/底色/圆角）② 内容（文字/图片）③ 装饰（角饰/图案/点缀）。删掉任意一要素仍成立的叫"裸组件"（纯文字），三要素齐备是"完整组件"。

## 二、组件体系（类型清单）

| 大类 | 组件 | 说明 |
|---|---|---|
| **文字类** | 大标题 / 小标题 / 主副标题 / 段落 / 列表 / 引用金句 / 代码块 | 以文字为主体，素材做容器与装饰 |
| **结构类** | 卡片 / 气泡 / 步骤 / 时间线 / 表格 / FAQ / 清单勾选 | 归纳多个文字块的结构容器 |
| **图文类** | 裸图 / 带框图片 / 多图行 / 图卡 / 图文混排 | 图片为主体，边框与图注是素材 |
| **装饰类** | 分隔线 / 花纹色带 / 横幅 / 页眉 / 页脚 / 花边 | 以素材为主体，文字可有可无 |
| **功能类** | 目录 / 倒计时 / CTA 按钮 / 二维码 / 留言引导 / 小程序卡 | 引导行动，素材+短文字 |

> 与 module 维度对应：每个 `module-*.md` 条目就是一个组件类型（module-heading=小标题组件、module-bubble=气泡组件、module-card=卡片组件……）。

## 三、组件的组合逻辑（一篇推文怎么拼）

1. **选型**：内容类型（type 维度）→ 风格（style 维度）→ 按矩阵选组件（module-guide-matrix）；先定"这节用哪 2-3 种组件"，再写文字。
   - **组件美术资产的两个角度（2026-08-29 第 8 轮确立）**：**类型决定骨架、风格决定内容**——类型（如小标题）回答"组件怎么组织"，提供可复用的结构模板（7 种组合方式）；风格回答"组件里放什么内容"，提供图案词汇表填入模板的零件位（如序号徽章式小标题 + 阳光校园风 → 徽章内容为足球/篮球/网球）。素材生成 = 类型模板 × 风格词汇（详见 module-subheading 〇/二/三节）。
2. **节奏**：文字组件与视觉组件交替——每 300-500 字一个"强停靠"（小标题/图片/卡片）；避免连续 3 个同类组件（三个气泡连排=视觉单调）。
3. **一致**：同篇同类组件**同一样式**——一种卡片样式、一种标题样式（≤2 种）、同套圆角；组件样式是"账号语言"，乱换=没有设计。
4. **层级**：组件可嵌套——卡片内嵌列表、小标题下接正文、图片组件夹在两段文字之间；嵌套 ≤2 层，嵌套越多信息密度越高、越要克制装饰。
5. **起承转合**：开篇组件（页眉/引导图/首屏标题）→ 主体组件（3-8 组内容组件，组间用分隔/小标题过渡）→ 结尾组件（CTA/关注/二维码）。

**真实推文组件数量实测（2026-08-29，宣传/活动型）**：典型宣传类推文 **30–80 个组件**——标题组件 3–8 个、图片 10–30 张、样式化卡片/区块 20–60 个、SVG 交互 1–7 个、分割线 3–10 条、装饰元素 10–25 处；HTML 级实测一篇 5085 字宣传推文 = 58 图 + 25 背景图 + 530 样式区块 ≈ **每屏 4–6 个视觉元素**。组件总量是"模块化程度"的度量，不是"装饰过度"的度量——组件多但每组件克制 = 丰富；组件少却每组件堆砌 = 凌乱。详见 `research/2026-08-29-research-subheading.md` 附录。

## 四、素材与组件的生产关系

- **素材库 = 组件的"零件库"**：ARTS 资产按用途分桶（角饰/花框/分隔/横幅/徽章/插画/边框），一个组件往往由 1-2 个零件 + CSS 容器拼出。
- **素材是图片、文字是 HTML**：组件在生成 HTML 时拼装——`![夹线](art://clamp-line)` 是素材零件，标题文字是 inline 样式；转换器负责把两者落进同一个组件块。
- **组件模板 = 零件 + CSS 结构的预制组合**：素材库给零件，module 条目给拼法（语法/参数/骨架），两者合起来就是可复用的组件。
- **素材替换规则**：同一组件换素材 = 换皮肤（如小标题夹线换花边）；同一素材换文字 = 换内容。组件结构稳定、零件可换，这是组件化的红利。

## 五、组件化带来的判断准则

- 写文时：**先想组件，再想词句**——"这节是气泡组件还是卡片组件？"比"这句话怎么写"更优先（copy-layout 的【小标题】【列表】标记就是组件思维）。
- 排版时：**每个组件三要素齐备但装饰克制**——容器统一、内容清晰、装饰 ≤1 处/屏。
- 选素材时：**按组件用途选桶**——做小标题找徽章/夹线/分隔桶，做气泡找角饰桶，做图片框找花框桶（module-art-assets 目录）。
- 审稿时：**数组件不数字数**——一篇推文有没有"组件单调区"（连续 5 屏只有段落组件）比总字数更能预测完读率。
