# 列表（module-list）

> 定位：**列表 = 一个组件类型（type）**。本条目记录**这一类组件的生成方式**——6 种组合方式（骨架模板）分别怎么组织、零件位在哪、怎么按风格替换内容；以及"**类型 × 风格**"二维模型（风格决定内容）。列表是"把 3 条以上**平级、并列**的信息用标记排成清单"的组件，让读者一次性扫读、不遗漏、不费眼——几乎零装饰成本却瞬间建立"并列结构"，是回读率最高的排版之一。生成 art:// 列表资产时必读 **§五 5.0 整图资产构建规范**（整组 750×200 / 衬底强调式单条 750×100 / PNG ≤1MB / 三层验证闭环）。
> 调用时机：并列要点、清单、特点、注意事项、可选项**多于 3 条**时。**黄金规则：>3 条用列表，≤3 条用分栏**（见「模块 · 卡片」的分栏变体）。列表只装"平级信息"，有层级、有因果的要用段落、步骤条或时间线。每个列表出现前必须是引出句或小标题，否则读者不知道这串符号在讲哪件事。**生成/改造列表时**：先定组合方式（类型），再按风格填充内容（标记图案/色板）；不是"从变体清单里挑一个"。
> 素材来源：真实知识库 module-list（6 变体 A-F 参数：标记 6px、行高 1.75、衬底 padding 8px 12px、ol padding-left 20px、色号 #ff6b35/#333/#555/#999/#fff7f2/#ffe0d0/#2777ff）+ 第 9 轮类型×风格模型（2026-08-29，与 module-bubble 同构）。

## 〇、核心模型：类型 × 风格（2026-08-29 第 9 轮确立）

**列表组件的美术资产由 2 个角度决定：类型（type）和风格（style）。**

| 角度 | 回答什么问题 | 在列表上的体现 |
|---|---|---|
| **类型（type）** | 组件**怎么组织**（结构骨架）——这类组件怎么构建 | 列表类型下有 **6 种组合方式**（圆点式/菱形引导式/编号式/衬底强调式/分组小标题式/品牌单色式） |
| **风格（style）** | 组件里**放什么内容**（零件填充） | 同一种组合方式配不同风格 = 标记图案与色板不同（圆点 / 草叶 / 球类 / 星星……） |

**两条核心关系**：
1. **类型决定骨架**：同一类型的所有列表共享结构。例如"圆点式"= 单个 `<p>`（块距 16px + 行高 1.75）+ 行首标记位 + 条目文字槽 + `<br/>` 换行，无论什么风格，骨架不变。
2. **风格决定内容**：骨架不动，内容图案随风格替换。**例如：圆点式 + 阳光校园风 → 标记圆点换成迷你球类/星星（迷你足球/篮球/网球或五角星）**；配自然田园风 → 标记是草叶；配品牌克制风 → 标记固定一枚品牌色。

**知识库应该记录什么**：记录**类型的生成方式**（骨架怎么搭、零件位在哪、怎么按风格替换内容），而不是一份"现成列表样式清单"。清单只是某个默认风格下的实现示例（见 §四）。

> 与 design-logic-components 的关系：组件 = 美术素材 + 文字；素材维度 = 类型 × 风格——类型管骨架（可复用结构），风格管内容（可替换零件）。列表的"美术素材"主要来自 **CSS 几何形状 span 标记 + 衬底**（art:// 图案仅在复杂标记时使用）：列表是**代码骨架组件**，素材只占零件位，与小标题的整图资产不同。

## 一、构建总则（列表类型怎么生成）

### 1.1 6 种组合方式（类型的子类）

| # | 组合方式 | 一句话结构 | 典型用途 |
|---|---|---|---|
| 1 | **圆点式** | 单 `<p>` + 行首实心圆点 span + 逐条 `<br/>` | 并列无顺序的通用列表 |
| 2 | **菱形引导式** | 单 `<p>` + 旋转 45° 方块 span + 逐条 `<br/>` | "先…再…最后"行动引导 |
| 3 | **编号式** | `<ol>` 自带数字 + `padding-left:20px` | 有先后顺序/计数 |
| 4 | **衬底强调式** | 每条整行浅色底 + 细边框 + 圆点标记 | 卖点/权益清单（宣传类） |
| 5 | **分组小标题式** | 小标题 + 组内全角空格同行排多条 | 信息分层、≥6 条 |
| 6 | **品牌单色式** | 同圆点式骨架 + 标记固定一枚品牌色 | 品牌克制风 |

### 1.2 构建五步（生成方式总流程）

1. **定组合方式**：按文体与内容选 1 种（双模式同篇只选其一：文字类全圆点灰/深灰、宣传类全菱形或衬底）。
2. **搭骨架**：按 §二 对应模板搭容器与零件位（先只画结构，不填内容）——标记位 + 衬底位（如有）+ 条目文字槽。
3. **按风格填内容**：查风格条目（style-* / index-style）得到该风格的**图案词汇表**（标记图案 + 色板），填入零件位（§三）。
4. **填字与排版**：引出句（冒号结尾）→ 逐条填字（每条 ≤1 行、结构一致：全名词或全动词或全判断短句）；间距按 6px 层级收紧、行高 1.75。
5. **验证**：375px 壳实测——密度铁律（>3 条才用、≤7 条/组、一篇 2-3 组）、对比度 ≥4.5:1、微信兼容检查（§五）。

### 1.3 通用约束（先读，违反即返工）

- **黄金规则**：**>3 条才用列表，≤3 条用分栏**（见「模块 · 卡片」分栏变体）；先数条数再决定用不用列表。
- **一组 ≤7 条**：超过 7 条读者就看不过来，拆成"核心—扩展"两组、或分组带小标题（⑤）。
- **一条 ≤1 行**：能在一行内扫完最好；超过就压缩措辞或拆成两张列表，别让单条膨胀成一段、拖慢整组节奏。
- **结构一致**：每条要么都是"名词短语"、要么都是"动词短语"、要么都是"判断短句"；每条首字尽量同词性对齐（扫读第一列即抓住规律）。
- **列表前必有引出句或小标题**："它的三个亮点是：""使用前请注意：""下单前确认如下几点"——列表绝不凭空出现，孤零零一列标记等于让读者猜"这串在讲哪件事"。
- **先想清是否真并列**：有主次关系、有因果推理、有包含关系的内容硬排成列表就是"列表滥用"，用段落、步骤条或时间线。
- **零 emoji/零图标字符铁律**：标记必须是**可绘制的图形**（CSS 几何 span：实心圆点/旋转 45° 方块，或 art:// 植物图案），字符图标永不进入列表。
- **对比度铁律**：标记色/衬底色与文字对比度 ≥4.5:1；浅底配深字最稳。
- **微信兼容**：标记用 CSS 形状 span **而非伪元素**（`::before` 大多被剥除）；`<ol>` 自带数字；`<br/>` 逐条换行；禁 emoji/Unicode 图标字符；禁 `display:flex` 复杂对齐。

**标记契约——三种标记规格表（选标记速查）**：

| 标记 | 中文名 | 实现（CSS span） | 表达的情绪 | 一句话区分 |
|---|---|---|---|---|
| 圆点 | 并列标记 | 实心圆 6px + `border-radius:50%` + 主色/灰 | 中性、列举 | "停在这里一起看"，纯并列 |
| 菱形 | 引导标记 | 旋转 45° 方块 6px + 主色 | 行动感、引导 | "跟我往下一步"，先…再… |
| 编号 | 顺序标记 | `<ol>` 自带数字 + `padding-left:20px` | 顺序、计数 | "按数来、别漏"，有先后 |

选标记不光看"有没有序号"，更要看想让读者怎么读：圆点是"停在这里一起看"，菱形是"跟我往下一步"，编号是"按数来、别漏"。标记契约是"全篇统一"：并列=圆点、引导=菱形、计数=编号，三种混着写 = 清单结构是乱的。风格替换只换标记的**图案内容**（草叶/球类/星星），不换形状语义（圆=并列、菱=引导、数字=顺序）。

## 二、6 种组合方式的构建模板（核心：这类组件怎么构建）

> 每个模板给出：**骨架结构**（元素清单与位置）、**零件位**（可替换槽）、**尺寸与间距规范**、**叠字方式**（条目文字排布）、**风格可变内容**、**默认实现**（当前库中已完成的一个风格版本）。

### ① 圆点式

- **骨架**（单块级容器）：单个 `<p>`（`margin:0 0 16px;line-height:1.75;font-size:14px;color:#333`）→ 每条 = 行首标记位（实心圆点 span，`display:inline-block`）→ 条目文字 → `<br/>` 换行。
- **零件位**：A. **标记图案**（6px 实心圆点/CSS 几何→风格词汇可换，或 art:// 植物图案）B. 衬底（无，本式不加衬底）C. 条目文字槽（每条 ≤1 行、结构一致）。
- **尺寸**：标记 `width:6px;height:6px;border-radius:50%`；正文字号 14px；行高 1.75；整组 `margin:0 0 16px`；条目间不额外加 margin（靠行高自然隔开）。
- **叠字**：标记为行内 span 前置（`margin-right:6px` 或一个空格）→ 条目文字 → `<br/>` 逐条换行；一条一行。
- **风格可变内容**：**标记图案**（圆点→草叶/球类/星星，见 §三）+ 标记颜色（主色橙 `#ff6b35` / 灰 `#999` / 品牌色）。
- **默认实现**：变体 A（`#ff6b35` 橙实心圆点 6px、`border-radius:50%`；正文 14px、行高 1.75、块距 16px；文字类可把圆点换成灰 `#999`，克制到极）。判断：纯并列、无顺序、无引导需求才用圆点。

### ② 菱形引导式

- **骨架**：同①单 `<p>` 骨架，标记换**旋转 45° 方块** span（拼出菱形）。
- **零件位**：A. **标记图案**（6px 方块 `transform:rotate(45deg)`→风格词汇可换）B. 衬底（无）C. 条目文字槽（动词短语，如"先做…再定…最后…"）。
- **尺寸**：标记 `width:6px;height:6px;transform:rotate(45deg)`；其余同①（14px、行高 1.75、块距 16px）。
- **叠字**：菱形 span 前置 → 条目文字 → `<br/>` 换行；一条一行。
- **风格可变内容**：标记图案/颜色（主色填充表达"指向/递进"）。
- **默认实现**：变体 B（`#ff6b35` 旋转 45° 菱形 6px、主色填充、行高 1.75；引导序列"先…再…最后"）。判断：想带读者一步步往下走、有"先…再…"就用菱形；需要严格计数就换③编号式。

### ③ 编号式

- **骨架**：`<ol style="margin:0 0 16px;padding-left:20px;line-height:1.75;">` → 每条一个 `<li style="font-size:14px;color:#333;">条目</li>`。
- **零件位**：A. **数字标记**（`<ol>` 自带，非手敲文字）B. 衬底（无）C. 条目文字槽。
- **尺寸**：`padding-left:20px`（给编号留位，**硬规范**）；行高 1.75；字号 14px；块距 16px。
- **叠字**：`<ol>` 自带换行，逐条 `<li>`；编号与文字由浏览器排布，无需手动标记。
- **风格可变内容**：条目文字（保持顺序语义）+ 颜色（深灰 `#333`）。
- **默认实现**：变体 C（`<ol>` 自带数字编号、`padding-left:20px` 硬规范；行高 1.75、字号 14px）。判断：真正有先后顺序、要计数才用；**别用手敲 "1. 2. 3." 文字**（换行时续号不受控、行首数字字体不受控）。

### ④ 衬底强调式

- **骨架**（块级容器）：`<section style="margin:0 0 16px;">` → 每条一个 `<p>`（浅色底 + 细边框 + 圆角 + padding + 行首圆点标记）→ 条目间 8px。
- **零件位**：A. **标记图案**（主色实心圆点 6px）B. **衬底**（极浅色 `#fff7f2` + 细边框 `1px solid #ffe0d0`；深浅随宣传强度可换到主色正衬底）C. 条目文字槽。
- **尺寸**：每条 `background:#fff7f2;border:1px solid #ffe0d0;border-radius:6px;padding:8px 12px`（padding **8px 12px 硬规范**）；条目间 `margin:0 0 8px`；字号 14px、行高 1.75。
- **叠字**：圆点标记 span 前置 → 条目文字（一条一行）；每条自成衬底块，逐条醒目地"跳"出来。
- **风格可变内容**：衬底深浅（极浅 `#fff7f2` → 主色正衬底）+ 标记图案 + 色板（底取主色极浅）。
- **默认实现**：变体 D（橙系极浅 `#fff7f2` + 细边框 `#ffe0d0`、圆角 6px、**padding 8px 12px**、条目间 8px、主色 `#ff6b35` 圆点 6px、行高 1.75）。判断：卖点/权益要读者逐条点头认可才加衬底；普通列举不加。

### ⑤ 分组小标题式

- **骨架**（块级容器）：`<section style="margin:0 0 16px;">` → 小标题 `<p>`（14px 加粗）→ 条目 `<p>`（组内多条同行，全角空格 `　` 分隔）。
- **零件位**：A. **标记图案**（主色实心圆点 6px）B. 衬底（无，靠分组建立层次）C. 条目文字槽 + 小标题文字槽。
- **尺寸**：小标题 14px `font-weight:600;color:#333`；条目 14px 灰 `#555`；组间 `margin:0 0 8px`；行高 1.75。
- **叠字**：小标题一行；条目组内用全角空格 `　` 在同一行排多条（最省屏），也可逐条换行（更好读）。
- **风格可变内容**：小标题样式、标记、色板。
- **默认实现**：变体 E（"核心功能"+"增值服务"两组：小标题 14px 加粗、条目 14px 灰 `#555`、主色 `#ff6b35` 圆点 6px、行高 1.75）。判断：清单 ≥6 条或信息有自然"核心—扩展"分层才分组，没有就保持一条干净清单。

### ⑥ 品牌单色式

- **骨架**：同①圆点式单 `<p>` 骨架，标记**固定一枚品牌色**贯穿全篇。
- **零件位**：A. **标记图案**（品牌色实心圆点 6px，唯一一枚色）B. 衬底（无）C. 条目文字槽（深灰正文）。
- **尺寸**：同①（14px、行高 1.75、块距 16px）；标记 `background:品牌主色`（示例 `#2777ff`）。
- **叠字**：同①，标记前置、逐条 `<br/>` 换行。
- **风格可变内容**：品牌色（换品牌 = 换整套标记色）。
- **默认实现**：变体 F（`#2777ff` 品牌蓝实心圆点 6px、正文深灰、行高 1.75，全篇列表一套色）。判断：品牌色够不够撑起"举例—重点"的区分——够就用，最专业也最省心；只能挤出一个色就退回"灰圆点 + 主色仅重点标粗"。

## 三、风格如何决定内容（填充规则）

1. **风格条目 → 图案词汇表**：每个风格条目（style-*，见 index-style）应提供该风格的**图案词汇表**（如：阳光校园风 = 迷你球类/星星/跑道/奖杯；自然田园风 = 草叶/花枝/果实；电商促销风 = 主推橙/草叶"限时权益"；科技风 = 品牌冷蓝/几何）。
2. **填入零件位**：把词汇表中的图案绘制为 CSS 几何 span 或 SVG 图形，填入 §二 对应模板的"风格可变内容"零件位——骨架（容器/标记位/衬底位/文字槽）保持不变，只换内容。
3. **列表是代码骨架组件（关键）**：标记优先 CSS 几何 span（实心圆点/旋转 45° 方块/`<ol>` 数字）——最稳、微信兼容最好；**复杂标记才走 art:// 资产**（如 `![草叶](art://sprig-grass)` 标记"限时权益"），整组列表通常无需任何图片资产。
4. **图案必须是可绘制图形**：迷你足球/篮球/网球/星星是**具体图形**（可用圆形+线缝弧线/五角星路径绘制），不是 emoji/字符图标——符合 v10 铁律（禁 emoji/图标字符，但允许具体器物图形）。
5. **颜色随风格**：标记色/衬底色从全篇色盘取——主色标记 + 主色极浅衬底；同篇颜色 ≤2 个主色，其余交给灰与深灰的层次（颜色越少越像"编辑过的定稿"）。
6. **验证**：生成后按 §五 铁律实测（375px 壳、对比度 ≥4.5:1、密度），并登记 REQUIREMENTS（先记录后开发）。

> 示例：**圆点式 + 阳光校园风**——骨架：单 `<p>` + 行首标记位 + 条目文字槽 + `<br/>` 换行；内容：标记①=迷你足球（圆形+五边形缝线）、标记②=迷你篮球（圆形+曲线缝线）、标记③=迷你星星（五角星路径）；色板：校徽橙/球场绿；条目文字与结构（每条 ≤1 行、结构一致）不变。复杂标记（球类/星星）用 art:// 资产或 CSS 绘制，简单圆点/菱形仍用 CSS span 拼。

## 五、构建验证与铁律（生成任何列表必须满足）

### 5.0 整图资产构建规范（生成 art:// 列表资产时必须满足，2026-08-29 第 9 轮·与气泡同构）

> 列表是**代码骨架组件**：标记以 CSS span 拼为主，**整图资产仅用于复杂标记（植物图案等）或"衬底强调式单条"**，整组列表通常无需整图；确需整图（如装饰性列表底图）时按以下规范。子智能体首轮失败根因（与气泡同源）：嵌字区高度只留一条，装不下多行条目；水平背景渐变致 PNG 超 1MB；只验"zone 内无装饰"未验"zone 装得下文字"。以下为强制规范：

1. **画布规格（默认）**：整组列表 **750×200**（375px 壳显示 343×91px，缩放比 ≈0.457），纵向容纳 5 条（每条一行 + 条目间距）；**zone 设计高 ≥140px**（含每条一行 + 间距，5 条以内）。衬底强调式单条按 **750×100**（单条衬底 + padding 8px 12px + 单行文字，显示 343×46px）。标记装饰贴左、随行居中，文字区整体右移留出标记位。
2. **文字区容量（核心，首轮失败点）**：zone 必须装下"每条 14px + 条目间距"。**整图嵌字行高（关键，2026-08-29 实测修正）**：整图资产内叠字必须用**紧凑行高 1.2-1.4**（每行 14px × 1.3 ≈ 18.2px 显示 ≈ 40px 设计），否则 5 行文字会溢出 zone——CSS 骨架版仍用行高 1.75（见 §二），整图版用紧凑行高。**zone 每行设计高 ≥40px**；整组 5 行总设计高 ≥200px（行距 40px：`y0=10+i*40, y1=50+i*40`）。衬底强调式单条 = 单行文字 + 上下 padding（8px×2）。**文案长度约束（375px 壳实测前提）**：每条 ≤1 行（14px 一行 ≈22 字），超长条目换行越界 = 不合格；整组 ≤5 条、超数拆分。375px 壳叠字实测用此长度的真实文案（行高 1.3）。
3. **PNG 体积铁律**：4x 渲染后 **≤1MB**（uploadimg 硬限）。列表为纯色平面化（零渐变铁律），无大面积渐变场景；确需渐变背景时**必须用垂直方向**（水平渐变在 750px 宽的每一行都是不同像素，PNG 熵爆炸），渐变仍用 `gradientUnits="userSpaceOnUse"` + 绝对坐标。
4. **zone 字段**：每个资产必须带 `zone`（单条 `{x0,y0,x1,y1}` 设计坐标；整组可用数组按条标注），标注文字安全区。
5. **验证闭环（三层，缺一不可）**：
   - ① 资产级：渲染 4x PNG + probe 像素验证（落纯色部件，容差 ±12）+ 体积 ≤1MB；
   - ② zone 洁净度：相邻像素突变扫描（zone 区域逐行扫，相邻像素 RGB 差之和 >40 计数，突变 >12 的行必须为 0 或只在 zone 外）；
   - ③ **375px 壳叠字实测**（首轮缺失项）：把真实文案（引出句 + 逐条条目）按 zone 缩放后叠入图片，DOM 检查文字边界全部落在 zone 矩形内（getBoundingClientRect 对比），**10/10 全部通过才算完成**。整组 5 条、衬底强调式单条都要实测。

### 5.1 通用铁律（继承 §一/§三）

- **密度铁律**：**>3 条才用列表，≤3 条用分栏**；**一组 ≤7 条**（超过拆"核心—扩展"两组或分组带小标题）；一篇通常 **2-3 组列表**足够。
- **文字铁律**：一条 ≤1 行；结构一致（全名词/全动词/全判断短句）；首字同词性对齐。
- **引出句铁律**：列表前必有引出句或小标题（"它的三个亮点是：""使用前请注意："），冒号结尾；列表后若有解释用普通正文收口，别让列表孤零零悬在文末。
- **标记契约铁律**：圆点=并列、菱形=引导、编号=顺序；选定后全篇统一，三种不混用。
- **对比度铁律**：标记色/衬底色与文字对比度 ≥4.5:1；浅底配深字最稳。
- **零 emoji/零图标字符铁律**：标记必须是 CSS 几何 span（实心圆点/旋转 45° 方块）或 art:// 可绘制图形。
- **微信兼容铁律**：标记用 CSS 形状 span **非伪元素**（`::before` 大多被剥除）；不用 `<ul>/<li>` 默认黑点；`<ol>` 自带数字 + `padding-left:20px`；`<br/>` 逐条换行；禁 emoji/Unicode 图标字符；禁 `display:flex` 复杂对齐；衬底写纯色浅底 + 细边框，不写渐变。
- **双模式铁律**：文字类全文灰圆点（克制列举）、宣传类全文主色菱形 + 衬底（逐条亮出），一篇只选其一——不要一半圆点一半衬底，混用等于让读者以为"圆点和衬底是两种不同层级"，破坏一致性。
- **不叠铁律**：列表不叠列表（一项里再缩进子列表破坏并列语义，有层级的用段落/步骤条/时间线）；一屏已有花纹色带 + 大字号标题 + 衬底列表，就别再叠气泡（气泡 ≤2、徽章 ≤3）。
- **验证方式**：375px 壳截图自查（一眼分清标记/条目/正文）；改参后整段截图到手机看一屏。

## 六、示例（骨架，markdown 用法）

```markdown
- 多账号切换管理
- 排版模板一键套用
```
（文字类默认圆点式。**可替换**：条目、标记样式——圆点 span / 菱形 span / 编号按语义换。）

```html
<p style="margin:0 0 16px;line-height:1.75;font-size:14px;color:#333;">
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 先做需求清单<br/>
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 再定风格选型<br/>
  <span style="display:inline-block;width:6px;height:6px;transform:rotate(45deg);background:#ff6b35;"></span> 最后套用模块排版
</p>
```
**可替换处**：菱形/圆点/编号标记、标记颜色、条目文字（保持结构一致、每条 ≤1 行）、是否加衬底（宣传类用④衬底强调式）。判断依据：>3 条并列才用列表；有顺序用编号或菱形、纯并列用圆点；想要一条条"亮出来"就加浅色衬底。


## 七、常见错误

- **反例**："优点：功能多。价格也不贵。然后客服还挺好的。界面好看点。"（句式参差、结构不一致）**正解**：统一为名词短语或判断短句——"功能全面、价格亲民、客服响应快、界面清爽"。
- **反例**：信息只有 2 条却用列表。**正解**：2 条用分栏卡或其他处理；列表是"3 条以上"的机制，2 条成行罗列纯属浪费屏（黄金规则 >3 条用列表、≤3 条用分栏）。
- **反例**：把有因果、有层级的内容硬做成列表（"第 1 步；而第 1 步是因为……"）。**正解**：有逻辑关系的用段落、步骤条或时间线，列表只装"并列"。
- **反例**：列表没有引出句，正文直接蹦出一个符号清单。**正解**：列表前加"它的三个亮点是""使用前请注意"或居中小标题，让读者先知道这清单在讲什么再逐条看。
- **反例**：一段 12 条的巨长列表，一屏装不下、滑都滑不完。**正解**：砍到 5-7 条，或按"核心—扩展"拆成两组带小标题的列表（⑤分组小标题式）。
- **反例**：标记乱用——这一组用圆点、下一条变菱形，计数项又用圆点。**正解**：同一列表用同一标记，全篇"并列=圆点、引导=菱形、计数=编号"的标记契约保持一致。
- **反例（类型×风格新）**：想换风格时改骨架——把圆点式改成衬底强调式（"换个风格"）。**正解**：换风格只换零件（标记图案/色板/衬底深浅），换骨架是换组合方式；组合方式按文体选（文字类圆点、宣传类菱形+衬底），风格按账号选。
- **反例（类型×风格新）**：风格词汇用 emoji/字符图标（⭐🔹🏀 直接贴进列表）。**正解**：标记必须 CSS 几何 span 或 art:// 可绘制图形（球类/星星绘制成具体图形），字符图标永不进入列表。
- **反例（类型×风格新）**：每种风格换一套标记（校园用星星、国潮用印章、科技用三角），读者认不出"这是列表"。**正解**：全篇一种组合方式贯穿（按文体定），风格只换内容零件——标记契约（圆=并列/菱=引导/数字=顺序）比换花样重要。
- **反例（整图资产·首轮实测失败）**：给代码骨架组件强行做整图列表底图，把 CSS 能拼的 6px 圆点做成图片资产，或嵌字区高度只留一条、装不下 5 行条目。**正解**：标记优先 CSS span，仅复杂标记（草叶/球类）或衬底强调式单条走 art://；整组列表画布 750×200、zone 设计高 ≥140px，见 §五 5.0。

## 八、个性化空间

- **标记选择**：圆点（中性并列）/菱形（递进行动）/编号（顺序计数）。判断依据：信息有无顺序与引导需求——纯列举用圆点、引导"先…再…"用菱形、计数用编号；全篇按此契约统一。
- **标记颜色**：正文灰 `#999` / 品牌主色。判断依据：想让标记"指引重点"就用主色（宣传），想安静克制就用灰（文字）。
- **是否加衬底**：整行浅色底适合"权益/卖点"类要逐条打卡认可的内容。判断依据：这几条是不是读者最看重、需要逐条点头的信息——是才加衬底，普通列举不加；衬底深浅随宣传强度（极浅 `#fff7f2` → 主色正衬底）。
- **条目在行内还是衬底**：行内靠行高隔开最省屏；衬底成块最醒目但最占屏。判断依据：信息量 vs 强调强度，普通清单用行内、重点权益用衬底。
- **条目长度**：1 行内 or 允许 1-2 行。判断依据：复杂名词可放 1-2 行，琐碎短句压到 1 行；超过一行就压缩措辞。
- **是否分组带小标题**：清单 ≥6 条 / 信息要分两档时才带小标题（⑤）。判断依据：清单有没有自然的"核心—扩展"分层，有才分，没有就保持一条干净清单。
- **列表在行内还是整段**：同一行用全角空格 `　` 排多条（最省屏）还是换行逐条（更好读）。判断依据：一扫而过的短清单还是逐条核对的要点，前者同行、后者换行。
- **列表出现次数**：一篇 2-3 组足矣。判断依据：列表越多阅读节奏越碎，干货密集处才上列表，叙述段落保持段落。
- **风格扩展方向**：阳光校园（迷你球类/星星标记）、自然田园（草叶 `![草叶](art://sprig-grass)`）、电商促销（衬底强调式 + 草叶"限时权益"）、教育干货（菱形 + 每条首字加粗）、科技（品牌冷蓝 + 参数条目对齐）——每种风格 = 一套图案词汇表填入 6 种模板的零件位，先调研再入库（REQUIREMENTS.md 登记）。
