# 卡片（module-card）

> 定位：**卡片 = 一个组件类型（type）**。本条目记录**这一类组件的生成方式**——5 种组合方式（骨架模板）分别怎么组织、零件位在哪、怎么按风格替换内容；以及"**类型 × 风格**"二维模型（风格决定内容）。卡片是"归纳容器"，把 3 条以上并列的关联信息"收进一个框里"，让读者把这一块当一个整体来看——**不是装饰**。生成 art:// 卡片底图资产时必读 **§五 5.0 整图资产构建规范**（画布 750×240 / zone 容量 / PNG ≤1MB / 三层验证闭环）。
> 调用时机：**3 条以上并列项**、产品参数、对比、小标题下的多要点需要归拢成"一块"时。**生成/改造卡片时**：先定组合方式（类型），再按风格填充内容（顶条图案/标题装饰/色板）；不是"从变体清单里挑一个"。一篇只用一个卡片样式（白卡/浅底/实色顶条/双线/分栏，选一），这是卡片模块的铁律。
> 素材来源：真实知识库 module-card（5 变体 A-E 参数：色号/圆角/padding/字号 100% 迁移）+ 第 9 轮类型×风格模型。

---

## 〇、核心模型：类型 × 风格（2026-08-29 第 9 轮确立）

**卡片组件的美术资产由 2 个角度决定：类型（type）和风格（style）。**

| 角度 | 回答什么问题 | 在卡片上的体现 |
|---|---|---|
| **类型（type）** | 组件**怎么组织**（结构骨架）——这类资产怎么构建 | 卡片类型下有 **5 种组合方式**（白卡细边框式/浅底圆角式/实色顶条式/双线角块式/分栏卡式） |
| **风格（style）** | 组件里**放什么内容**（零件填充） | 同一种组合方式配不同风格 = 顶条/标题装饰的图案与色板不同（球类 / 印章 / 几何……） |

**两条核心关系**：
1. **类型决定骨架**：同一类型的所有卡片共享结构。例如"实色顶条式"= 外层白卡容器（白底 + 细边框 + 圆角 + `overflow:hidden`）+ 顶部实色条 + 标题槽 + 条目槽，无论什么风格，骨架不变。
2. **风格决定内容**：骨架不动，内容图案随风格替换。**例如：白卡细边框式 + 阳光校园风 → 顶条换成球类图案、标题竖条换成小奖杯**；配国潮风 → 标题装饰是印章竖条、边框换朱砂红、底换米白；配科技风 → 底色换冷蓝、装饰是几何网格。

**知识库应该记录什么**：记录**类型的生成方式**（骨架怎么搭、零件位在哪、怎么按风格替换内容），而不是一份"现成卡片样式清单"。清单只是某个默认风格下的实现示例（见 §四）。

> 与 design-logic-components 的关系：组件 = 美术素材 + 文字；素材维度 = 类型 × 风格——类型管骨架（可复用结构），风格管内容（可替换零件）。卡片的"美术素材"主要来自 **CSS 容器 + 顶条/标题装饰零件**（art:// 图案或 CSS 几何），与气泡同为**代码骨架组件**，素材只占零件位；需要复杂装饰（顶条图案/标题图案）时才走整图资产（§五 5.0）。

## 一、构建总则（卡片类型怎么生成）

### 1.1 5 种组合方式（类型的子类）

| # | 组合方式 | 一句话结构 | 典型用途 |
|---|---|---|---|
| 1 | **白卡细边框式** | 白底容器 + 细边框 + 标题槽 + 条目槽 | 文字类默认，一切信息归纳，兼容性最好 |
| 2 | **浅底圆角式** | 极浅底色容器（无边框无投影）+ 标题槽 + 内容槽 | 想让这块"有底色地浮起来"，不靠边框 |
| 3 | **实色顶条式** | 外层白卡 + 顶部实色条 + 标题槽 + 条目槽 | 宣传类推荐项突出、三选一推荐/主推套餐 |
| 4 | **双线角块式** | 较深细边框容器 + 标题槽 + 说明槽 | 规则、注意事项、明细（强调边界） |
| 5 | **分栏卡式** | `<table>` 两列/三列 + 每格一个卡容器 | 两两对比、横向并列特征 |

### 1.2 构建五步（生成方式总流程）

1. **定组合方式**：按文体与内容选 1 种（双模式同篇只选其一：文字类全白卡细边/浅底、宣传类全实色顶条/彩色点缀）。
2. **搭骨架**：按 §二 对应模板搭容器与零件位（先只画结构，不填内容）——容器（底/边/圆角）+ 顶条或边框 + 标题槽 + 条目槽。
3. **按风格填内容**：查风格条目（style-* / index-style）得到该风格的**图案词汇表**（顶条图案 + 标题装饰 + 色板），填入零件位（§三）。
4. **填字与排版**：标题放标题槽（首行加粗）、条目逐行放条目槽（`·` 前缀）；间距按 6px 层级收紧（标题与首条 10px、条目间 6-8px）；行高 1.75。
5. **验证**：375px 壳实测——密度铁律（一篇 3-5 张、一种样式到底）、对比度 ≥4.5:1、微信兼容检查（§五）。

### 1.3 通用约束（先读，违反即返工）

- **一卡一主题**：同一张卡内并列项**性质要一致**——都是优点、或都是参数、或都是注意点，别把"优点 + 注意事项"混进同一张卡。
- **卡内要有标题 + 至少 2-3 条内容**才配叫"归纳容器"；只有一个标题下面空空的是空架子。只有一句话是气泡的活，不是卡片。
- **密度铁律**：一篇 **3-5 张**足够，别把全文装进卡里；**一种样式到底**（白卡/浅底/实色顶条/双线/分栏选一，三种混用 = 灾难）；**卡片不嵌套卡片**（双层可接受，三层以上手机挤到没法读）；**卡片不叠加气泡**（同屏一个亮块就好）。
- **卡内密度**：条目 **3-5 条**（≥6 条拆两张卡或改用「模块 · 表格」）；卡内字号 ≤15px，不出现 17px+ 大字。
- **零 emoji/零图标字符铁律**：顶条/标题装饰必须**可绘制的图形**（CSS 几何 span 或 art:// 图案），字符图标永不进入卡片。
- **对比度铁律**：卡内文字与底色对比度 ≥4.5:1；浅底配深字、实色顶条配白字最稳。
- **微信兼容**：纯色底 + 细边框最稳；禁投影/渐变/backdrop-filter/伪元素/outline/border-image/float/grid；分栏必须 `<table>` + `<td style="box-sizing:border-box">`；实色顶条卡外层 `overflow:hidden` 让顶条圆角贴合。
- **双模式铁律**：文字类全文白卡细边框或浅底、宣传类全文实色顶条或彩色点缀，一篇只选其一——混用等于让读者以为"细框和顶条是两种不同语义"。
- **同组圆角统一**：8/10/12/14px 由风格软硬决定，一张卡一个圆角、同组统一；圆角不超过内容高度的一半。

## 二、5 种组合方式的构建模板（核心：这类组件怎么构建）

> 每个模板给出：**骨架结构**（元素清单与位置）、**零件位**（可替换槽 A-D）、**尺寸与间距规范**、**叠字方式**（卡片内文字排布：标题栏 + 条目）、**风格可变内容**、**默认实现**（当前库中已完成的一个风格版本，参数 = 原变体 A-E 原值）。
>
> **卡片统一零件位（A-D 可替换槽）**：A. **容器**（边框/底色/圆角）B. **顶条**（有无 + 图案）C. **标题装饰**（竖条/几何/art 图案）D. **条目文字槽**（3-5 条）。所有卡片硬规范：外间距下方 `margin:0 0 16px`、内文行高 1.75、卡内文 padding `14px 16px 12px`（除非该模板另有说明）。

### ① 白卡细边框式

- **骨架**（块级容器）：白底容器（`background:#fff` + `border:1px solid #f0f0f0` + 圆角 12px）→ 标题槽（首行）→ 条目槽（逐行 `·` 前缀）。
- **零件位**：A. **容器**（白底 #fff、边框色 #f0f0f0、圆角 12px）B. 顶条（默认无；风格需要时加实色细条，见③骨架）C. **标题装饰**（默认无；可加左竖条 `border-left:3px solid 主色` 或 CSS 几何/art 图案前缀）D. **条目文字槽**（3-5 条）。
- **尺寸**：padding `14px 16px 12px`；圆角 12px；卡标题 15px 加粗 `#333`（行高 1.5）；条目 14px `#555`（行高 1.75）；标题与首条间距 10px、条目间 6px。想更"立"可加深描边 `border:1px solid #e0e0e0`，不靠投影。
- **叠字**：标题栏（首行加粗）→ 条目逐行（`·` 前缀，最后一条 `margin:0`）。
- **风格可变内容**：边框色/底色（风格色板）+ **标题装饰**（竖条/几何/art 图案）+ 顶条图案（风格词汇）。
- **默认实现**：变体 A（`#fff` 底 + `#f0f0f0` 细边 + 圆角 12px + `14px 16px 12px`，文字类默认最稳）。

### ② 浅底圆角式

- **骨架**（块级容器）：极浅底色容器（`background:#f7f9fc` + 圆角 12px，无边框无投影）→ 标题槽 → 内容槽。
- **零件位**：A. **容器**（浅底色 + 圆角）B. 顶条（可选，同色系加深档）C. **标题装饰**（可选，竖条/几何）D. **条目文字槽**（3-5 条）。
- **尺寸**：底色 `#f7f9fc` 极浅灰蓝；圆角 12px；padding `16px 16px 12px`；卡标题 15px 加粗 `#2c3e50`（行高 1.5）；正文 14px `#4a5a6a`（行高 1.75）。底色越浅越安静，越接近主色越醒目（换色见 §三 风格色板）。
- **叠字**：标题栏 → 条目/说明段落。
- **风格可变内容**：底色深浅（靠色成块的"柔和"感）+ 标题装饰。
- **默认实现**：变体 B（`#f7f9fc` 极浅灰蓝，靠底色成块，不靠边框）。

### ③ 实色顶条式

- **骨架**（块级容器 + 内层条）：外层白卡（`background:#fff` + `border:1px solid #f0f0f0` + 圆角 12px + `overflow:hidden`）→ **顶部实色条**（零件位，`background:主色` + 白字标题）→ 内容区（`padding:14px 16px 12px`，条目槽）。
- **零件位**：A. **容器**（白底 + 细边框 + 圆角 + overflow:hidden）B. **顶条**（实色块 + 白字，风格词汇可换图案/主色）C. 标题装饰（顶条内白字标题即标题槽，可加小图案前缀）D. **条目文字槽**（3-5 条）。
- **尺寸**：外层 `#fff` + `border:1px solid #f0f0f0` + 圆角 12px；顶条 `background:#e56b2f`、padding `10px 16px`、白字 15px 加粗（行高 1.5）；内容区 padding `14px 16px 12px`；条目 14px `#555`（行高 1.75）、间距 6px。顶条是整张卡最醒目的"抬板"。
- **叠字**：顶条标题（白字加粗）→ 条目逐行。
- **风格可变内容**：**顶条图案/主色**（球类/印章/几何 → 风格词汇）+ 顶条有无（只在"我要你选这个"时加）。
- **默认实现**：变体 C（顶条 `#e56b2f` 橙、白字 15px；宣传类推荐项突出首选）。

### ④ 双线角块式

- **骨架**（块级容器）：较深细边框容器（`border:1px solid #c8c8c8` + 圆角 12px）→ 标题槽 → 说明槽。
- **零件位**：A. **容器**（深一档细边框 #c8c8c8 + 圆角 12px）B. 顶条（默认无）C. **标题装饰**（可选，竖条/几何）D. **条目文字槽**（1-3 条说明，≤5 条）。
- **尺寸**：`border:1px solid #c8c8c8`（较深细边）；圆角 12px；padding `14px 16px 12px`；标题 14px 加粗 `#333`（行高 1.5）；说明 13px `#666`（行高 1.75）。双线边界不用内层描边阴影，改用"外边框 + 内留一条 `1px solid #f0f0f0` 细边 span"或直接加深外描边来宣告边界。
- **叠字**：标题栏 → 说明条目。
- **风格可变内容**：边框深浅（边界强弱）+ 标题装饰。
- **默认实现**：变体 D（`#c8c8c8` 深细边，规则/注意事项/明细专属）。

### ⑤ 分栏卡式

- **骨架**（table 并排）：`<table cellpadding="0" cellspacing="0" border="0" style="width:100%;border-collapse:collapse">` → 每 `<td>` 内一个卡容器（各自底色/边框/圆角/标题槽/条目槽）。
- **零件位**（每格独立一套）：A. **容器**（底色 + 边框 + 圆角）B. 顶条（可选，推荐项格加）C. **标题装饰**（各格标题色）D. **条目文字槽**（每格 1-2 条，行数保持接近）。
- **尺寸**：两列各 50%（三列各 33%）；卡内 padding 14px；圆角 10px；两卡中缝各 8px 凑成 16px（`margin:0 6px 0 0` 与 `0 0 0 6px`）；**所有并排卡必须 `box-sizing:border-box`**，防止 padding 撑破宽度；标题 13px 加粗、条目 13px（行高 1.7）。
- **叠字**：各格标题栏 → 各格条目（左右两格文字基线对齐阅读）。
- **风格可变内容**：各格底色/边框色（对比双方用不同色系）+ 标题色 + 顶条图案。
- **默认实现**：变体 E（左格"优点" `#f0fbff` 底/`#d9f0f5` 边/`#0ba89b` 标题 + 右格"注意" `#fff7f2` 底/`#f7e0d3` 边/`#e56b2f` 标题，两两对比首选）。
- **风险注意**：两栏高度差大时 table 自动等高会让矮的一栏下方一大块空白——左右内容保持行数接近，或改成上下两张卡，别强撑两栏。

## 三、风格如何决定内容（填充规则）

1. **风格条目 → 图案词汇表**：每个风格条目（style-*，见 index-style）应提供该风格的**图案词汇表**（如：阳光校园风 = 球类/跑道/奖杯/校徽；国潮风 = 印章/回纹/祥云/朱砂红；科技风 = 几何/菱形/网格/冷蓝；电商促销风 = 价格高亮/主推框）。
2. **填入零件位**：把词汇表中的图案绘制为 SVG/CSS 图形，填入 §二 对应模板的**风格可变内容**零件位（B 顶条、C 标题装饰、A 容器色板）——骨架（容器/边框/圆角/标题槽/条目槽）保持不变，只换内容。
3. **图案必须是可绘制图形**：足球/篮球/网球等是**具体图形**（可用圆形+线缝弧线绘制），不是 emoji/字符图标——符合 v10 铁律（禁 emoji/图标字符，但允许具体器物图形）。
4. **简单装饰优先 CSS 几何、复杂图案走 art://**：卡片是代码骨架组件，简单装饰（左竖条 `border-left:3px`、CSS 方块/菱形 span 前缀）用 CSS 拼（最稳）；需要风格图案（顶条球类/标题小奖杯）时用 `![图案](art://资产名)` 或新增资产（按 §五 5.0 整图资产规范构建）。
5. **颜色随风格（全篇色盘协同）**：卡片不是独立色块，颜色必须从全篇色盘取——**一篇正文只用 1 个主强调色贯穿所有强调点**（卡片、气泡、列表符号、高亮共用同一主色），全篇卡片颜色 ≤2 个主色（一个主色 + 一个警示色已是上限）；换品牌色时整套深浅档位一起换，判断依据：品牌色能否连贯表达"普通 → 重点"的梯度，挤不出梯度就退回灰边框 + 主色点缀。
6. **验证**：生成后按 §五 铁律实测（375px 壳、对比度 ≥4.5:1、密度），并登记 REQUIREMENTS（先记录后开发）。

> 示例：**白卡细边框式 + 阳光校园风**——骨架：白卡容器（`#fff` + `1px solid #f0f0f0` + 圆角 12px）+ 标题槽 + 3 条条目槽；内容：**B 顶条图案 = 迷你足球**（圆形+五边形缝线，art:// 资产）、**C 标题装饰 = 小奖杯**（竖条位 art:// 图案）、色板 = 校徽橙/球场绿；标题/条目结构不变。
>
> 再例：**分栏卡式 + 电商促销风**——左"优点"右"注意"两格骨架不变，推荐项所在格加实色顶条（`#e56b2f`）+ `border:2px solid #e56b2f` 高亮，其余格同款式弱化（无顶条、细边框），让"推荐的那个"一眼跳出来。

## 四、现有实现 = 默认风格（中性/极简）的实现示例

> 真实知识库 module-card 的 5 个变体 A-E 是**默认风格（中性/极简）**下各模板的实现示例——不是全部可能，只是一份样板。生成新风格时按 §二 模板 + §三 规则重新填充即可。

| 组合方式 | 默认实现（变体） | 语义落点 |
|---|---|---|
| ① 白卡细边框式 | 变体 A（`#fff`/`#f0f0f0`/圆角 12px） | 文字类默认，一切信息归纳 |
| ② 浅底圆角式 | 变体 B（`#f7f9fc` 极浅灰蓝） | 底色分区、安静"浮起来" |
| ③ 实色顶条式 | 变体 C（顶条 `#e56b2f` 橙） | 宣传类推荐项突出 |
| ④ 双线角块式 | 变体 D（`#c8c8c8` 深细边） | 规则/注意事项/明细 |
| ⑤ 分栏卡式 | 变体 E（青 `#0ba89b` 优点 + 橙 `#e56b2f` 注意） | 两两对比/横向并列 |

> 变体参数（色号/圆角/padding/字号）完整保留于 §二 各模板"默认实现"行，不再重复列出。

## 五、构建验证与铁律（生成任何卡片必须满足）

### 5.0 整图资产构建规范（生成 art:// 卡片底图时必须满足，2026-08-29 第 9 轮·实测修正）

> 卡片底图是**整图资产 + 中央嵌字模式**（与小标题 combo 资产、气泡底图一致）：SVG 画布模拟卡片容器 + 顶条/标题装饰长在结构上，**中央区域留作文字区（zone）**。首轮失败根因同气泡：嵌字区高度只留 27px 显示，装不下文字；水平背景渐变致 PNG 超 1MB；只验"zone 内无装饰"未验"zone 装得下文字"。**卡片是归纳容器（标题栏 + 3-5 条条目），zone 容量是气泡的 2-3 倍**。以下为强制规范：

1. **画布规格（默认紧凑档）**：750×240（375px 壳显示 343×110px，缩放比 ≈0.457）。容器圆角矩形 y10 h220；**顶部装饰贴顶（y≤50）、底部装饰贴底（y≥190）**，中央 110..730 × 50..210 为文字区（zone 设计高 160px）。
2. **文字区容量（核心，首轮失败点）**：卡片 zone 必须装下"标题栏 15px（行高1.5）+ 间距 10px + 3-5 行条目 14px（行高1.75）"。换算为设计尺寸（缩放比 ≈0.457）：
   - **紧凑卡（标题 + 2 行条目）**：显示高 ≈82px → **设计高 ≥180px（画布 750×240，y 50..230）**；
   - **完整归纳卡（标题 + 3-5 行条目）**：显示高 ≈106-155px → **设计高 ≥232-340px（画布加高到 750×360-400，y 30..370）**。
   - zone 显示宽 ≥280px → **设计宽 ≥620px（x 110..730）**。默认画布 750×240、zone 设计高 ≥160px 是紧凑档底线，**条目 ≥3 行必须按上表加高画布，不得硬塞**。
   - **文案长度约束（375px 壳实测前提）**：标题 ≤8 字、单行条目 ≤22 字（14px 一行 ≈22 字，条目必须单行不换行）；分栏卡每格 zone 显示高 ≥53px（设计 ≥116px），每格只放标题 + 1-2 行条目（≤10 字/行，格宽减半）。375px 壳叠字实测用此长度的真实文案，超长文案会换行越界 = 不合格。
3. **PNG 体积铁律**：4x 渲染后 **≤1MB**（uploadimg 硬限）。**大面积背景渐变必须用垂直方向**（水平渐变在 750px 宽的每一行都是不同像素，PNG 熵爆炸：实测 bar-note 1309KB 超限；改垂直后 ≤348KB）。渐变仍用 `gradientUnits="userSpaceOnUse"` + 绝对坐标。
4. **zone 字段**：每个资产必须带 `zone`（单卡 `{x0,y0,x1,y1}` 设计坐标；分栏卡用数组两个 zone），标注文字安全区。
5. **验证闭环（三层，缺一不可）**：
   - ① 资产级：渲染 4x PNG + probe 像素验证（落纯色部件，容差 ±12）+ 体积 ≤1MB；
   - ② zone 洁净度：相邻像素突变扫描（x105..730 区域逐行扫，相邻像素 RGB 差之和 >40 计数，突变 >12 的行必须为 0 或只在 zone 外）；
   - ③ **375px 壳叠字实测**（首轮缺失项）：把真实文案（标题栏 + 条目，按容量表条数）按 zone 缩放后叠入图片，DOM 检查文字边界全部落在 zone 矩形内（getBoundingClientRect 对比），**10/10 全部通过才算完成**。紧凑卡两行、完整卡 3-5 行、分栏卡每格一行都要实测。

### 5.1 通用铁律（继承 §一/§三）

- **密度铁律**：一篇 **3-5 张**；**一种样式到底**（白卡/浅底/实色顶条/双线/分栏选一）；**卡片不嵌套卡片**（双层可接受、三层以上挤）；**卡片不叠加气泡**（同屏一个亮块就好——这一屏已有重点气泡就不放实色顶条卡）。
- **文字铁律**：一卡一主题（并列项性质一致）；卡内标题 + 2-3 条内容才配叫归纳容器；条目 ≤5 条；最重字号 ≤15px（卡是归纳不是标题，不出现 17px+）。
- **对比度铁律**：卡内文字与底色对比度 ≥4.5:1；浅底配深字、实色顶条配白字最稳；卡底色/边框要与正文文字 `#333`、正文灰 `#555` 区分度足够。
- **性质一致铁律**：同一张卡内并列项都是优点/或都是参数/或都是注意点，别把"优点 + 注意"塞进同一张卡。
- **零 emoji/零图标字符铁律**：顶条/标题装饰必须是 CSS 几何 span 或 art:// 可绘制图形。
- **微信兼容铁律**：纯色 + 细边框；禁投影/渐变/backdrop-filter/伪元素/outline/border-image；分栏用 `<table cellpadding="0" cellspacing="0" border="0">` + `<td style="box-sizing:border-box">`，禁 float/grid；实色顶条卡外层 `overflow:hidden` 贴圆角；装饰失效后"白底/浅底 + 细边框 + 圆角"兜底仍可读。
- **双模式铁律**：文字类全文白卡细边/浅底、宣传类全文实色顶条/彩色点缀，一篇只选其一。
- **验证方式**：375px 壳截图自查（一眼分清卡片/气泡/正文）；改参后整段截图到手机看一屏。

## 七、常见错误

- **反例**：同一篇用了实色顶条卡 + 白细边框卡 + 分栏卡三种。**正解**：只选一种全篇统一；要突出重推项，可在同款式内用边框粗细/顶条做"程度"区分，不换样式。
- **反例**：卡片里只有一句话"本产品很好"。**正解**：一句话用重点气泡（「module-bubble」）；卡片至少要有标题 + 2-3 条内容才算"归纳容器"。
- **反例**：分栏卡两栏高度差很大（左卡 8 行、右卡 2 行），table 自动等高后右卡下方一大块空白。**正解**：左右内容保持行数接近，或改成上下两张卡，别强撑两栏。
- **反例**：卡片内装了整整 200 字的一段 + 一张大图。**正解**：卡内内容控制在标题 + 3-5 条要点；长段落交给正文，大图交给「模块 · 图片」。
- **反例**：卡内文字缩到 13px 还塞了 8 条要点，字号太小、内容太多。**正解**：卡内要点 ≤5 条，正文保持 14px，别排版排到反人类。
- **反例**：一张卡里既写"优点"又写"注意事项"，读者分不清到底在夸还是在提醒。**正解**：一张卡一个主题，多主题就拆成两张卡（优点一张、注意一张）。
- **反例（类型×风格新）**：想换风格时改骨架——把白卡细边框式改成实色顶条式（"换个风格"）。**正解**：换风格只换零件（顶条图案/标题装饰/色板），换骨架是换组合方式；组合方式按文体选，风格按账号选。
- **反例（类型×风格新）**：风格词汇用 emoji/字符图标（🏀⚽ 直接贴进卡顶条）。**正解**：球类必须绘制成具体图形（圆形+缝线）或 art:// 资产，字符图标永不进入卡片。
- **反例（类型×风格新）**：每种风格换一套骨架（校园用白卡、国潮用浅底、科技用双线），读者认不出"这是卡片"。**正解**：全篇一种组合方式贯穿（按文体定），风格只换内容零件——"一种样式到底"的铁律比换花样重要。
- **反例（整图资产·首轮实测失败）**：画布 750×180、zone 只留 90px 设计高（显示仅 41px），装不下"标题栏+条目"两行以上。**正解**：画布 750×240 起、zone 设计高 ≥160px（紧凑档）/≥340px（5 行条目），见 §五 5.0。
- **反例（整图资产·首轮实测失败）**：大面积背景用水平渐变，PNG 4x 渲染超 1MB（每行像素全不同，熵爆炸）。**正解**：大面积背景渐变用垂直方向（实测 ≤348KB），见 §五 5.0。
- **反例（整图资产·验证缺失）**：只验证"zone 内无装饰侵入"就宣称完成，没把真实文字叠进去实测——条目多的卡文字实际放不下。**正解**：三层验证闭环（资产级 probe + zone 洁净扫描 + **375px 壳叠字 DOM 实测**），见 §五 5.0。

## 八、个性化空间

- **样式选择**：白卡（通用）/ 浅底（分区）/ 实色顶条（推荐）/ 双线（规则）/ 分栏（并列）。判断依据：内容的"语义"——并列对比用分栏、主推用实色顶条；但全篇锁定一种（主推项可在同款式内加粗/加框做程度高亮）。
- **边框 vs 底色**：边框 = 靠线成块的"正式"感；底色 = 靠色成块的"柔和"感。判断依据：行业与风格——金融/数码用边框，生活方式/教育用浅底。
- **圆角**：8（利落/商务）/ 10（分栏）/ 12（通用）/ 14（柔软/童趣）。判断依据：风格软硬，同篇统一；圆角不超过内容高度的一半。
- **标题装饰**：CSS 方块/菱形 span 前缀，或左竖条 `border-left:3px solid 主色`。判断依据：想让标题更"立"用左竖条，否则用 CSS 形状前缀即可（用 `display:inline-block` + `transform:rotate(45deg)` 拼菱形，不写字形字符）；风格图案（小奖杯/球类）走 art://。
- **卡内密度**：3-5 条。判断依据：≥6 条拆成两张卡，或改用「模块 · 表格」做真正的大表格——卡片装得下要点，装不下数据表。
- **顶条有无**：只在"我要你选这个/这是主推"时加实色顶条。判断依据：顶条是额外强调通道，普通归纳不加，保持卡片本身的克制。
- **风格扩展方向**：阳光校园（球类顶条图案/奖杯标题装饰）、国潮（印章竖条/回纹/朱砂红边/米白底）、科技（冷蓝浅底/几何网格）、电商促销（主推项实色顶条 + `border:2px` 高亮）——每种风格 = 一套图案词汇表填入 5 种模板的零件位（B 顶条/C 标题装饰/A 容器色板），先调研再入库（REQUIREMENTS.md 登记）。
