# 模块 · FAQ / 问答卡

> 定位：用"问一句、答一段"的固定结构，把读者最关心的几个问题逐一交代清楚。答案永远**先给结论、再展开理由**，让扫读者 3 秒就拿到答案——不想读正文的人，也能靠这一块把"买不买/用不用"的关键考量补齐。
> 调用时机：产品介绍、答疑、购买决策场景——当文章存在"读者必然想问的几个问题"（多少钱/有效期/怎么退款/适合谁）时。放到正文靠后、行动号召之前，先消除顾虑再促行动。一屏一个问答，全篇 3-6 问最佳。

## 一、可用写法与语法

写作语法用容器：`:question 问题` 与 `:answer 答案`，或使用问答容器把一组"问–答"包起来，以"问题再答案"成对出现，一问一答，不留悬念。

**两个关键结构**：
1. **问题命名 = 读者的嘴替**：问题要用**读者会问的原话**来写，不是编辑术语。读者心里是"这贵不贵"，别写成"本产品的价格策略分析"。读者怎么张口问，Q 就怎么写——这是 FAQ 和普通正文最大的区别：Q 是**读者伸出的手**，而不是你列的功能清单。
2. **答案 = 先结论后展开**：答句第一句就给出确定结论（"答案是 A"），后面才是理由、前提、程度。别先绕一大圈铺垫再揭晓——FAQ 场景下读者是带着"疑问"来的，他要的是"痛快"，不是"剧透前戏"。

**写法铁律**：
- 一个问题只答一个点，答案首句必须能独立成立（单独拿出来也读得通）。
- 用词跟读者同频：Q 用问句原话，A 用口语化的确定口吻，别在 FAQ 里堆术语。
- 结论句里放"数字"最有说服力（价格、时效、天数、字数），数字是要害。
- **全文问答语气一致**：所有问题都用同一种"读者语气"（都是口语、都不要官方腔），读者才觉得"这套问答真的是在替我说话"。

## 二、双模式表现（文字类/宣传类）

**文字类（文字排版优先）**：问答列表式——每问用加粗 + "Q" 标识，答案用普通正文承接，视觉安静，靠"结构对仗"而非色块区分。适合观点答疑、教程后附常见问题。文字类的核心是"把问答当普通文本排"，颜色最轻，读者靠 Q 加粗和"序号"建立"这是在问答"的直觉。

**宣传类（视觉优先）**：问答卡片组——每个"问–答"收进一张浅色卡片，问题做色标 / 答句做色边，视觉分组更强，一屏一块，像"逐张发牌"一样把安心感递到读者手里。适合产品页、购买决策、促销顾虑打消。宣传类的核心是"这块就是要强调给你看"——卡片把每个问题独立成块，让犹豫的读者"停在某一张卡上反复看"。

**两个模式在同一篇里只选其一**：文字类全文所有 Q 都是加粗行，宣传类全文所有问答都是卡片，不要前三问用列表、后两问用卡片——混用等于让读者以为"列表和卡片是两种不同信息"，严重破坏一致性（见模块组合铁律）。

## 三、样式变体（5 种常用，具体参数）

几种布局各覆盖一个场景；**所有问答的答案正文都统一 `line-height:1.75`，组与组之间 `margin:0 0 16px`**。

**变体 A｜极简问答列表（文字类·最常用）**——适用：教程附问、纯信息答疑：
```html
<p style="margin:0 0 8px;line-height:1.5;font-size:15px;font-weight:bold;color:#2c3e50;">Q1 这个能免费试用吗？</p>
<p style="margin:0 0 6px;line-height:1.75;font-size:14px;color:#333;">能，注册即可试用 14 天，无需绑卡。</p>
<p style="margin:0 0 16px;line-height:1.75;font-size:13px;color:#888;">试用期间可使用全部功能，到期自动转免费版，不会扣费。</p>
```
- 参数：问题 15px 加粗深灰（`#2c3e50`）、行高 1.5；答案首句 14px `#333` 标出结论；展开用 13px 灰 `#888` 作小字承接；组与组之间 16px。

**变体 B｜问答卡片组（宣传类·常用）**——适用：产品页、促销：
```html
<div style="background:#f7f9fc;border-radius:12px;padding:16px;margin:0 0 16px;">
  <p style="margin:0 0 10px;line-height:1.5;font-size:15px;font-weight:bold;color:#333;"><span style="background:#e56b2f;color:#fff;border-radius:4px;padding:1px 6px;margin-right:6px;font-size:13px;">Q</span>退款要几天到账？</p>
  <p style="margin:0;line-height:1.75;font-size:14px;color:#555;">3 个工作日内到账，原路退回，无需申请。</p>
</div>
```
- 参数：每问整块浅底卡（`#f7f9fc`、圆角 12px、卡内 padding 16px、底部 16px），问题上挂"Q 色标"小签（白字、圆角 4px、padding `1px 6px`、字号 13px）。

**变体 C｜带 Q 色标签的卡组（宣传类·重点顾虑）**——适用：最影响决策的那几个问题：
```html
<div style="background:#f7f9fc;border-radius:12px;padding:16px;margin:0 0 16px;">
  <p style="margin:0 0 10px;line-height:1.5;font-size:15px;font-weight:bold;color:#333;"><span style="background:#6b4fc4;color:#fff;border-radius:6px;padding:2px 10px;margin-right:8px;font-size:13px;">Q：适合谁</span>我是写作新手，能直接用吗？</p>
  <p style="margin:0;line-height:1.75;font-size:14px;color:#555;"><strong style="color:#6b4fc4;">完全可以</strong>，卡片式操作零门槛，跟着一步步点就行。</p>
</div>
```
- 参数：Q 标签从"纯字母"升级为"语义标签"（如 `Q：适合谁`），标签圆角 6px、padding `2px 10px`、字号 13px，结论句用同色 `<strong>` 高亮。判断依据：当问题本身带"类别"（适合谁/有效期/售后）时，语义标签比纯 Q 更省读者眼球。

**变体 D｜"适合谁"内置小结构（宣传类·精准人群）**——适用：把人群判断放进卡内，让读者对号入座：
```html
<div style="background:#fff8ef;border-radius:12px;padding:16px;margin:0 0 16px;">
  <p style="margin:0 0 8px;line-height:1.5;font-size:15px;font-weight:bold;color:#2c3e50;"><span style="display:inline-block;width:16px;height:16px;border-radius:50%;border:2px solid #e56b2f;margin-right:6px;"></span>这门课适合谁？</p>
  <p style="margin:0 0 6px;line-height:1.75;font-size:14px;color:#333;">你只要符合一条，就值得入：</p>
  <div style="margin:0;line-height:1.75;font-size:14px;color:#555;">
    <span style="display:block;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#e56b2f;margin-right:6px;"></span>每天要写工作总结 / 周报的上班族</span>
    <span style="display:block;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#e56b2f;margin-right:6px;"></span>想给公众号/小红书定期更新的内容er</span>
    <span style="display:block;"><span style="display:inline-block;width:6px;height:6px;border-radius:50%;background:#e56b2f;margin-right:6px;"></span>被"提笔没选题"卡住的自由职业者</span>
  </div>
</div>
```
- 参数：卡带米色浅底 `#fff8ef`，问题句用 CSS 圆形描边作"问号标记" + 加粗，答案先给"一个结论句 + 三条并列"。判断依据：当"适合谁"是唯一能留下/劝退读者的关键问题时，用卡内并列 > 干答一句话。

**变体 E｜对照问答（教学·反例 vs 正解）**——适用：教"这件事该怎么做"时，问题后把错误做法与正确做法各放一句：
```html
<div style="background:#f7f9fc;border-radius:12px;padding:16px;margin:0 0 16px;">
  <p style="margin:0 0 10px;line-height:1.5;font-size:15px;font-weight:bold;color:#2c3e50;">Q：标题到底要不要带关键词？</p>
  <p style="margin:0 0 6px;line-height:1.75;font-size:14px;color:#333;">答案是：带，但别堆。</p>
  <div style="display:flex;align-items:center;gap:8px;margin:0 0 6px;line-height:1.75;font-size:14px;color:#555;">
    <span style="width:10px;height:10px;border-radius:2px;background:#c0392b;"></span><span>错误：标题塞满 6 个词，读起来像报菜名。</span>
  </div>
  <div style="display:flex;align-items:center;gap:8px;line-height:1.75;font-size:14px;color:#555;">
    <span style="width:10px;height:10px;border-radius:50%;background:#2f9e5f;"></span><span>正确：一个情绪钩子 + 一个主关键词，标题就立住了。</span>
  </div>
</div>
```
- 参数：结论句先给"答案是……"，展开用两块对照——红方块 span 标「错误」、绿圆点 span 标「正确」，为读者直接挑明对错。判断依据：答疑夹带"教学纠正"时，一对对照比一段分析更直观。

## 四、使用时机与位置

- **产品介绍文**：把"参数之外"的顾虑（价格/售后/适合人群）做成 FAQ，紧跟产品主体之后、行动号召之前——先回答质疑，再请他下单。
- **答疑文**：本身全文就是答疑，直接按 FAQ 结构排布，最清晰的"一问一答"就是全文骨架。
- **购买决策 / 促销**：FAQ 打消临门一脚的疑虑（退款、物流、有效期），放 CTA（行动号召）**紧前方**——读完 FAQ 恰好是"决策完成的瞬间"。
- **位置顺序**：把"最伤转化"的顾虑（价格/退款）放最前，越往后越细节、越不致命；避免"先小后大"，读者可能在第一个软问题上就划走了。
- **不要开头放、不要压轴放**：开头该讲价值与钩子，把 FAQ 压得越靠前越像"辩解"；结尾最后一句要给 CTA 留位置，FAQ 是收尾前的"定心丸"，不是终场致谢。

## 五、风格适配（4 个例子）

- **极简/商务**：变体 A 极简列表，问题 15px 深灰加粗加 "Q1/Q2" 序号，答案全 14px 黑白灰，靠序号与字号不靠色块。克制到极致。
- **电商/促销**：变体 B 卡片组，Q 色标用主推橙 `#e56b2f`，答案里的**关键结论（价格/时效/保障）**用品牌色加粗，重点是让读者扫到"退款无忧"。
- **教育/生活方式**：问题区加 CSS 圆形序号或色标（空心圆描边 + 主色），卡片用米色浅底 `#fff8ef` 更暖，答案更口语；适合亲子号、成长号。
- **科技/数码**：卡片用冷蓝浅底，问题加 "Q" 方块像终端提示，答案里参数加粗，整体更"硬核清晰"。

**风格统一原则**：FAQ 的风格要与整篇其他模块（卡片、列表、气泡）一致——如果正文其他归纳块用浅底圆角卡，FAQ 也用同色系浅底卡；如果全文是黑白色调，FAQ 也别破例上彩。FAQ 是"全篇穿的一套衣服"的一部分，不能单独换风格。

## 六、间距与尺寸（遵守硬规范）

- **问答组与前后**：每组底部 `margin:0 0 16px`（块距基线 16px）。不要用两个答案拼在一行；一问一答之间不插其他元素。
- **行高**：问答内文字统一 `line-height:1.75`（与正文一致，保证扫读节奏不乱）；问题标题行可用的 1.5 便于区分层。
- **字号**：问题 **15px**、答案 **14px**、展开/补充小字 **13px**；Q 色标小签 13px。别为了"醒目"把问题抬到 18px+。
- **内边距**：卡片组卡内 `padding:16px`（比默认 14px 大，因为卡较空）；圆角 12px，不能超过内容高度一半。
- **问题与答案间距**：问题与答案首句 **8px**；答案首句与展开 **6px**；问题标题行内 "Q 色标" 与问题文字间距 6-8px。
- **问题长度**：一个问题是一整句"读者原话"，≤25 字；长了说明问题不聚焦，拆成两个或多个。

## 七、配色配合（与全篇色盘协同）

FAQ 不是独立装饰，它的颜色必须从全篇色盘里"取"，且与正文颜色协同：

- **卡片与正文对比**：卡片浅底（如 `#f7f9fc`）与正文白底拉开层次，卡内答案文字用正文深灰 `#333/#555`，保证对比度 ≥4.5:1；浅底配深字最稳。
- **单主色用法**：整篇 FAQ 的"Q 色标 / 结论高亮"统一用一个主色（如主推橙），靠"色标 + 加粗"两个通道，不靠换色。
- **主色 + 警示色**：一个主色（结论高亮）+ 一个警示红（退款/风险类问题用红）——红色只能是少数点，全篇 FAQ 颜色 ≤2 主色。
- **避免"彩虹问答"**：每个问题都换一个色（橙紫蓝绿开会），读者分不清轻重。FAQ 是"收尾定心"的，颜色越稳越安心。
- **与正文关系**：Q 色标/结论高亮只在答案里点"决策关键词"，正文里的普通动词、名词一律不给色，避免全篇花掉。

## 八、微信兼容注意

写问答卡时的"可用子集"与"要绕开的坑"（微信富文本编辑器）：

- **可用**：`background` 纯色浅底、`border-radius`、`padding/margin/line-height:1.75/font-size`、`display:inline-block`（给 Q 色标）、简单 `display:flex`（卡内居中）、`<br>` 分行。
- **尽量别用**：`position:absolute` 做角标/叠加（旧客户端易飞逸）、伪元素 `::before/::after`（编辑器多剥除）、`backdrop-filter`（不生效）。
- **Q 色标写法**：用行内 `<span style="background:色;color:#fff;border-radius:4px;padding:1px 6px;">Q</span>`，不依赖定位，永不跑飞。
- **结论高亮写法**：用 `<strong style="color:主色;">` 或 `<span style="color:主色;font-weight:bold;">`，不用多层描边或装饰。
- **无外链字体**：字号全部用系统自带 px，不 `@import` 字体，不用外链 font-family。
- **纯色为主**：本规范不推荐渐变，卡片统一用低饱和纯色浅底 + 细边框，装饰失效后内容仍可读、仍成块。

## 九、密度限制（重要）

- **一屏一个问答**：一屏（约 6-8 行）内只放一个完整问答，别把三个问题挤成一屏让读者分不清谁答谁。
- **全篇 3-6 问**：少于 3 问不必开 FAQ 模块（改用普通段落）；多于 6 问说明正文没讲透，先精简问题——只留"最伤转化"的那几个，其余放正文或略去。
- **一次一答**：一个问题只答一次，别"这个问题我要分三段慢慢说"，FAQ 是"干脆利落"的体裁。
- **FAQ 内不嵌其他块**：问答卡内不要再嵌卡片/气泡/列表总结，问答本身就是归纳块，层层嵌套一屏就崩。适合谁这类小并列（变体 D）可以例外，但也只允许排在问题后紧凑三行。
- **与正文字数关系**：FAQ 段篇幅约占全文 15-25%，别让问答区喧宾夺主盖过主体价值描述。

## 十、常见错误（反例 + 正解）

- **反例**：Q 写成编辑口吻："Q：本产品在价格方面的竞争力如何体现？"。**正解**：Q 写读者原话："Q：跟同类比，这个贵不贵？"
- **反例**：A 一上来绕弯："关于退款这个问题呢，我们其实考虑了很久，最终决定……"。**正解**："**3 个工作日内到账**，原路退回。退款不用申请，提交后自动处理。"
- **反例**：一篇 12 问，越问越深，读者看到第 8 问早跑了。**正解**：砍到 5 问以内，只留最影响"买不买/用不用"的顾虑。
- **反例**：把"适合谁 / 不含什么"这种正文要点硬拗成问答。**正解**：能写在正文就正常写，FAQ 只留给"读者会主动提问"的那几类。
- **反例**：问答卡组每个问都用纯色高亮顶条，整屏亮块一堆。**正解**：FAQ 一屏只先答完一个，卡组样式统一用一种浅底，重点结论加粗即可，不必每个都亮。
- **反例**：每个答案都塞一长段（像"为什么会这样……另外还要注意……"）**正解**：答案首句给结论一行，理由最多再展开两行，装不下的留给正文，别在 FAQ 里讲课。
- **反例**：一个问题里嵌套两个问题（"多少钱？能分期吗？呢？"）**正解**：一个问题只答一个点，两个问题拆开，各答各的。

## 十一、示例（可用骨架，标注可替换处）

```markdown
:question 能免费试用吗？
:answer 能，注册即可试用 14 天，无需绑卡。
```
（文字类默认问答。**可替换**：问题、结论句。）

```html
<!-- 问答卡片组（购买决策适用）：可替换 Q 内容/颜色/结论 -->
<div style="background:#f7f9fc;border-radius:12px;padding:16px;margin:0 0 16px;">
  <p style="margin:0 0 10px;line-height:1.5;font-size:15px;font-weight:bold;color:#2c3e50;">Q 退款要几天到账？</p>
  <p style="margin:0;line-height:1.75;font-size:14px;color:#333;">3 个工作日内到账，<span style="color:#e56b2f;font-weight:bold;">原路退回</span>，无需申请。</p>
</div>
```
**可替换处**：问题文字、结论句（加粗/品牌色 `<span>`）、卡底色、圆角。判断依据：这是不是读者下单前最犹豫的一点？是——放 FAQ 并给结论加粗。答案首句一定给确定的数字/是/否，别给模棱两可的"基本可以"。

**一篇 FAQ 的稳妥编排**：紧跟在价值主体之后，最伤转化的 1-2 问在前（价格/退款/适合谁），中段 1-2 问细节（有效期/对比），以一句"还有什么想问的，评论区告诉我"收尾接 CTA。密度保持一屏一问、全篇 3-6 问。

## 十二、个性化空间（可调参数与判断依据）

- **问题选取**：从"价格、时效、适用人群、售后、对比"5 类里挑，判断依据是账号后台留言/销售提问里出现频率最高的那几个——FAQ 是"读者视角",不是你的产品说明书。
- **卡片 or 列表**：感情投入高（购买/促销）用卡片组，纯信息答疑用极简列表。判断依据：需不需要"一块块"地逐问题营造安心感。
- **结论高亮**：价格、退款时效、适用保证这类"决策关键词"加粗或用品牌色。判断依据：哪几个词最影响决策，就高亮哪几个，别全亮。
- **Q 色标样式**：纯 `Q` 字母、`Q：适合谁` 语义标签、或 CSS 圆形/方块标记；判断依据：问题是否有明确"类别"可归——有就用语义标签省眼球，没有就用纯 Q。
- **问的数量**：3/4/5 问。判断依据：一次决策向的问题越多，越要精简到核心 3-5 个。
- **答案展开长度**：1 行结论 + 0-2 行理由。判断依据：大众决策向（价格/退款）尽量 1 行结论、干脆；专业向（参数/算法）可展开 2 行,但仍以结论先行。
- **是否配对照**：教学答疑可在答案里加 CSS 方块/圆点对照（红标「错误」、绿标「正确」），判断依据：这个问题"做得对/做错"差别是否影响结果——影响就可以给对照，纯信息告知就不必。
