# 步骤（module-steps）

> 定位：**步骤 = 一个组件类型（type）**。本条目记录**这一类组件的生成方式**——4 种组合方式（骨架模板）分别怎么组织、零件位在哪、怎么按风格替换内容；以及"**类型 × 风格**"二维模型（风格决定内容）。步骤是把"读者要照着做"的操作流程拆成一、二、三步的指令组件：用数字圆编号 + 连线串成纵向流程，让读者明确知道"做完第 1 步才开始第 2 步"。步骤是**操作指令**，不是叙事。生成 art:// 步骤条底图资产时必读 **§五 5.0 整图资产构建规范**（画布 750×220 纵向 4 步 / 750×120 单步横向卡 / zone 容量 / PNG ≤1MB / 三层验证闭环）。
> 调用时机：教程、新手引导、操作流程、上手引导——当读者要真正"动手执行"一篇连续动作时。**生成/改造步骤条时**：先定组合方式（类型），再按风格填充内容（数字圆图案/色板）；不是"从变体清单里挑一个"。**步骤条与时间线要分清**：步骤是"该这样做"（指令），时间线是"曾经这样发生"（叙事，见「模块 · 时间线」）。
> 素材来源：真实知识库 module-steps（4 变体 A-D 参数：数字圆 28/32px、圆与文字间距 12px、连线占位 16px、行高 1.75）+ 2026-08-29 类型×风格模型（对齐 module-bubble / module-subheading 样板）。

---

## 〇、核心模型：类型 × 风格（2026-08-29 第 9 轮确立）

**步骤条组件的构建由 2 个角度决定：类型（type）和风格（style）。**

| 角度 | 回答什么问题 | 在步骤条上的体现 |
|---|---|---|
| **类型（type）** | 组件**怎么组织**（结构骨架）——这类组件怎么构建 | 步骤类型下有 **4 种组合方式**（单色数字圆式/竖线贯穿式/纯色圆+文字卡式/前提行+步骤组式） |
| **风格（style）** | 组件里**放什么内容**（零件填充） | 同一种组合方式配不同风格 = 数字圆图案与色板不同（单色 / 纯色 / 描边 / 球类徽章 / 草叶环徽……） |

**两条核心关系**：
1. **类型决定骨架**：同一类型的所有步骤条共享结构。例如"单色数字圆式"= 数字圆位 + 每步文字槽（纵向多行），无论什么风格，骨架不变；"前提行+步骤组式"= 前提行帽 + 正式步骤组，帽与组的骨架同样不变。
2. **风格决定内容**：骨架不动，数字圆图案随风格替换。**例如：单色数字圆式 + 阳光校园风 → 数字圆换成球类图案徽章（足球/篮球/网球）**；配自然风 → 圆徽是草叶环徽；配国潮 → 圆徽是印章方块/回纹；配科技风 → 圆徽是几何菱形底。

**知识库应该记录什么**：记录**类型的生成方式**（骨架怎么搭、零件位在哪、怎么按风格替换内容），而不是一份"现成步骤条样式清单"。清单只是某个默认风格下的实现示例（见 §四）。

> 与 design-logic-components 的关系：组件 = 美术素材 + 文字；素材维度 = 类型 × 风格——类型管骨架（可复用结构），风格管内容（可替换零件）。步骤条的"美术素材"主要来自 **CSS 圆徽 + 连线**：步骤是**代码骨架组件**，素材只占零件位（数字圆图案可用 CSS span 拼，风格图案才走 art:// 资产）。

## 一、构建总则（步骤条类型怎么生成）

### 1.1 4 种组合方式（类型的子类）

| # | 组合方式 | 一句话结构 | 典型用途 |
|---|---|---|---|
| 1 | **单色数字圆式** | 数字圆前置 + 每步文字槽（纵向多行） | 文字类默认，教程/新手指引/中性操作流程 |
| 2 | **竖线贯穿式** | 圆形 → 竖线 → 圆形串成一条竖向轨道 | 强调"严格先后"的流程（填表→提交→等待） |
| 3 | **纯色圆+文字卡式** | 大号纯色圆 + 浅色文字小卡并排 | 宣传类默认，营销活动/注册引导/报名流程 |
| 4 | **前提行+步骤组式** | 前提行帽（左竖条浅底）+ 下方正式步骤组 | 开工前需备齐东西（注册账号/准备资料/开通会员） |

### 1.2 构建五步（生成方式总流程）

1. **定组合方式**：按文体与内容选 1 种（双模式同篇只选其一：文字类全单色圆、宣传类全纯色圆+小卡）。
2. **搭骨架**：按 §二 对应模板搭结构与零件位（先只画结构，不填内容）——数字圆位 + 连线位 + 每步文字槽（+ 前提行帽）。
3. **按风格填内容**：查风格条目（style-* / index-style）得到该风格的**图案词汇表**（数字圆徽章图案 + 色板），填入零件位（§三）。
4. **填字与排版**：每步文字动词开头、≤15 字、一步一句；间距按 12px 层级收紧（圆与文字 12px、步距 12px、整组底 16px）；行高 1.75。
5. **验证**：375px 壳实测——密度铁律（≤5 步、一屏一组）、每步 ≤15 字、对比度 ≥4.5:1、微信兼容检查（§五）。

### 1.3 通用约束（先读，违反即返工）

- **每步一个动作**：每步首词是动词（打开/填写/上传/配置），让读者知道"要做什么"；别用名词或形容词开头。
- **每步 ≤15 字**：一步一句、指令清晰；带前提的用括号补充（"上传（≤5MB 的图）"），别写整句长句；超过 15 字就拆成"第 1 步……然后第 2 步"。
- **≤5 步**：5 步以上连读者和编辑自己都记不住；6 步以上果断合并，或拆成两组"流程 A/流程 B"，真正要很多步的分章节讲。
- **一屏一组**：一组步骤（含所有步）尽量控制在一屏能看完，别跨两三屏让读者滑到头忘了第 1 步。
- **只装"该怎么做"**：只有"读者照做就能达成结果"的连续动作才进步骤条；解释、背景、注意事项是铺垫，放步骤前后，不塞进某一步；只是并列列举要点（"优点：A、B、C"）用列表（见「模块 · 列表」），不硬掰成步骤。
- **不嵌其他强调块**：步骤条内不再嵌气泡/卡片等其它强调块，步骤本身就是干净流程；前提行算作步骤条的"帽"，不算额外强调块。
- **双模式铁律**：文字类全文单色圆（简洁利落，靠编号顺序感）；宣传类全文纯色圆+浅色小卡（视觉更强，"步骤感"更明显）；**一篇只选其一**，混用等于让读者以为"单色和纯色是两种不同环节"。
- **零 emoji/零图标字符铁律**：数字圆图案必须**可绘制的图形**（CSS 几何 span 或 art:// 图案），字符图标永不进入步骤条。
- **对比度铁律**：数字圆白字圆底要够饱和（浅色圆配白字会糊）；说明文字与底色对比度 ≥4.5:1。
- **微信兼容**：纯色底 + 细边框最稳；连线用 `border-left` 占位 `<p>`（**非伪元素**）；禁投影/渐变/backdrop-filter/伪元素/outline/border-image；`line-height:1px;font-size:1px` 防占位段被默认行高撑高。
- **步序号表达**：一律阿拉伯数字（1/2/3），别用"第一步/第二步/第三步"文字堆叠（数字更省字、更好扫读）。

## 二、4 种组合方式的构建模板（核心：这类组件怎么构建）

> 每个模板给出：**骨架结构**（元素清单与位置）、**零件位**（可替换槽）、**尺寸与间距规范**、**叠字方式**（步骤文字排布）、**风格可变内容**、**默认实现**（当前库中已完成的一个风格版本）。**全局统一参数**：行高 1.75、说明文字 14px、数字圆 `border-radius:50%`、圆与文字间距 12px、整组底部 `margin:0 0 16px`。

### ① 单色数字圆式

- **骨架**（纵向多行）：每行 = 数字圆位（行首，`flex-shrink:0`）+ 每步文字槽（同行右侧）；行 1（圆1+文字1）→ 行 2（圆2+文字2）……自上而下即执行顺序。
- **零件位**：A. **数字圆图案**（圆徽样式：单色底/纯色底/描边——**风格词汇可换**）B. 连线（默认无；需要强先后时加，见②）C. **每步文字槽**（动词开头 ≤15 字）。
- **尺寸**：数字圆 28×28px（紧凑文字类）、白字 14px 加粗、`line-height:28px` 垂直居中、数字单字居中；圆与文字间距 12px；步与步间距 12px；说明文字 14px 色 `#333`（正文灰 `#555` 亦可）；行高 1.75。
- **叠字**：数字圆 flex 行首（`align-items:flex-start`）→ 说明文字右侧（`margin:4px 0 0 12px`）；每步说明首字即动词。
- **风格可变内容**：**数字圆图案**（单色圆 / 纯色圆 / 描边圆 / 球类徽章 / 草叶环徽……）+ 圆径 28-32px + 色板（数字圆颜色 = 全篇主强调色）。
- **默认实现**：变体 A（青 `#00b8a9` 圆底白字 28px，文字类·最稳，教程/新手指引/中性操作流程）。

### ② 竖线贯穿式

- **骨架**（竖向轨道）：左列（固定 28px 居中：数字圆 + 圆下竖线占位段）+ 每步文字槽（右侧）；圆形 → 竖线 → 圆形串成一条竖向轨道。
- **零件位**：A. **数字圆图案** B. **连线**（有无/颜色/深浅——`border-left:2px solid 主色浅一档` 的占位 `<p>`）C. **每步文字槽**。
- **尺寸**：左列 28px 固定居中；圆 28×28px；**连线占位 16px**（`height:16px` 的 `border-left:2px solid <淡化主色>`；占位段 `line-height:1px;font-size:1px` 防默认行高把竖线撑高）；圆与文字间距 12px；**末尾一步不画竖线**（收尾）。
- **叠字**：数字圆 → 竖线占位 → 下一数字圆（圆在上、线在下串行）；文字右列同行。
- **风格可变内容**：**连线有无**（有严格先后依赖才画：填表→提交→等待；并列分支不画）+ **连线颜色/深浅**（取主色浅一档，别用黑线抢圆的视觉）+ 数字圆图案。
- **默认实现**：变体 B（橙 `#ff6b35` 圆 + 浅橙 `#ffd9c8` 竖线，强调"严格先后"的流程）。

### ③ 纯色圆+文字卡式

- **骨架**（横向单卡）：每行 = 大号纯色数字圆（行首，`flex-shrink:0`）+ 浅色文字小卡（右侧，`flex:1`）。
- **零件位**：A. **数字圆图案**（纯色底白字，宣传类最醒目；风格词汇可换）B. 文字小卡（浅色底 + 细边框 + 圆角，可略边框 = 无阴影）C. **每步文字槽**。
- **尺寸**：数字圆 32×32px（宣传类更醒目）、白字 15px 加粗、`line-height:32px` 垂直居中；文字卡 `background:主色极浅底`、`border-radius:8px`、`padding:10px 14px`、与圆间隔 12px（`margin-left:12px`）；卡内文字 14px 色 `#5a4a3a`；行高 1.75；步距 12px。
- **叠字**：纯色圆行首 → 文字卡右侧（`flex:1` 撑满）；卡内一行动词开头 ≤15 字。
- **风格可变内容**：**数字圆图案**（纯色主色/品牌色纯色）+ **卡底浅色**（主色极浅一档）+ 圆径 32px。
- **默认实现**：变体 C（橙 `#e56b2f` 32px + 浅橙卡 `#fff7f2`，宣传类"步骤感"最重，营销活动/注册引导/报名流程）。

### ④ 前提行+步骤组式

- **骨架**：前提行帽（左竖条浅底块，复用「模块 · 气泡」的说明底）置于顶部 + 下方正式步骤组（默认沿用①单色数字圆式骨架，也可套③）。
- **零件位**：A. **前提行帽**（左竖条 + 浅底 + "准备：…"文字）B. 数字圆图案 C. 连线 D. **每步文字槽**。
- **尺寸**：前提行 `padding:12px 16px`、`border-left:3px solid 主色`、`border-radius:0 8px 8px 0`、文字 13px 色 `#1a4a66`；前提行与步骤间距 12px；整组底部 16px；正式步骤参数同所选骨架（默认单色圆 28px、圆与文字间距 12px、行高 1.75）。
- **叠字**：前提行（一行"准备：注册账号 / 准备一张图 / 手机连网"）→ 正式步骤**从"1"开始编号**，前提行不占编号。
- **风格可变内容**：前提行帽底色/文字 + 数字圆图案 + 色板（前提行浅底 = 主色极浅一档，左竖条 = 主色）。
- **默认实现**：变体 D（浅青 `#eef6ff` + 青条 `#00b8a9` + 单色圆 28px，流程开始前需要先备齐东西的场景）。

## 三、风格如何决定内容（填充规则）

1. **风格条目 → 图案词汇表**：每个风格条目（style-*，见 index-style）应提供该风格的**图案词汇表**（如：阳光校园风 = 足球/篮球/网球/跑道/奖杯/校徽；自然田园风 = 草叶/花枝/果实；国潮风 = 印章/回纹/祥云；科技风 = 几何/菱形/网格）。
2. **填入零件位**：把词汇表中的图案绘制为 SVG/CSS 图形，填入 §二 对应模板的"风格可变内容"零件位——骨架（数字圆位/连线/文字槽/前提行帽）保持不变，只换内容。
3. **图案必须是可绘制图形**：足球/篮球/网球等是**具体图形**（可用圆形+线缝弧线绘制），不是 emoji/字符图标——符合 v10 铁律（禁 emoji/图标字符，但允许具体器物图形）。
4. **标记优先 CSS 几何、复杂图案走 art://**：步骤是代码骨架组件，简单圆徽（单色/纯色/描边圆）用 CSS span 拼（最稳）；需要风格图案（球类徽章/草叶环徽/印章回纹）时用 `![图案](art://资产名)` 或新增资产（按 §五 5.0 整图资产构建规范）。
5. **颜色随风格**：数字圆颜色 = 全篇主强调色（圆底取主色深一档、连线取浅一档、卡底/前提行取极浅一档）；步骤条颜色 ≤2 档最佳（主色 + 动作色只点亮决定性一步），别"彩虹步骤"。
6. **验证**：生成后按 §五 铁律实测（375px 壳、每步 ≤15 字、对比度 ≥4.5:1、微信兼容），并登记 REQUIREMENTS（先记录后开发）。

> 示例：**单色数字圆式 + 阳光校园风**——骨架：数字圆位 + 每步文字槽（纵向多行）；内容：数字圆①=迷你足球徽章（圆形+五边形缝线）、数字圆②=迷你篮球徽章（圆形+曲线缝线）、数字圆③=迷你网球徽章（圆形+弧线缝线）；色板：校徽橙/球场绿（同一校园色系深浅）；数字 1/2/3 与每步文字槽结构不变。

## 五、构建验证与铁律（生成任何步骤条必须满足）

### 5.0 整图资产构建规范（生成 art:// 步骤条底图时必须满足，2026-08-29 第 9 轮·实测修正）

> 步骤条底图是**整图资产 + 嵌字模式**（与小标题 combo 资产一致）：SVG 画布模拟步骤条容器，数字圆徽章/连线装饰长在结构上，**每步右侧留文字区（zone）**。子智能体首轮失败根因与气泡相同：嵌字区高度只留 27px 显示，装不下文字；水平背景渐变致 PNG 超 1MB；只验"zone 内无装饰"未验"zone 装得下文字"。以下为强制规范：

1. **画布规格（默认·纵向 4 步条）**：750×220（375px 壳显示 343×100px，缩放比 ≈0.457）。数字圆列 x 0..110（圆 28px 显示 ≈61px 设计）；**每步文字区 x 130..730**；圆徽/连线装饰长在左列（首步圆徽 y ≤50，后续沿轨道分布），右侧中央 130..730 × 30..180 为文字 zone。**或按"单步横向卡"设计 750×120**（单卡 = 圆徽居左 + 文字居右，显示 343×55px，zone y 32..88）。
2. **文字区容量（核心，首轮失败点）**：zone 必须装下"每步一行文字 14px（动词开头 ≤15 字）+ 步距 + 上下留白"。纵向 4 步条：**zone 设计高 ≥150px（y 30..180）**——4×（单行文字）+ 3×步距 + 留白；每步文字行在整图嵌字时用紧凑行高（1.2-1.4），避免把画布撑高（CSS 骨架版仍用行高 1.75，见 §二）；zone 设计宽 ≥620px（x 110..730）。**文案长度约束（375px 壳实测前提）**：每步 ≤15 字（14px 一行 ≈22 字，15 字必须单行不换行）；单步横向卡 zone 设计高 ≥55px（y 32..88）装一行 14px 文字。375px 壳叠字实测用此长度的真实文案，超长文案会换行越界 = 不合格。
3. **PNG 体积铁律**：4x 渲染后 **≤1MB**（uploadimg 硬限）。**大面积背景渐变必须用垂直方向**（水平渐变在 750px 宽的每一行都是不同像素，PNG 熵爆炸：实测 bar-note 1309KB 超限；改垂直后 ≤348KB）。渐变仍用 `gradientUnits="userSpaceOnUse"` + 绝对坐标。
4. **zone 字段**：每个资产必须带 `zone`（纵向 4 步条用数组 4 个 zone 或总 zone + 行规格；单步横向卡一个 zone），标注每步文字安全区。
5. **验证闭环（三层，缺一不可）**：
   - ① 资产级：渲染 4x PNG + probe 像素验证（落纯色部件，容差 ±12）+ 体积 ≤1MB；
   - ② zone 洁净度：相邻像素突变扫描（x130..730 区域逐行扫，相邻像素 RGB 差之和 >40 计数，突变 >12 的行必须为 0 或只在 zone 外）；
   - ③ **375px 壳叠字实测**（首轮缺失项）：把真实步骤文案（每步 ≤15 字）按 zone 缩放叠入图片，DOM 检查文字边界全部落在 zone 矩形内（getBoundingClientRect 对比），**10/10 全部通过才算完成**。纵向 4 步每步一行、单步卡一行都要实测。

### 5.1 通用铁律（继承 §一/§三）

- **密度铁律**：≤5 步；一屏一组步骤；6 步以上拆成两组（流程 A/流程 B）或按章节拆。
- **文字铁律**：每步 ≤15 字、动词开头、一步一个动作；圆内数字 ≤15px（28px 圆 14px / 32px 圆 15px），靠圆底 + 白字 + 圆角表达步骤感，别靠超大字号。
- **对比度铁律**：白字圆底要够饱和（浅色圆配白字会糊）；说明文字与底色对比度 ≥4.5:1。
- **双模式铁律**：文字类全文单色圆（28px）、宣传类全文纯色圆+浅色小卡（32px），一篇只选其一，不混用。
- **零 emoji/零图标字符铁律**：数字圆图案必须是 CSS 几何 span 或 art:// 可绘制图形。
- **微信兼容铁律**：纯色 + 细边框；**连线用 `border-left` 占位 `<p>`（非伪元素）**，占位段设 `line-height:1px;font-size:1px` 防默认行高撑高；禁投影/渐变/backdrop-filter/伪元素/outline/border-image；`display:flex` 做横向排布（卡内圆+文字左右对齐）；末尾一步不画竖线。
- **验证方式**：375px 壳截图自查（一眼分清步骤/正文/强调块）；改参后整段截图到手机看一屏。

## 七、常见错误

- **反例**："第一步：这个功能的设置，需要你登录之后，找到个人中心里的高级选项，点开后……"（不是动词开头 + 超长）。**正解**："1 登录账号并打开个人中心"（动词开头、≤15 字）。
- **反例**：报 8 步，第 4 步和第 5 步其实是同一件事拆两半。**正解**：合并成 5 步以内，保证每步真正不同、真正顺序执行。
- **反例**：把时间线当步骤用——"2019 年上线、2021 年改版、2023 年获奖"放进步骤条。**正解**：这是叙事，用「模块 · 时间线」，步骤只用于"该怎么做"。
- **反例**：步骤之间没有竖线也没有编号逻辑，读者不知道先做谁。**正解**：务必用数字圆编号 + 明确顺序，或至少按 1-2-3 编号；需要强先后再画竖线。
- **反例**：第 1 步前没有前提说明，读者一上来就"上传文件"结果没有文件。**正解**：步骤条前一句话（或前提行帽）交代"准备：注册账号 / 准备一张图"，把前置条件外提。
- **反例**：圆形数字用大红字满屏堆加粗，满溢占半屏。**正解**：圆内数字 ≤15px，靠圆底 + 白字 + 圆角表达步骤感，别靠超大字号。
- **反例（类型×风格新）**：想换风格时改骨架——把单色数字圆式改成纯色圆+文字卡式（"换个风格"）。**正解**：换风格只换零件（数字圆图案/色板/卡底），换骨架是换组合方式；组合方式按文体选（文字类单色圆、宣传类纯色卡），风格按账号选。
- **反例（类型×风格新）**：风格词汇用 emoji/字符图标（⚽🏀 直接贴进数字圆）。**正解**：球类必须绘制成具体图形（圆形+缝线弧线）或 art:// 资产，字符图标永不进入步骤条。
- **反例（类型×风格新）**：每种风格换一套骨架（校园用单色圆、国潮用竖线、科技用文字卡），读者认不出"这是步骤条"。**正解**：全篇一种组合方式贯穿（按文体定），风格只换内容零件——编号顺序感与数字圆形态的契约比换花样重要。
- **反例（整图资产·首轮实测失败）**：画布 750×120、zone 高只留 27px 显示，装不下纵向 4 步文字。**正解**：纵向 4 步条画布 750×220、zone 设计高 ≥150px（或改单步横向卡 750×120），见 §五 5.0。
- **反例（整图资产·验证缺失）**：只验证"zone 内无装饰侵入"就宣称完成，没把真实步骤文字叠进去实测——文字实际放不下。**正解**：三层验证闭环（资产级 probe + zone 洁净扫描 + **375px 壳叠字 DOM 实测**），见 §五 5.0。

## 八、个性化空间

- **数字圆直径/颜色**：28-32px；纯色，可加深一档或浅一档。判断依据：风格软硬与"步骤感"需求——硬核教程用单色 28px，营销引导用纯色 32px。
- **连线有无与颜色**：需要"强先后顺序"（填表→提交→等待）就画竖线，并列分支不画；连线取主色浅一档。判断依据：步骤有无严格的先后依赖——有则连线更清楚。
- **每步是否配小注**：需要解释"为什么这步重要"时可加 13px 灰小注。判断依据：读者会质疑或需要动机的步骤才加，别每步都加（冗长）。
- **前提行有无**：开工前要备东西就加"准备"帽（④前提行+步骤组式），没有前置条件就不加，让步骤直接从"1"开始。
- **步数**：3-5。判断依据：流程本身复杂性——能 3 步说清绝不上 5 步；真到 6 步拆成两组流程，别硬塞一条。
- **步序号表达**：一律阿拉伯数字（1/2/3），别用"第一步/第二步/第三步"文字堆叠（数字更省字、更好扫读）。
- **风格扩展方向**：阳光校园（球类图案徽章数字圆）、国潮（印章方块/回纹徽章）、科技（几何菱形底徽章）、手账（涂鸦/胶带）——每种风格 = 一套图案词汇表填入 4 种模板的零件位，先调研再入库（REQUIREMENTS.md 登记）。
