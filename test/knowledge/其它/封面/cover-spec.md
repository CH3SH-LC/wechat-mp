# 封面图规范（cover-spec）

> 定位：定义公众号封面的硬性尺寸、用途、安全区、格式限制与无设计基础也能做封面的方法——封面是硬门槛，尺寸错了整篇发不出去。
> 调用时机：每次做封面图前必读；确定两张图（大图+方图）的规格、移动端会被裁切到哪里、要不要压字，以及怎么从零做出一张能用的封面。

**这条目写给谁**：写给「没有设计软件背景、也没有美工」的运营/编辑。只要会「开一张图、填色、打字」，就能按本条目做出一张合规、可用、不掉链子的封面。硬数字直接用，风格给了两条最低成本的路线，不需要任何专业设计技能。

## 一、核心规范

### 1. 两种规格，一张原图出两版

微信一篇图文需要**两种比例的封面**，它们是同一张视觉设计按不同比例裁切出来的结果，不是两张各画各的图。搞懂这两版，是封面制作的第一步，也是很多人第一处翻车的地方。

**（1）这张封面一栏里到底要填几张图**

微信后台新建图文时，「封面」这一项会让你分别设定两个比例，各自独立：

- **大图（2.35:1）**：一张很宽很扁的横图，推荐尺寸 **900px 宽 × 383px 高**（也可 1080×460 等比）。它出现在**订阅号消息列表的封面**，也出现在你把文章转发到微信群、朋友圈时的**分享卡片**上。这是你整篇图文被看到次数最多、最该花心思的一版——它直接决定「点开率」，也就是封面最重要的生意。
- **方图（1:1）**：一张正方形图，推荐 **900px × 900px**。它出现在**公众号主页的文章卡片**、以及后台部分位置的缩略显示。它没有大图出现得那么频繁，负责在主页撑起账号的身份感，同样不能缺。

**（2）为什么是「一张原图出两版」**

很多人误以为要做两张画，结果做了两张构图完全不同的封面，导致列表和主页观感割裂。正确的做法：

- 只设计**一张原图**，把核心内容放在画面**最正中的一个虚拟正方形区域**里；
- 再让画面两侧延伸，把大面积的氛围、环境、留白补充到 2.35:1 的宽度；
- 导出时分别裁出一张 2.35:1 和一张 1:1。

因为核心内容全程装在那个虚拟正方形里，裁成两版都不会丢字、丢主体，两版信息完全一致。这就是推荐的默认路径。

**（3）进阶路径**

进阶账号也可以让两版画面略有差异（比如大图重氛围、方图重文字），但前提是**两张风格统一、内容都完整**，否则主页卡和列表卡观感撕裂。多数账号不必冒这个险，用「一张设计裁两版」更稳。

**（4）一句话核心**

> **以 2.35:1 大图为设计主体，1:1 方图从同一设计里裁出居中部分即可；排内容时先在「正方形核心区」内放好关键元素，再向两侧扩展出大图比例，这样两版都不缺信息。**

### 2. 主体居中 + 安全区留边

「主体居中」和「四面留安全区」是封面不翻车的两条铁律，它们服务于同一个目的：**无论微信在哪个设备上怎么裁、怎么缩，封面主体都完好。**

**（1）主体必须居中**

- 主体指图上最想让人一眼看到的东西：标题大字、人物、产品、核心图标等。
- 横向居中：主体中心落在画面水平中线 ±10% 以内。
- 纵向居中：主体中心尽量靠近垂直中线；不要贴着最上沿，也不要沉到最下沿压到「地面」。
- 为什么必须居中：手机列表里封面缩得很小，取景边界在各机型上不一致，偏心元素最容易在缩略或转发时被裁掉。

**（2）安全区留边（给出可以直接照抄的数字）**

| 方向 | 留边比例 | 900px 宽的折算 | 作用 |
|---|---|---|---|
| 左右 | ≥8% | 各约 72px | 防缩略/转发时左右内容被切 |
| 上下（大图） | ≥8% | 383px 高约 30px | 防上下被列表头部/标题区咬掉 |
| 上下（方图） | ≥8% | 900px 高约 72px | 防主页卡片上下被切 |

- 主体核心文字、按钮、关键图形要**整体落在安全区以内**。
- 一个更稳的简化做法：**把全部关键内容收进画面中央的一个「中等矩形」**，这个矩形距离每条边都留 ≥8% 的空隙。这个空隙就是给各设备不同取景预留的缓冲。

**（3）安全区和微信的裁切机制**

- 微信列表缩略、转发到微信/朋友圈的卡片、不同手机的屏幕比例，都可能对封面做不同程度的截取。
- 你只要一直遵守「内容在 ≥8% 安全区以内」，就天然给这些场景留出余量，主体一定完整。
- 反过来，只要有一处贴边，就有可能在某个设备上被吃掉——你无法预测用户用什么设备看，所以只能用「统一留边」来兜底。

### 3. 格式与大小上限

**（1）允许格式**

- `jpg`、`png`、`gif`、`bmp` 四种，其它格式一律传不上去。记住这一点，就能避开大部分「为啥传不上」的问题。

**（2）大小上限**

- 单张图片 **≤10MB**，超过直接上传失败，微信返回错误码 **40009「图片太大」**。

**（3）格式怎么选（按用途给结论）**

| 格式 | 什么时候用 | 想清楚的点 |
|---|---|---|
| jpg | 优先默认 | 照片、实景、细腻色彩过渡都用它；同内容体积最小 |
| png | 需要透明 / 纯色大块 / logo 精细边缘 | 边缘干净，但体积比 jpg 大 |
| gif | 需要动态封面时 | 平时用不上 |
| bmp | 基本不用 | 文件容积巨大 |

**（4）压体积的办法（三四选一即可）**

- jpg 质量调到 70%–80%，肉眼几乎看不出差别；
- 把宽缩到 800–900px 再保存；
- 交在线压缩工具一键处理；
- 或者直接在导出时选择「适合网络」级别的压缩。

目标首先保证 ≤10MB，能到 ≤2MB 更稳妥——体积越小，上传越快、越不容易在手机上出问题。

### 4. 封面与标题的配合：标题会不会被裁切

第一次做封面的人往往最担心「标题会不会被微信裁掉」。把机制讲清楚，这个担心就放下了。

**（1）微信会在封面外自动叠加标题**

- 订阅号消息列表、转发到会话 / 朋友圈时，微信会在封面图下方或图上自动叠加你填写的「标题」文字。
- 这个叠加标题的字体、颜色、位置，用户都无法控制，长什么样取决于微信客户端版本和系统。
- 由此得到一个关键认知：**封面图本身不要再放和标题一字不差的完整句子**，否则图上文字和系统标题叠两层、信息重复、视觉打架。

**（2）图内文字会不会被裁切**

- 做进图片里的字是「固定像素」，只要它装在你设的 **≥8% 安全区内**，并且落在 2.35:1 裁切范围以内，就**不会被系统裁掉**。
- 会出事的只有两种情况：一是字顶到画面边缘越界；二是微信把系统标题正好叠在图内文字的同一位置造成遮挡。
- 解法统一：**图内核心字一律收进安全区，且不要在画面底部正中央（最容易被叠字的位置）塞满文字。**

**（3）图内字与系统标题的分工**

- **图内大字负责「一眼看懂」**：放主卖点的关键词（如「效率翻倍」「理财入门」），大字 + 高对比，让扫过列表的人半秒就懂。
- **系统标题负责「在信息流里读完整句」**：放完整、带钩子的标题（按 copy 维度标题条目写）。
- 两者互补、互不重复，就是封面 + 标题配合最好的状态。

**（4）关于「会不会被裁切」的直接答复**

- 系统标题文字放在封面图之外的排版区域，**不会去裁你的图**。
- 会被裁的只有两类：超出画布比例的内容、以及你主动贴边的元素。
- 所以「守好安全区」就是「守住不被裁切」的底线。

### 5. 无设计基础的封面制作法（两条真能落地的路）

不需要会 PS、不需要会配色，两条路足够覆盖绝大多数账号的需求。这里把两条路的执行要点写全。

**路线一：纯色 + 大字的极简封面（最稳，推荐新手）**

- 选一个纯色背景（取账号主题色或正文主色，配色方法参读 cover-consistency 一致性条目）。
- 配一句关键词语：字号 **≥60px、用粗体**（或自带粗重感的系统字体）。
- 文字颜色与底色做强对比：**深底白字、浅底深字**，详见 cover-text 封面文字排版条目。
- 优点：几乎不可能出错、和正文视觉天然统一、制作成本约一分钟、手机上就能搞定。
- 具体怎么做：手机相册自带的加字功能、任意拼图软件加字、或排版工具的美术资产功能（生成纯色带字底图）都可以。
- 适用：所有场景，尤其适合资讯、观点、干货、教程类公众号。

**路线二：模板式封面（固定版式、每期只换内容）**

- 先做一版固定版式：底图 / 纯色底+细边框 + 标题字的位置 + 角落 logo 或栏目名，整体存成模板。
- 之后每次只换两样——背景图和本期标题文字；字号、位置、版式一律不动。
- 优点：形成强辨识度、大幅降低每次设计成本、且能建立读者的「追更感」（详细机制见 cover-consistency 一致性条目的「系列封面模板化」）。
- 适用：周更栏目、长期教程系列、日常规律更新的干货号。

### 6. 一处常被忽略的坑：封面图背后还有一张「阅读背景」

除了出现在封面位的两张图，微信图文卡片在部分界面（如搜一搜、公众号主页信息流）还会用到一张**文章背景图**，视觉上和封面密切相关。这里提醒两点：

- **统一性**：如果背景图和封面图风格、色调明显不一致，会影响「封面观感统一」（详细做法见 cover-consistency 一致性条目）。
- **做法**：背景图可以就用封面的延伸版，或直接用封面的同一底影像素平铺，保证整篇卡片观感是一条线。
- 这属于加分项，不影响封面本身能否发布，但影响「观感」这项软指标，值得顺手带上。

关于「要不要为方图单独重排」：纯色+大字、模板式这两种封面，方图直接裁同区即可；实景压字类封面若方图裁出来觉得构图偏，可对方图单独微调位置，但不要改到和封面「不是一篇文章」的程度。判断「是否一致」的标准：两者把缩略图并排放在一起，读者能立刻认出是同一篇——达到这个就算过关。

## 二、可执行步骤（制作封面完整流程）

1. **先定标题与摘要**（取自 copy 维度的标题条目 + cover-summary 摘要条目）：封面图上的大字关键词从标题里提炼。**顺序千万不要反**——先做图再凑标题，很容易做成图和标题两张皮。
2. **建画布**：新建画布按 **宽 900px、高 383px（2.35:1）** 画大图；另开一版 **900×900 的方图框**，用于把核心内容裁到居中正方形后，核对方图版本。
3. **排主体**：把核心元素 / 大字放在正中间，四周各留 ≥8% 安全边；心里先框一个「正方形核心区」，所有关键内容都装进这个区。
4. **处理文字（若压字）**：字号建议 **60–100px**、用粗体，文字与底色做强对比；位置、避让安全区的细节参读 cover-text 封面文字排版条目。
5. **出两个文件**：导出大图（2.35:1）一份、方图（1:1）一份；两份都检查是否 ≤10MB，超标就用「jpg 质量调 70–80%」或「缩宽到 800–900px」压体积。
6. **上传预览**：到公众号后台「新建图文」，把两张封面分别上传，用**手机预览**订阅号消息列表和转发卡片两种形态，确认主体与安全都完好。
7. **发布前核对**：回到本条目的第五部分自查要点，逐项打钩。

## 三、示例

**示例一：极简纯色大字封面（干货文「7 个让你效率翻倍的阅读习惯」）**

```
背景：账号主题深蓝色纯色（#1F3A5F）
大字：居中两行——
      第一行「效率翻倍」（约 90px）
      第二行「7 个阅读习惯」（约 90px）
文字颜色：纯白 #FFFFFF（深底白字，对比强烈）
字体：粗黑体（系统默认加粗即可，不用下载字体）
安全区：核心文字距四边 ≥8%；左右各留 ≥72px，上下各留 ≥30px
方图版：裁出居中正方形区域，确保两行文字都完整
→ 大图给列表看、方图给主页看，两版信息完全一致。
```

（可替换处：背景色换成你的主题色；大字换成这次文章的主卖点关键词；字号按画面比例微调。）

> 用「示例一」落地最快的路径：在任何能加字的图片工具里，先建一个 900×383 的画布，填满一个纯色，再打两行居中的白字、选加粗，导出就是一张可用的封面。真正的门槛不是工具，而是「内容要点是否提炼准确、安全区是否留足」。

**示例二：模板式封面（周更栏目「本周书单」第 12 期）**

```
固定版式（每期只改文字 + 背景图）：
  顶部：栏目名「本周书单」+ 期数「NO.12」（小字，约 28px）
  中部：本期主题大字（如「理财入门」，约 70px）
  底部：一句本期封面金句（约 30px）
  角落：账号 logo（固定大小与位置）
背景：每期换一张与该期主题相关的实景图，统一压暗约 30%，保证白字清晰
→ 读者扫一眼列表就知道是同一个栏目的新一期，形成追更期待。
```

（可替换处：栏目名 / 期数 / 主题大字 / 金句每期更新；背景图按主题替换；其余版式固定不动。）

**示例三：实景压字封面（旅游 / 生活方式类推文「在这座小城，我戒掉了无效社交」）**

```
背景：一张有氛围的实景图（小城街景一角），先整体压暗/加一层半透明白或黑罩，
     让文字位置变「干净」
大字：画面偏上的三分之一处，白字，约 72px，粗体
      「戒掉无效社交」（关键词——不是完整标题，完整句交给系统标题）
副字：大字下方一行小字「小城生活日记」（约 28px，同色系白字降透明度）
安全区：文字一行太宽时注意别伸到左右 ≥8% 以外的区域
→ 实景图提供情绪与画面感，压字负责把「钩子词」钉在读者眼前。
```

（可替换处：实景图每次换；压字关键词换成当期主卖点；罩色深浅按图明暗调，保证白字可读。）

## 四、常见错误

| 错误反例 | 问题出在哪 | 正确做法 |
|---|---|---|
| 只做一张竖图或 4:3 横图当封面 | 微信按 2.35:1 截，主体被切坏、构图突变 | 严格按 900×383（2.35:1）出大图 + 900×900 方图 |
| 把主体 / 文字贴到四边四角 | 各机型缩略和转发时裁掉边缘内容 | 核心内容收进 ≥8% 安全区、居中放置 |
| 大图压了和标题一字不差的句子 | 图上字和系统标题信息重复、视觉打架 | 图内只放提炼出的关键词，完整句交给系统标题 |
| 图片 12MB / 8MB 直接上传 | 超 10MB 上限直接报错 40009 | 先压到 ≤10MB 再传（质量 70–80% 或缩宽） |
| 封面图重复标题却又没放钩子词 | 列表里只剩系统标题，图内没有任何让人停下的点 | 图内放大字点题，标题负责完整句，各司其职 |
| 方图直接拿大图横着塞进去 | 方图裁掉两侧内容，主题或字全没了 | 设计时就以居中正方形为核心区，再扩成 2.35:1 |

这组错误的共同根源，其实只有一句话：**把做图的重点放在了「好看」上，而没放在「尺寸、安全、信息分工」这三件硬事上。** 封面翻车几乎不因为「不够美」，而因为「比例不对」「内容贴边」「字和标题重复」。先把这三件硬事做对，美观才有发挥的空间。

## 五、自查要点

> 发布前把下面每一项当作「硬检查」逐条过一遍；漏任何一条，都可能让封面在某个平台形态下翻车。做「检查」而不是「看一眼就发」。

- [ ] 大图是 2.35:1、方图是 1:1，两个文件都齐了
- [ ] 两张图核心主体都居中、都完整；方图没有丢关键元素
- [ ] 核心文字 / 元素都在 ≥8% 安全区内，不贴边、不顶头、不压角
- [ ] 文件格式为 jpg / png / gif / bmp 之一，且 ≤10MB
- [ ] 图上若有字，位置、字号、对比度符合 cover-text 规范
- [ ] 用手机预览过订阅号列表 + 转发卡片两种形态，主体完好
- [ ] 图上大字是从标题提炼的关键词，不与系统标题一字不差重复
- [ ] 方图版单独确认过，核心内容没被裁
- [ ] 封面和标题、摘要信息互补，没有三层堆同一句话的问题（可先读 cover-summary）
- [ ] 栏目类/系列类内容检查了与上一期的版式是否一致（一致性做法见 cover-consistency）

## 六、个性化空间

- **大图 vs 方图的投入比例可调**：若账号主要靠转发卡片和社会化分享涨阅读，就把设计和质量优先砸在 2.35:1 大图上；若读者更多从公众号主页点进来，方图的质感就别省。判断依据：流量主要从列表来，还是从主页来。
- **安全边幅度可调**：喜欢「大而满、冲击感强」的风格，安全边可以收到 ≥5%，但只建议主体本身就很有辨识度时用；保守稳妥的风格上浮到 10% 也完全没问题。判断依据：主体复杂程度和风格偏好。
- **是否压字取决于账号调性**：**图文教学号 / 栏目号**建议固定版式让读者可识别；**新闻资讯 / 视觉大片 / 摄影型**号可让封面更有画面感、少压一行字。判断依据：读者是靠「图内关键词」还是「画面氛围」产生点开冲动。
- **工具选择自由**：手机拼图、免费在线设计、排版工具的美术资产功能都可以，封面不必强迫自己学专业设计软件——先用「极简 / 模板」两条路把门槛降到最低。
- **栏目化程度可调**：想做「系列感」就上游到模板化路线；想做「每篇新鲜感」就每篇独立设计。判断依据：账号是否长期垂直一个栏目，以及你愿意为每篇封面投入多少时间。

**个性化小结**：封面的「个性」应该建立在「安全区、比例、格式」这些硬规矩之上——规矩保证每篇都能发、发得出、主体完整；个性决定这篇的风格、色调和栏目气质。先守住本条目第一二部分的所有硬数值，再去第三、六部分里取用风格与示例，是这套规范的正确打开方式。不要把「个性化」当成「可以不守尺寸」。把上面第一部分当铁律、第二部分的数值当默认值、第六部分当可调旋钮，封面这关就稳了。

**和相邻条目的关系**：本条目管「图的形态与规矩」；压字怎么做见 cover-text 封面文字排版条目；摘要和标题怎么跟封面配合见 cover-summary 摘要写法条目；整篇发布前的首屏检查见 cover-firstscreen 首屏组合拳条目；如果封面和正文分开制作、要核对观感一致，见 cover-consistency 一致性条目。做封面时按需跳读，不必一次读全。
