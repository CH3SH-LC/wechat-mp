# 视频插入组件（video-insert）

> 定位：视频素材就绪后如何"插进组件"——编辑器插入路径、与 module-media 卡片模板的配合顺序、插入后五查。本篇是「视频插入组件」链条的**第二环（插入）**；卡片的 HTML 排版代码在 视觉/模块 的 module-media.md，本篇负责"最后一公里"的操作检查，不重复模板代码。
> 调用时机：视频素材上传成功后、正文排版时。
> 依据：module-media 的平台硬约束（视频须经视频号/小程序/音频通道插入，不能嵌入外部播放器 iframe/外链）+ 编辑器实际操作路径。

## 一、插入路径（平台事实）

- **微信正文不能直接贴任意视频/音频**：视频必须通过「视频号」或「微信小程序」插入，音频通过「微信音频号」或素材库插入；不能嵌入 YouTube/外部播放器 iframe 等外链（平台硬约束，详见 module-media 第一节）。
- 实际操作：在微信编辑器的正文光标处，用编辑器提供的「插入视频/音频」能力插入对应素材（视频号动态 / 小程序视频 / 音频号音频）。
- 在 HTML/模板侧：正文里**预留插入位**——用注释占位标明"在这里插入视频号视频"，发布前在编辑器里对准占位插入（module-media 的卡片模板就是这种写法：占位注释 + 伴生标题/说明）。

## 二、配合顺序（操作流）

1. 素材就绪：按 video-prepare 准备并上传素材库（或确认视频号/小程序素材可用）；
2. 选卡片：按内容形态从 module-media 选模板——视频号视频卡片 / 小程序视频卡片 / 音频卡片；
3. 排版占位：把 module-media 的卡片 HTML 放进正文，标题与说明行写好；
4. 编辑器插入：在卡片内的占位处用编辑器插入对应素材（视频号/小程序/音频）；
5. 复核：做过下面的"插入后五查"再发布。

## 三、插入后五查

1. **卡片包住视频**：视频块在卡片内（标题 + 说明 + 播放块是完整单元），没有裸视频悬在正文里；
2. **标题有信息量**：卡片标题点出"教什么/看点"，不是笼统的"点击观看视频"；
3. **与文字分工**：视频演示过程、正文文字承接结论/步骤清单——"看完视频再看文字"或反向衔接写清楚；
4. **封面可读**：插入后预览一眼，封面帧不是空白缩略图、小图下仍可辨；
5. **无外链残留**：正文 HTML 中没有外部视频 URL/iframe 残留（发布后不可播），占位注释已全部被真实素材替换。

## 四、常见错误

1. **裸插视频不配卡片** —— 反例：视频悬在文字间，没有标题与说明，读者不知道看点。正解：module-media 卡片包住。
2. **HTML 里直接写外链视频地址** —— 反例：编辑器不识别、发布后不可播。正解：编辑器插入通道，HTML 只留占位。
3. **占位注释发布前没替换** —— 反例：正文出现"在这里插入视频"字样。正解：发布前逐处核对占位已替换。
4. **视频与正文文字无承接** —— 反例：看完视频没有文字步骤可回查。正解：文字版要点与视频互补（见 video-prepare 第五节）。
5. **同篇多视频无节奏** —— 反例：连续三个视频块。正解：视频是锚点不是常态，一篇 1-2 个为宜，间隔用文字/图片（见 module-guide-rhythm）。

## 五、自查要点（可勾选）

- [ ] 素材已上传且与正文位置对应（无本地文件残留）
- [ ] 卡片模板（标题 + 说明 + 播放位）完整，无裸视频
- [ ] 卡片标题点出看点，非"点击观看视频"
- [ ] 视频与文字分工明确（过程在视频、结论/步骤在文字）
- [ ] 封面帧信息量足、小图可读
- [ ] HTML 无外链视频/iframe 残留，占位注释已替换

## 六、个性化空间

- **视频卡的说明行风格**：教学号写"配合下文步骤食用"；访谈号写"时间点：xx:xx 讲 XX"。判断依据：引导读者怎么用这段视频。
- **视频位置偏好**：演示类放对应步骤旁（随文）；长篇完整版统一放文尾延伸。判断依据：视频与文字的依赖关系。
- **是否给视频配文字稿**：访谈/课程可附精简文字稿（要点式），长尾搜索友好。判断依据：内容的可检索价值 vs 排版篇幅。
