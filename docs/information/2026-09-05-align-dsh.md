# 与 DeepSeek Harness 差异检查与全面对齐（第 13 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户问题

> 检查为什么和我用在 deepseek harness 里的差这么多 → 全面对齐优化

## 差异检查结论（证据）

1. **模型配置不一致（主因）**
   - DSH 运行配置（`~/.dsh/settings.yaml` + base bundle）：provider deepseek-official / model
     `deepseek-v4-flash` / reasoningEffort max。
   - 桌面端：默认 `deepseek-chat`，请求体只有 model/stream/messages（无推理参数）。
   - 同 key 官方端点实测：`reasoning_effort: "max"` 对 deepseek-chat 与 deepseek-v4-flash 均
     HTTP 200 兼容；v4-flash 回复带 reasoning_content、文案更自然具体；
     用户另配的 49.233.218.211 网关对这把 key 返回 401（未使用，不影响结论）。
2. **对话行为不一致**：DSH 模型完全自主（对话/创作/反问一体）；桌面端第 12 轮仍是
   本地正则路由 + expectRef 状态机，部分自然表达会被本地判定左右。
3. **人设不一致**：DSH 预设 persona 对话与创作一体；桌面端是分离的对话人设与创作人设。

## 对齐实施（第 13 轮）

1. Rust：默认模型 → `deepseek-v4-flash`；请求体加 `reasoning_effort: "max"`（流式）。
2. 前端设置默认值同步（`DEFAULTS.model`）。
3. persona 统一：PERSONA_RULES 重写为「对话+创作一体」，模型自主判断闲聊/答疑/创作/反问/取消；
   删除独立对话人设 buildChatSystem 与本地路由（App turn 单通道；needs 降级仅供模拟端近似）。
4. chat.ts 模拟端启发式近似模型自主（保持 E2E 语义可测）。
5. 知识库结构不动（wechat-mp 第 13 轮设计已排除发布/复盘类；桌面三层即创作知识面）。
