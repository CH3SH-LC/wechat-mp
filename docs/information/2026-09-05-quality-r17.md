# 四项质量修复——文案克制 / 组件必用 / 强制询问 / 风格真正落地（第 17 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户反馈

> ① 文案用力过猛；② 只有 svg 插图，没有各种组件（比如修饰了的小气泡）；③ 依旧不询问清楚；
> ④ 完全没有考虑风格，把显式的风格按钮全部删了，改为 AI 内部判断或者询问

## 根因

1. 文案：persona 无语气护栏，模型默认营销腔。
2. 组件：仅"可用语法"罗列，模型倾向大段文字 + 插图，无组件化强制。
3. 询问：第 13 轮删除本地路由后完全依赖模型自律（persona 有"模糊反问"条款但模型常直接默认产出）。
4. 风格：compose 只有 DESIGNS 双骨架色，UI 风格选择只注入 prompt 文字、渲染层不生效。

## 实施

1. **palettes.ts**（新）：从 `src/knowledge/视觉/风格/*` 条目提取 8 套风格主题色板
   （日系/国潮/校园/科技/极简/商务/手账/森系），每套含正文底色 + 文字类 7 键
   （accent/accentDark/heading/soft/soft2/border/hl）+ 宣传类 5 键（orange/amber/teal/ink）+ 共用浅底；
   知识缺"深档"处按同色系合理近似（报告注明）。
2. **compose.ts**：`resolveTheme`（UI opts.theme 优先，否则正文 `[[theme:名称]]` 首个声明）；
   `makeDesign` 主题键覆盖；wrapper 带主题底色；theme 声明行不渲染；
   **组件化校验**：容器（steps/cols/card/band/frame/timeline）≥2 + 气泡 ≥1 + 列表/引用 ≥1，
   不足产生警告。
3. **persona** 新增三段：
   - 文案语气规则：具体细节代替空泛形容词；禁用夸张营销词（极致/不容错过/绝绝子/天花板…）；
     感叹号 ≤1；结尾号召平实。
   - 结构规则：正文必须组件化（容器 ≥2 + 气泡 ≥1 + 列表/引用 ≥1；纯文字 ≤2 连段；
     宣传类参考结构 banner → 钩子 → 小节 → 气泡 → 平实号召）。
   - 风格规则：界面显式选择时渲染引擎已按选择着色；自动时按主题判断并在正文顶部
     `[[theme:名称]]` 声明；素材 SVG 配色同步。
4. **App**：**强制澄清回合**状态机——创作请求（isCreateRequest/isDemoTopic）且需求评估缺 ≥2
   （无"直接写"、非演示）→ 先走澄清回合（CLARIFY_SYSTEM：只问 1 个精简问题、禁止产出），
   回答后进入创作；会话恢复/清空复位 askRef。UI 风格 → compose theme 注入；
   恢复会话按 item.style 上色。

## 遗留说明

- 组件化校验为下限提示（预览区警告），不做硬阻断；模型遵循度由 persona + 引擎提示双保险。
- 风格"深档/近似"色（如 accentDark/ink）为知识色板的同色系近似；后续可逐风格精修。
- 气泡等组件内嵌角饰素材（> [!KEY|grass] 类）暂未提供（桌面无预置资产）；当前以
  "气泡后邻接 inline 素材"实现组件装饰，若需组件内装饰可下一轮扩展 art 引用协议。
