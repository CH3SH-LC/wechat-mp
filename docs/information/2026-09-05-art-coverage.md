# 素材用量升级——组件装饰全覆盖（第 16 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户问题与口径确认

> 强制使用美术素材不够，量太少，每个组件都必须使用美术素材

经 1 问确认口径 = **组件装饰全覆盖**（推荐）：所有组件装饰位都用上现场生成素材——
开篇 banner 配主题插画、每个 ## 小节标题下配小插画、每个 [!KEY/TIP] 气泡邻接素材、
换场分隔配花饰素材、容器附近按需配图；**单篇 5-8 处素材、单屏仍 ≤1**、
克制不花哨（对齐 DSH v10.3 样文质感）。

## 实施

1. persona 美术素材铁律 v2：
   - 用量：每篇 5-8 处（400-600 字短篇 ≥4）；任何一屏（约 120-150 字）装饰 ≤1；
   - 组件全覆盖映射：banner 附近 1 处 wide 插画；每个 `##` 小节标题下紧跟素材；
     每个 KEY/TIP/DANGER 气泡后邻接 inline 素材；换场用 wide 花饰分隔；容器前后按需；
   - 每处素材仍须现场绘制 SVG：viewBox + 图形元素 ≥6（引擎硬校验）、意象呼应、
     零文字零 emoji、透明底、低饱和同色系 ≤4 色、轻量明暗渐变允许。
2. compose 引擎用量校验：正文素材 0 处 →「未包含美术素材」警告；<4 处 →「素材用量偏低」
   警告（预览区展示，提醒模型下次补足）。
3. mock 样例扩到 5 处素材（旗帜宽幅 + 花枝变体：banner/小节×2/气泡/收尾）。
4. chat.rs max_tokens 16000 → **32000**：实测 reasoning_effort=max 下"5-8 个 SVG +
   正文"的复杂创作会把 16k 预算全耗在推理（completion=15999、content 空）；32000 在
   API 接受范围内（实测 24000/32000 均 HTTP OK）。

## 验证

- compose-check 30 项全绿（新增 zero-art/low-art 用量警告断言、5 素材收集断言）。
- E2E 33 项全绿零浏览器错误：S1.8 升级为 five art assets rendered（预览出现 5 张
  渲染 data 图）；S1.5 导出 195KB（5 张内嵌 PNG）；S9a-d/S2 语义保持。
- 真实模型 live（v4-flash + max 推理 + 32000 预算）：日系咖啡开业 5876 字正文，
  **6 处素材**（目标 5-8）：banner 暖帘 wide、小节拉花 inline、豆子旅程 inline、
  托盘四季 wide、手冲壶 inline、收尾横幅 wide——元素 8-13 全部 ≥6，compose 渲染
  promo 767 字、0 警告。产物 verify-artifacts/compose-live-art5.html。
- cargo 17/17。

## 遗留说明

- 单屏 ≤1 与"5-8 处"按模型自律 + 引擎数量下限提示执行；像素级密度校验未做
  （后续如需可在渲染后按高度分组统计）。
- 素材数量目标与正文长度相关：引擎只在下限 <4 时提示，persona 根据字数在 5-8 内浮动。
