# 风格选型教程注入 + 反模板化（第 20 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户反馈

> 目前只有风格参考，没有风格选择的教程，全都是成国潮模板了

## 根因

1. **没有选型依据**：知识库里本有完整的风格选型教程——`视觉/风格/00-索引.md` 的
   「内容类型 → 首选/备选风格」速查（咖啡餐饮→美式复古/日系、科技新品→科技、节日国货→国潮…）
   与 `style-guide-choose.md` 决策流——但桌面检索从不注入它们（00-* 索引在加载时被过滤掉），
   模型在 auto 场景没有依据 → 瞎选或偏爱国潮。
2. **模板化套用**：注入的 style-* 文件含"标题层级/模块表现/文案调性"等规范与示例，
   模型把它当整篇模板照搬 → 不同主题产出一律"国潮模板"长相。

## 实施

1. **retrieval.ts**：
   - `ensureKnowledgeLoaded` 不再过滤 00-*（保留全库，含各方向 00-索引）；
   - 相似度兜底排除 00-* 与 design-logic-components（索引不当普通知识节选）；
   - 新路由：auto（assess 无风格命中）且创作请求 → 注入 `视觉/风格/00-索引.md`
     （内容类型→首选/备选风格速查，用路径定位避开各方向同名 00-索引），命中提示"风格速查"；
   - 用户点名风格仍注入 style-<key>；路由条目按原对象输出（避免同名索引错取）。
2. **persona 风格规则 v3**：
   - auto：先按注入速查与读者/情绪匹配选风格，再在 v2 正文第一行声明 `[[theme:名称]]`；
     拿不准且无合适候选时宁可不声明（默认双色系），不硬套风格；
   - **风格 = 皮肤，不是内容模板**：正文结构与文案由内容类型模板与主题决定；
     注入风格文件里的标题/模块/文案示例仅说明规范，禁止照搬骨架句式；
     同一风格的不同主题必须产出互不雷同的内容。

## 验证

- pnpm build exit 0；E2E 40 项全绿零浏览器错误（S8 断言补"风格速查"命中：
  知识命中 = 活动 / 内容类型:promo / 风格速查 / 合规红线）。
- 真实模型三场景（同质注入：风格速查 + type-promo + comp-banned；均 auto 不指定风格）：
  - 咖啡店开业 → `[[theme:日系]]`：米纸底、木牌/窗台/热咖啡意象，banner「树下咖啡·滨江店，开了」；
  - 科技新品（智能手环）→ `[[theme:科技]]`：深蓝表带、心率刻度，banner 参数化利益点；
  - 中秋国货礼盒 → `[[theme:guochao]]`：朱红/鎏金桂花满月，banner「把旧时的中秋味 装回这一盒」。
  三篇风格、配色、素材意象、banner 文案与结构全部差异化——不再是"全国潮模板"。
  产物：verify-artifacts/style-choice-{coffee,gadget,festival}.md。
- cargo 17/17（Rust 零改动）。

## 遗留说明

- auto 选型质量依赖模型对速查的遵循（推理 max 下表现稳定；偶发未闭合 v2 围栏已见一例，重试即好）。
- UI 显式选择风格仍为最可靠路径（渲染由 opts.theme 直接保证）。
