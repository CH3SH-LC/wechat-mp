# 需求报告：界面体验修正——常驻会话栏 + 对话流隐藏代码

> 元信息
> 生成日期：2026-09-04
> 调用方：wechat-mp-desktop 维护会话（用户直接反馈后经 myworkflow-req-clarify）
> 澄清轮次：2
> 选定方案：待用户确认（推荐 A）
> 决策理由：用户两轮澄清分别选定「常驻会话栏」与「默认隐藏、可展开源码」

## 核心目标

1. 会话上下文以**左侧常驻栏**呈现（像 DSH 的会话侧栏）：会话列表常驻可见，新建/切换/删除一步直达，当前会话高亮。
2. 对话流**净化**：AI 气泡不再显示 ```html 代码原文，只显示说明文字；HTML 自动进入右侧 375px 预览；每条助手消息提供「查看 HTML 源码」入口，点击才展开代码（默认收起）。

## 原始需求（用户原话）

> 首先，为什么输出的代码会被用户看到
> 其次，为什么不搞清楚用户需求就直接开干？…没有项目的概念或者没有上下文的概念，需要能像 dsh 那样有不同的上下文窗口

## 澄清要点

- Q1（上下文形态）→ A：**常驻会话栏**——多会话已实现（第 9 轮 sessions），入口由顶栏弹层改为左侧常驻栏，一步直达；不需要"项目=顶层容器"或"命名上下文卡片绑定设定"。
- Q2（代码展示）→ A：**默认隐藏、可展开源码**——气泡只显示说明文字；右侧预览承载 HTML；点「查看 HTML 源码」才展开。

## 输入 / 输出

- 输入：现有桌面端（React+TS / Tauri+Rust sessions 存储）
- 输出：
  - 三栏布局：会话栏（左，约 200px，可折叠）｜对话（中）｜预览（右，375px 手机壳不变）
  - 助手消息渲染拆分：说明文字 + 折叠的源码查看器

## 涉及范围

- 新建：`src/components/SessionRail.tsx`；本文档 `docs/information/`
- 修改：`src/App.tsx`（布局三栏 + 会话栏状态）、`src/components/ChatPane.tsx`（消息渲染拆分 + 源码展开）、`src/App.css`、`scripts/verify-ui.mjs`（选择器适配：会话按钮→侧栏行；新增断言：气泡不含 ```html、点击展开可见源码）、`RELEASE-NOTES.md`、四文件文档
- 不涉及：Rust 侧（sessions/settings/export/chat 全部不变，仅 UI 改造）；存储结构

## 约束条件

- 零 emoji / 零图标字符铁律
- 375px 预览渲染逻辑不变
- busy（流式生成中）禁止切换会话（沿用第 9 轮语义）
- 浏览器模拟与 Tauri 桌面两通道行为一致
- 现有 E2E（S1-S8）语义保持，选择器随 UI 迁移

## 边界条件

- 消息只有代码无说明文字 → 显示占位"已生成推文，见右侧预览"
- 说明文字中出现多个 ```html 围栏 → 全部从气泡剥离（只留围栏外文字），源码取首个围栏
- 展开源码默认收起；每条助手消息独立展开状态

## 方案对比

| 方案 | 思路 | 优点 | 缺点 | 工作量 |
|---|---|---|---|---|
| **A（推荐）** | 会话栏常驻 + 气泡净化（可展开源码） | 直达 DSH 观感；改动聚焦、可一轮完成并回归 | 会话栏占 ~200px 宽度 | 1 轮 |
| B | A + 会话重命名/拖拽排序/折叠动画 | 更完整 DSH 观感 | 超出本次诉求（YAGNI：可后续轮） | 1.5-2 轮 |
