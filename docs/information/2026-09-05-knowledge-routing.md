# 三层数据库按任务路由注入——让最终三层库真正驱动创作（第 19 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户问题

> 我需要的就是最终的三层数据库，为什么没能体现出这个性能

## 根因

桌面端的知识运用方式与 DSH 差距巨大：
- DSH（wechat-mp preset agent）：模型按 00-GUIDE「路由 → 方向索引 → 点文件」主动读
  目标文件全文再创作；
- 桌面端：发送前本地关键词检索一次，取 ≤6 条节选、每条截断 4500 字注入 system——
  三层库的 46 模块 / 30 风格 / 内容类型 / 模板 / 合规红线绝大部分内容**从不进入生成上下文**，
  知识库再全也体现不出来。

## 方案

桌面没有工具调用能力（模型不能自己读库），因此由**前端在单次请求内执行 00-GUIDE 的
路由逻辑**（属于单次请求的知识组装，不是对话流程状态机，不违反永久禁令）：

1. **retrieval.ts 任务路由注入**：
   - 内容类型（needs.assess 判定）→ 注入 `文本/内容类型/type-<key>` + `文本/文案/copy-tpl-<key>`（该类型成稿模板）；
   - 风格（assess/文本词）→ 注入 `视觉/风格/style-<key>` 全文（含库中完整色板表）；
   - 营销类（promo/soft/brand）→ 注入 `文本/合规/comp-banned` 合规红线；
   - 用户明示的主题词命中（模块/文案位词）优先保留；相似度二元组兜底补足 topK；
   - 路由点文件截断放宽到 8000 字符（其余 4500）。
2. **persona**：知识库参考段改为「按任务路由注入，注入内容即该任务权威细则——
   类型模板按模板执行、风格色板用于主题与素材、合规红线必须遵守、冲突以库为准」；
   风格规则强化：auto 场景必须在 v2 正文第一行声明 `[[theme:名称]]`（不声明则渲染停留在默认双色系）。
3. scripts/live-knowledge-probe.mjs：真实注入对比验证脚本。

## 遗留说明

- auto 场景下模型是否声明 `[[theme:名称]]` 依赖模型遵循（persona 已加"不声明属明显失误"强调）；
  UI 显式选择路径由 opts.theme 保证渲染，不受影响。
- 组件化不足仍靠 persona + 引擎下限警告双保险（本轮未见结构性提升，若需更强制可再议）。
