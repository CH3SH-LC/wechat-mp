# 素材具体插画化 + 正文加长 + 气泡角饰修饰（第 21 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户反馈与根因

1. **SVG 插图过于抽象、没有具体图像**：persona 素材铁律此前写的是"植物/自然/器物**线条意象** +
   平面克制观感"，模型按字面产出几何线条剪影（live 证据：轮廓线+圆点的装饰画），
   知识库里"具体插画"（明暗层次/细节）的引导从未进入素材规则。
2. **文案太短**：默认长度 800-2000 字偏低且无"充实度"要求，模型倾向精炼短篇；
   live 常见 600-800 字。
3. **所有气泡缺少修饰**：bubble() 只有纯色/左条；组件内装饰素材（DSH `|grass` 角饰类）
   桌面未实现，气泡外邻接图替代不了组件内修饰。

## 实施

1. **persona 素材铁律 v4**：
   - 素材必须是"看得懂的具体图像"：明确对象轮廓与结构（杯有杯身/手柄/液面/拉花）、
     对象前后关系、同一画面 ≥2 层明暗（渐变或深浅色块）、1-2 处细节纹理；
     自查标准 = 读者一眼能说出画的是什么；禁止几何剪影冒充插画；
   - 正文默认 **1500-2500 字**，每小节展开细节/场景/数据，禁止敷衍成文；
   - 每个 KEY/TIP/DANGER 气泡必须带**角饰**：`::: art deco 名称`（方形 300×300、
     右下 1/3 具象小图案、≥6 元素）+ `> [!KEY|名称]` 引用，示例给出；
   - 移除 v2 内普通代码块语法（防围栏嵌套干扰提取）；
   - 风格规则：采用某风格（界面选择/用户点名/自主判断）一律在正文首行声明 theme
     （界面优先，重复声明无害）。
2. **compose.ts**：`::: art deco` 预扫描注册（SVG ≥6 元素 + viewBox 校验，未达标警告）；
   bubble 支持现场角饰（60px 右下 data uri）；引用未定义角饰产生警告；
   正文偏短（<600 字）警告。
3. **chat.rs**：max_tokens 32000 → **64000**（实测 1800+ 字 + 多素材 + 角饰的长创作在
   max 推理下仍会吃光 32k 预算，content 为空）。
4. mock 样例加长（1500 字级正文）并演示 KEY 气泡角饰；compose-check/E2E 断言更新。

## 验证

- pnpm build exit 0；compose-check 41 项全绿（角饰渲染/未定义警告/偏短警告/长文无警告）；
- E2E 41 项全绿零浏览器错误（素材+角饰渲染 data 图；S8 路由注入；S9a-d 语义保持）；
- 真实模型 live（有闲茶咖开业，信息齐全、1800-2200 字指令、要求气泡带角饰）：
  - 正文 1518 字（warnings=0）；
  - 2 个气泡分别带 `keyflower`、`tipdessert` 角饰（deco 定义 + 引用均正确）；
  - 7 处素材全部"具体插画"：朱红门前的第一盏茶与咖（41 元素门面场景）、窗边小桌与茶壶、
    一杯手冲与一盏热茶、一碗桂花茶冻、桂花枝下的一盏茶（元素 16-41，深浅色块塑形）；
  - 产物：verify-artifacts/probe-injected.md、compose-probe-r21.html。
- cargo 17/17（Rust 仅 max_tokens 数值调整）。

## 遗留说明

- 素材"具体性"由 persona 规则引导 + 引擎元素/占位校验保障，无法自动判定"是否抽象"；
  若个别素材仍偏抽象，可让用户重试或点"再写一篇"。
- 角饰等组件内装饰依赖模型正确使用 deco 定义/引用协议；引用错误时引擎会提示而非静默。
