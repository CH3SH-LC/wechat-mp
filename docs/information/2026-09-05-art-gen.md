# 现场生成美术素材——按知识库每次创作 SVG + 强制使用 + 结构 ≥6（第 15 轮报告）

日期：2026-09-05 ｜ 状态：已实施并验证

## 用户问题

> 为什么现在没有生成素材了？我希望能够根据知识库，每次现场生成需要的 svg 素材；另外，强制规定要使用美术素材，且每个 svg 内部结构不得少于 6。

## 根因

第 14 轮移植 DSH compose 时按"未上传即移除"处理 art://（桌面无微信上传通道），
正文里的素材引用被移除并警告——所以桌面端创作不再带美术素材。

## 方案

桌面本地素材管线（无微信上传，全部自包含）：

1. **创作协议**：模型在 ```v2 正文里按知识库规范现场绘制 SVG，用新容器表达：
   `::: art wide 说明` / `<svg …>…</svg>` / `:::`（wide=整行横幅，inline=居中 ≤56%）。
2. **引擎校验（确定性门槛）**：`svgElementCount` 统计 circle/rect/ellipse/line/path/
   polygon/polyline（剥离 defs/渐变/注释），并要求带 viewBox；**图形元素 ≥6 才渲染**，
   不达标 → 占位文本 + 警告（用户"结构不得少于 6"由此硬性保证）。
3. **渲染**：达标素材由前端 canvas 2x 渲染为 PNG data URI，内嵌 <img>（预览可见、
   导出自包含，微信后台粘贴可转存）；canvas 不可用时回退 svg data URI。
4. **强制使用**：persona 美术素材铁律——每篇推文必须包含 ≥1 处素材；素材意象与正文
   呼应（杯盏/拉花/豆枝、旗帜/书本/朝阳…）；植物/器物线条意象、零文字零 emoji、
   透明底、低饱和同色系 ≤4 色（按知识节选风格色板）、SVG 内允许轻量明暗渐变
   （作为图片渲染合法，不违正文平面化铁律——module-art-assets 规范）、密度每屏 ≤1。
5. 知识库配合：module-art-assets.md 等素材规范已在检索池中（本次引用其核心规则
   固化进 persona 硬规范）。

## 遗留说明

- 素材密度与"每屏 ≤1"靠模型自律 + 引擎只保证元素数与 viewBox；若出现素材过量/过密，
  可在后续轮次加密度计数检查。
- data URI PNG 内嵌 HTML 在本机预览与导出可用；微信后台粘贴时由编辑器转存为素材。
