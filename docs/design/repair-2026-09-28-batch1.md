日期：2026-09-28。依据：仓库外的真实运行调查与修复计划（`.codex/visualizations/2026/09/28/01a0e80f-…/`）。
本记录保留**决策与口径**；逐文件改动与验证结果见 [详细进度](../../PROGRESS.md)。

起因是一次真实交付事故：用户拿到的「筑基」稿**一张图都没有**，而库里明明有四枚可用素材；
文档里的 7 条告警（3 条"装饰素材未达标"、3 条"角饰未定义"）与"绑定全部 `source=failed`"说明
素材链路从引用识别那一步就断了；助手的最后一句却是"修好了"。

| 现象 | 根因 | 证据 |

## 二、本批的口径（用户已确认的计划原文即决策）

1. **先补观测，再谈优化。** 没有逐请求证据时，"为什么慢/为什么失败"只能猜。
2. **素材协议只有一套：** 主模型只写 `[[asset:分类|素材ID|用途]]` / `[[img:…]]` / `[[deco:…]]`；
   `::: art` 系容器是**内部编译产物**，不向主模型暴露，也不作为诊断话术出现。
3. **解析器先宽匹配、再校验**，绝不因为"分类写法不认识"就把整条引用静默丢掉。
4. **同一素材位在整个回合内只做一次决定**：成功即复用成品，失败即沿用失败，不因重新排版重获预算。
5. **完成状态按事实判定**（绑定 + 实际渲染 + 告警），不采信助手的一句"修好了"。
6. 沿用既有边界：deepseek-flash 锁定不变；不用前端状态控制对话意图（铁律 6）；
   不新增默认付费视觉调用。

## 三、关键设计取舍

### 3.1 日志为什么放 Rust 写盘，而不是前端
模型请求的 `finish_reason` / `usage` / 网络错误只有 Rust 侧拿得到；耗时用**单调时钟**（`Instant`）
而不是墙钟（系统对时会跳变）。前端负责"素材位决策"这类编排层事实，两边写同一个 JSONL 文件
（`<workspace>/traces/<runId>.jsonl`）。**写盘失败一律吞掉**：日志是旁路，不能因为它失败而打断创作。

### 3.2 失败为什么要分成五类而不是一句话
"素材生成失败"这句文案在真实故障里毫无用处——网络错、服务空返回、正文里没有 SVG、
被本地质检拒收、用户取消，**处置完全不同**。五类分类同时写在 Rust（`trace.rs::FAILURE_CLASSES`）
与前端（`trace.ts::FailureClass`），并由 `trace-check.mjs` 交叉比对两侧文本，防止改一侧漏一侧。

### 3.3 分类写错：兼容就恢复，不兼容就拒绝
- 声明分类与实际分类不一致、但**安放位相同**（`bubble` ↔ `deco`、`heading` ↔ `art-inline`）：
  按库记录恢复并保留可解释告警，**不进**自动修订清单（重写正文解决不了它）。
- **安放位不同**（把宽幅插画声明成角饰）：明确拒绝，并把它算作"引用不可用"交给有界自动修订——
  这一点与 2026-09-24 的 P0 口径有**有意的差别**：那条口径针对的是"分类名写错但用途没写错"，
  而"用途不兼容"是真正无法解析的引用，必须让模型知道。

### 3.4 旧 `::: art deco` 文字块：只恢复，不绘图
恢复顺序：文档已有绑定 + 固化快照 → 精确素材 ID → **唯一**库名称。只接受 `usage=deco` 的素材。
未知、重名、用途不符、与 `|new` 冲突，一律返回明确错误。**绝不因此自动发起绘图**——
那正是把等待放大的老路。

### 3.5 未完成素材的单项重试算不算"前端状态机"
不算，且必须说清边界：铁律 6 禁止的是**用前端状态控制对话流程、澄清或路由**。
"重试"重跑的是**素材任务队列里的一个条目**（同一素材位、同一描述、同一轮创作），
消息仍直通模型、不产生新回合、不改变任何对话判断。它显示在预览区而不是对话区，
也刻意做成"就地重跑"而不是"再问模型一次"。

## 四、有意**没有**做的（属第二批，或需要授权）

1. **并发绘图**（每篇最多 2 个并发）、**初始超时参数**、**后端取消句柄**：阶段 4 内容。
2. **自动修订接上 `revise` 预算档**（high/32000）：需要真实模型先验证"正文保留能力"，
   不能盲改（改错会让修订稿被截断）。
3. **鉴权/无效参数不重试**：当前 `401/403` 仍归入 `network` 并允许一次重试；细分需要新增分类，
   与阶段 4 一起做。
4. **最终尺寸（60px）视觉检查**：阶段 5 内容。本批只做到"结构检测 + 栅格检测"不变。
5. **真实模型小样**（有库复用 / 仅缺一张新图 / 已有稿只改正文）：需授权付费调用。

## 五、验收对照（计划原文 → 实际结果）

| 计划验收 | 结果 |
| --- | --- |
| 五类失败能明确区分 | `trace-check.mjs` 逐个注入网络错/空返回/无 SVG/质检拒收/取消，五类各自命中且尝试次数符合预算（见 PROGRESS） |
| 同一请求可沿 runId/slotId 对到最终绑定 | 每条 slot 记录带 `slotId`，文档 `bindings` 同字段持久化（Rust 侧 `#[serde(default)]`，旧文档可读） |
| 日志失败不阻塞创作 | 命令恒返回 Ok；`sink` 抛错被 `trace.ts` 吞掉并有断言 |
| 四枚已有素材恢复绑定且 **0 次绘图** | 真实失败样例回归：4 枚全部 `source=asset/recover`，台账里这 4 位的 `attempts` 全为 0 |
| 中文分类不泄漏进 HTML | 样例成品里已无 `[[asset:`，compose 输出无协议残留 |
| 未知旧角饰块 0 次绘图 | 遗留块只走恢复路径，恢复不了即报错，不触发绘图 |
| 只改正文不重画已成功素材 | 台账跨三轮复用成品块，跨 3 轮只画 1 次 |
| 失败素材不因自动修订重获预算 | 三次素材化共 2 次绘图（旧实现 6 次） |
| 零图失败稿不能标为完成 | 未完成清单 + `unfinishedWarning`，且保存时不用零图版本覆盖上一版可用成品 |
