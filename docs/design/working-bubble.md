## 为什么取消独立「质量检查」阶段（W5 的由来）

原设计有 8 个阶段，其中 `quality`（`checkHtml` + `fixableWarnings`）是纯字符串检查，**实测 < 1 ms**。实现时实测确认：浏览器根本没有机会把它绘制出来——React 会把「质量检查」和紧随其后的「保存」并成一次提交，DOM 里从不出现这一帧（用 rAF 采样与 MutationObserver 双重验证）。

两个可选处置：给它一个约 0.4 秒的人为最小停留（可看见，但每次成稿结尾多锁输入 0.4 秒，且这 0.4 秒并非真实耗时），或并入相邻的真实耗时阶段。用户选择后者：**合并为「排版与质检」**，质检结论改由它本来就能被看见的地方承载——需要重写时写进「自动修订」的细节（`发现 N 个可修复问题，正在重写…`），不需要重写时保留在右侧预览的质检条（`质量检查 · 通过`，一直显示）。

同类问题也出现在「保存文档」：浏览器 mock 下 localStorage 落库是微任务链，几毫秒走完，React 同样会把它并掉。这里保留该阶段（桌面端落库要走 Tauri invoke，本来跨多帧、看得见），实现上用 `flushSync` 强制提交 + 让出一帧（`requestAnimationFrame`）保证这帧真的到达 DOM 并被绘制。代价约一帧，换来阶段不会被静默合并。

## 与铁律 6 的边界

气泡是**纯展示**：由 `busy` + 前端各步骤就地上报的 `TaskEvent` 推导，只读 `Date.now()` 计时，没有任何分支判断、澄清或路由依赖它。`asset-resolve-check.mjs` 里有一条不变式断言——同一输入在「上报进度」与「不上报进度」两种情况下产物逐字一致，防止进度上报日后长出副作用。

## 未做 / 待跟进

- 素材工坊与导出图片的进度展示未纳入本轮（W2）；工坊的 `rerenderDocWithCurrentAssets`（被引用文档用新版素材重渲染）目前**完全没有忙碌态**，属既有缺口。
- 保存失败目前只写控制台（`console.warn`），界面上不提示。用户会以为已保存。这是本轮保留下来的既有行为，需要单独一轮处理。
- 事件不带结构化进度字段（如 `done/total`），"第 2/5 张" 是拼进文案里的。若以后要画进度条，需要扩 `TaskEvent`。
- 桌面真实模型下的完整阶段走查（读取资料 → 思考 → 撰写 → 素材 → 排版与质检 → 保存）需要授权付费调用，本轮未跑。
