## 3. 包 A：先让回归能够证明失败

### 3.1 修唯一判定器

`preview-resource-check.mjs:179–185` 在导航异常、零条检查时仍写“全部 PASS”，虽然进程 exit 1。统一计算一个结果对象，所有输出从它派生：

```ts
type RunResult = {
  status: 'PASS' | 'FAIL' | 'ERROR' | 'BLOCKED';
  executionComplete: boolean;
  plannedCases: string[];
  executedCases: string[];
  checks: { id: string; pass: boolean; evidence: string[] }[];
  errors: { stage: string; message: string }[];
};
```

PASS 必须同时满足：计划场景执行完整、必需检查存在、没有失败或基础设施错误、必要证据可读。异常捕获写 ERROR，缺依赖/无法开始写 BLOCKED；都退出非 0。finally 只负责落盘与关闭资源，不根据 `failed===0` 推导成功。零检查是错误，不是通过。

修正等待条件：先确认本轮 run 已开始，再等待同一 run 终结及提交/失败结果；`waitForFunction` 的超时放正确 options 参数。不能仅等待“工作气泡不存在”。

## 6. 包 D：预览资源与渲染

修 `preview-safe.ts:35/42/61/85` 的语法覆盖与序列化，不继续叠加几条只针对已知字符串的正则后声称不会漏放。

实现应按浏览器 HTML/CSS 解析语义识别并安全序列化资源值，正确处理实体、引号、srcset 的 data URI 逗号。任何解析过程都不先把未处理节点插进活动文档触发加载。可以加预览专用 CSP 作第二道防线，但必须核对 data/blob、现有样式与本地预览需要，不能禁掉所有图片来过测试。对被防线拦下的加载尝试保留诊断；不要只屏蔽 console/request 监听。

浏览器测试在发送/渲染前挂网络监听，外站 route 只用于防止实际访问，**捕获到请求即失败**，不能把被 abort/本地 fulfill 当作产品没请求。CSP 拦截不一定产生 Playwright request 事件，还须采集 iframe 的 `securitypolicyviolation` 并检查实际显示副本。已知四个外链反例必须证明资源引用已正确处理，不能只因网络为 0 就把“仅被 CSP 挡住”判为净化成功。第二道防线的单独故障注入可期待 CSP 阻断，但报告须与正常净化场景分开。

## 8. 包 F：用户已授权的真实模型测试

### 8.1 直接执行条件与建议批次预算

B/C/D 关键确定性反例与 E 集成通过后，直接使用本机已有有效端点、凭据和当前锁定模型配置执行。不能继续以“需付费授权”挂起本任务；凭据缺失、端点故障或额度不可用应报告具体阻塞，不伪造成功。

为落实“少量”，建议固定 **4 个用户场景，本次真实验收及针对性复验累计最多 20 次可能计费的 completion 派发，其中 gen_svg 累计最多 4 次；单回合约 5 分钟、单批运行约 15 分钟**（不包含修代码时间）。这是本指南的执行默认值，不是用户给定的硬金额限制，也不是性能 SLA；现有更严格的单槽/修订预算保持不变。所有 prep、write、revise、draw、补描述调用合并计数，视觉复核默认保持关闭。通常首图与换图各只需一次绘图，额外名额仅容纳现有有界重试与必要复验；新批次不清零，四个场景之外的重复发送也计入累计账本。
