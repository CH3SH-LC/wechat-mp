## 3. 包 A：先让回归能够证明失败

### 3.1 修唯一判定器

`preview-resource-check.mjs:179–185` 在导航异常、零条检查时仍写“全部 PASS”，虽然进程 exit 1。统一计算一个结果对象，所有输出从它派生：

```ts
type RunResult = {
  status: 'PASS' | 'FAIL' | 'ERROR' | 'BLOCKED';
  executionComplete: boolean;
  plannedCases: string[];
  executedCases: string[];
  checks: { id: string; pass: boolean; evidence: string[] }[];
  errors: { stage: string; message: string }[];
};
```

PASS 必须同时满足：计划场景执行完整、必需检查存在、没有失败或基础设施错误、必要证据可读。异常捕获写 ERROR，缺依赖/无法开始写 BLOCKED；都退出非 0。finally 只负责落盘与关闭资源，不根据 `failed===0` 推导成功。零检查是错误，不是通过。

修正等待条件：先确认本轮 run 已开始，再等待同一 run 终结及提交/失败结果；`waitForFunction` 的超时放正确 options 参数。不能仅等待“工作气泡不存在”。

### 3.2 修过弱或相反的测试预期

- prep 返回 source 不等于进入 App 交付：增加实际 App 的候选、门禁、提交、读回断言。
- `correctionSent` 必须识别实际追加的纠偏轮，不能因初始提示已经包含工具名而恒真。
- 普通问答测试必须包含历史创作，使用真实 App 入口，不手工将 `creationContract=false` 排除缺陷。
- preserve 无绑定仍绘图不是合法正例；改正 `asset-completion-check.mjs:343` 的预期。
- 预览必须挂载各变体，断言网络事件、DOM、computed style 和有效图片解码；不能只检查字符串没有 https。
- 原始违规稿至少断言特定 `html.external-img` 问题及原文，不能任意 `html.*` 就算外链证据保留。

正式 runner 每次要求新 outDir；同日多跑使用时间与随机后缀。已存在的结果目录默认拒绝覆盖。原 `live-three-samples.mjs` 未整改，不可直接作为本轮签收工具；可以修它或新建替代入口，但只能有一个实际业务判定来源。

### 5.4 preserve 在任何绘图前闭锁

修 `image-agent.ts:465/891–925`。preserve 只接受当前文档的稳定引用，或依据绑定/来源唯一恢复出的同一素材。无命中、多个不同命中、新引用、新占位、删除或更换既有素材都要明确阻断，不能掉回普通检索/新绘制。预检整组素材再进入执行，不能前几位先画、最后一位才发现 preserve 违规。

文档快照是保持素材的权威输入：同 ID 库升级到 v2，仍用文档 v1 内容与版本；库删除而快照有效时仍能恢复。快照缺失或损坏要明确失败，不能拿库最新版悄悄补齐。显式 `[[asset]]` 与旧 `[[img:...|new]]` 恢复路径都适用。

精确 slot 匹配也要检查唯一性，不能 `find()` 取首项。只有身份、版本、快照完全相同的重复记录才可去重。除 ID 外比较版本和内容哈希；`gen_svg=0` 或 ID 相同不足以证明素材不变。

modify 仍允许用户明确新增/换图，走现有预算和质检。不要全局剥掉 `|new`、永远强制复用或关闭绘图。

## 6. 包 D：预览资源与渲染

修 `preview-safe.ts:35/42/61/85` 的语法覆盖与序列化，不继续叠加几条只针对已知字符串的正则后声称不会漏放。

必须覆盖原八组输入：带引号外链图片对照、无引号 src、实体 URL、CSS 字符串 @import、style 内实体 URL、CSS 属性保留、有效 data 图片、混合 data srcset。四种外链应在实际 iframe 上零网络请求；两个显示反例应恢复原 computed style/可解码图片。

实现应按浏览器 HTML/CSS 解析语义识别并安全序列化资源值，正确处理实体、引号、srcset 的 data URI 逗号。任何解析过程都不先把未处理节点插进活动文档触发加载。可以加预览专用 CSP 作第二道防线，但必须核对 data/blob、现有样式与本地预览需要，不能禁掉所有图片来过测试。对被防线拦下的加载尝试保留诊断；不要只屏蔽 console/request 监听。

原始 source/HTML、质量诊断、失败草稿继续保留；显示副本与正式验收/导出输入分开。原外链仍应触发明确质量问题。正常 data/blob 素材不变，CSS 的无关颜色/尺寸保持，图片用真实可解码数据并检查 naturalWidth。

浏览器测试在发送/渲染前挂网络监听，外站 route 只用于防止实际访问，**捕获到请求即失败**，不能把被 abort/本地 fulfill 当作产品没请求。CSP 拦截不一定产生 Playwright request 事件，还须采集 iframe 的 `securitypolicyviolation` 并检查实际显示副本。已知四个外链反例必须证明资源引用已正确处理，不能只因网络为 0 就把“仅被 CSP 挡住”判为净化成功。第二道防线的单独故障注入可期待 CSP 阻断，但报告须与正常净化场景分开。

## 8. 包 F：用户已授权的真实模型测试

### 8.1 直接执行条件与建议批次预算

B/C/D 关键确定性反例与 E 集成通过后，直接使用本机已有有效端点、凭据和当前锁定模型配置执行。不能继续以“需付费授权”挂起本任务；凭据缺失、端点故障或额度不可用应报告具体阻塞，不伪造成功。

为落实“少量”，建议固定 **4 个用户场景，本次真实验收及针对性复验累计最多 20 次可能计费的 completion 派发，其中 gen_svg 累计最多 4 次；单回合约 5 分钟、单批运行约 15 分钟**（不包含修代码时间）。这是本指南的执行默认值，不是用户给定的硬金额限制，也不是性能 SLA；现有更严格的单槽/修订预算保持不变。所有 prep、write、revise、draw、补描述调用合并计数，视觉复核默认保持关闭。通常首图与换图各只需一次绘图，额外名额仅容纳现有有界重试与必要复验；新批次不清零，四个场景之外的重复发送也计入累计账本。

预算必须在派发前约束，不能只事后数 trace。优先使用既有请求预算机制或隔离测试专用计数入口，不为测试增加新的产品对话状态机。累计次数与剩余额度写证据；达到预算/时限就终结该批并保留未完成状态，不静默追加回合直到变绿。

第一次业务失败立即保存证据、停止该批后续付费回合并定位修复。修复后的针对性复验仍属于本次授权，不需重复询问同一许可；提前登记新批次、累计派发和剩余预算，不能无限重跑。累计预算用尽仍未通过时，交付失败与未覆盖结果，提出下一步所需调用量，不能另起批次绕过上限。若要扩大到批量压测、其他模型或未约定功能，另行说明范围。

### 8.5 每轮账本与判定

请求记录：本地 requestId、runId、phase、attempt、实际模型、派发/结束时间、耗时、结果类别、服务端 requestId、可得 finish_reason/usage。元数据查询与 completion 分开。失败/取消可能已经计费；没有 usage/价格就写费用未知，不用 0 或请求数代替金额。

业务记录：操作前后 session/document/generation/accepted 与 draft revision；新版本的 source、HTML、bindings、snapshots、quality、runId 与哈希；模型完整原文；实际调用增量；候选、提交回执与独立磁盘读回；预览/导出图。采集脱敏，不保存请求头或密钥。
