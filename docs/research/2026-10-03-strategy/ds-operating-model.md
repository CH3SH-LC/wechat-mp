# 如何高效驱动 DS：从开放式续跑改为有边界的交付

日期：2026-10-03。方案基于推文助手当前 `839183b`、本机DSH源码的工具契约及本轮独立研究；这是后续执行建议，没有启动DS付费任务或改动其运行配置。

实际下一轮请使用[五字段F1任务卡](next-ds-task.md)。本页提供通用协作约定，专题证据按需读，不作为每个实施者的全量必读上下文。阶段0的IPC67/67与ledger39/39独立复核已完成，直接进入内容任务。

## 1. 两套智能体分工要分开

- **开发智能体**：Codex做需求切片、疑难诊断、独立验收与集成判断；DS做边界明确的实现和既定回归。不要让Codex只追加审计，也不要把DS放进“继续做到所有问题都消失”的无限循环。
- **产品里的主创/素材智能体**：继续按已有产品契约工作。本方案不要求把桌面产品迁回DSH、不换模型、不引入前端意图状态机。
- 把“DS写了多少代码”改为“这一包让用户哪一步更快或更可靠”；把“Codex发现了多少问题”改为“是否找到了足以改变交付决策的证据”。

## 2. 默认一实施一复核，独立任务足够大时再并行

下表是角色职责，不要求每轮凑满四个agent。小改动由一名实施者加一名独立成品复核者完成；只有第二个独立用户结果已经明确、预计收益超过协调成本时才增加写者。

| 角色 | 工作与所有权 | 禁止 |
| --- | --- | --- |
| 调度/集成 | 固定用户结果、基线、允许文件与验收合同；合并、构建、真实桌面/预算/发布产物唯一写者 | 自己写完又作为唯一验收人 |
| DS实现A | 一个独立模块及其局部测试，例如分页算法 | 顺手改prompt、素材库、发布脚本 |
| DS实现B | 另一个无写冲突模块，例如安装手册/设置错误提示；或独立分析 | 与A同时改App.tsx、同一夹具、同一证据目录 |
| 独立验证者 | 用已冻结输入验证行为与成品，找决定性反例，报告缺陷分类 | 为过关修改期望值、接着大范围找新问题 |

研究任务可以三路并行。代码任务以可隔离程度决定并发，生产改动WIP先限2；真实桌面、全局账本、同一个release输出目录串行。两个任务都需要App.tsx时排队，不用“高并发”覆盖掉文件冲突成本。需要工作树时先固定共同base和各自提交，不能把未提交脏目录当作隐式共享协议。

## 3. 每个任务包只包含一个可验收结果

派给DS的上下文控制在必要范围；先给最新状态页、目标源码入口、一个失败/成功样本，不复制全部历史审计。推荐任务卡：

```text
1. 用户结果：操作前后变化。
2. 基线与允许改动：commit、dirty文件、允许文件；需要时附exe指纹。
3. 原始样本：路径、当前观察，事实与假设分开。
4. 验收：最多三条核心条件及受影响检查。
5. 截止与回报：时间/调用上限、停止条件、唯一证据目录及未覆盖项。
```

建议初始时间盒为45–90分钟实现、20分钟定向验证；这是试行调度阈值，不是估算承诺。第一次诊断到一半须交“当前证据和下一步”，避免90分钟后才发现题面或工具不可用。连续两次修复同一问题仍失败，停止追加补丁，把最小复现交给独立诊断者；不是停止整个项目。

## 4. 把失败分流，防止一个问题锁死所有工作

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 产品行为 | 改文字偷偷换图、分页把一行字切开 | 保留输入/成品，按用户影响排序修；高影响阻对应交付 |
| 模型契约 | 不声明结果、同条混用工具 | 固定原始响应，先回放；改变prompt后做小样，不靠无限真实重试 |
| 验收脚本 | 字数上限写死、成功提交被断言判错 | 修runner并标旧判断无效；不重写已成立的产品成品 |
| 证据缺口 | 账务某条无trace、旧控制台没存 | 保留UNKNOWN；只阻依赖它的声明，不锁住无关UI/导出开发 |
| 外部条件 | 无公众号账号、无隔离安装环境 | 明确条件和负责人，交付清单；其余独立任务继续 |

预算绕过、真实数据隔离、错误清理身份仍是相关付费/桌面测试的硬门槛。其余问题不能一律提升到“全项目停工”。

## 5. 验收合同先冻结，修实现不能顺手改裁判

- 开工前固定合法变化与不变量；例如“只改文字”允许标题/正文变化，但素材ID/版本/内容必须保持，不能要求所有绑定元数据逐字节不变。
- 实现者可补测试，但独立验证者必须有一条不依赖实现者自报的成品检查。
- 三个指标分开：执行是否完整、断言是否通过、用户成品是否可接受。五页拼回像素相等仍不能证明不切字或好读。
- 每个新缺陷先归类再决定修复优先级；只有改变结果的可复现发现才回到本包。剩余推测进入backlog，不继续扩大冻结题面。
- 同一合同连续一轮独立复核没有阻断项就结束本包。缺陷越少不代表需要增加更多无关场景寻找下一条。
- 修字数、标题等runner判据时，先纯读已保存的前后成品，保留旧FAIL并另存新判断；不为改裁判重生成上游成功作品。精确模型响应未留存时只称成品重判或受控夹具，不伪称完整请求回放。

## 6. 按变更影响复用证据

保留现有release重建约束；本次不擅自改CLAUDE。最新需求记录载有当轮“scripts-only不重建”经用户确认，但本次未读取那条原始授权；执行者应按已有原始授权的实际范围沿用，不把一次例外自动扩大成永久豁免，也不对已明确长期授权重复确认。

| 变更 | 本包必验 | 可保留的证据 |
| --- | --- | --- |
| 纯文档/导航 | 链接、口径、文件编码 | 产品二进制与业务样本 |
| runner/断言 | 生产调用路径的定向回归、故障注入及正常对照 | 产品未变时的成品；不沿用被改错裁判的判定 |
| prompt/prep契约 | 冻结响应回放、实际请求消息断言、少量真实对照；产品重建/冒烟 | 保存/导出等未受影响层，但新二进制对应层仍须定向签收 |
| 分页/排版 | 长短、带图、边界夹具及人工观感；产品重建/冒烟 | 既有模型契约样本 |
| 安装资源/手册 | 重建、安装/启动及资源存在；记录核心产物差异 | 不把整套付费创作自动宣布失效；用输入影响与运行定向证据决定复测 |
| 跨模块保存/版本结构 | 数据迁移、写读回、失败恢复、重开与相关业务 | 独立但未变化的模型内容能力 |

关键区别：新二进制不能冒充旧二进制已验；也不能因此一律把所有历史业务证据作废。形成“改了哪些输入→哪些层需补证→哪些旧证据仍有效”的小表。全量复验留给发布候选或真正影响整条链的变更，不每一条注释都重跑付费L1–L8。

启动生命周期另做窄优化：同一隔离root的有序业务可验证复用已核验的存活实例，L5专门检查正常退出、新PID及读回。每phase仍做预算预留、当前探针身份与证据检查；关闭前PID身份保护不删。这是基于实际启动重试耗时提出的建议，尚未实施，不先建设新的调度平台。

## 7. 本机DSH能力核查对调度的直接影响

本次只检查 `D:/deepseek-harness/deepseek-harness` 源码，没有验证你当前DS会话装载的版本/插件。运行前先让DS回报实际可用工具，不照搬下列名字启动不存在的能力。

- `tool-subagent`支持一次性job和continuable两条路线；工具名由部署配置，不能假设一定叫subagent。
- 当前checkout的 `send_message` 是**下一轮FIFO消息**，不会立刻改变正在执行的那一轮。紧急改范围时，应先中断目标当前轮，再发新合同；连发“先别做/又改成这样”可能只是排队。
- `interrupt_agent` 接受停止请求不等于已经静止，且目标已启动的后代继续运行。设截止时先停止新委派，枚举descendants，逐个中断并确认终止；不能只给根一句“到点停”。
- one-shot后台job使用其对应job状态/收集/取消工具；不要拿continuable的ID规则去操作job。
- SDK提供方是新进程、新上下文。给它完整小任务卡和必要路径，不能假定它继承父对话。
- 不建议引入Ralph无限续跑来解决本项目的“慢”；当前Ralph有轮数上限，但worker报告complete仍不是独立认证，循环会放大错误合同。

本地依据：[控制工具](D:/deepseek-harness/deepseek-harness/packages/subagent/tool-subagent-control/README.zh.md)、[委派工具](D:/deepseek-harness/deepseek-harness/packages/subagent/tool-subagent/README.zh.md)、[SDK提供方](D:/deepseek-harness/deepseek-harness/packages/subagent/subagent-dsh-sdk/README.zh.md)、[Ralph](D:/deepseek-harness/deepseek-harness/packages/workflow/tool-ralph/README.zh.md)。

## 8. 以后衡量效率，用这些数据

首周只补轻量登记，不先造新看板系统。每个任务一行：开始/结束、首次是否可交付、必要请求/绘图、最终成品；有真实用户试用时再记人工修正分钟，不要求手工拆出全部工时。

北极星：**从已有材料到用户愿意发出的稿件，净人工时间是否减少**。辅助：首次交付通过率、单篇总等待、每篇总请求/绘图、误改已有内容次数、用户主动复用率。请求成功率、测试条数、代码行数与文档数量都不能替代这些结果。

先复用现有L7/L8和一个不同材料的保留样本，共三个；不要立即重跑十二题。通知、预告、总结、长文各三题的十二题集只作为后续候选，等真实需求和复用价值明确后分批冻结/执行，开发与保留样本分开。每次只跑受影响小组，首次失败保留，不以“最终总能成功”替代首次成功率。

## 9. 可直接交给DS的下一轮总指令

> 读取next-ds-task.md五字段卡，以当前commit和原始成品为准。第一包只处理本轮新写内容的材料依据，必须覆盖prep直接candidate入口及共同persona/知识优先级。用户明确只改标题时保留正文和素材，不静默纠正历史疑点、不强迫追问；保留也不代表事实已认证。一个实施者加一个独立复核者，三个样本起步，实际截获App派发消息，受控替身不冒充真实语义通过。旧IPC/ledger专项已独立复核，裁判修正先重判原件，禁止为此付费重生上游。分页和交付另包，禁止重写App或大建平台。按有效授权与现行规则完成适用构建/冒烟，真实模型/账本保持单一写者。两次同因失败转最小复现；冻结合同签收即停止，交成品、实际验证和限制。
