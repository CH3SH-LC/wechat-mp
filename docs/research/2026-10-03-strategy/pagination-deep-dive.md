## 3. 最小方案：改裁图坐标，不重排稿件

推荐保留现有长 canvas、字号、HTML 与落盘协议，仅增加一个**几何测量 → 切点计划**过程，替换固定 `y += 1000`。不要先改 DOM 分页、复制表头、加页眉或缩小整个稿件。

1. 在现有 host 仍挂载时等待图片与字体布局稳定，再测量。当前 `:37` 等图片但吞解码错误，`:38` 只等两帧；不能由注释推断字体完成。正常字体可使用 `document.fonts.ready`，但仍须验证与 foreignObject 光栅化所得布局一致。[Document.fonts](https://developer.mozilla.org/en-US/docs/Web/API/Document/fonts)
2. 遍历可见 text node，用只覆盖该文本节点的 Range 取每行矩形；收集 `img`、内联 SVG、表格行等需保护对象。不要用全篇 Range 的祖先大框，也不要把整篇外层 section 都视为不可分割。Range 返回片段矩形，并非精确字形轮廓；这是保守保护区域。[Range.getClientRects](https://developer.mozilla.org/en-US/docs/Web/API/Range/getClientRects)
3. 将所有对象换算到 host 顶部的 CSS 坐标，再**统一转换到 2 倍 canvas 的整数像素坐标**。保护区上缘向下取整、下缘向上取整，可加 1 个图片像素的余量；合并相交区间，跨列布局必须合看各列，不能只顾左列。保护端点的余量和实际字形是否一致须由带上/下标、粗体、斜体夹具验证。
4. 每次从当前切点 `s` 目标前进 2000 图片像素。目标若落在保护区中，取该区之前最后一个合法整数切点；安全间隙中取靠近目标的点。页底只需位于安全间隙，页高可以不同。
5. 如果向前的合法点仍等于 `s`，说明当前不可分割保护区超过目标高度：**向后找到第一个安全点，输出一张超高页**，记录原因与实际高度。禁止在原地循环、默默切字或整体缩小文字。若该区域一直延伸到稿尾，就以稿尾结束该页。2000 图片像素是目标，不是硬上限；这项新分页合同须先登记。
6. 所有页面只从原 canvas 用连续的整数区间 `[cut[i], cut[i+1])` 裁出。首点 0，末点 H；严格递增，页高用相邻切点相减。**不分别对每页高度四舍五入**，不加重叠像素，不留遗漏。返回或记录 `cutsPx`、原因、超高页信息，使测试和诊断可观察。

只补 `break-inside: avoid` 不会修好当前实现：该属性约束分页/分栏等布局碎片中的断开，而这里是对一张已经绘制好的 canvas 做固定像素裁剪；现有代码不执行 CSS 分页。[break-inside](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/break-inside)

## 4. 具体边界与不保证的事

| 内容 | 本包确定策略 | 明确不保证 |
| --- | --- | --- |
| 普通段落、超高文本块 | 保护每条文字行，允许行间切；优先相邻自然块间隙可作为次级优化 | 不承诺整段/整张背景卡片永不跨页；圆角/背景边缘可能断开 |
| 单张普通图片/内联 SVG | 图片可放进目标高度时整张保留；跨线则提前切页 | 不通过识别图中内容决定切点 |
| 超过 1000 CSS px 的图片 | 独占或延伸为一张超高页，保持 750px 输出宽度与原字大小，记 `oversize-unbreakable` | 不保证每页 ≤2000px；不静默缩图；超高上传限制待真实后台确定 |
| 超高表格 | 正常行按 `tr` 整行保护；太高的行输出超高页；rowspan 关联区域须合并保护，或明确登记暂不支持该结构 | 不自动重复表头、不拆复杂合并单元格、不声称全类型表格皆已覆盖；实际 compose `:417` 当前输出简单表格 |
| 超长链接 | 按可见文本行保护，允许在换行间分到不同页；HTML 与 href 不变 | PNG 本身没有可点击链接；不为完整 URL 强行造超长页。当前链接输出见 `compose.ts:109` |
| 列表与微信兼容标签 | 文字行矩形覆盖 `section/span` 与普通 `li` 两条路径，不能只选 p/h/li；当前促销列表见 `compose.ts:402`–`:409` | 不由“没有 li”推断没有列表；不要求每个列表整体一页 |

巨大 canvas 是**独立资源边界**：现有 `htmlToImage.ts:40` 只拒绝 >200000 CSS px；750×400000 的 RGBA 原始缓冲即约 1.2GB，还未算副本与 PNG。该数是尺寸算术，不是实测内存。本包不扩容上限、不重构流式渲染、不借分页修复宣传超长稿支持。

## 5. 一致性验收：保留正确部分，解除固定高度耦合

“内容一致”分三层，不能互相替代：

- **输入身份**：导出使用哪一个 revision/HTML/素材快照，导出前后不改文稿；链接文字、数字与图像身份仍一致。
- **覆盖完整**：所有源 canvas 像素行恰好出现一次、顺序正确，文件名与实际新增文件对得上。
- **阅读可用**：内部切线不穿受保护文字行或图片；仍由 PNG 接缝实图检查兜底，不把几何报告当最终观感。

本最小方案继续使用同一 canvas，所以 `scripts/export-paging-check.mjs:453` 的“拼回逐像素 diff=0”**完全可以保留**，且是有力的遗漏/重复检查。它不是错误耦合；错误在于把它单独当成“不切字/可读”的证明。

必须一起替换的旧断言：

1. `export-paging-check.mjs:444` 的所有非末页等高与 `:449` 的 `长图高−(页数−1)×首页高`。改为实际页高之和 H、每页正高、切点连续、按实际高度拼回。
2. `live-acceptance.mjs:2308` 的 `ceil(长图高/2000)` 与固定末页公式。改为实测 pages 与 cuts 对应、总覆盖完整、超高页有原因；不能让正确自适应分页变成新假红。
3. `cutsOf(host,pageCss)`/markers 的固定倍数算法。以**实际 cutsPx**逐一核对每条线与行/图保护区，仍保留“探针在位、矩形非空”的正向条件。

将来若另立需求采用重排、页边距、重复表头，就不能继续要求拼接图与未分页原长图像素相等；届时应登记新的输入内容与布局合同，去掉或对齐新增结构后比较。**本包不做这些变化，因此无需提前放松像素一致。**

## 9. 四分钟反方审查：文字行安全缝仍可能切装饰

第一版算法需要补一类**当前生产就有**的保护对象：没有 text node、没有 img，但有可见背景/边框的装饰叶子。

| 真实生成代码 | 漏检机制 | 本包处理 |
| --- | --- | --- |
| `compose.ts:137`–`:142` 花边分隔线；`:297`–`:305` 促销分隔符 | 空 span/section 绘圆点、横线、菱形。文本 Range 完全没有节点可量 | 保护这类有尺寸且有可见填充/边框的非文本叶子 |
| `compose.ts:131` 时间线圆点；`:399` frame 角线 | absolute 装饰不参加正文排版，正文行间空白仍可能有装饰 | 用元素相对 host 的真实矩形，不以父流式高度或 textContent 是否为空过滤 |
| `compose.ts:141`、`:300`、`:385` 的 rotate(45deg) | 原 width/height 不是变换后的可见范围 | 读取变换后 `getBoundingClientRect()`，不从 style.width 推几何；8px 正方形旋转后包围框理论高度约11.31px |

本包修补仍很小：在文字行、img/SVG、表格行之外，加上**实际可绘制的非文本叶子**。按计算后样式与正尺寸筛选，记录其矩形供测试；不能把所有带背景的祖先 section 都保护为一整块，否则大卡片或全篇背景会导致无意义的超高页。visibility/display/透明度、裁剪祖先要保守处理；暂时多保护一小段可以接受，漏掉真实可见装饰不可以。阴影不是 border box 的一部分，下面另列边界。

**明确后置**：定向检查未在当前 compose 输出中定位 box-shadow/text-shadow/filter；`compose.ts:378` 还注明 band 为零渐变零阴影。素材 SVG 当前经 `compose.ts:815`–`:821` 变成 img，先作为整图保护，无需解析内部所有滤镜。本包不建设通用 CSS 绘制边界分析器。若将来允许未被容器裁住的 drop-shadow、text-shadow、伪元素、任意 transform/overflow，border box 或 Range 不保证覆盖所有可见像素：应新增对应固定样本和保守外扩/整对象策略，或明确此类输出未获证，不能宣传“所有样式绝不切”。不以一个固定 1px 余量假装解决任意阴影。

## 10. 对事实来源方案的交叉审查

只读 `grounding-deep-dive.md` 当前最小实现包与 G1–G3 卡：方案已识别 prep 直接 candidate 路径，也已把来源日志压缩为路径/实际回传指纹/现有 runId，因此不需要扩大成事实数据库或新审稿模型。

需要在执行任务卡中钉住一个接线验收：**从真实 App 发起流程，截获实际 `prep_turn` outgoing 消息，并返回合法 candidate，观察其经过共同候选流程与原有提交门槛。** 直接调用 `runPrep(手工拼好的baseMsgs)` 只能测 prep，不能证明 App 的 persona/本稿材料真的传到它。compose/revise 同理按实际派发观察；旧反例首发不能只测 WRITE_INSTRUCTION 常量。

另一个不可混淆边界：stub 写出的有依据候选被 accepted，证明消息/处理/提交接线，不证明真实模型学会遵守新提示；将无依据文本作为固定返回也不能要求现有质量门槛凭空识别全部事实真实性。首包是提示契约与来源可观测性，语义遵循仍须后续获授权的小样或人工材料对照。当前卡已写明这一点，建议保留而不是为了离线全绿加关键词拦截器。
