# 下一包：F1 全入口遵守材料依据边界

2026-10-03。此卡只派 F1；依据[入口深挖与拟议文字](grounding-deep-dive.md#第二短批三个入口的优先级与拟议最小文本)。一名实施者、一名独立复核者，完成下列合同即结束，不并入分页、安装或新一轮基础设施审计。

## 1. 用户结果

用户给稀疏材料并要求“直接写、用默认、写长一些”时，能够获得不擅自补定机构规则的稿件。给定事实准确保留；未给出的费用、名额、预约衔接、恢复日期和服务时段不被写成确定承诺。连接语、风格选择与明确的一般建议照常允许。非必要缺项可省略，必要未知才由模型向作者确认，不能改成缺任何字段都不成稿。

## 2. 基线与允许改动

先记录当前 commit、已有 dirty 文件及所用原件身份，保护别人改动。阶段0已完成：独立 IPC **67/67**、ledger **39/39**，见[本轮复核](verification/README.md)，不再预留半天重跑或扩大同一专项。

实施者只改共同 persona、prep/WRITE/REVISE 的短依据约束、App 实际消息组装中与这些约束冲突的局部措辞，以及已定位的公告知识示例。重点入口是 `persona.ts`、`prep.ts`、`revise.ts`、`App.tsx` 的 digest/正式稿说明、`type-announcement.md`，加定向回归。共同规则只维护一份，各入口短句引用同一边界；语法和视觉知识不能覆盖用户事实。正式稿“权威”仅指当前版本与素材引用，保留源文回读及素材快照，不能把旧模型陈述当用户确认。

不建来源数据库、额外审稿智能体、前端意图状态机、关键词封禁或全库清洗；不顺手重构 App。文档按现行仓库要求简短同步。本卡不修改既有发布重建规则。

## 3. 固定样本与先做的检查

最多三组，准确输入、允许变化及素材策略开工前写在同一证据目录。复用既有图片，不为文本检查新增绘图。

- **G1 原 L7/L8**：原四事实、长篇及直接写要求，配既有坏稿。纯读原件，识别“次日恢复、续借不受影响”等未给定承诺；验证 prep 直接 candidate 也受共同规则约束。
- **G2 未知与继承**：分清两种操作：首稿的费用、人数明确未定，不能补成免费或固定限额；旧 accepted 稿已含未给依据规则，用户只改标题时，本包必须保留正文和素材，不静默删除、不强迫多轮追问，也不把保留等同事实认证。遗留规则仅在独立人工核对报告列明，未来提示界面或编辑合同另包处理。
- **G3 正向授权**：材料明确含免费、预约顺延和 9–17 值守，要求两句一般建议。准确保留已给规则，允许自然表达，不一律删承诺或反复追问已知信息。

先纯读重判已保存的前后成品，禁止为了修字数、标题等 runner 判据重新创作基线。然后用零模型替身截获**真实 App 实际发出**的消息：prep 普通轮与末轮、compose WRITE、candidate/compose 后的自动 REVISE。检查共同规则、digest 优先级和局部保留约束实际都在实参中；不能以常量匹配或源码字符串断言代替。已有 trace 不含完整请求时，受控响应须标为夹具，不冒称原响应回放。

## 4. 三条验收与分工

① 三组样本的给定、未定、已生成但未确认信息边界正确，正向授权不误伤。② 实际 App 消息截获证明各入口携带同一依据规则，既有素材保持、版本回读和局部修订约束不退化。③ 独立复核者从原始输入、最终保存稿及差异逐条审稿，核对新增办事规则的依据，不只看测试数、accepted 或模型自报。

实施者先给旧行为反例和正常对照，再交修复、截获实参及成品判定。保留 candidate/text 互斥合同，不能承诺同一回复既提交 candidate 又附普通 text 提醒。复核者不改实现或偷偷换期望值。离线替身只能证明接线与受控行为；真实语义遵守未跑就明确未验。产品改动通过后，由集成人一次完成适用的 release 重建和冒烟，不因每改一句提示就先买一轮真实样本。
