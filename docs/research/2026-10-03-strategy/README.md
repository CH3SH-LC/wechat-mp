# 推文助手未来方向、慢因复盘与 DS 执行计划

研究日期：2026-10-03。首轮北京时间00:45开始，原定01:00截止，最终文件核对实际延至01:01:54；随后用户明确授权继续深研，以订阅额度/重置为停止条件。四路并行：产品方向、错误与返工、工程/证据、DS调度与综合。研究基线为 `839183b`（主体 `63f83ad`）；没有修改产品、启动真实模型或执行安装。续研新增两项现有离线检查的独立复跑，具体范围见下文。

## 续研新增的实施结论

直接派单只读[下一包F1任务卡](next-ds-task.md)，其余专题是按需查证资料。旧两项阻断的独立复核已经完成，不再给DS安排一次重复的“半天准备”。

1. **F1必须覆盖prep直接候选入口。** L7/L8原始trace显示，正文由`finish_preparation(candidate)`直接进入门禁并正式保存，没有单独WRITE/REVISE请求。只改写作提示词会漏掉真实反例。知识范例含高度相似规则，但旧日志没记录加载路径，仍不能确证来源因果。[依据链与三样本卡](grounding-deep-dive.md)
2. **F2先改切点，不先重排。** 保留原始长canvas，按DOM安全边界输出可变高度分页，可继续保留拼回逐像素一致验证。需要修改的是旧等高/页数公式断言；普通图片、表格、装饰物和超高块须明确策略。[分页算法与边界](pagination-deep-dive.md)
3. **减少重复生成和冷启动。** R8一次换图任务223.102秒，首创作请求前116.918秒，原件支持CDP超时与重开；绘图请求71.764秒且只有一张图，加worker无法平分它。R9的runner假红发生时产品已经提交，应该重判原件，不重新生成上游基线。[关键路径与DS调度](ds-throughput-deep-dive.md)
4. **本地成品到公众号之间仍需实际验证。** 当前“复制HTML”是源码文本；PNG能保留画面，但不保留原始可编辑文本/链接结构。先用现成成稿测交付，再决定是否值得增加富文本能力。手册有未经实测的时间、普遍适用和网络边界表述，应在下一交付包准确修订。[交付实验](delivery-experiment.md)
5. **旧两项阻断已有本轮独立复核。** IPC 67/67、ledger finalize 39/39均退出0，包含旧形状反例与新子进程；不是实机或真实模型复测。按本合同结束旧专项，不将分页/手册改动又变成全量门禁审计。[结果与边界](verification/README.md)

两条后续边界也已查清：照片占位虽可保存/导出，但会固化在PNG内部，不能当已补图或后台可编辑槽；一次65.334秒绘图记录15228个completion tokens，而实际SVG为5347字符，现有日志缺细分，不能把等待全部归为SVG源码长或凭空定量为推理。分别见交付实验与关键路径深拆的补充，不扩成F1的新前置。

同时勘误：最终R8的L1/L4是2次prep加1次绘图，不是第3次prep才声明；无法据此证明最后一轮提醒的决定作用。“12px切字”中的12是span框跨切线的CSS余高，非准确字形损失量；原图目视仍能确认同一行被拆成上下两页。

## 判断与推荐方向

**项目已具备可用的单篇创作链路，下一阶段应集中做“有依据、能续改、可交付”的公众号成稿工作台。** 产品价值建议定位为：把用户已有材料整理成一篇可发稿，修改时保住已认可的事实、文字、图片与风格，并减少最后人工修稿的时间。

这比继续扩展“AI能写、能画、能排版”的功能数量更有区分度。当前竞争与用户需求判断仍需真实使用验证；本轮没有用户访谈、支付意愿或市场规模证据，不能称定位已被市场验证。详细研究见[产品方向](product-direction.md)。

当前不建议迁回DSH、重写成通用agent平台、扩到账号运营/自动群发/多账号/SaaS。保留独立Windows、单机单用户、自然对话、模型自主意图判断与本地作品资产这条主线。

## 最新做到什么程度

旧“IPC和收尾仍待修”的结论已经有新修复与反证，不能把前轮任务重新派一遍：

- 默认发布exe `b3cbb966…` 已有真实L1–L6，长文L7为930字，L8续改424字且零绘图、素材身份不变；R8的L5第一次BLOCKED仍保留，后续正常重开通过。
- 纯文字固定夹具可导出5页，分页拼回与长图逐像素一致；真实WebView2带图长文另有2页输出。这是两组互补证据，不是同一带图夹具达到5页。
- IPC检查67项、最终收尾39项在续研中独立复跑通过；原始结果保存在verification。旧阻碍已显著收敛，后续主线不再是穷举同一验收器故障。
- 安装动作与公众号后台仍NOT RUN；安装包存在与本地预览不能替代这两层。
- **新的产品限制**：给定四项事实都保留，不代表全文有依据。L7/L8增加“10月12日恢复”“线上续借不受影响”等题面未给的办事规则；不能判定现实中必假，但成品没有来源或待确认标记。
- **分页观感仍有缺口**：5页文件完整，但原图可见同一行文字被拆到相邻两页；几何报告的12 CSS px是span余高，不能当字形损失量。像素完整性PASS不等于每页可以直接发。

因此当前水平是**有真实链路的小范围内测版**；本地制作能力已有证据，是否为真实使用者节省时间仍待验证，跨题材稳定性、事实可信度和实际发布体验也需补证。[工程复核](engineering-plan.md)

## 为什么推进这么慢

不是简单的“DS模型弱”或“额度不够”。当前证据更支持以下五条：

1. **验收基础设施变成了第二个项目。** 在 `472fd3d..839183b` 的47小时20分提交时间窗口，133文件新增10,906行；scripts新增6,928行，docs新增3,641行（含探针/日志），产品src与src-tauri仅两个文件新增40行。这描述工作重心，不能当浪费率或连续工时。
2. **契约不清使修复诱发新错误。** 三轮准备预算没讲清，补“每次都结束”后又与“并列取工具”冲突；最终需要再修互斥语义、再构建、再验。应先检查提示、工具schema、执行器三者的同一合同，而不是先怪模型。
3. **裁判错误被付费模型重复执行掩盖。** 长文300–500字被旧≤180字判据误杀；重发时标题已经改过又假红，之后新root再生成上游作品。正确做法是冻结成功基线，用原产物/隔离副本重判。
4. **因果结论过早。** CDP无端口被数次归因到环境或feature，后续默认版能连又推翻。没有新区分信息就继续等端口，增加工作但不增加认识。
5. **我们的指导也有责任。** Codex持续补审计项、加长历史指南、把证据不足与产品失败放在同一阻断清单。保留原件有价值，但不该让“当前该做什么”埋在几十KB的所谓精简进度里。

可复算的真实调用：R6–R8预留+21/3，其中最终R8为9/2；R9–R10实际+12/2，P2文档的+10/2存在登记漂移。R6–R8跨度50分34.5秒，已登记脚本区间合计12分14.7秒，余下38分19.8秒未归因，不能写成空等、编码时间或浪费。没有完整计费/工时证据，本报告不报虚构的费用节省百分比。[完整复盘](retrospective.md)

这里要分别回答“研发为什么推进慢”和“用户为什么等得久”。前者已有裁判假红、重复生产、启动诊断与审计扩围的证据；后者在R10样本中，新长文加一图的runner总段为114.209秒，纯文字续改为18.868秒，其中新图调用65.334秒。这些是含驱动/收尾的个别记录，不是用户界面响应SLA或总体分位数。减少研发返工不自动缩短单图调用；增加单稿worker也不能平分一个有依赖的绘图请求。两者分别改，才不会把未来任务又变成盲调模型或盲加并发。

## 三个近期任务包

当前状态与旧P0定向签收已在续研完成，直接进入F1，不再围绕已关闭不变量反复扩展。以下包可并行研究；写同一生产模块时串行集成。

| 包 | 用户结果 | 最小改动与证据 | 完成/停止条件 |
| --- | --- | --- | --- |
| F1 事实有依据 | 用户不必逐句排查AI擅加的办理规则 | 从L7/L8未给依据的规则做固定反例；审查现有prep/知识/写作提示的矛盾；保留材料来源，未知运营细节询问或标待确认；先用现有展示/校验接口，不建通用事实平台 | 固定集给定事实不丢、不矛盾；新增运营承诺均有来源或显式待确认；独立人工审稿。两次同因失败转诊断，不无限加prompt |
| F2 分页可直接读 | 每页不把文字行/插画切成两半 | 保留同一长canvas，仅以DOM安全间隙调整切点，输出可变页高；超高无安全缝块明确处理；短稿、三页以上纯文、带图边界各一夹具 | 无丢失/重复；普通文字行和图片不被截断；保留同canvas拼回像素一致检查，修正旧等高/页数公式；若另选重排方案须单独改验收合同 |
| F3 安装到草稿交付 | 拿到正确安装包的人能完成一篇实际稿件 | 更正手册包名；一名集成人构建/验资源/启动；隔离账户或VM做安装与本地作品导出；后台可用时验证草稿/预览 | 有账号/环境即完成实际检查；没有就提交准确包、成品与人工清单，NOT RUN与所缺条件具体，不拖住F1/F2 |

F1优先级最高；F2解决已经观察到的真实可读性问题；F3负责跨过“机器上跑通”到“用户拿得到”的边界。缺公众号登录态时，不为此研发自动发布，也不凭本地画面宣称后台通过。常规安装本身不应被笼统称为不可逆；风险点是可能覆盖现有程序/配置，选择隔离环境或明确安装目标即可。

## 分阶段计划：以结果开下一阶段，不靠日期自动升级

下表是建议的工作顺序和时间盒，不是工期承诺；依首批实测修正。

| 阶段 | 建议投入窗口 | 产出与进入下一阶段的条件 |
| --- | --- | --- |
| 0 冻结基线 | 本轮已完成 | 当前状态、已知限制与67/39独立复核已齐；后续只核当前版本/工作树是否变化，不重跑整个前置阶段 |
| 1 可放心用一篇 | 接下来2–3个聚焦批次 | 完成F1/F2，交一篇实际材料的成品、修改版、导出；F3外部条件并行准备 |
| 2 多种材料仍成立 | 后续一周试用窗口 | 先复用L7/L8加一个不同材料的保留样本，共3题；12题仅为后续候选，不立即全量付费执行。记录首试交付、必要请求与成品，实际使用时记人工修正分钟 |
| 3 小范围真实使用 | 随后的2–3周 | 建议3–5名内容创作者各完成2篇自己需要的稿件；人工招募/反馈需实际取得，不能冒称本次已做。评估是否比其旧流程省时、是否主动继续用 |
| 4 有证据后扩展 | 4–6周评估点 | 只有真实需求反复出现才做风格包/素材复用增强/有限导入；后台复制、图文呈现路径由实测决定，不预先堆全套编辑器 |

试行门槛可以设为：冻结验证集无未提示的高影响事实篡改/新增承诺、保存续改无错版本、绝大多数稿件不需手工重排；具体数量和“高影响”的定义开工前固定。这些是目标，不是当前已经达成的指标。12题不足以证明统计上稳定，更不是产品SLA。

## 该保留、削减、后置什么

- **保留**：真实成品与磁盘读回、素材固化快照、失败不覆盖旧成品、累计预算和隔离、明确人工发布边界；这些就是产品可信度基础。
- **削减**：重复全量付费复测、每轮复制全部历史、没有新区分力的环境矩阵、产品未变时重新生成上游验收稿。
- **后置**：通用agent框架迁移、插件市场、云协作、多账号运营、自动群发、大量主题模板、全能视觉事实验证。
- **谨慎演进架构**：先按正在修改的热点提取可测试服务，不发起App.tsx“大重构周”；现有v2排版结构可继续演进，不先推倒另造文稿平台。
- **规则调整单列**：四文档维护、release重建等现有要求不擅自取消；可在现有要求内改成每轮简短状态+链接。手册变更需要打包/资源验证，但不应自动作废所有未受影响的真实模型业务证据。

## 给DS的执行方式

默认一名实施者加一名独立成品复核；只有第二个独立任务足够大且已经明确，才扩为调度集成、两个无写冲突实施包和独立验证，生产WIP上限2。研究可以高并发，真实桌面/全局账本/release目录保持单一写者。

两个具体减法：runner判据修正先纯读重判原件，不重生成成功上游；有序业务phase可窄范围验证复用已核验的隔离实例，L5继续单独验退出/重开，各phase预算预留、门禁身份和证据核对均保留。当前未实施实例复用，不把建议写成已经获得的提速。

每张任务卡只给：一个用户结果、当前基线、允许文件、三个以内核心判据、固定样本、所需检查、唯一证据目录、时间/调用预算和停止条件。30–45分钟应有可见中间产物，45–90分钟实现时间盒到点做一次明确继续/转诊断决定；这些是调度建议，首周按实际数据调整。

DS输出应是“成品+改动+已执行验证+限制”，Codex输出应是“接受/哪条具体合同未满足”，而不是两方继续生产越来越长的新清单。细则和可复制派单内容在[DS驱动方案](ds-operating-model.md)。

本机DSH源码提示一个实操陷阱：其send_message是下一轮FIFO，不一定能改变当前工作；interrupt只停止目标当前轮，后代可能继续。实际部署前核对工具版本与能力，截止时停止新委派、检查整棵任务树并确认停止，不用一句“自动停”代替运行状态。
