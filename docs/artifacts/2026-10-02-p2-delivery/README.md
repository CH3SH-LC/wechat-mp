## 一、P2.1 多页导出（零模型，**已完成**）

新增 `scripts/export-paging-check.mjs` + 冻结夹具 `scripts/fixtures/2026-10-02-longarticle/source.md`（1778 字符，7 节）。
在真实浏览器里走**真实链路** `composeMarkdown(夹具) → exportArticleImages → renderArticleImages → export_images`，
只有最后那步 Rust 落盘用替身（本机浏览器里执行不了），并把**真正传给它的文件清单**抓下来自己做文件级核对。

结果（`EXPORT-PAGING PASS 16/16`，run-result 与 6 张 PNG 在 `%TEMP%/wxmp-paging-evidence/`）：

| 核对项 | 实测 |
| --- | --- |
| 页数 | **5 页**（正文 4214 CSS px；长图 750×8428；分页高度 2000/2000/2000/2000/428） |
| 宽度 | 长图与每一页都是 **750px**（Node 侧独立核对 PNG 签名 + IHDR + IEND） |
| 顺序 / 无缺页 / 无重复 | 所有分页高度相加 = 长图高度；**分页逐张拼回后与长图逐像素一致（diff=0）** |
| 末页 | 428px（= 8428 − 4×2000，>0） |
| 空白页 | 无（每页"有墨"比例 74.5%–80.7%） |
| 文件命名 | `…-长图.png` + `…-01..05.png`，逐项对应 `export_images` 实参 |

**页边界切口（目视用的事实，不是判定项）**：3 处内容块跨过分页线，位置与文字都记下来了——

- 1000px：`<section>` 被切 29px「需要说明的是，每日闭馆前 30 分钟为当日最后一次借还与预约取件的受理截止时间。」
- 2000px：`<span>` 被切 12px「借书：自助借还机办理，或在一层服务台人工办理」——**这一处是把一行文字切开了**
- 4000px：`<section>` 被切 64px「饮食请到一层东侧休息区，阅览区内不要携带含糖饮料与带汤食物。雨天入口处备有伞袋与…」

小节标记落页：第 1 节→第 1 页、第 2/3 节→第 2 页、第 4 节→第 3 页、第 5/6 节→第 4 页（共 5 页）。
**"固定 1000 CSS px 切一刀"本来就会切开文字行**，这是既有设计行为；上面这份清单是给人工判断"观感是否可接受"用的，
本轮不把它当作通过/不通过。

**未覆盖（如实记录）**：正文含 `<img>` 的多页导出。本 runner 用的 playwright Chromium **无法**把含图片的正文转图
（`EncodingError`：SVG 当图片时内部不能再嵌图片；headless 与 headed 都一样）。真实 WebView2 可以——
已用真实导出成品反查：L6 那张 750×1300 长图里强饱和像素占 **12.21%**（纯文字页远达不到），说明插画确实被渲染进去了。
"带图多页"需要真实 WebView2 驱动才能覆盖，**本轮记为未覆盖**，不写成已通过。

沿途还纠掉了本 runner 自己的两个假绿，记在这里以免后人重踩：
① 断言"0 处切口"时，几何测量其实**量不到元素**（探针写在 `host.remove()` 之后，矩形全为 0）——现在有一条
"几何测量可用"的断言钉住（elCount=67、hostH 与转图高度一致）；② 切口选择器原来照搬标准 HTML（`p,li,h1..h4`），
而 compose 输出的是**微信兼容标记**（标题/卡片/列表项都是 `<section>` 套 `<span>`），照搬会漏掉几乎全部内容。
