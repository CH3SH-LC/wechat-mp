## 应纠正的证据表述

### 尝试分母归属错误

closeout `attempt-inventory.json` 的38条确可重新枚举出来，统计为PASS8/FAIL14/BLOCKED14/ERROR1/无结果1。但它只枚举16个 `wxmp-live-*` roots，**不包含** `wxmp-pubver-1790940744`。

这8个PASS实际为run1六个加 `wxmp-live-real6` 的旧L1、L3；不是README所称“六业务场景+发布L5/L6”。发布root另有3次：19:32:29 L5因Playwright未配置BLOCKED（0检查、无launch），19:32:35 L5 PASS，19:32:48 L6 PASS。将发布root也纳入，应为**41目录：PASS10/FAIL14/BLOCKED15/ERROR1/无结果1**，不能混用38分母和发布场景说明。

原文用“21条request全部ok=true”谈模型契约合规也需收窄：request.ok是请求层成功，不代表candidate/text契约合法；已知L2协议失败也有ok=true的prep request。21还包含4次绘图。模型合规率需要定义“适用该契约的模型响应/终结候选或业务回合”，分别统计首次合法、纠偏后合法、协议失败、基础设施失败；不能把所有请求混作统一合规率分母。此次不从混合历史重建一个比例。
