# 「有 N 个可见元素完全落在画布外」根因排查（2026-10-08）

只查不修。未改任何 `src/`、`src-tauri/`、`scripts/` 文件；未启动桌面应用、未调用真实模型、未跑任何 build。
所有结论都由**产品自己的** `checkSvgQuality` 在两个真实原件（BIG / G2A）上离线复算得出，可重跑（见 §8）。

---

## 0. 结论摘要

**能确定的（有代码与实跑证据）**

1. 这条判定**不在第二个坐标系里做**。它用的画布就是 **SVG 自己声明的 `viewBox`**（只取宽高）。
   所谓"提示词说画布 400×300、质检按另一个尺寸判"——**不存在**。提示词与质检用的是同一个坐标系（§1、§2）。
   所以"口径不一致"不是提示词 vs 质检之间的分歧，只可能是**模型自己声明 viewBox 与它自己落笔坐标之间的分歧**。
2. 判定的精确含义是**包围盒与 `[0,vw]×[0,vh]` 无交集**（`svg-quality.ts:315`），且 `offCanvas > 0` 是**全有全无的硬否决**（`svg-quality.ts:389`）——**1 个装饰元素越界 = 整张图作废**。
3. 判定口径有**三类已实证的误判**，全部用真实 `checkSvgQuality` 差分跑过（§1.3 D1/D2/D3）：
   贴边零厚度元素、祖先 `transform` 搬进画布的元素、非零 `viewBox` 原点。
4. 被拦原件**全部没有落盘**：trace 只记 `responseLength`，质检失败分支不写任何文件，素材库只存已验收项。因此
   **"被拦的是不是真坏图"本次无法定论**（§3 明确记 UNKNOWN，并给出可判别的替代读数）。
5. 三个**确定存在的放大器**（都在代码层，与模型行为无关）：
   ① 无"部分降级"通道；② **重画是盲重画**——同一 prompt 原样再发（只有 trace 里的 attempt 号不同，见 §2.3），
   模型拿不到"哪里越界"的反馈，于是实测出现 **11 → 44**（越修越坏）和 30 → 15；③ 每素材位只有 2 画，一次画坏吃掉一半预算。

**未定的（不要编）**

- 被拦那 7 张（BIG 5 张 + G2A 2 张）**到底是模型画错、还是判定误杀**。缺的东西只有一样：**SVG 原文**（§6）。
- 因此"修哪一层"（修判定口径 vs 修重画反馈 vs 加部分降级）**现在还不能拍板**；但三者的收益与风险已可按代价排序（§5）。

## 1. 这条判定在哪个坐标系里做（问题 1）

### 1.1 实现位置

| 入口（Tier 1 门禁） | `src/lib/image-agent.ts:1414-1424` → `checkSvgQuality(svg, kind)` |

### 1.2 判定口径（逐条读清）

```ts
// svg-quality.ts:282-287 —— 画布尺寸从这里来；min-x / min-y **被读出来又丢掉**
const vb = /viewBox\s*=\s*"([^"]*)"/i.exec(body)
if (p.length === 4 && p[2] > 0 && p[3] > 0) viewBox = { w: p[2], h: p[3] }

// svg-quality.ts:313-318
const box = a['transform'] ? null : boxOf(tag, a)
if (!box || !viewBox) continue
const inside = box.x + box.w > 0 && box.y + box.h > 0 && box.x < viewBox.w && box.y < viewBox.h
if (!inside) { offCanvas++; continue }
```

- **画布尺寸从哪来**：SVG 自己的 `viewBox` 的**第 3、4 个数**。`min-x`/`min-y` 解析出来后**被丢弃**。
- **元素坐标怎么解析**：对 `circle|rect|ellipse|line|path|polygon|polyline|image` 逐个用正则取属性，按 `boxOf` 算**包围盒**。
  嵌套 `<g>` **无树结构**（纯正则扫描，不建层级）；`path` 自研命令遍历，**遇到 `A`（弧线）直接放弃**（返回 null）。
- **`transform`**：**只看元素自己身上的 `transform` 属性**——有就整个跳过（既不计包围盒、也绝不算越界，`svg-quality.ts:311-313` 的注释写明"宁可放过，不能误杀"）。**祖先 `<g>` 上的 `transform` 完全不看**。
- **`viewBox` / `<use>` / `clipPath`**：`clipPath`/`mask`/`defs`/渐变在剥离清单里；`<use>`、`<symbol>` **不在剥离清单，也不匹配元素正则**（所以 `use` 自身不计，但 `symbol`/模板 `<g>` 里的子元素**会被当普通元素按原始坐标计**）。
- **"完全落在画布外"的精确定义**：`!(x+w>0 && y+h>0 && x<vw && y<vh)`，即**包围盒与 `[0,vw]×[0,vh]` 无交集**。注意三点推论：
  - 只要**有 1 单位重叠**就不算越界（压着边出去的元素永远是安全的）；
  - **不算笔画宽度**（`stroke-width` 不扩包围盒）；
  - **零厚度**（`w==0` 或 `h==0`）的元素**贴在边界时**必然"无交集"→ 被算越界（见 D1）。
- **`slotPx` 与本判定无关**：`SLOT_PX[kind]`（`svg-quality.ts:19-26`）只喂 `motifPx` / `slotPx` 两个**只报告不判定**的字段（`svg-quality.ts:323,339,364-365`），以及 Tier 2 栅格的 `targetWidth`（`image-agent.ts:1418`）。**`offCanvas` 只用 `viewBox`。**

### 1.3 判定口径的三类误判（已用真实 `checkSvgQuality` 实证）

差分实验脚本 `demos.mjs` / `demos2.mjs`，全部调用产品自己的 `analyzeSvg`：

| 编号 | 情形 | 输入 | 真实读数 | 判定对不对 |
| --- | --- | --- | --- | --- |
| **D1a** | 顶边横线（`<line y1=0 y2=0 stroke-width=4>`） | 750×220 | `off=1` | **误判**。线在 y=0，笔画 4 单位跨 −2..+2，**下半 2 单位是可见的** |
| **D1b** | 底边横线 `y=220` | 750×220 | `off=1` | **误判**（同上，上半可见） |
| **D1c** | 左边竖线 `x=0` | 750×220 | `off=1` | **误判** |
| **D1d** | **同一条线移到 y=1** | 750×220 | `off=0` | 只挪 1 单位就从"越界"变"合格"，说明是**边界条件**不是内容问题 |
| **D1e** | `path d="M0 0 H750"`（顶边） | 750×220 | `off=1` | **误判**，与 D1a 同因 |
| **D1f** | `rect width="0"` 在原点 | 750×220 | `off=1` | 零尺寸元素 |
| **D1g** | `<image href="photo.png"/>`（无 x/y/w/h） | 750×220 | `off=1` | 缺省属性全 0 → 零尺寸 → 误判 |
| **D2b** | 元素原始坐标 (900,300) 在画布外，**但被祖先 `<g transform="translate(-880,-280)">` 搬进画布** | 750×220 | `off=1` | **误判**：渲染后它在 (20,20)，完全可见 |
| **D2c** | 同上，10 个叶子 | 750×220 | `off=10` | **误判**，且**成簇**——这正是小批次计数（3/11/21/44）的可疑形状 |
| **D3a** | `viewBox="-400 -200 750 220"`，内容在 `x=-300..-200`（**在画布内**） | — | `off=1` | **误判**：`min-x/min-y` 被丢弃，画布永远被当成 `[0,w]×[0,h]` |
| **D3b** | 同一批绝对坐标 + `viewBox="0 0 750 220"` | — | `off=1` | 与 D3a **读数完全相同** → 证明原点信息确实被忽略 |

D4（语义，非缺陷但与定性有关）：**"完全落在画布外"的元素在渲染时被 `viewBox` 裁掉，产生零像素**。`demos.mjs` D4a 用 44 个完全在画布外的竖条 + 一张完好的画面复现出**恰好 `off=44`**——即**这条计数不可能意味着"图看起来缺一块"**；它只能意味着"模型画了一部分内容用户永远看不到"。（真正"缺一块"的风险来自**部分越界**，而部分越界这条规则从来就不拦。）

## 2. 模型被要求按什么尺寸构图（问题 2）

### 2.1 全局契约原文（`src-tauri/src/chat.rs:762-773`，`SVG_SYSTEM_PROMPT`）

```
5. 元素坐标落在 viewBox 范围内，必须带 viewBox。
4. 画面要有**细节密度**：横幅 / 大插画通常需要 20 个以上可见元素（…），
   小插画（inline/deco）不少于 10 个才算充实；元素 ≤6 只是系统能通过的最低门槛，不要按最低门槛画。

9. 整段回答只包含从 <svg 到 </svg> 的 SVG 原文：不解释、不用代码围栏…
```

### 2.2 按角色的画布建议（`chat.rs:776-789` `svg_user_prompt`，另见 `chat.rs:801-832` `svg_kind_prompt`）

| kind | 提示里建议的 viewBox | 实际提示来源 |
| --- | --- | --- |
| `wide` | `0 0 750 220` | `chat.rs:778` |
| `inline` | `0 0 360 240` 或 `0 0 300 300` | `chat.rs:779` |
| `deco` | `0 0 300 200`（且"主体集中在右下 1/3"） | `chat.rs:780,805` |
| `divider` | `0 0 750 120`（且"必须横向贯穿 85%+") | `chat.rs:781,815` |

| `photo-frame` | `0 0 600 600`（中央 60% 必须透明） | `chat.rs:783,826` |

### 2.3 结论：提示与质检**是同一个坐标系**

- 提示说"元素坐标落在 **viewBox** 范围内"，质检唯一用的也是**该 SVG 自己的 viewBox**。**没有任何第二套尺寸参与 `offCanvas`。**
- 因此最可疑的那条假设（"提示说 400×300、质检按另一个尺寸判"）**被否证**。
- 不过有一处**真实但不同性质**的口径不一致，值得单独记：**提示建议的 viewBox 宽高比 ≠ 素材槽的实际显示尺寸**
  （`SLOT_PX`：`wide` 343×220 = 1.56 vs 建议 750×220 = 3.41；`inline` 210×160 = 1.31 vs 360×240 = 1.5；
  `deco` 60×60 = 1.0 vs 300×200 = 1.5）。它**不会**触发本条报错（`slotPx` 不参与 `offCanvas`），
  但会让"模型按 3.41 构图 → 在 1.56 的槽里显示"产生构图被压扁/加白边的问题。**这条登记为待确认项，不是本次根因。**
- **重画是盲重画（确定）**：`drawSlot` 重试时把**同一个 `brief`** 再交给 `genOnce`（`image-agent.ts:1546`），
  `brief` 只在 CLARIFY 路径被改写（`:1548-1567`）。`gen_svg`（`chat.rs:870-935`）只把 `attempt` 写进 trace，
  **完全不进提示词**。所以第二次画图与第一次**提示词逐字相同**，模型无从知道上次因何被拒。

- **30 / 44（≈28%）** 这一类：接近"半个画面"。要么是**模型真的把 1/4 画面画到 viewBox 外**（真坏图），要么是 **D2 类误杀一个整簇**（祖先 `transform` 搬进来的元素）。**两者都能产生 28% 的成簇计数，现有证据无法区分。**

### 3.3 一个必须说清的方法论限制（选择偏差）

已验收语料在 `offCanvas == 0` 上**被截断**——D1/D2/D3 类一旦发生就直接被拒、不会入库。
所以**这个语料库在原理上不可能包含任何"误杀"的正例**；用它（或任何只由已验收项构成的集合）反复验算
**永远无法**区分"误杀"与"真坏图"。**唯一的出路是采集被拒原件。**

### 3.4 关于 D2 的强度校准（避免夸大）

我对所有 18 份真实样本做了结构扫描（`analyze.mjs`）：

- **真实模型确实大量使用 `<g>` 与 `transform`**，且**祖先带 `transform` 的元素最多占到 46%**
  （`wide-muys93cq`：34/73；`wide-muys7rn8`：28/232；`wide-muys7nf9`：7/65）。所以 D2 **一旦命中，规模就足以解释 21/44**。
- **但是**：在我能读到的每一份样本里，模型用的是**安全句式**——`<g transform="rotate(a cx cy)">`（绕画布内点旋转）
  或 `<g transform="translate(x,y)">` 且子元素画在原点附近，或 `<use transform="translate(...)">` + `<g id>` 模板。
  这些句式下子元素的**原始坐标本来就在画布内**，D2 不会触发。
- 结论：**D2 是一条已被我实证存在的判定缺陷，但我没有它在本次两批实例中真的发生过的证据。** 不夸大。

## 4. 是不是存在"该拦但不该整张丢弃"的中间态（问题 4）

**存在，而且现在完全没有利用**：

- `offCanvas > 0` 直接 `ok=false`（`svg-quality.ts:389`），**没有分级**——1 个和 44 个后果相同。
- 由 §1.3 D4：**完全落在画布外的元素渲染时零像素**。所以"越界 3 个装饰"与"主体被切掉"在**可见结果上完全不同**，
  但在**判定上完全相同**。
- 代价结构（`asset-ledger.ts:25-27`：`MAX_DRAW_ATTEMPTS = 2`、`MAX_CLARIFY = 1`）：
  **一次画坏 = 吃掉半个预算**；而第二次机会是**盲重画**（§2.3），既没有"哪里越界"的反馈，也**可能更坏**
  （实测 `11 → 44`）。BIG 里 5/14 被拦、G2A 里连续 2 次被拦，正是这个结构在真实链路上的表现。
- 另有一条**未被使用**的信息：判定其实已经算出了"可见子集"的 `coverage` / `centroid` / `inkXRatio`
  （`svg-quality.ts:329-351`）。**这些只对"在画布内"的元素统计**（越界元素被 `continue` 掉，`:316-319`）。
  也就是说，"保留下来那部分构图是否自足"**可以零成本算出来，但当前没有任何地方用它做决策**。

## 5. 候选修复方向（**均未实现**，按 代价 × 风险 排序）

### C. 把"盲重画"改成"有信息重画" —— 代价最低、风险最低，建议先做

做法：第二次 `gen_svg` 时把上一次的失败原因拼进 user 提示词（例如"上一版有 N 个元素坐标落在 viewBox
之外，请把所有元素坐标控制在 viewBox 范围内"）。落点 `image-agent.ts:1530-1571`（把 `last.detail` 传进 `genOnce`）
与 `chat.rs:870-935`（新增一个可选参数进 `svg_user_prompt`）。

- 副作用：① 提示词一变，`gen_svg` 相关的既有契约与验收口径需要重新确认（`chat.rs` 里有多条断言
  `chat.rs:1703-1710,1909`）；② 多花几十 token；③ 本地生成的措辞进提示词（内容是自家文案，注入面可控）。
- 为什么排第一：它**不改判定**、不改变"什么算合格"，只提高第二次命中率。即使 §3 的 UNKNOWN 未解，
  它也是稳赚的。

### A. 把硬否决改成分级（需要一次阈值标定）

做法：`offCanvas` 不再单独否决，改为与"可见元素数/越界占比/越界面积占比"比较后再决定；
同时把"保留子集是否自足"（已有的 `coverage`/`centroid`）纳入判据。

- 副作用：**会真的放过一批图**。放过的实际风险是"这部分内容用户看不到"（零像素），
  而不是"图上缺一块"——缺一块的风险来自**部分越界**，那条从来就不拦。
  但如果模型**系统性**地画大了，放过的图会是**构图重心偏移**的图（主体在画布一角），
  这就属于"视觉上确实变差"，现有确定性指标只能部分兜住。
- 代价：需要一次阈值标定（要对"越界占比 vs 人眼是否可接受"取样），不是拍脑袋能定的。

### B. 先修判定的三类可证伪偏差，再谈阈值 —— 代价中、风险中低

- **B1 祖先 `transform`**：把"元素自带 transform 就豁免"扩展为"存在带 `transform` 的**祖先**也豁免"，
  或退一步做轻量栈解析（当前是纯正则，无树；`svg-quality.ts:298-321` 需重写为带嵌套/transform 栈的扫描）。
- **B2 非零 `viewBox` 原点**：`svg-quality.ts:282-287` 丢掉了 `min-x/min-y`。要么按真实原点判，
  要么**明确拒绝**非零原点的 `viewBox` 并给出可读理由。
- **B3 贴边零厚度元素**（D1）：把 `> 0` / `< vw` 换成按"是否至少有 1 个可见像素"判（或引入 epsilon，
  并把 `stroke-width` 计入包围盒外扩）。
- 副作用：**B1/B3 会削弱这条规则的拦截力**——但要注意它现在拦的东西**本来就不是它想拦的东西**
  （它拦的是"原始坐标在画布外"，不是"变换后在画布外"）。收益是**判定语义与渲染语义一致**。
  代价是代码从"正则一把梭"变成"轻量解析"，回归面变大（`scripts/svg-quality-check.mjs` 的 20 条断言要重新过一遍）。

### D. 让产品替模型"修剪/落位"（**不建议**）

做法：把完全在画布外的元素删掉，或把整体按包围盒等比缩放平移进 viewBox。

- 副作用：**改变了用户拿到的图，用户不知道**。对 ≈28% 越界的那批，等于**悄悄删掉四分之一内容**；
  平移缩放会把主体挤小、破坏构图。且它与"素材必须用户看着满意"的定位冲突。
