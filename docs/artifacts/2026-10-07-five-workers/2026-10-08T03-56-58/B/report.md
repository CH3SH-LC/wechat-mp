## 1. 安全切点算法（`src/lib/htmlToImage.ts`）

### 1.1 目标怎么定

`PAGE_CSS_H = 1000` 从「硬性页高」降级为**目标页高**：`TARGET_PX = 1000 × 2 = 2000` 设备像素。实际页高 = 相邻切点之差，允许不同。

### 1.2 保护区测量（在 host 仍挂载时）

对隐藏 host 遍历**四类对象**，收集「切点不得穿过」的区间（CSS 坐标，相对 host 顶）：

| # | 对象 | 取法 | 为什么这样取 |
| --- | --- | --- | --- |
| ① | 文字行 | 逐个**文本节点** `Range.selectNodeContents(tn)` → `getClientRects()` 每行一个矩形 | 多行 `span` 的 `getBoundingClientRect()` 是整块包围框（含行间空白），用它判断会既漏切又误判 |
| ② | 图片 / 内联 SVG / canvas / video | `getBoundingClientRect()` 整块 | 不识别图内内容；`<img>`（含生产 `artRender` 产出的 data:image/png）与内联 `<svg>` 都覆盖 |
| ③ | 表格行 | `tr` 整行 | 不拆行、不重复表头 |
| ④ | 非文本可见叶子 | 无子元素、无文字、`display/visibility/opacity` 可见、非 `position:fixed`，且有**背景色/背景图/边框**的叶子元素，按**变换后**矩形取 | `compose` 的花边分隔线、时间线圆点、`rotate(45deg)` 菱形角饰没有文字也没有 `<img>`，文本 Range 完全量不到；只取叶子，**不**把带背景的祖先 section 整块保护（否则大卡片会把整段正文变成不可分割区，动辄产出超高页） |

`transform` 一律以 `getBoundingClientRect()` 为准，不从 `style.width/height` 推；完全落在画布外的装饰不计。

### 1.3 CSS 坐标 → 整数设备像素（统一换算）

```
top    = max(0,  floor(cssTop    × 2) − 1)
bottom = min(H2, ceil (cssBottom × 2) + 1)
```

上缘向下取整、下缘向上取整，**各 1 个设备像素余量**。区间按 top 排序后合并**相交或相接**的区间（相接即合并，保证合并后任意两区间之间至少留 1 个设备像素的空隙）。`H2 = ceil(host 高) × 2`，与长图/host 的换算同源。

### 1.4 选切点（`planCuts`）

从当前切点 `cur`（初始 0）出发：

1. `aim = cur + 2000`。若 `aim ≥ H2`，本页就是末页，切点取 `H2`。
2. **向小**找 ≤ `aim` 的最近合法点：从最后一个合并区间倒着扫，`若 iv.top < v < iv.bottom 则 v = iv.top`。合法点 = **不严格落在任何保护区内部**的点。
3. 若上一步得到 `back > cur` → `next = back`（**页高变短**，内容完整）。
4. 否则说明「从 `cur` 起的这一段保护区一路盖过 `aim`」（= 一块**高于目标页高且不可分割**的内容）→ **向大**找 `aim` 之后第一个合法点（覆盖 `aim` 的那个区间的 `bottom`），`next = min(fwd, H2)`，并记一条 `oversize-unbreakable`（含起止、页高、目标页高）。**禁止**原地循环 / 静默切字 / 缩小字号。
5. 末页小尾巴：若 `H2 − next < 8`（设备像素），把尾巴并入上一页（`next = H2`）。
6. 重复直到 `cur === H2`。

**边界条件（已按这些条件写死在代码里，违反即抛错中止导出，不静默出图）**：

- `cutsPx[0] === 0`，`cutsPx[末] === H2`，**相邻切点严格递增**（`cuts[i] > cuts[i-1]`）→ 否则抛错「分页切点非严格递增…」；
- 每页高度必须 `> 0` → 否则抛错「第 N 页高度非正…」；
- 页区间**连续覆盖** `[0, H2)`：页 i = `[cuts[i], cuts[i+1])`，**不在每页高度上各自四舍五入**，不重叠、不遗漏（拼回逐像素一致就是这条的可执行证明）；
- **末页不得为空**：先按 5 合并小尾巴，再做一次「碎片页/空白页合并」——任何 `高度 < 40 设备像素` 或**整页无墨**（逐像素抽样，`r/g/b ≥ 250` 视为白）的页都并入相邻页（第 0 页没有上一页时改为并入第 1 页），循环到没有这种页为止。合并不丢像素（页区间仍连续覆盖），只是两页变一页。

### 1.5 超高块策略

**整块输出为一张较高页**（不拆、不缩）：

- 触发条件是「不可分割保护区跨过目标页高」。实测：`art.md` 的 1372 CSS px 竖版长插画 → 一张 **1373.5 CSS px**（2747 设备像素）的页，原因 `oversize-unbreakable`，页高与目标页高都写进 `oversize[]` 返回值。
- **高度风险如实记录**：该页比普通页高，上传到公众号后台是否有单图高度限制**未实测**（本机无后台授权）。这是已知边界，不是「已经没问题」。
- 若一块不可分割内容**超过画布能力**：见 1.6，直接给准确错误，**不伪造成功**。
- 说明边界：**只有**「整块输出的超高页」这一条路径保证图片不被切开；如果将来允许拆分，必须显式标注属「超高块例外」，不得写成「所有图片均不切」。

### 1.6 画布能力上限（本轮新增的准确错误）

实测本机 Chromium 1234、宽 750 时：高度 **65535 设备像素仍能出图，65536 起 `toDataURL()` 不抛异常、只返回 `"data:,"`——画布是空的**。也就是说超限原本是**静默失败**：旧实现的 `h > 200000` CSS px 上限（= 400000 设备像素）根本挡不住它，会悄悄导出一张空长图。

现在：

- `H2 > 65535` → 抛错「正文高 32800 CSS px（65600 设备像素）超出画布能力上限 65535 设备像素，无法转图：请缩短正文」
- 单页 `> 65535` → 抛错「第 N 页高 … 超出画布能力上限 …（不可分割块过高）」
- 长图/分页的 `toDataURL()` 结果不再是有效 PNG（`data:image/png;base64,` 后不足 100 字符）→ 抛错「…未产出有效 PNG」（兜住「静默空图」这一类）。

实测（`B/probe6.mjs`）：32700 CSS px 正常出图；32800 CSS px → 准确错误，退出为异常而非空图。

## 3. 旧切法证红 / 新切法证绿（实测输出）

两套判据用的是**同一个独立探针**（脚本自己实现，不复用产品代码）：文字行按 `Range.getClientRects()` 逐行取，图片/SVG 整块，`tr` 整行。

- **矩形口径**：切点是否**严格落在**某对象的竖直范围内。
- **逐像素口径**：取切线上下各一行，统计「同一列两行都有墨（alpha>8 且 R+G+B<600）」的列数。落在空隙里的干净切点两侧都是白 → 0；字形/图形被劈开 → > 0。它比行盒矩形更接近「肉眼看到被切开」。
