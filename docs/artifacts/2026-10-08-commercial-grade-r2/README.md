# 商用级加固 R2：有信息重画 + 长短两档复跑（2026-10-08）

目标（用户原话）：**"以实现商用级长短均可的推文作为目标，持续进行推进"**。

本轮做两件事：① 修一个**有实证**的素材质量缺陷（质检拒收后的重画没有把失败原因带回模型）；
② 在**同一个发布产物**上把"短篇 + 长文"两档各跑一次真机真实模型验收，让"长短均可"从单次样本
变成可复现证据。阈值、模型侧提示词、账本口径一律未动。

## 一、缺陷：重画是"盲画"（产品侧，已修）

**现状（改前）**：`src/lib/image-agent.ts` 的 `drawSlot` 在素材被本地质检拒收后，
**原样重发同一个 brief**（`genOnce(..., brief, theme)`）。模型拿不到"上一版哪里不合规"。

**实证代价**：G2A 两次生成分别有 **30 / 15** 个可见元素完全落在画布外，重画后变成 **44 / 15**——
**越画越差**。同一批证据见 [越界判定修复记录](../2026-10-08-out-of-canvas/fix.md)。

**为什么这是缺陷而不是"模型不行"**：产品里**已经**有一条同构的通道——`refine_brief`。
模型 CLARIFY 追问时，前端把问题交回主模型补 brief 再画一次。也就是说"把上一个失败的事实交回模型"
这条路是通的，**只有质检拒收这条路径没有接上**。

**修法**（只做事实转述，不猜画法）：

| 层 | 改动 |
| --- | --- |
| `src/lib/image-agent.ts` | `GenOnce` 增 `reasons`（**完整**理由，`detail` 仍只留前 2 条）；新增纯函数 `qualityRetryHint(reasons)`（过滤空白、**最多转述 3 条**、无理由返回 `null`）；`drawSlot` 维护 `qualityHint`，**仅在上一次是质检拒收时**写入，并传给下一次 `genOnce` |
| `src-tauri/src/chat.rs` | `gen_svg` 增可选 `hint`；`svg_user_prompt` 把 hint 作为**独立一句**追加，**不混进"画面内容"** |

**几个刻意的边界**：

1. **网络类失败不带提示**——那类失败重发同一 brief 才是对的，加提示只会污染画面描述。
2. **brief 被 `refine_brief` 重写后清空 hint**——旧理由针对的是**旧的画面描述**，继续带着会指错方向。
3. **提示只追加、不替换**——`画面内容：{desc}` 保持原样（Rust 单测钉住这一点：模型不能把几何约束
   当成要画的对象）。
4. **不告诉模型"该怎么画"**——本地质检只掌握几何事实，越界去猜画法等于把提示词变成另一套规则。

## 四之二、R3：L6 分页断言补强（待办 T6 的第一处盲点）

**背景**：`L6` 是**真机导出路径**上的分页验收（复用已有成稿、**零模型调用**）。2026-10-08 上游把它
写死实现细节的断言（`页数 = ceil(长图高/2000)` 且每页等高）换成了不变式 `Σ页高 = 长图高`。
这条是对的，但**证明不了"每一页画的是它该画的那一段"**——**页序颠倒**、或每页整体偏移 ±N 像素
（只要页高之和仍等于长图高），旧断言一律通过。这正是 T6 记的第一处盲点。

**改动**：只改 `scripts/live-acceptance.mjs`（新增页面辅助 `comparePagesToLong` + `runL6` 一条断言与
一条观测），**不动产品代码**。口径：第 k 页的像素 vs 长图从 `top = Σ前 k-1 页高` 起的同尺寸条带，
**逐像素、零容差**；页宽不一致 / 条带越界单独标出（`diff:-1` = 没比），不冒充"比过了"。
长图 + 全部分页要一次性进页面，合计超 24 MB 时**如实记为"未比较"**，不做半截比较。

**真机结果**（复用 BIG 成稿，`--root %TEMP%\wxmp-r2\big1`，零模型调用，账本 182/75 不变）：

```
PASS - L6：分页严格连续拼接（页高之和 = 长图高）  (长图 750x12892；7 页，页高=[2000,1984,1960,2000,2000,2000,948]，合计=12892)
PASS - L6：分页每一页与长图对应条带**逐像素一致**（页序颠倒 / 整体偏移同样会被这条拦下）
       (长图 750x12892；第1页(top=0,h=2000)一致(0 像素差异)；…；第7页(top=11944,h=948)一致(0 像素差异))
LIVE-ACCEPTANCE PASS（L6）
```

顺带取得一项此前没有的证据：**带图 + 多页**的真机导出——**7 页、750×12892 长图、11 张内联插画**，
是长文成品第一次在真机上走出多页分页（此前多页只在纯文字夹具上验证过）。

> **后记（2026-10-08 R9）**：恰恰是在这类"带图多页"的真机导出里发现了一个**真缺陷**——
> 真机分页会**切穿文字行**（6 刀里 1 刀）。本节上面这条断言证明的是"每页像素等于长图对应条带"
> （**拼得回去**），它**不等于**"这一刀切得干净"（**没切在字上**）。两条是不同的事，
> 详见下面 §4.7。

**可证伪证明**（`l6-pixel-red.mjs`，同一批真机 PNG，故意把条带配错）：

```
对照 1 真机原样        → diff=[0,0,0,0,0,0,0]（合计覆盖 12892/12892）
反证 A 交换第 1/2 页    → 两页都非 0（diff=1,134,209 / 1,135,844，首个差异行 4 / 20）
反证 B 丢掉第 1 页错位  → 非 0（diff=1,134,209，占该页 76.2%）
对照 2 同一页重复两次   → 第 1 条 0、第 2 条非 0（证明"0"不是常量返回）
L6-PIXEL-RED PASS（比对可证伪：原样 0、配错必红）
```

两条防漂移规矩照抄本仓库既有做法：比对函数**从 runner 里抽取**（抽不到即报错退出，不允许用自带
副本），输入就是**真机导出的那批 PNG**（不另造夹具）。

## 四之三、R4：G2A 的「名额」假红（待办 T4，已修）

**问题**：`G2A` 的一条 forbidden 判据是**裸子串**——正文只要出现「名额」就判"补写了材料未给的规则"。
2026-10-08 真机复跑逐字复现：正文写的是

> 具体场次时段、报名入口与截止时间，会在费用、**名额**确定后一并向大家说明。

——**恰好是在说明"还没定"**，也就是**没有编造**，却被判红。这是**判据**的缺陷，不是产品的缺陷。

**修法**：把判据从"某个词出现"改成"**给未定项安上一个数字**"这个真正的缺陷形态。

- `scripts/lib/fact-assert.mjs` 新增纯函数 `inventedQuotaHits(body)`（+ `RE_INVENTED_QUOTA`）：
  覆盖 `名额60` / `限额：30` / `60 个名额` / `限 30 人` / `人数上限 50` / `人数不超过 40`，
  中文数字**要求带单位**（个/名/人/位），全角数字先归一。
- `scripts/live-acceptance.mjs` 的 forbidden 循环支持第三种条目形态 `[标签, 说明, 'quota']`。
- **明写的覆盖面边界**：中文数字**不带单位不覆盖**——因为「名额**一旦**确定」里的「一」会被误伤，
  宁可少拦也不制造新的假红。

**离线（可证伪）**：`fact-assert-check` **45/45**（原 30 条 → 新增 ⑧ 组 15 条，`plannedCases` 加 `⑧`）：

```

PASS - ⑧ 必须不命中：会在费用、名额确定后一并向大家说明。/ 报名费用与人数上限暂未确定，/
                        名额一旦确定就会通知 / 费用尚未确定，确定后在本通知中同步 / 请提前 5 分钟到场

   - `src/lib/htmlToImage.ts::planCuts` **自己在校验后 `throw`**：切点非严格递增、末切点 ≠ 画布高
     都直接"已中止导出"；
   - 而且**页数就是由切点生成的**（`for (let i = 0; i < plan.cutsPx.length - 1; i++)`）——
     `页数 ≡ 切点数 − 1` 是**构造性**结论，不是需要另外断言的经验事实；
   - `scripts/export-paging-check.mjs` 另有独立断言："切点严格递增、首 0、末 = 画布高" +
     "分页逐张拼回后与长图**逐像素一致**"。

**残留（写明，不装作没有）**：`L6` 走真机路径**读不到**模块的 `cutsPx`；它验的是**输出**
（逐页像素与长图对齐），这比读中间数组**更强**，但确实不等于"在真机上核一遍切点数组"这一种表述。

### 6.3 有信息重画：三跑 35 次绘图，仍未触发（边界更新）

`BIG` 三次合计 **35 次 `gen_svg`**，**全部 attempt=1、全部成功，0 次质检拒收**——R2 引入的
"有信息重画"路径在真实链路上仍然**一次都没被走到**。这个数字现在比 R2 时更硬（那时是 1 次跑、
23 次绘图里的 0），但它证明的东西没有变：**真机证明的是没有回归，收益仍未取得真机证据**。
要取得，需要一个**真的出现质检拒收**的样本——本轮三次都没有。

## 四之六、R7：导出的 `.html` "真的能打开、内容完整"（GOAL 验收表的本地半边）

### 7.1 为什么补这一条

GOAL 的验收表里"导出交付"写的是：**"HTML、750px 宽长图及分页 PNG 可打开，内容完整；在实际公众号
后台验证手动使用效果"**。后台那半边没有账号、做不了；**本地这半边此前没有被真正验证过**——
`L6` 只核了两件事：文件与"最后成功版本"**逐字节一致**、正文**无外链资源**。
这两条**都推不出**"用户双击打开后看得到东西"：一个图全裂、正文缺失的 HTML，同样能逐字节一致、
同样没有外链。

### 7.2 加了什么

`scripts/live-acceptance.mjs`（只改驱动，**不动产品代码**）：在 `L6` 的 HTML 导出断言之后，
**真的用浏览器打开那个 `.html` 文件**（`file://`，新建一个页面、不碰应用页面），核对

- 图片**全部解码**（`naturalWidth > 0`，不是"src 存在"）；
- 成品标题在渲染文本里**可见**；
- 渲染出的可见字数与预览读数**相差 ≤10%**。

打不开新页面时**如实记为"未核验"**（`observe`），不冒充通过、也不据此判失败。

**真机结果**（L6，零模型调用，账本 227/103 不变）：

```

       (图 1 张（解码失败 0，宽度 [1500]）；渲染可见字数 126（预览读数 120）；

### 7.4 一个**被证伪**的猜想（记下来，免得下次又去查）

## 四之七、R9（发现缺陷）：真机长文分页**切穿了文字行**（待办 T7）

**这是本轮最重的一条：不是"多了一项证据"，是"发现了一个缺陷"。**

### 9.1 现象与证据

R8 里给 `L6` 加"导出的 HTML 打开后内容完整"时，我把长文那次的 7 张分页拼起来看，
发现**最后一页的顶上是一行被横切掉一半的字**。于是做了一次独立的逐切点量测
（`paging-seam-probe.mjs`，口径与 `export-paging-check` 同一套：深墨 = RGB 三通道都 < 180，
跨缝 = `cut-1` 行与 `cut` 行**同列都深墨**）：

```
长图 750×12058；分页 7 张，页高 [1990,2000,1967,2000,1988,1992,121]，合计 12058
  切点 y=1990  跨缝列数=0  最近墨迹距离=15px  → 干净
  切点 y=3990  跨缝列数=0  最近墨迹距离=-1px  → 干净
  切点 y=5957  跨缝列数=0  最近墨迹距离=4px   → 干净
  切点 y=7957  跨缝列数=0  最近墨迹距离=-1px  → 干净
  切点 y=9945  跨缝列数=0  最近墨迹距离=26px  → 干净
  切点 y=11937 跨缝列数=160  最近墨迹距离=0px  → **切穿墨迹**
```

裁图肉眼可见：红线就是页边界，`打 010-55566666；想直接去看看，那就` 这一行被从中间横切，
上半截留在第 6 页、下半截掉到第 7 页。

### 9.2 为什么这一条要紧

- **它是用户直接看得见的东西**：分页 PNG 是给用户**逐张上传到公众号**的（手册里就是这个流程），
  页边界上出现半截笔画，是交付物本身的瑕疵。
- **它正好是"离线全绿、真机不绿"的那一类**：`export-paging-check` 有一条断言
  **"新切点逐像素未切穿墨迹（跨缝列数 = 0）"**，它在自己的夹具上**通过**；真机路径此前
  **没有**这条量法。所以这条保证在真机上**不成立**，而离线绿灯给了假的安心。
- 命中率不是 100%：这次是 **6 刀里的 1 刀**（最末一刀）。

### 9.3 根因：**尚未确证**（下面是假设，不是结论）

可以确定的**事实**：5 刀干净、**只有最末一刀**切穿；干净的那几刀里，最近墨迹距离分别是
15 / 无 / **4** / 无 / 26 px——**4px** 这个数偏小（保护区本该把切点抬到墨迹之外一个 `PROTECT_PAD_PX`），
提示"量出来的行位置"和"画出来的行位置"**本来就存在一个小的累积偏移**。

由此提出**假设**（未验证）：`renderArticleImages` 是**先量后画、且量/画两套 DOM 不同**——
量的是挂在文档里的 `<div>`（吃页面全局 CSS），画的是 `<img src="data:image/svg+xml,…">`
里的 `<foreignObject>`（**图片是独立文档上下文，页面 CSS 不参与**）。若两者的
`line-height` / 字体回退有差，行盒位置就会整体错开、并**向下累积**；越靠尾部越大，
于是最末一刀落在了一行字上。

**没有验证的部分**：我没有在真机里把"量到的行盒位置"与"画出来的像素位置"逐行比对过。
所以这条**只是假设**，不当结论用。

### 9.4 复现

  --dir "$TEMP/wxmp-r5/big3/profile/Documents/wechat-mp-workspace/exports/img-tuiwen-20261008-2307" --crop
```

（`--crop` 会把每个切穿处的上下文裁成 PNG，红线上方/下方就是页边界两侧。）

### 9.5 已经把它变成**验收里看得见的一条**（L6 现在是红的）

只记录不设防，下次还会悄悄溜过去。所以把 `export-paging-check` 的那条量法**搬到真机路径上**：
`L6` 新增断言 **"分页没有一刀切在字上（每个切点跨缝列数 = 0）"**，量法与离线那条**同一套口径**，
在**同一次 `comparePagesToLong` 调用里**顺带算出（不多一次往返）。

实测（长文 root，零模型调用）：

```

**即：`L6` 现在是红的，红的正是 T7 这个真缺陷**——这是诚实的状态，不是回归。
对照：单页导出（没有内部切点）不会假红，只记一条"缝口无对象可查"的观测
（在 1 页的 root 上复跑 `L6` → **PASS**）。

### 9.6 根因定位（R10）：一条假设被削弱，另一条被**真机自己的数字**支持

**先说结论边界**：**仍未确证**。下面区分"实测到的"与"推断的"。

**实验一（在真机里做）**：给 `L6` 加了一段**只观测不判定**的诊断
（`measureRenderAgreement`）——在应用页面里把产品自己的"量 → 画"两步重跑一遍。
真机结果（长文 root）：

```
量到的文本行盒 175 个，其中渲染后**完全没有墨**的 5 个；
量到的正文底 = 11980 设备像素，实际最底墨迹行 = 11997（差 17）；
画布高 12058（= 量到 CSS 高 6029×2）
抽样：#172(top=11827,墨=2928) #173(top=11883,墨=2536) #174(top=11939,墨=1127)
```

- **被削弱的那条假设**：上一节写的"量的是 `<div>`、画的是 `<img src=svg>` 里的 `foreignObject`，
  两套文档上下文导致行位置整体错开"——真机上 **175 个行盒里只有 5 个渲染后无墨**，
  **行盒与墨迹基本对得上**（同一实验在普通 Chromium 里是 **31/175** 无墨，差一个量级）。
  所以**这条不足以解释现象**。
- **但有一个小的尾部偏差是真的**：实际最底墨迹比"量到的正文底"**低 17 设备像素**——
  累积偏差存在，只是量级是十几像素、不是一整行。

**实验二（用产品自己的函数，在真机的行盒上推）**：把 `htmlToImage.ts` 里真正干活的
`toDeviceRanges`（保护区 → 设备像素区间）与 `planCuts`（切点计划）**按源码抽取**出来
（`t7-cut-repro.mjs`；抽不到即报错，不允许用自带副本），拿真机测到的行盒去推：

- 末刀的目标点 = 上一刀 9945 + 目标页高 2000 = **11945**；
- `11945` 落在**第 174 行的行盒** `[11939, ≈11995)` 里 → 于是"退到该区间的 top"，
  而该 top 在 `toDeviceRanges` 里**被减掉了 `PROTECT_PAD_PX = 1`** ⇒ **11938**；
- 而**第 173 行的行盒是 `[11883, 11939)`**——两个行盒**首尾相接**，
  所以 **11938 落在第 173 行的盒子里面**。（实测切点是 11937，与推算差 1 像素，
  属两次运行之间的排版抖动；`11939-2` 与 `11939-1` 只差在那一像素。）

**即：保护区上边界那 1 个像素的 padding，把切点推进了上一行**——而 export-paging-check 的探针
量的是"刀口上下两行同列都有墨"，这 1 像素的侵入正好被它抓到（跨缝 160 列）。

**这条仍只是"推断"**：我用的行盒来自**另一次运行**的测量，不是导出那一次的。
要把它钉成结论，需要**让导出把它的切点计划与当次保护区间一起报出来**（见下）。

**实验三（能不能在应用外面复现）**：`t7-cut-repro.mjs` 在普通 Chromium 里跑同一篇正文，
量到高 **6041** CSS（应用里是 **6029**）——字体度量不同，切点变成
`[0,1997,3997,5971,7971,9963,11959,12082]`，**没有一刀落在行盒里**。
**结论：这个缺陷在应用外面复现不出来**，必须在真机上验证与修复。这条本身也是有用的信息——
任何"我在本地跑通了"的说法对这个缺陷都不成立。

### 9.7 下一步（T7 的收口路径）

1. **让导出把自己的切点计划与当次保护区间报出来**（观测性改动，不动切点算法）——
   这样"切点落在哪个区间、为什么退到这里"就能用**同一次运行**的数字定死，不再跨运行推断；
2. 据此再决定改法（候选：退到区间 top 时**不要让上边界的 padding 跨进上一个区间**，
   或干脆切在两个保护区之间的空隙中点），按行为变更**单独验收**（真机多篇、多刀）。

### 9.8 已登记为待办 T7，**本轮不改产品**

它要动的是 `htmlToImage.ts` 的"量/画一致性"——属**行为变更**，需要单独验收（真机多篇、多刀）。
按本仓库的规矩，**先记录、不夹带**：本轮不为了"看起来绿了"去改阈值或截断策略。
但**验收侧已经先设防**：修好之后这条断言会自动转绿，改坏也会立刻变红。
