## 1. 执行摘要

小标题是公众号推文的"文中路标"与"第二道标题"：把长文切成可扫描模块、二次抓眼球、浓缩要点，直接关系完读率。文案写法共识可归纳为 **"短、准、钩、统"四字诀**——长度 8–15 字、精准概括本节、自带阅读钩子（数字/问句/悬念）、全文风格统一；平台级红线是标题党、空话、文题脱节（微信官方治理）。

排版样式生态上，主流编辑器（壹伴/135/小墨鹰）的标题样式可归为 **15 类**（序号/线框/底色/夹线/胶囊/圆形/花边/箭头等），使用规范为"一文 1–2 种样式、全文 3–5 个小标题、文字 ≤10 字"。素材维度，标题装饰 SVG 可归为 **16 类**，其中与 wechat-mp 现有"25 纯色 + 14 插画"双桶资产最兼容、性价比最高的是 5 类：**直线/双线分隔线、左右夹线、序号徽章、卷曲涡卷、几何点缀**（均可单色化、可程序化换色）。

兼容性上，微信图文**不能直接上传 SVG 文件**（uploadimg 仅 jpg/png、add_material 图片仅 bmp/png/jpeg/jpg/gif），内联 SVG 受国家团体标准 **T/CASME 1609—2024 属性白名单**强制清洗（id/class/href/defs 禁用），正文 CSS 仅内联可用。**"SVG 源资产 → canvas 渲染 PNG → 素材库上传"是唯一稳妥的装饰素材路线**——与 wechat-mp 现有资产管线完全一致，本次调研从官方文档层面证实了该策略的正确性。

核心结论（可信度：🟢 多源交叉确认）：小标题素材库应优先扩充**序号徽章、左右夹线、分隔线、几何点缀**四类单色可换色资产 + 每类附"形态/尺寸/适用场景/字号配色"元数据。

## 3. 调研发现

### 3.1 小标题的作用（为什么需要）

1. **对抗碎片化阅读**：手机端长文读者耐心有限，小标题把长文切成可"扫描"模块，读者随时知道"这段讲什么、值不值得读"，留人、提升完读率（🟡 多源：小墨鹰/猪八戒/博客园）。
2. **充当"文中路标"**：对材料分门别类，读者随时知道"我在哪、下一站是什么"（🟡 ck.xwpx《请在文中设点路标》）。
3. **二次抓眼球**：正文里的"第二道标题"，用数字/悬念/问句驱动继续读。
4. **浓缩要点助记忆**：只看小标题即可掌握骨架，方便收藏转发。
5. **视觉节奏与留白**：一屏一标题产生呼吸感，层级分明是排版的颜值组成。

### 3.2 小标题文案写法（核心）

#### 3.2.1 十种类型（定义 + 示例 + 适用场景）

| # | 类型 | 定义 | 示例 | 适用 |
|---|---|---|---|---|
| 1 | **数字型**（清单型） | 用数字量化，承诺具体信息量 | "3 个方法，让你的开头不再平淡" / "写公众号踩过的 5 个坑" | 教程干货、清单、复盘 |
| 2 | **问句型** | 问题切入，制造悬念与代入 | "为什么你读了那么多书，还是写不好？" | 科普、干货、观点文小节开头 |
| 3 | **悬念型**（留白型） | 只给诱因不给答案，制造好奇心缺口 | "我辞掉月薪 3 万的工作后……" | 情感故事、深度报道（勿长期透支） |
| 4 | **总结型**（观点型） | 直接亮结论，观点先行 | "自律的本质，是摆脱多巴胺" | 观点文、干货段落收束、金句号 |
| 5 | **对比型** | 对比制造张力 | "穷人与富人的差距，不在努力" | 成长观点、职场分析 |
| 6 | **对仗型** | 两段式对偶，工整有节奏 | "三分选对赛道，七分持续深耕" / "向内生长，向外绽放" | 总结材料、党政宣传、品牌调性 |
| 7 | **引用型**（金句型） | 引用名言/台词/高赞评论借力 | "知乎最高赞：所谓成熟，是学会闭嘴" | 情感故事、人物报道（引用须真实） |
| 8 | **命令型**（祈使型） | 直接给指令，行动导向 | "先学会存钱，再谈理财" | 干货行动建议、宣传号召 |
| 9 | **场景型**（时间/地点轴） | 时间地点场景串叙述，画面感强 | "凌晨四点的医院" / "入职第 1 天、第 30 天、第 100 天" | 情感故事、人物通讯、纪实 |
| 10 | **修辞型**（比喻/拟人/双关） | 修辞让抽象变生动 | "职场就是一场马拉松，拼的不是起跑线" | 情感、科普、品牌（谐音梗慎用） |

#### 3.2.2 不同类型推文的写法差异

| 推文类型 | 写法特征 | 典型示例 |
|---|---|---|
| **新闻资讯** | 客观短语概括"时间+事件+要点"，忌夸张，像"新闻提要" | "政策速览：三部门联合发文" / "数据：上半年新增用户 1.2 亿" |
| **教程干货** | 数字/步骤/命令型为主，每节一个可执行点 | "第一步：先定选题再动笔" / "记住这个公式：观点+案例+金句" |
| **宣传推广** | 利益前置、场景代入、稀缺感；悬念/命令型，承担卖点大纲与转化钩子 | "这次，我们准备了 100 份福利" / "报名倒计时：名额仅剩 30 个" |
| **情感故事** | 情绪化口语化，问句/金句/场景式，像"剧集预告" | "那天晚上，我删掉了所有聊天记录" / "妈妈的那通电话，我等了 3 年" |
| **科普** | 问题切入、比喻化解术语，一节解决一个"为什么" | "为什么一熬夜就长痘？" / "把身体想象成一座城市" |

#### 3.2.3 写作技巧细则

- **长度**：**8–15 字为宜、一般不超过 20 字**（多源经验共识，⚠️ 无官方数据；政务/公文可稍长）。"长标题更吸睛"的观察多指主标题，文内小标题以短、准为佳（🟢 中国新闻出版广电报）。
- **句式**：短语/动宾结构/完整短句，避免长从句；一段一节、一节一标题；标题间逻辑递进（并列/递进/因果）；**全文风格统一**（全问句或全数字或全动宾，混用显杂乱）。
- **关键词布局**：核心关键词前置（数字/冲突词/情绪词/热点词放前 3–4 字）；每节含"记忆锚点"；自然嵌入用户会搜的词（🟢 与 wechat-mp 已有 copy-tags 条目"小标题是关键词黄金位"互证）。
- **与正文呼应**：小标题 = 本节最大信息量浓缩；正文第一句回应、末句回扣，形成闭环；**严禁"两张皮"**；叙事类"标题剧透一点点、正文展开全部"，干货类"标题给结论、正文给步骤"。
- **使用约束**（编辑器生态交叉）：一文 1–2 种标题样式、全文 3–5 个小标题、文字 ≤10 字（🟢 壹伴官方 + 🟡 小墨鹰）；每 300–500 字一个小标题（🟢 与 wechat-mp 已有 copy-style-rhythm 互证）。

#### 3.2.4 八个坑（必须规避）

1. **标题党/夸大其词**：微信官方《关于标题党问题的规范》治理混淆官方/煽动蛊惑/对抗审核，不符限流甚至删除（🟢 微信官方 + 财联社）。
2. **空洞无物/正确而无用的废话**："四宜四忌"宜具体忌空泛（🟢 共产党员网）。
3. **与正文脱节**：标题写 A 正文讲 B。
4. **过密过碎或全文无标题**：三五行为一节打断阅读；通篇无标题的长文劝退。
5. **乱用谐音梗/烂梗**：中新网点名批评，过时且显廉价（🟢）。
6. **风格不统一**：问句/数字/文言混排。
7. **悬念型剧透**：自问自答把答案写进标题。
8. **层级与格式混乱**：主副标题字号层级不分、半角全角标点混用、错别字。

#### 3.2.5 好/坏案例对比（6 组）

| ❌ 坏案例 | 坏在哪 | ✅ 好案例 | 好在哪 |
|---|---|---|---|
| "文章写作技巧" | 空洞无信息量 | "3 个方法，让你的文章开头不再平淡" | 数字承诺+具体利益 |
| "读书的重要性" | 说教、正确废话 | "为什么你读了那么多书，还是写不好？" | 问句引发共鸣代入 |
| "一个女人的奋斗故事" | 泛泛无钩子 | "她辞掉铁饭碗，35 岁重头再来" | 具体细节+悬念冲突 |
| "自律很重要，大家一定要自律" | 空喊口号 | "先做这 1 件事，再谈自律" | 命令+顺序逻辑可执行 |
| "熬夜危害大，大家不要熬夜" | 说教无画面 | "熬夜后的身体，正在经历这 5 个变化" | 具体可感知有量化 |
| "努力很重要" | 无信息量 | "三分选对赛道，七分持续深耕" | 对仗工整观点明确 |

### 3.3 小标题排版样式生态（编辑器视角，15 类）

**三家官方分类基准**：壹伴（序号/主副/线框/底色，线框最火 🟢）、135 编辑器（三级/注释/单线/底色/线框/虚线/序号/主副/描边共 9 子类 🟢）、小墨鹰（数字编号/项目符号/线框/底色/主副 🟡）。

| # | 样式 | 形态描述 | 适用场景 |
|---|---|---|---|
| 1 | 纯文字加粗/描边 | 无装饰，仅加粗/描边+留白 | 极简、商务、科技号 |
| 2 | 序号数字标题 | 数字（01/一、）引导，数字可放大套色块 | 教程步骤、产品介绍、并列要点 |

| 4 | 线框标题 | 矩形/圆角边框包裹文字（含双线叠加） | 观点论述、通用百搭 |
| 5 | 底色标题（色块底衬） | 色块铺底+文字（含莫兰迪、撞色拼接） | 强调重点、简约点缀 |
| 6 | 单线/下划线标题 | 左右线条夹文字或底部单线（"──标题──"） | 杂志风、文艺风 |
| 7 | 虚线标题 | 虚线边框/分隔 | 极简清爽 |
| 8 | 主副标题 | 主标题+副标题两行 | 活动报道、长文分段 |
| 9 | 卡片式/胶囊式 | 圆角胶囊、卡片框（可行业化带图标） | 医疗/教育/政务行业号 |
| 10 | 圆形/几何图形 | 圆形承载序号或文字（深蓝圆+白字"1"） | 步骤类、年轻化 |
| 11 | 花边/装饰性 | 上下花边、异形素材框包裹文字 | 文艺、节日、强品牌调性 |
| 12 | 箭头标题 | 箭头图形引导/指向 | 教程推进、科技/运动 |
| 13 | 渐变/撞色标题 | 渐变文字或色块、高饱和撞色 | 活动推广、年轻化 |
| 14 | 花漾文字/Emoji/艺术字 | 花字特效、emoji、特殊字符 | 种草、生活方式（⚠️ 与 wechat-mp v10 零 emoji 铁律冲突，仅作生态了解） |
| 15 | SVG 互动/动态标题 | 点击展开、轮播、弹跳（"黑科技"） | 活动宣传、教程、campaign（⚠️ 受白名单约束，见 3.5） |

**审美趋势（2024–2026，定性）**：① 极简/留白/高级感成主流（"越简单越高级"）；② 低饱和莫兰迪色系大流行；③ 治愈系/文艺清新；④ 数字放大吸睛（大号序号数字成设计点）；⑤ 不规则/异形边框标题崛起（秀米 2026 官方教程）；⑥ SVG 互动标题常态化；⑦ 撞色拼接/渐变节奏感；⑧ AI 一键排版接管样式选择；⑨ 行业细分定制（商务/科技/政务/医疗各有专属样式）。

**秀米五层组合方法论**：所有标题效果由「布局 + 背景 + 文字 + 边框圆角 + 间距」五层拼出（🟢 秀米官方教程）：圆形序号 = 固定布局 + 背景色 + 圆角 100% + 白字；异形框 = 素材图设背景 + 首中尾三段裁剪拼接 + 蒙版镂空叠加。

### 3.5 微信兼容性（官方实证，决定素材落地路线）

1. **SVG 不能直接作为图片上传**：图文编辑器无"插入 SVG"入口；`uploadimg` 仅接受 jpg/png 且 <1MB；`add_material` 图片仅 bmp/png/jpeg/jpg/gif（🟢 微信官方文档抓取；第 3 路 w3cschool 转述同结论，交叉确认）。
2. **内联 SVG 受白名单强制清洗**：2016 年制定、2024 年归档为国家团体标准 **T/CASME 1609—2024**——`id/class/href/xlink:href/defs/embed` 禁用，marker/渐变被过滤，动画属性白名单外一律消除；`<g style>` 在 iOS 失效；无 JS（🟢 官方 + 🟡 CSDN/博客园/数字营销网交叉）。
3. **正文 CSS 仅内联可用**：`<style>` 与外链被过滤；id 删除、position 过滤、无 @media/@keyframes/伪类；transform 曾失效现已恢复（🟡 企鹅编辑器技术说明 + 博客园）。
4. **正文硬限制**：content <2 万字符且 <1MB；图片 URL 必须来自素材库链接（mmbiz.qpic.cn），外链图片与 base64 被过滤；img 需显式宽高否则 iOS 不显示（🟢 官方 + 🟡 多源；与 wechat-mp SKILL.md 关键事实一致）。
5. **SVG→PNG 可行**：浏览器 canvas 可行（本项目客户端方案正确 ✅）；服务端 sharp 最省事；resvg 中文字体受限（实测中文渲染成豆腐块）；小程序 canvas 不支持 SVG（🟢 官方 + 🟡 工程实践）。canvas 渲染注意：SVG 含外部引用（外链图/外部字体）会**污染 canvas** 报 SecurityError——转 PNG 前必须内联或移除（🟡 lihuanyu 一手实测）。
6. **推荐落地路线**：SVG 源资产 → canvas 渲染 PNG（PNG-24 保质量、宽度 **≤1080px**（超出必被微信压缩）、正文列宽约 677px 为导出基准、体积 **<1MB** 硬限）→ uploadimg 上传 → CDN URL 引用；**内联 SVG 与 data URI 均不推荐用于装饰**（🟢 官方实证 + 第 2/3 路交叉一致）。
7. **其他已知坑**：已推送图文中的 SVG 图片可能莫名变空白（平台侧不可控，社区热帖）；SVG 交互图文不能标原创；普通订阅号正文外链被过滤为纯文本（仅认证服务号可外链跳转）（🟡 数英检查清单 + 微信开放社区）。

### 3.6 真实推文装饰密度与组件构成（v2 补充调研，18 来源 + 1 篇 HTML 实测）

**组件化现实**：真实宣传类/活动类推文由 **30–80 个组件**构成——标题组件 3–8 个、图片 10–30 张、样式化区块 20–60 个、SVG 交互 1–7 个、分割线 3–10 条、装饰元素 10–25 处（🟡 5 篇案例拆解外推）。

**HTML 级实测**（🟢 一手数据，营销案例合集推文，5085 字 ≈ 10–14 屏）：**58 张图片、25 处背景图、13 处渐变、530 个样式化 section（折算可见视觉块 100–180）、236 个段落**——平均 88 字/图，**每屏约 4–6 张图、约 3 处装饰层**，是旧知识库"每屏 ≤1 处"上限的 3–10 倍。

**密度规范修正结论**（🟡 基于实测 + 多源交叉）：
1. **分层规范**：正文型/干货文保留"每屏 ≤1 处核心装饰"；宣传/活动型放宽至**每屏 3–6 个视觉元素**。
2. **装饰标题**：宣传类推文常见 3–8 个标题组件，上限从"≤2 处"放宽至 **3–5 处**。
3. **重分类**：装饰拆为"**功能性视觉元素**"（分隔/强调/导航/编号/CTA，50–70%，不限量随组件走）与"**纯装饰**"（花边/图案/氛围元素，30–50%，每屏 1–2 处）。
4. **对立观点**：md2wechat 主张"模块越多越难读"（针对正文型 + 乱堆行为）与"装饰即信息分区"派（卡片式排版）——两类文体规范不同，不矛盾。

**组件 = 美术素材 + 文字**（用户指定的设计逻辑，详见 test 模拟的 design-logic-components 条目）：标题组件=底色块/花纹+标题文字、气泡=边框+底色+角饰+文字、图片组件=边框+图片+图注、卡片=底色+边框+标题栏+列表；组件三要素（容器/内容/装饰）、5 大类（文字/结构/图文/装饰/功能）；素材库=组件零件库，组件模板=零件+CSS 拼装。

## 5. 对立观点与争议

1. **小标题字数：8–15 字 vs ≤10 字**——第 1 路调研"8–15 字"（多源经验）、第 2 路编辑器生态"≤10 字"（壹伴/小墨鹰使用规范）。裁定建议：**默认 ≤12 字，宣传/情感类可到 15 字**（两者共识区间为 8–12 字，均标注经验值，无官方数据）。
2. **"SVG 推文"玩法 vs PNG 稳妥路线**——存在把 SVG 作 HTML 内联图形+CSS 动画的"黑科技"玩法（CSDN/GitHub 实践），但受白名单清洗且多机型有坑（微信开放社区 Skyline 真机渲染问题）。裁定：**装饰素材一律走 PNG**，不追内联 SVG 玩法。
3. **谐音梗**——中新网点名批评（🟢），但仍有大量账号使用（利益驱动）。裁定：知识库按"禁用"写入，与 wechat-mp v10 零 emoji/零图标字符铁律一致。
4. **花字/Emoji 标题样式**——编辑器生态广泛存在（🟡），但与 wechat-mp v10"零 emoji、零图标字符"审美硬规范直接冲突。裁定：**生态了解入档，但作为反例写入知识库**，不进入素材库。

### 8.3 使用约束（写入知识库，强制）

- 一文 1–2 种标题样式；全文 3–5 个小标题；每 300–500 字一个小标题
- 小标题 ≤12 字（宣传/情感可 15 字）；全文风格统一
- 装饰素材走 art:// PNG 资产或内联 CSS 几何；**禁用**内联 SVG、data URI、emoji 花字
- 红线：标题党/空话/文题脱节/谐音梗（微信官方治理范围）
